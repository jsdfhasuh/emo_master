# 相机节点草稿预览与 Runtime

## 为什么会提示节点不属于工作流

算子类型与节点实例是两回事。`vision.io.huaray_camera` 在 Runtime 的内置插件目录中注册；拖入画布后形成的节点实例属于 Designer 当前工程草稿。Runtime 此前加载的工程不一定包含这个新增节点。旧版预览仅校验已加载工程，因而可能返回 `node is not part of the workflow`。

## 当前行为

点击相机编辑器的“连接相机”时：

1. Designer 在 UI 线程捕获当前画布和全部工作流，冻结草稿快照，保持真实工程 revision 和 updatedAt 不变。
2. `EditorContext` 将快照与明确选择的相机连接参数分别交给固定的 Runtime 客户端；连接、读写与取帧在后台执行。
3. 专用 `OpenCameraConfigurationSession` RPC 进入草稿校验路径，验证工程、工作流、节点和算子标识的一致性，包括节点必须是 operator、节点标识不得重复、算子必须支持配置会话。
4. Runtime 只为该节点建立只读连接并读取实际配置，不自动应用节点参数、不开始采集、不加载或编译整条流程、不创建 Job，也不替换已加载工程。
5. 用户再点击“开始预览”或“单帧”。默认自由采集与节点保存的触发模式分开；停止或完成单帧保留连接与恢复基线。

因此，**新增节点无需先保存工程，也无需先运行流程，即可预览**。其他未完成算子的参数、流程尚未连接，以及没有进入正式 Runtime 加载阶段的 2.2/2.3 草稿，不会成为单个相机预览的整流程编译门槛。工程本身仍须符合草稿结构规范。

## 参数保存和正式运行

- 连接后，完成参数编辑会实时写入、回读并记录恢复基线；无效数字不会写入。首次连接和回读刷新不会写入配置。
- “试用节点配置”才会显式应用节点已保存的相机参数。预览默认值和设备实际值不会自动覆盖节点。
- “应用”让用户选择将哪些已核实属性提交到 Designer 草稿；只有工程保存才落盘。这不代表“保留相机调整”，也不会重置恢复基线。
- `waitMode` 和 `sequencePolicy` 保留新版工作流含义，不作为相机属性写入。硬件预览等待外部触发；软件模式每次点击仅触发一次。
- 预览快照不是正式运行的工程。正式运行仍走现有的显式准备/加载/启动链路。
- 配置会话未关闭时，Runtime 拒绝加载其他工程或启动 Job。Designer 的关闭、删除、切换项目和撤销/重做入口必须先处理相机会话，取消确认则保留原操作状态。
- 关闭时可保留调整、放弃并恢复，或继续调整。恢复逐项回读验证；失败保留会话以便重试，不伪报设备已释放。
- 异常关闭保留未完成调整日志，下次启动提示人工核查，不自动恢复或重放写入，不执行 `UserSetSave`。
- 任意 Runtime Job 仍运行或仍拥有未释放资源时，新草稿相机预览返回 `E_RESOURCE_BUSY`，不尝试抢占设备。
- 请求已取消时不打开设备；打开期间取消会关闭刚创建的会话。
- 草稿预览请求限制为 768 KiB，低于现有 1 MiB 入站 RPC 限额，不放宽传输或执行检查。

## 兼容与更新

旧 `OpenOperatorPreviewSession` 和 `OpenDraftOperatorPreviewSession` 保留普通预览行为。新相机编辑器使用独立的配置 RPC；如果连接的是不支持它的旧 Runtime，会明确提示更新并重启 Runtime，不回退到旧工程或普通采集接口。这样可避免旧服务忽略新字段后意外开始采集。

源码更新后，已经运行的 Python/Qt 进程不会自动重载。先保存当前工作，再正常关闭并重启 Designer；使用远程 Runtime 时也须更新并重启该 Runtime。

模拟相机、Qt 编辑器、回环 gRPC 和隔离 Job 的回归测试不等于实际 IMV SDK、相机网络或实机采集验收。
