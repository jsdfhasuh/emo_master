# 相机节点草稿预览与 Runtime

## 为什么会提示节点不属于工作流

算子类型与节点实例是两回事。`vision.io.huaray_camera` 在 Runtime 的内置插件目录中注册；拖入画布后形成的节点实例属于 Designer 当前工程草稿。Runtime 此前加载的工程不一定包含这个新增节点。旧版预览仅校验已加载工程，因而可能返回 `node is not part of the workflow`。

## 当前行为

点击相机编辑器的“连接并预览”或“单帧”时：

1. Designer 捕获当前画布和全部工作流，生成当前草稿快照，保持真实工程 revision 和 updatedAt 不变。
2. `EditorContext` 将快照与临时相机参数分别交给 `RuntimeClient`。
3. `OpenDraftOperatorPreviewSession` 验证工程、工作流、节点和算子标识的一致性，包括节点必须是 operator、节点标识不得重复、算子必须已注册且支持 live 预览。
4. Runtime 只为该节点建立临时采集会话，不加载或编译整条流程，不创建 Job，也不替换正常运行已加载的工程。
5. 预览临时使用自由采集，关闭/停止或完成单帧后释放采集会话。

因此，**新增节点无需先保存工程，也无需先运行流程，即可预览**。其他未完成算子的参数、流程尚未连接，以及没有进入正式 Runtime 加载阶段的 2.2/2.3 草稿，不会成为单个相机预览的整流程编译门槛。工程本身仍须符合草稿结构规范。

## 参数保存和正式运行

- 相机表单中的临时预览参数不自动写回节点。只有“应用”将参数提交到 Designer 草稿；只有工程保存才落盘。
- 预览快照不是正式运行的工程。正式运行仍走现有的显式准备/加载/启动链路。
- 加载其他工程、启动普通 Job 或启动图片测试 Job 前会关闭相机预览；释放失败则拒绝继续，不伪报设备已释放。
- 任意 Runtime Job 仍运行或仍拥有未释放资源时，新草稿相机预览返回 `E_RESOURCE_BUSY`，不尝试抢占设备。
- 请求已取消时不打开设备；打开期间取消会关闭刚创建的会话。
- 草稿预览请求限制为 768 KiB，低于现有 1 MiB 入站 RPC 限额，不放宽传输或执行检查。

## 兼容与更新

旧 `OpenOperatorPreviewSession` 仍保留已加载工程预览行为。正常 Designer 使用新增的草稿 RPC；如果连接的是不支持它的旧 Runtime，会明确提示更新并重启 Runtime，不静默回退到旧工程。

源码更新后，已经运行的 Python/Qt 进程不会自动重载。先保存当前工作，再正常关闭并重启 Designer；使用远程 Runtime 时也须更新并重启该 Runtime。

模拟相机、Qt 编辑器、回环 gRPC 和隔离 Job 的回归测试不等于实际 IMV SDK、相机网络或实机采集验收。
