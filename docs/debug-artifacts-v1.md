# 调试输入集与完整结果 v1

这些文件是调试附属资料，不修改 `.emoproj`、工程 schema、变量定义或生产 Job。

## 用户入口

- 算子调试「输入」及流程调试「根流程输入」：**保存命名输入集… / 载入输入集…**。
- 两个调试窗口的结果选择栏：**导出完整结果… / 保存原始数据…**。
- 输入集仅在 READY 时载入。当前执行或命令未确认时不能替换输入。
- 完整结果包包含完整 PNG / JSON 和调用身份；原始数据文件不包含身份元信息，复核证据请使用完整结果包。
- 历史结果导出对应所选历史身份；流程的独立试运行仍控制当前暂停节点，不因历史选择而改变控制目标。

## `.emofixture`

ZIP 包包含 `metadata.json` 和按 SHA-256 命名的 `assets/*.png|json`。元数据格式为
`format=emo-debug-fixture, version=1`，含名称、工程/工作流/节点身份、保存时参数和逐端口记录。

- 明确区分 `missing / value / null / source`；整数零、负数、空字符串不等于缺失。
- 记录端口类型、配对 frame 端口、资产大小、SHA-256、完整来源与 captureId。
- 保存时将 Runtime 资产及同会话输出引用物化，不保存依赖旧会话的 assetRef / executionId 作为数据。
- 载入先完整验证版本、名称/身份/参数元数据、端口、类型、路径、大小、摘要与 PNG/严格 JSON，再上传到新会话；同时提供图像及 frame 时必须保留相同 captureId，不能混用两轮来源。
- 所有上传成功才整体替换输入行；失败不部分覆盖当前输入。失败上传的临时资产仍由该调试会话限额及生命周期管理。
- 参数只用于核对，不自动应用到工程。真正执行仍由 Runtime 校验必填、nullable、完整 frame 和同源关系，不绕过任何安全准入。

## `.emodebug.zip`

格式 `format=emo-debug-result, version=1`，内含原始 `value.png` 或完整 `value.json`，及 `metadata.json`。
身份包含适用的 project/workflow/node、execution/snapshot/nodeRun、iterationPath、trial/observed、phase、所选当前/历史归属及参数。
资产按 Runtime 全部分片读取并校验，不导出树的当前页、缩略图或截图。过期来源报错，不用其他调用或摘要替代。

「保存原始数据」仅保存相同的原始 PNG / 完整 JSON 字节，适合直接交其他工具读取；没有暗含的元数据侧写或截图。

## 写入与文件安全

- 每项操作先在目标同目录暂存，fsync 后单次原子替换。取消文件选择不创建文件；关闭中取消未提交写入。
- 完整证据的数据和身份在同一个包内原子提交，避免 PNG 与 sidecar 来自两轮不同结果。
- 单资产上限 64 MiB，整包上限 256 MiB；ZIP 成员数与解压大小受限，不解压到任意路径。
- 只允许声明的摘要路径；拒绝重复/大小写别名、未声明文件、越界路径、未知版本和类型不匹配。
- 选择文件后自动补后缀时，另行确认实际目标的覆盖，不把 Qt 对另一个文件名的确认当成授权。

以上是格式与行为契约；真实 GTK 文件窗口、Debian 桌面和现场设备的最终验收仍由 dot 独立复验。
