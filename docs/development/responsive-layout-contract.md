## 1. 合同归属与版本

工程 `2.8`、Presentation `1.1` 在本轮引入页面基础响应式布局。它们不同时承诺尚未实现的 Web 页面目标、远程历史来源、Web 包发布或新 RPC。

两级版本配套校验：工程 `2.8` 要求 Presentation `1.1`，Presentation `1.1` 不可放入更早工程。Presentation `1.0` 不接受响应式容器。普通读取旧工程不隐式升级；未声明页面内部版本的旧输入按 `1.0` 解析。

正式支持状态以源码模型与工程规范为准。Web 接入计划以后增加严格模型字段时，重新核对当前版本和兼容边界，不将原来预留的 `2.8/1.1` 当作仍未使用的版本号。

同一页面的基础布局由 Qt 编辑预览、Qt 运行页面与未来 Web renderer 共用。浏览器实现可以采用 CSS，但不能另行定义“桌面按固定网格、网页再猜测响应式”的布局合同。

后续发布 Web 的 JSON Schema、TypeScript 类型、fixtures 或样例包前，先核对本合同和实际模型，冻结同一组字段、默认值和语义。发布包是工程的派生描述，不成为第二个布局编辑来源；本轮没有生成这套 Web 交接产物。

## 2. 容器与子控件

根页面的 `layout` 与容器组件的 `grid` 使用相同的布局描述。沿用 `grid` 字段名是工程结构的局部扩展，不表示响应式布局仍使用行、列和跨度定位。

| 响应式容器字段 | 类型／默认值 | 含义 |
| --- | --- | --- |
| `type` | `"responsive"` | 明确选择响应式布局 |
| `direction` | `vertical/horizontal/wrap`，默认 `vertical` | 上下排列、可收缩并排、按首选宽度换行 |
| `spacing` | 整数，默认 `12` | 相邻控件及换行之间的基本间距 |
| `alignment` | `start/center/end/stretch`，默认 `stretch` | 容器交叉轴的默认对齐 |
| `justify` | `start/center/end/space-between`，默认 `start` | 主轴上有剩余空间时的排列方式 |
| `equalWidth` | 布尔，默认 `false` | 在可并排的一行中统一控件宽度 |

每个组件另有 `responsive` 尺寸规则；组件自己的 `layout` 行列跨度仅供旧网格读取，不用于响应式位置排序。

| 子控件字段 | 类型／默认值 | 含义 |
| --- | --- | --- |
| `width` | `fill/content`，默认 `fill` | 分配剩余宽度，或保留内容首选宽度 |
| `minWidth` | 默认 `160` | 并排时的换行阈值，不强迫窄窗口产生整页横向滚动 |
| `preferredWidth` | 默认 `240` | 首选宽度及自动换行模式的排布依据；`0` 使用内容测量值 |
| `weight` | 默认 `1` | 多个填充控件之间分配剩余宽度的比例 |
| `minHeight` | 默认 `64` | 控件的最低显示高度 |
| `preferredHeight` | 默认 `0` | `0` 表示按内容测量；正数提供期望下限，不裁剪自然内容 |
| `alignSelf` | `auto/start/center/end/stretch` | 当前控件的交叉轴对齐；`auto` 沿用父容器 |

完整范围与校验由 `core/presentation/models.py` 定义，本文件不建立另一套 Python 模型。以下只是布局字段片段，不是可保存的完整工程：

```json
{
  "type": "responsive",
  "direction": "wrap",
  "spacing": 12,
  "alignment": "stretch",
  "justify": "start",
  "equalWidth": true
}
```

## 3. 排列与窗口变化

页面 `components`、容器 `children` 的数组顺序是唯一的展示顺序。不再保存另一套像素坐标或 `order` 账本。插入和移动修改数组位置；同一组件的 `componentId`、绑定、查询来源和导航动作保持原归属。

- `vertical`：按数组顺序自上而下排列。`width=fill` 或交叉轴对齐为 `stretch` 时占满可用宽度；`content` 配合 start/center/end 时采用首选宽度，受可用宽度限制。
- `horizontal`：填充控件按 `minWidth`、内容控件按 `max(minWidth, preferredWidth 或内容测量值)` 尝试并排；容器变窄到无法容纳时按稳定顺序换行。
- `wrap`：所有控件以 `max(minWidth, preferredWidth 或内容测量值)` 决定一行可容纳多少控件，剩余控件继续下一行；适合指标卡片组。
- 划分各行后，填充控件按 `weight` 分配该行剩余宽度；内容控件不参与填充。`equalWidth=true` 统一基础宽度并等分剩余空间，优先于单个控件的 content/fill 选择。
- 宽度分配后仍有剩余空间时，`justify` 决定起点或附加间距。vertical 的主轴是可用高度，horizontal/wrap 的主轴是当前行宽度。没有剩余空间时，不通过挤压自然内容或重叠制造等距。
- 当单个控件的最低或首选宽度大于当前内容区域时，将该控件宽度限制在可用区域内。图片保持内容比例，文字换行，表格在内部滚动；不能用强制整页横向溢出来维持首选宽度。
- 嵌套容器递归执行同一组规则。实际高度使用原生控件的内容测量，包括文字换行，不依靠只适用于某个窗口宽度的固定坐标。

Qt 逻辑像素与浏览器 CSS 像素分别使用各自环境的常规缩放。共同合同要求顺序、换行、填充、间距与对齐语义一致，不承诺不同平台字体渲染得到逐像素相同的文字宽度。

窗口缩放只调整现有控件几何，不改工程 dirty 或历史，也不重新创建查看会话、重新开始查询或清空选中记录。表格分页、筛选、图片来源和冻结查看状态继续由原来的组件拥有。

## 4. 编辑命令

拖动影像、插入线、对齐参考线、框选和宽度预览均为编辑状态，不保存到工程。拖动中的候选布局使用当前显示测量，松手才提交一次已校验的工程修改。

“对齐”和“等距分布”保存布局规则，不写入随窗口失效的绝对坐标：

- 命令作用于选中对象。选择完整组时可修改组级规则；只选择部分兄弟控件时不静默改变未选控件的规则。
- 交叉轴对齐使用选中组件的 `alignSelf`：上下排列时适用左／水平居中／右对齐，并排或换行排列时适用顶／垂直居中／底对齐。主轴对齐使用父组 `justify`，仅完整同级组被选择时可执行，避免连带修改未选兄弟控件。
- 可执行方向与选择范围在菜单打开和执行时检查；不适用时说明原因，并提供明确的上下／并排／自动换行编组入口，不以互相覆盖的坐标模拟成功。
- 等距分布对应布局主轴上的剩余间距分配。发生换行后，每行按相同规则处理，元素顺序不变。
- 跨容器移动保留子树和内部引用，不允许容器放进自身或后代。新建分组需让落点预览清楚显示结果。预览复用同一摆放函数和布局求解器，借用既有原生叶子控件测量，用临时容器测量标题和边框；绘制移动对象与受影响兄弟控件的候选轮廓，不重排或重建真实数据控件。同一候选复用结果，新组件原型每次拖动只建立一次。
- 取消恢复原布局；无变化的操作不增加历史。属性面板合法的待应用输入沿用现有提交边界，非法输入保留供修正。主选对象不变、仅多选集合变化时不重载属性表单；实际拖动前先处理待应用输入。

“动态参考线”“轻微吸附”是本机编辑偏好。它们不进入页面包，不改变运行页面，不影响响应式布局合法性。

## 5. Qt 与未来 Web 的接口边界

模型与纯布局测量负责表达布局；Qt renderer 负责原生控件测量和几何应用；Designer 负责选择、拖动和菜单命令。编辑预览与 Qt 运行页面消费相同模型及布局实现，避免出现预览能摆放、实际显示却不同的两套规则。

未来 Web renderer 消费发布包中同一基础布局，并按照同一组件顺序和身份渲染。若后续增加终端覆盖，应明确版本和字段，仅覆盖布局／样式，不复制组件、绑定、历史来源或运行控制逻辑。

新增 Web `targets`、Runtime 历史来源位置以及发布包权限仍归各自计划。本轮响应式实现不会自动完成这些功能，也不会修改它们的执行和访问边界。

## 6. 本轮验证要求

以宽、中、窄窗口及连续调整宽度验证同一页面，覆盖文字、图片、表格和嵌套容器。检查稳定顺序、无控件重叠、可读尺寸、内部滚动，以及数据组件对象和查看状态在尺寸变化后仍然保留。

编辑验证包括插入、重排、多选、跨容器移动、分组、调整尺寸、取消、撤销／重做和属性待应用输入。新格式经过模型校验、保存重读、工作流编译与真正的 Designer 打开入口验证。

Qt 源码测试、原生交互自动化、人工 UI、Web renderer 和安装包验证分别记录。本轮未执行的 Web 或部署检查不能因 Qt 验证通过而记为完成。

当前格式从 Designer 文件菜单导出 Runtime 项目包时使用权威草稿，保留响应式规则和组件身份。资源路径转换作用于包内副本，不隐式保存工程或写入 Runtime；旧页面测试包入口的格式限制继续保留。
