# 全局变量和算子引用

全局变量替代原“全局计数器”管理入口。工程只保存定义和初始值，运行当前值由 Runtime 的 SQLite 状态服务管理。变量定义从工程 2.4 起支持；新建、生成和交付工程使用当前最新 2.7，打开旧工程不因此自动升级。

## 使用方法

1. 在 Designer 的“运行 → 全局变量”中新建变量，选择布尔、整数、数值或字符串。
2. 选择“只读常量”或“变量”。常量初始值可以在设计时修改，但运行期间不可写。
3. 可写变量可选“项目持久化”或“每次任务初始化”。保存并重新加载工程后，新定义才进入 Runtime；修改已有初始值不会覆盖持久化当前值。
4. 算子参数窗口中选择参数来源。通用表单在字段旁选择；专用编辑器使用公共参数来源面板。选择变量后仍保留固定值，但执行时不用它。
5. While 的“条件来源”选择“全局布尔变量 / 常量”，再选布尔变量。不需要额外条件工作流，也不需要循环体回传这个布尔值。

While 每轮开始前读取最新值：false 不进入下一轮；true 继续。取消、超时和最大迭代次数仍有效。恒真常量不是绕过安全上限的无限循环开关；生产 Runtime 的 continuous 策略不变。

管理窗口“编辑定义”参与工程保存及撤销。“设值”和“恢复初始值”只修改 Runtime 当前值。设值使用版本检查，遇到冲突必须刷新后重试。任务变量必须选择对应任务；没有任务时表格标识初始状态，不伪装成运行当前值。任务结束后任务值只读。

## 运行队列

“运行 → 全局变量”打开“全局变量与队列”窗口，包含“业务变量 / 运行队列”两个标签页。
两个页面共用查看入口，但**图片不写入全局变量，也不逐帧写入变量数据库**。
图片继续由 Runtime 帧存储及 Dispatch 投递管理，队列页只读取调度器元数据。

1. 在 Dispatch 节点中将“队列满时”设置为“等待容量”。超时 0 表示等到有容量或停止；旧工程缺省仍为报错。
2. 生产流程使用 While 采图、翻转并 Dispatch；消费工作流每次执行一轮处理、留档即可，平台的持久消费进程负责重复取项，不需要再嵌套无限循环。
3. 运行后切到“运行队列”。优先显示当前生产 Job 所属组；多个组且无当前匹配时须明确选择。
4. 每个槽位单独显示等待 / 容量、处理中、累计入队、完成、失败，以及实际的生产等待状态。
5. 展开“队列项与图像明细”查看所选槽位的调用 ID、FIFO 等待位置、入队和开始时间，以及图像 frameId、尺寸和类型。完整身份通过文本或工具提示查看；不读取缩略图。

容量不包含正在处理的一项，队列项也不等于图片数，一次调用可能不含图片或含多张图片。
每槽累计值从本次运行组创建开始，满足：

```text
累计入队 = 等待 + 处理中 + 完成 + 失败 + 取消
```

拒绝独立计数；容量等待还未入队，不计拒绝或已接纳取消。组释放后不保留历史队列快照，
界面显示不可用而非假零。生产者结束但消费者仍在处理时继续显示运行组。
断连保留最后快照并标记“数据已过期”；错误区提供简短原因和可展开详情，成功重连后恢复。
旧 Runtime 不支持此 RPC 时明确提示，不影响业务变量操作。

当前可见页每秒读取一次，同一页最多一个请求在途，折叠明细时不请求队列项。
切换到变量页、隐藏或关闭窗口会停止队列轮询；没有清空、设值、重放或停止队列的按钮。
监控查询不复制图片、不 retain/release 帧、不写变量数据库；没有进行专项吞吐或摄像头节拍测试。

### 消费结果页面

在页面设计中将结果作用域绑定到**消费工作流入口**，把数量、图像等数据源绑定到消费流程
真实节点或工作流输出。原来绑定生产流程的页面不会自动迁移。
从生产 Job “查看运行结果”时，只有一个带页面的消费者会直接选择它；多个槽位会提供
包含工作流和槽位 ID 的选择。单次结果中的数字和图像使用同一结果身份，不跨 Job 拼接。
关闭页面观察窗口不会停止消费或取消留档，页面的有界采样也不等于业务队列丢帧。

开发环境可生成无凭据模拟工程：

```powershell
$env:PYTHONPATH='src;.'
python -X utf8 -m examples.dispatch_queue_demo build/dispatch-demo
```

生成器使用 `WorkflowStore().toPayload()`、`ProjectDocument` 和保存重读；输出 2.7 `.emoproj`。
默认 While 持续运行，示例队列容量 1，含模拟相机、双轴翻转、消费页面和 `latest.png` 覆盖保存。
示例数量是固定模拟值 1，不是人脸检测或身份识别，不下载/运行 YOLO；真实工程的模型、冷却留档和设备参数不被修改。
文件已存在时生成器拒绝覆盖。Designer 打开后仍须显式写入隔离的测试 Runtime，打开和保存不等于在线发布。

## 数据与执行规则

- 引用使用稳定 ID，重命名不改变绑定。既有变量的类型、常量属性、生命周期不能原地修改；被引用的变量不能删除。
- 整数严格拒绝布尔值，范围为有符号 int64；数值拒绝 NaN 和无穷大。兼容计数器仍为非负 int64，溢出失败。
- 持久化值以项目 ID、变量 ID 隔离。任务值还按 jobId 隔离；子工作流、循环以及同一 continuous 任务的后续周期共享它，不逐轮重置。
- 每次算子执行前批量读取引用值，生成参数快照，并执行 Schema 与算子参数验证。执行开始后的设值不会改变该次参数，下次调用才更新。
- 参数引用不产生隐式执行顺序。先写后用需要显式连线；“写入全局变量”节点的 `value` 必须有输入，输出为写入后的同类型值。
- 数组、对象整体、数组元素和表达式不属于本版绑定范围。资源绑定、现场参数绑定占用的位置不可再绑定全局变量。
- **文件／目录参数（包括图片、模型、输出路径）本版不允许直接绑定全局变量或常量**，以免绕过路径保护或遗漏导出依赖。请使用原有固定路径、资源绑定或现场参数配置；普通字符串参数仍可绑定。已有不支持的绑定保持可见，必须显式移除，编译、预览及导出均会报 `E_VARIABLE_FILE_BINDING`，不会静默使用固定值。
- 其他设备参数沿用算子自身重配置行为；不承诺无缝切换。
- 新建、重命名或撤销变量定义后，已打开的通用／专用算子编辑器同步更新选择列表，保留未应用的参数与引用；失效引用不会自动替换。
- 管理窗口刷新期间提交设值会等待刷新结束后发送，仍使用打开设值窗口时的版本检查。项目／任务切换或关闭窗口会取消尚未发送的操作；已发出的操作不会自动重试。设值失败与“设值成功但刷新失败”分别显示。

## Runtime API

新增 RPC 为 `ListGlobalVariables`、`GetGlobalVariable`、`SetGlobalVariable`、`ResetGlobalVariable`；设值和复位要求 `expected_revision`。

队列使用独立的只读 `GetDispatchQueueState`：请求包含 `project_id`、可选 `run_group_id`、
`target_slot_id` 和 `include_items`。回复的 `state_json` 包含 Runtime 实例身份、活动组、
所选组、可用性及快照时间；明细最多返回该槽位 64 个等待项和 1 个处理项，每项最多 16 个图像元数据。
`selected=null` 不代表队列长度为 0，项目身份不匹配返回错误。接口不返回原始输入输出、共享内存句柄或设备配置。

算子通过 `runtimeContext["globalVariables"]` 调用 `get(id)`、`readMany(ids)`、`set(id, value)`、`reset(id)` 和 `increment(id, delta)`。旧 `globalCounters` 访问器和 `vision.state.counter` 算子保留，访问同一份状态。

数据库迁移 v5 将旧计数器转换为 `counter:<原名称>` 的持久化整数变量，保留当前值和更新时间，初始值为 0。旧物理表保留为 `globalCountersLegacy` 恢复归档；`globalCounters` 是兼容只读视图，不是第二份可写状态。

预览在开始时冻结只读快照。重新开始才刷新；没有任务上下文的任务变量使用初始值。预览不能通过变量访问器写入、递增或复位，变量写节点和旧计数器节点不允许产生预览副作用。

## 工作流包和页面

工程包保存定义、初始值、引用，不打包 Runtime 状态数据库。新工作流包版本为 1.1，仅带被引用的变量定义。导入时遇到 ID 或名称冲突明确拒绝，不按名称合并；工程内部“复制工作流”显式复用原有变量 ID。

页面数据源新增 `global_variable`，按声明类型校验。页面呈现工作流调用结束时的变量结果快照；实时当前值在全局变量窗口查看。原 `global_counter` 数据源继续支持。

## 示例

`examples/global_variables/project.json` 是独立示例，包含 `alwaysTrue`、`runEnabled` 和 `threshold`。

- 主流程 While 读取 `runEnabled`，循环体的数值算子引用 `threshold`。
- 可将 While 条件切换为 `alwaysTrue`，验证严格布尔恒真条件和迭代上限。
- `stop` 工作流演示读取 false 常量、显式连线后写入 `runEnabled`。要停止同一任务，应把它编排为该任务中的子工作流；另起一个任务不会修改原任务的 job 变量。
- 示例不调用设备、不会自动运行。循环体很轻，可能迅速达到上限；它是连接方式示例，不是长期生产运行配置。
