## 2026-10-21 TCP 设备化

新建工程使用 2.7、流程包使用 1.4、DeviceType／驱动 API 使用 1.1。
TCP 服务、单次客户端、单次接收由设备管理器创建，节点通过设备槽位与静态 selectors 绑定。
原 TCP 状态快捷入口进入设备管理；两端查看同一 Runtime 的状态、通道和诊断日志。
关闭窗口停止观察，不停止服务。可选业务动作只展示类型声明的动作，使用真实管理来源。

配置从 Runtime 菜单或设备页快捷入口进入同一个窗口校验和明确写入；COMMITTED＋PENDING 只读跟踪原请求，
后续连接失败保留已提交事实并去重提示。设备／流程包新建禁用副本，完整 Runtime 包保留启用策略，
导入新目录并补齐现场字段后从正式入口运行。旧工程兼容不纳入本轮范围。
使用方法见 [TCP 设备指南](project-tcp-service.md)，开发契约见
[设备契约](device-catalog-contract-v1.md)，实际证据见
[本轮验证记录](../testing/2026-10-21-tcp-device-integration.md)。


## 2026-10-20 主界面入口调整

本节对应本轮源码调整，**没有重建或替换正在使用的冻结 EXE**。此前构建记录仅适用于各自版本，
不表示已包含本轮修改。本轮验证范围见
[菜单与首次写入验证记录](../testing/2026-10-20-runtime-menu-device-layout.md)。

```text
菜单栏：文件 | 运行 | 编辑 | 视图 | Runtime | 设备管理
工作区切换：[流程设计 / 页面设计]
```

- **文件**：新建、打开、保存、另存、最近工程、工程资源 / 现场绑定。打开与保存不再重复放在工具栏。
- **运行**：运行流程 `F5`、停止运行 `F6`、停止全部、运行目标与并发及既有辅助操作。
  运行命令没有合并到 Runtime 菜单；流程设计和页面设计下都能进入运行菜单。
  停止运行作用于运行摘要中所选任务，停止全部作用于当前 Designer 管理的全部流程任务，
  不根据当前画布猜测任务对象。
- **编辑**：撤销 `Ctrl+Z`、重做 `Ctrl+Shift+Z` / `Ctrl+Y`、整理流程 `Ctrl+L` 及原有编辑操作。
  整理流程复用原自动布局，只修改当前草稿布局，可撤销；没有移到画布工具区。
- **Runtime**：连接 Runtime、写入 Runtime、在线监视、发布工作页面。
  写入和页面发布打开同一工程配置窗口，不是点击菜单立即提交。
- **设备管理**：编辑设备列表、属性和所选设备的操作；提供转入同一发布窗口的快捷入口，不替代文件保存。

顶部只保留工作区切换，不保留运行、停止、撤销、重做或其他工程命令按钮。
执行端仍由当前选定 Runtime 承担：本机内嵌无需另开 Runtime 窗口；独立地址通过 gRPC 执行。
状态栏显示本机内嵌或连接地址及已读取的在线版本；未读取时不会仅因本地工程打开成功就显示在线就绪。

图片测试通过流程图中的 `vision.io.image_loader` 加载图片，连接处理节点后正常运行或调试；
全局“图片测试”及其图片选择、开始、停止入口已移除。远程执行要求执行端能访问已声明的资源，
Designer 选中文件不等于远端文件已就绪。普通流程保留自身副作用语义，不会因为包含图片节点就自动禁用 PLC 或写文件。

### 设备管理布局与空 Runtime

列表上方提供新建、导入、导出、“设备列表操作”和一个刷新入口；删除和旧节点迁移归列表操作。
所选详情提供测试连接、按在线状态显示的连接或断开、诊断和“设备维护”；读取实际参数在诊断菜单中。
“立即应用到草稿”“恢复当前输入”靠近属性表单；底部保留工程历史、发布快捷入口和“保留草稿并关闭”。
关闭不会自动保存或下发。

Runtime 明确没有在线配置时显示“当前工程未下发”，不是设备故障；草稿仍可正常编辑。
不可达和在线工程不一致分别显示真实原因，不把断连冒充未下发。刷新只读元数据与已有状态，
不隐式加载工程、发现硬件、连接设备或启动任务。

未下发的 IMV 设备仍可从详情“设备维护 → 设备发现”进入仅发现窗口；先只读确认 Runtime 能力，
再由用户明确点击发现。采用标识只修改草稿，不连接、发布或改实物 IP；该离线窗口不提供改址控件。
旧 Runtime 不支持时显示升级提示，不要求先启动流程来绕过。
读取发现能力期间关闭设备管理器，会放弃这次待弹窗请求；随后重开也不会复活旧请求。
如果因非法属性而未能关闭，仍保留当前窗口的操作意图；元数据读取器可继续正常使用。

### 本机首次写入

对当前 2.7 格式工程，从 **Runtime → 写入 Runtime…** 进入统一配置窗口。空 Runtime 会显示完整首次候选，
可先校验再明确确认首次写入，不必先运行流程。提交使用当前有效草稿，不覆盖磁盘上的旧工程，
相对资源由当前工程目录解析，并复用 Runtime 的输入资源准备与私有副本机制。

校验不连接设备、不启动任务；写入成功后有在线文档和执行版本，不创建 Job、不采集或执行 PLC 节点。
正式写入时设备是否建连遵循原连接策略，确认区域会说明这一影响，不能理解成绝不连接设备。
校验或确认前取消不会提交。确认后，首次写入和后续写入使用同一后台写入队列：准备阶段显示
“校验中”，可以查询原请求或取消，不需要等资源准备结束才能取消。取消回执可能暂时仍显示准备中，
以随后查询到的“已取消”为准；提交前取消会释放本次准备资源，不安装在线配置或激活设备。
已经提交的写入不能用取消回滚；失败或取消的原请求不会因再次查询或重复发送而重新执行，
修正后需由用户明确发起一次新写入。提交已发出后若响应丢失，用原请求查询结果，不自动重放；
软件已提交但发布失败仍显示已提交事实及恢复错误，不通过再次首次加载覆盖在线工程。

本轮首次写入支持本机内嵌，以及与 Designer **共享本机文件系统**的 localhost / 127.0.0.1 / ::1 Runtime。
跨机器的空 Runtime 安装不在此入口支持范围内；非回环目标会明确拒绝发送 Designer 本地路径，
应先在执行端导入工程。端口转发到另一台机器也不应当作共享本机目录的证据。
远程已有在线工程仍使用原比较、上传资源和显式写入流程。

运行前遇到首次写入或草稿与在线版本不同时也复用此配置窗口；单独写入不会自动继续运行。
需要运行时明确选择“运行在线版本”，或完成配置后通过运行菜单启动；打开监视不会启动任务。

### 校验反馈与旧格式草稿

校验按钮点击后立即显示“正在校验”，仅在请求处理中禁用重复提交。通过时使用图标和醒目文字显示
“校验通过，尚未写入 Runtime”，不会把校验通过当成已经下发。主动校验成功不额外弹成功框；
写入前自动校验成功，直接进入原有的写入影响确认。

校验失败、明确失败回执及连接候选失败会弹出错误框；窗口保留简短摘要，详细信息可展开查看和复制。
可获得的错误码、流程、节点和字段位置会保留。一次后台请求的相同失败 / 警告不会反复弹出；
修正后重新发起操作仍会正常报告。正常等待、尚未加载工程和取消不是错误。
响应丢失时提示结果尚未确认并保留原请求；已经提交后的发布、清理、副本导出、设备重连或通信监听恢复失败，
会弹出“配置已提交，但后续操作异常”，保留“已提交”事实及对应失败明细，不自动重发，也不建议用重复写入当作恢复。
连接仍在等待时可通过“查询写入结果”核对原请求；查询后明确失败会通知，相同失败不会因其他设备连接成功而再次弹出。
正常连接 / 监听成功、被后续操作替代或重启后状态未知不会被误报为失败。

当前 2.7 工程直接走校验和显式写入，不需要升级按钮。旧格式迁移和旧节点兼容不属于本轮 TCP 交付验收范围；历史迁移记录仍保留于各自验证报告。

### 查看当前 Runtime 与切换目标

**Runtime → 连接 Runtime…** 分为“当前连接”和“切换到独立 Runtime”两个区域。
打开立即显示真实连接类型，再异步读取现有连接的实例、在线工程及可获得的文档 / 执行版本。
本机内嵌 Runtime 随 Designer 启动，不要求填写网络地址；候选地址为空不表示当前未连接。
“尚未加载工程”与“连接信息读取失败”分别展示，版本读取失败不会抹掉已经取得的实例信息。

内嵌 Runtime 即使已有页面服务端点，仍显示为本机内嵌；本机独立 gRPC 服务则显示实际主机和端口，
不会仅凭回环地址判成内嵌。查看连接信息不会新建 Runtime、页面端点或启动任务。
主界面 Runtime 摘要使用同一连接类型表达。

填写候选地址后先点“读取目标信息”，读取成功再点“切换到此 Runtime”。候选信息不覆盖当前连接区。
探测失败或取消保持原连接不变；取消会释放本次候选，正在返回的迟到结果也不会自动切换连接。
打开或取消窗口不会关闭原内嵌 Runtime，也不要求为查看信息停止全部任务；实际切换仍遵循原有的
窗口任务、调试和未结束请求规则。查看完成可直接点中文“取消”关闭。

## Runtime 连接

“Runtime / 连接 Runtime…”先只读探测指定主机和端口，展示实例、在线工程、版本和设备能力；再次确认才切换。
失败保留原连接，本地草稿不被覆盖。切换不会发布配置、启动任务，也不会擅自关闭原内嵌 Runtime 的任务；
内嵌 Runtime 的生命周期仍随 Designer 正常关闭清理。当前窗口自己的运行、调试或未完成请求需先结束。
旧 Runtime 缺少探测能力时会明确提示升级。

## 设备设置与诊断

新建设备向导的“发现设备”仅显式发现 Runtime 主机上的 IMV 设备，选择结果只填写草稿标识；
该窗口不提供实物改址。“测试连接”需明确确认，只连接并回收本次新开的连接；复用已在线设备时保持原连接，
不拍照、不写 PLC、不保存草稿，也不发布在线配置。
已有设备详情也提供“测试当前连接草稿”，测试尚未应用的连接字段，不先提交属性或发布配置。

TCP Server 的监听端点不变时，合法的通道显示名称等草稿变化允许复用原后端测试。
成功只表示监听端点可用，不表示草稿通道规则已在线生效，也不表示外部客户端已经验证。

受管相机诊断把“读取实际参数”和“临时调参试拍”分开。读取不触发采集；试拍支持曝光/增益，
正常完成或取消后恢复原实际值和配置缓存，不修改设备定义。硬件触发状态下的试调仍须先完成现场同步，
不自动改触发方式。恢复失败单独报错并隔离，不伪称已恢复；旧 Runtime 不支持时提示升级。

相机弹窗默认只观看已有生产采集结果。观看不取图、不持有原图引用或长期维护权限，
显示源任务、周期、执行版本及时间；首次订阅后还没有生产帧时保持等待，不偷偷触发相机。
非生产时可明确开启“实时预览”，最多一个待执行取图；生产启动后转为只读观看。
硬触发不允许连续预览消费触发队列，也不会自动切换触发模式。关闭停止本窗口预览，不停止生产任务。
状态或版本改变导致观看中止时，可用刷新按钮重新读取并观看；不自动重放取图或试调。

**相机硬触发与 PLC 时序：** 当前相机 connect 只连接会话，首次 capture 才执行对应采集准备；
因此“连接成功”不等于“已经准备接收硬触发”。PLC 按自身工艺独立产生触发时，相机节点可以等待外部图像。
同一同步工作流不能安排成“相机等待硬触发 → 后续 PLC 节点产生这个触发”，因为流程到不了后一个节点。
也不能只把 PLC 节点移到相机前就认为时序正确：软件控制硬触发应依据实际相机就绪状态和 PLC 握手，
按“相机准备好 → 允许／请求触发 → 获得图像 → 回传结果”安排。
普通“相机取图 → 处理／判定 → PLC 写结果”继续通过流程依赖表达先后。
这些说明对应现有采集行为，不提供新的 arm／trigger／wait 接口。

设备节点向导在每个来源字段旁显示 Runtime 已提交配置的值/来源、文档版本以及草稿是否未应用。
动态变量和节点输入标为运行时取值，不把它们当前未知的值或设备回读值冒充固定配置。
刷新在线字段对比不修改节点草稿；实际硬件参数仍由独立的“读取实际参数”动作获取。

## 本地编辑与在线版本

- 设备管理弹窗编辑设备、默认参数、节点来源、资源及现场绑定，修改进入工程草稿。
- 正常保存仍只保存本地工程，不自动提交在线配置，不连接设备、不采集、不执行 PLC 节点。
- 主界面“Runtime / 写入 Runtime…”打开工程配置窗口，“与 Runtime 比较”读取在线快照。勾选差异后，先检查必要依赖，
  再验证候选，最后明确提交。不要用旧 `LoadProject` 路径绕过已激活工程的版本检查。
- 修改设备连接、工作流结构、模型或其他非周期安全参数时，选择明确的策略：
  默认拒绝影响运行任务；停止受影响任务；或先排空受影响任务。
- 排空不等于无限等待，也不会自动升级为强制杀进程。超出预算、诊断 owner 未退出、
  驱动不支持替换时，应先处理显示的原因，不要更换 requestId 反复提交。
- 软件“已提交”与设备“已重连”是两项结果。重连失败或未知不代表软件版本回滚。
  已停止的任务不会在失败后自动恢复运行。
- 运行策略、生产策略、变量定义、通信配置及算子依赖声明也通过此入口提交。
  非周期安全修改必须先退休任务；生产策略写入本身不会自动启动生产。
- 修改持久变量的名称或初始值不会重置当前值。删除定义不会删除历史值。
  改变变量类型、常量/变量种类或生命周期时使用新 ID，不把旧值强制转换。
- 算子依赖支持已安装算子的 ID，或 `operatorId` / `version` 精确版本声明。
  在线配置写入不安装插件代码；缺少插件或版本不符时拒绝提交。
- 通信替换默认要求先停止监听。选择停止/排空策略后，才会退休任务并停止旧监听；
  原先正在监听且新配置仍启用时，提交后尝试恢复监听。端口绑定失败单独记录，
  不撤销已提交版本，也不重新发送旧消息。
- TCP 监听替换只停止使用受管 TCP 的相关流程及其调用/分发依赖，不停止无关相机任务。
  切换期间明确执行“停止监听”，会使较早的自动恢复意图失效，不在提交后偷偷重启监听。
- 选择停止/排空策略后的“校验选中变更”只预检并显示受影响任务、需断开设备和监听切换；
  校验不会提前停止任务或构造设备适配器。真正停止发生在明确写入之后。
  差异表逐项展示文档、下一检测周期、空闲安装、替换/重连或停止/排空类别及关联设备/流程/任务。
  直接点击写入也会先校验，再展示影响并确认；改变选择或策略会使旧校验说明失效。
- 本地与在线工程 ID 不同时，比较窗口选择完整候选，并要求明确停止/排空策略。
  写入会退休旧工程全部任务、断开旧设备和监听；不继承旧连接意图，不自动启动新工程。
  持久变量按工程隔离，历史图按所属工程读取；失败或取消不回滚已经发生的停止。
- “运行在线版本”打开独立只读监视窗口，使用在线启动目标和图，不覆盖草稿、磁盘或撤销栈。
  比较后在线版本或 Runtime 实例变化会拒绝启动。响应丢失后用原请求查询，不自动再次启动。
  窗口提供停止所选任务及停止本窗口任务；此入口不请求工作页面采集。
- 配置写入保留最近 4096 条成功回执及最多 2048 条内存尝试，旧请求由文档/实例版本阻止重放。
  同版本失败/取消填满内存窗口时，仅推进文档版本并要求重新比较，不改变执行计划。
  这不是永久幂等承诺；查询不到旧请求时先核对在线配置，不更换 ID 盲目重试。

## Dispatch / Join

1. 先创建消费者工作流，声明明确的输入、输出接口。
2. 从控制流算子库添加 Dispatch，设置每个目标槽的工作流、输入映射和排队容量。
3. 将采集图像连到 Dispatch 对应输入。同一目标工作流可拥有多个独立槽位。
4. 需要等待消费者结果时，添加 Join，选择同一流程内的 Dispatch，连接 token。
   Join 每个输出对应一个目标槽，其值是该消费者的工作流输出对象。
5. 不需要等待时可以省略 Join。生产者结束不会提前释放已投递消费者所需的图像和计划。

运行容量必须能同时容纳生产者和所有持久消费者。不足时在采集之前拒绝启动，
不会让生产者占满槽位后再等待消费者。

排队满、部分受理、执行失败、Join 超时均有独立结果。部分受理不会重发整批。
消费者执行副作用后故障时不自动重跑本次调用；不能把这套机制理解为跨崩溃“恰好一次”。

## 在线历史只读图

“Runtime / 在线监视…”，或配置比较窗口的“在线 / 历史只读图”，打开独立非模态只读窗口，
选择文档版本、工作流和 Job。不替换编辑区，不要求尚未完成的草稿属性先通过校验，
不改变工作区、草稿、选择、缩放、滚动或撤销栈；编辑区上方不再提供“编辑工程 / 在线监视”切换条。
同一目标重复打开激活已有窗口；关闭后可重开，关闭不停止任务。切换 Runtime 时关闭旧目标监视。
普通监视窗口不提供启动、停止或写入按钮；由明确“运行在线版本”创建的任务窗口仍保留原请求查询及停止出口。
直接进入在线监视读取当前 Runtime 工程，即使它与本地工程不同；成功读取后绑定对应工程和实例。
右侧参数与结果属于选中的在线快照，不取本地尚未提交的画布。
结果必须同时匹配文档版本和执行版本；无保留结果或缺失历史会明确显示，
不会将旧结果按新参数解释。

## 资源与现场绑定

主界面“文件 / 工程资源 / 现场绑定…”可独立打开，不要求先构建设备管理弹窗。可选择声明的文件用途、导入文件，
并绑定到受支持的节点或设备属性。现场字段可设置实际值和必填状态。
凭证字段仅接受带版本的 `secret://...@...` 引用。

导入确认前不复制文件；确认失败只回滚本次新建文件。移除资源登记不删除原磁盘文件，
仍被引用的资源不能直接移除。撤销草稿修改不擅自删除其他版本可能使用的资产。

Runtime 会准备输入文件的私有副本，旧消费者不会因为源文件被替换而读到新字节。
同内容资源的路径归一化不会把未变化的在线设备错误判定为需要断开重建。

远端使用时，在比较窗口勾选资源变更，再点击“上传候选资源”，核对清单后确认。
只上传最终候选的声明资源，不上传未选中的草稿资源或任意路径。没有勾选变更时，
该按钮传输在线快照已声明的资源。上传前验证本地大小与 SHA-256；上传按 512 KiB
以内的块进行，Runtime 再验证长度、偏移、摘要及项目/实例身份。已完成且内容一致的
资源可复用，不重复占用上传容量。

“上传完成”不改变在线版本，也不连接设备。资源就绪后仍需校验并明确“写入 Runtime”。
源路径不会被伪装成远端路径；Runtime 在已确认上传的资源中解析候选清单，再创建不可变执行副本。
已提交的上传资源在重启后继续可用，不要求 Designer 源文件仍存在。读回工程仍只读定义，
不会把资源二进制自动下载到本地。其他未绑定的本地路径不会因为上传而自动转为远端资源。

上传存储限制为 4 GiB 和 4096 条传输记录；执行副本另有 4 GiB 上限。容量不足明确拒绝，
不会驱逐仍可能被引用的完整上传。显式取消可删除未被在线配置或准备阶段引用的 READY 资源；
关闭比较窗口只取消后续上传，不批量清理已有 READY 资源，也不会撤销之前提交的配置。
已取消传输保留最近 256 条状态，不再永久占用活动传输配额。

准备文件的所有权在创建前写入 SQLite。重启可清理有记录、尚未交出使用的中断准备文件；
正常退出确认所有执行者退休后，下一次启动可回收上一代副本。未知缓存文件保持不动。
新版 Runtime 和读取这些文件的 Job、Dispatch 消费者、相机 Host、调试 worker
在读取前持有操作系统级代次租约。父 Runtime 异常退出而子进程尚活着时，重启回收
仍保留原文件；确认所有租约退出后，后续启动恢复才可回收。退休标记阻止迟到子进程
重新进入。旧版本没有租约记录的已交出文件仍保守保留，不推断其使用者已经退出。
回收不是后台定时清理；保留文件计入容量，未知文件不会被删除。

## 流程包依赖

含节点或设备资源/现场绑定的流程包使用 1.4 格式，携带引用的资源字节、大小和 SHA-256。
导出需要已保存的源工程目录；总资源上限 64 MiB、JSON 文件上限 96 MiB。更大资源使用完整工程部署包。
预览列出依赖及待填现场参数，确认前不复制文件。现场值在包内清空，新设备禁用；有资源或现场绑定的
设备只能新建，不能覆盖已有设备的现场绑定。无此类依赖的设备仍可明确选择兼容复用。

导入需要已保存的目标工程目录，资源写入新建的独立目录，设备、工作流、节点与现场字段引用一并重映射。
失败只清理本次新建文件；成功是一次可撤销的草稿修改，不保存工程或连接设备。撤销保留资源字节以支持重做。
同工程复制复用已有资源/设备，只重映射新工作流和节点的绑定。现场值补齐并确认启用设备后再运行。

## 发现与实物改址

离线新建设备时，插件声明的完整身份与已有定义一致，会提示复用已有设备。
确认只选择已有设备，不覆盖刚才输入的默认值/策略；取消不会新增重复定义。
设备属性编辑也会拒绝引入相同身份。未声明或不完整的标识不作猜测，不执行网络发现。

设备管理的网络入口只在明确点击“发现 Runtime 主机设备”后启动隔离 Host。
结果来自 Runtime 所在电脑，不是 Designer 网卡。当前已核对的 ABI 为 IMV 2.4.2
系列；其他版本明确拒绝此功能，不猜测原生结构体布局。没有 SDK 仍可编辑和保存草稿。

“采用所选标识到草稿”只修改选中设备的 cameraKey，仍需正常保存或在线写入；
“修改实物设备 IP”是独立硬件操作，必须先停止相关任务并明确断开/暂停该设备。
确认窗口显示 MAC、原地址、目标地址、掩码和网关。Runtime 再核对工程、实例、
设备定义、执行代次及 30 秒以内的发现快照，并在调用前持久化请求回执。

使用厂商 ForceIP，**不承诺断电后保留**，也不自动重连或更新工程连接参数。
只有按相同 cameraKey/MAC 重新枚举并读回匹配才报告 COMPLETED。调用丢回执或
读回不一致保留 UNKNOWN；用原回执 ID 查询，不能以新请求自动重复改址。
重复提交同一请求不会再次调用硬件。回执上限 4096 条，满额明确拒绝、不静默删除。

## 有限连接恢复

受管 SLMP 可在设备策略中配置 connectionRetryCount（0 至 5，默认 0）、
recoveryTimeoutMs（1 至 60000）和 recoveryBackoffMs（1 至 10000）。
仅声明为 NOT_EXECUTED 的连接失败允许有限重试，恢复总预算不会随重试刷新。
排队、连接恢复和业务操作预算分开；PLC 读写和相机触发不会因此自动重放。
写入确认未知仍为 UNKNOWN，相机隔离后的重新布防仍要求显式确认现场同步。

## 旧工程迁移

“旧设备节点迁移预览”列出整个工程中的设备节点及原始参数、变量和绑定。
逐个选择节点，通过正常设备向导绑定已有设备或创建新设备，再确认迁移影响。

- 原先明确的工作参数保留为明确来源；`keep` 不被伪装成继承默认值。
- 可支持的旧变量目标转为设备动态参数来源，原节点变量绑定随同清除。
- 连接属性上的资源/现场绑定可明确迁到设备属性，确认窗口会提示共享影响。
- 设备、节点、参数来源和目标迁移属于一次可撤销事务。保存前不改原工程文件。
- 旧无限硬件等待模式明确映射为受管相机 `captureTimeoutMs=0`，保留硬件触发。
  该值只在驱动声明可取消等待且触发模式为硬件时允许，软件触发/自由运行拒绝零超时。
- 不能唯一映射的旧字段、无法支持的连接变量不会自动转换。
  这些情况需要明确解决，不能为了“迁移成功”改写成不同的物理行为。

无限取图等待不取消其他调用的排队超时。停止会取消等待并等待 Host 实际退出；
取消过程中丢失设备回执仍报告结果未知，不把“资源已释放”等同于“物理触发未发生”。
原生调用不响应取消时沿用既有 Host 隔离/终止路径，不重发触发。

## 工作页面发布

页面设计器的“发布工作页面…”进入相同在线比较通道，预选页面类变化。
缺少数据源、scope 或工作流的变更需要一起确认；未绑定的必需组件不能发布。

运行界面采用已提交页面时会退休旧显示会话。旧 Job 的结果不会重新解释为新页面的数据。
本地文件保存和在线页面发布仍是独立动作。

图片组件可选择用途为 page_image 的静态资源；导航按钮可选择用途为 icon 的资源。
静态图片与动态图片绑定互斥。发布前解析资源依赖，Runtime 准备独立、校验摘要的
执行副本；删除 Designer 源文件不影响已经上传并提交的页面。
当前支持 PNG/JPEG/BMP，单文件编码上限 8 MiB，窗口还有编码与解码内存预算。
切页、隐藏、重载和关闭会释放显示资产；静态图片不增加任何采集请求。

仅外观、文字、静态图片或图标变化不改变执行版本，也不停止正在运行的 Job。
它们可与声明为下周期生效的参数一起提交。改变实际数据源或结果 scope 时仍按
执行变化处理，不把新采集需求伪装成纯布局更新。
