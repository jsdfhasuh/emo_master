# 项目 TCP 通信服务

## 入口和生命周期

Designer：**运行 → 通信服务…**。也可以点击底部状态栏的 TCP 摘要，打开与日志并列的通信 Dock。Dock 支持隐藏、浮动；关闭视图不停止服务。

独立操作端：点击工具栏下方的通信状态按钮。它复用同一个 Runtime 的服务和监控组件，配置来自项目文件，不另设现场配置文件。

服务由 Runtime 主进程持有，不归某个算子或某个工作流所有：

- 新项目、没有通信配置的旧项目默认关闭。
- 打开项目、打开设置、保存参数，都不启动监听。
- **随项目开始运行**：通过相机配置/调试等准入检查后，先监听，再启动 Worker。不必先等客户端连接。
- **手动启动**：先在通信面板启动服务，再运行依赖此服务的流程。没有通信依赖的流程不受此要求限制。
- 停止当前流程、停止全部流程、正常完成一轮，均保持监听和其他客户端连接。
- 显式停止服务、成功切换/卸载项目、Runtime 退出，释放监听和连接。
- 远程 Runtime 失联只表示**状态未知**，不表示远端已停止。关闭远程 Designer 不等于关闭远程 Runtime。

监听或通信线程异常会进入 FAILED，关闭监听与客户端连接并撤销旧会话。再次显式启动前会确认旧线程和 socket 已释放；清理失败显示 `E_TCP_RELEASE_FAILED` 并保留资源归属，不创建第二个监听器，也不自动重发数据。

## 项目设置

1. 打开通信面板 → **项目设置…**。
2. 勾选“本项目启用 TCP 通信”，选择启动方式。
3. 配置 Runtime 所在机器的监听 IPv4、端口、服务名称。
4. 添加通道，填写显示名称与允许客户端 IPv4。一个 IP 只能映射到一个通道；一个通道同时只允许一个客户端。通道 ID 是稳定引用，改名称不会改变它。
5. 设置发送超时（毫秒）、单条报文上限（字节）。
6. 保存配置。首次保存显式升级到项目 schema 2.5，并沿用原有原子保存及备份机制。

默认监听 `127.0.0.1`，只适合本机测试；现场需要显式选择 Runtime 网卡地址。`0.0.0.0` 会监听所有 IPv4 网卡。白名单不是加密或身份认证，首版不提供互联网/TLS 服务。

正常保存先用编辑基线申请 `PREPARE_SAVE`，取得 Runtime 的配置保存保护后才写文件，最后采用轻量 `SYNC` 提交并释放保护，不以整次 LoadProject 代替配置同步。设置页打开后即固定编辑基线，后续状态刷新不会使旧草稿自动获得最新修订号。其他客户端已经修改配置时，在写文件之前报告冲突、保留草稿，不静默覆盖。请核对本地和 Runtime 配置后重新编辑；“同步已保存配置”明确选择本地已保存版本，不是自动合并。

若项目尚未载入 Runtime，保存流程先加载磁盘上的原配置并核对基线，不先把新草稿写入文件；全新未落盘项目先通过原保存入口建立保留原配置的文件。也可用**同步已保存配置**显式载入已保存工程；它不启动服务，编译/资源错误会保留原始诊断。未保存的草稿不会被当作已保存配置同步。

保存失败时保留草稿，不修改 Runtime。项目已落盘而 Runtime 同步失败时，面板明确显示“已保存，但 Runtime 尚未同步”，可重新同步。启动前必须完成同步确认。

运行中修改监听/路由/发送参数只生成待生效配置，不切断现有连接。旧 Job 固定原服务快照；依赖待生效配置的新 Job 被拒绝，提示先停止流程并重启服务。关闭项目开关前必须先停止服务；状态未知时不允许乐观关闭。

关闭开关的保存采用 Runtime 保护：先原子确认服务已停止并阻止其他客户端/正式运行入口重新启动，再在界面线程沿用项目保存通道落盘，最后同步禁用配置、释放保护。文件保存失败会撤销保护，项目已应用配置和 Runtime 配置保持原值，设置对话框仍保留待修改草稿。

普通保存和禁用保存共用一个有界保护凭据，不自动超时释放，避免缓慢落盘时重新开放启动或配置覆盖；普通保存不要求停止现有监听，也不会中断现有连接。若同步回执丢失，可在原窗口使用“同步已保存配置”完成确认：已提交且配置一致时只确认，不重新提交；若已有更新配置或项目身份改变则报告冲突，不用新修订号覆盖。若发起保存的窗口已崩溃或丢失，面板会明确提示保护未完成，需要显式重启 Runtime，再加载磁盘上实际保存的项目。不会因此自动启动或重发任何报文。

“另存为”即使保留项目 ID，也不是同一个运行上下文。成功另存为会在切换当前文件身份之前释放旧运行上下文；释放失败仍保留原项目，并明确说明副本是否已写入。新路径在同步确认前不能使用旧项目的启动/停止权限；显式同步也经过正常项目替换保护。通信管理协议升级为 **1.1**，要求项目路径与 ID、加载代次同时匹配；旧版管理端/Runtime 明确拒绝，不忽略新增校验。工作流会话与回执数据版本仍为 1.0。

## 工作流接线

新增三个算子，现有 TCP Client、TCP Receive Once 和 PLC 算子行为不变：

| 算子 | 输入 | 输出 | 说明 |
| --- | --- | --- | --- |
| TCP 通道会话 | 服务/通道选择、等待连接时限 | `session: tcpSessionRef` | 取得已启动服务中的连接，不负责创建监听 |
| TCP 会话发送 | `session: tcpSessionRef`、`data: string` | `receipt: tcpSendReceipt` | 只使用输入会话的原连接，不找“最新连接”补发 |
| 坐标报文格式化 | `x: number`、`y: number` | `data: string` | 数值格式、引号和后缀独立于网络 |

**必须在本轮采集/计算之前取得会话。** 仅在最后发送前取得“当前连接”，不能防止把旧视觉结果发送给重连后的新客户端。

可沿用现有子流程的数据依赖作为控制屏障：

```text
TCP 通道会话.session ──┬──> 采集/计算子流程.session 输入
                     └──> TCP 会话发送.session
采集/计算子流程.data ─────> TCP 会话发送.data
```

子流程必须声明 `session: tcpSessionRef` 输入，使它只能在取得会话后被调用；将相机等待和本轮计算放在该子流程内部。会话引用贯穿本轮，不能在末尾重新获取替换。连续模式每轮重新执行会话节点。

`examples/project_tcp_service.py` 提供不访问任何设备的可编译示例：两个普通通道、一个计算子流程，默认禁用、手动启动，地址仅为回环测试示例；不是双工位调度器，也不是现场工程。可以按需使用 `sampleProject(port, enabled=..., startupPolicy=...)` 生成项目模型。

托管会话的孤立单算子发送调试首版不支持，能力列表会明确标记 unsupported；不能以手写会话字典或历史结果绕过 Job 授权。纯坐标格式化支持普通调试。

## 发送回执不能解释为机器人动作完成

| outcome | 含义 | 处理 |
| --- | --- | --- |
| `NOT_SENT` | 在进入发送边界前已拒绝 | 检查通道、超时、取消、背压、配置和会话代次 |
| `SENT_TO_TRANSPORT` | 完整写入本机 TCP 栈 | `deviceConfirmed=false`；没有业务 ACK/动作确认 |
| `OUTCOME_UNKNOWN` | 部分发送、发送边界异常或 IPC 回执丢失，无法证明未送达 | **不自动重试、不重连补发**；先核对设备实际结果 |

部分报文发送异常后会断开原连接，避免后续报文拼接到不完整数据上。重连产生新的连接代次；旧会话、旧 Job、旧 Runtime 或旧项目引用一律不能向新连接发送。服务重启也不会重新授权尚未结束的旧 Job。

“最近发送”只属于当前服务和当前连接；新连接接入时清空该摘要。旧连接延迟完成的回执可以作为原代次的历史记录保留，但不能覆盖新连接摘要；旧项目的延迟完成不写入新项目历史。

发送队列每通道最多 32 条、16 MiB；单条报文最多 16 MiB（还受项目配置的更小上限限制）。Worker 桥最多 128 个，仅给实际依赖通信的 Job 创建，不给未使用此功能的旧项目增加 IPC 配额。

等待/发送请求携带同机单调时钟的绝对时限，IPC 写入、接收、Runtime 排队和网络发送都遵守该时限。发送超时涵盖 IPC 和网络阶段；仅为收取终态回执保留最多 250 毫秒宽限，不延长实际发送截止时间。Windows 使用可取消的 overlapped Pipe I/O，不依赖额外后台写线程或父端读取来解除阻塞。取消/超时后若无法证明请求未处理，仍返回 OUTCOME_UNKNOWN，不自动重试。

记录最多 512 条且总计最多 1 MiB；每条只展示最多 1024 字节原始数据。RX 是 TCP 原始字节块，不是完整协议报文。面板显示断档/截断、Job/节点来源、回执和 HEX/UTF-8 详情，不提供手工发送、自动 ACK 或历史重发控制台。

## LN5 字节兼容边界

坐标格式化默认：Python `round(value, 3)` 后 `str`，逗号分隔，字面单引号包围，后缀 `EY`，UTF-8，无换行。例如：

```text
'12.345,-6.78EY'   # 16 字节，包括两端单引号，不补齐 3 位小数
```

测试保留 NG 样本 `'0,0EN'` 和两种 EX 原样 `0,0EX` / `'0,0EX'`；不归一、不新增自动发送 NG/EX 的业务逻辑。不能用既有网关算子的默认输出代替这一格式。

本次不改视觉算法、两拍策略或 PLC 地址；现场 PLC 按已确认 **D800**。源码/本机传输通过不等于机器人动作、现场节拍或打包发布已通过。
