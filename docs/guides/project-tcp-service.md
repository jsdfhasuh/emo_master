# 项目 TCP 设备

本指南适用于新建 **2.7 工程**、**1.4 流程包**和 DeviceType／驱动 API **1.1**。
本轮按 [TCP 设备化 v1.5 计划](../plans/2026-10-20-tcp-device-integration-plan-v1.md)实施，
旧工程兼容不在本轮交付范围。

## 创建、保存与写入

1. 从主界面 **设备管理**打开独立窗口，创建 TCP 服务、TCP 单次客户端或 TCP 单次接收设备。
2. 在“连接”中填写地址、端口及通道，在“默认参数”和“策略”中选择本次工作参数、启动与释放方式。
   非法字段会保留输入并显示位置；未下发的工程也可编辑。
3. 在节点设备绑定向导中选择设备。`communication.tcp.session` 还需选择稳定的通道 ID；
   `communication.tcp.session_send` 只绑定 Server，通道由输入 session 决定，无需额外静态 selector。
4. “应用到草稿”和“保留草稿并关闭”保留当前工程编辑；从文件菜单保存后可以重开。
5. 从 **Runtime → 写入 Runtime**校验完整候选，再明确写入。校验不监听、不连接、不创建 Job。
6. 通过 **运行**菜单启动正式流程。保存文件、写入配置和运行流程是三个明确动作。

原 TCP 状态快捷入口进入设备管理，不再打开另一套工程通信配置 Dock。
主界面菜单、设备窗口底栏和 Runtime 连接切换沿用现有职责。

## 三类设备与四个算子

| 设备类型 | 算子 | 绑定与动作 |
| --- | --- | --- |
| device.tcp.server | communication.tcp.session | tcp 槽绑定设备及 channelId，取得会话 |
| device.tcp.server | communication.tcp.session_send | tcp 槽只绑定设备，通道来自输入 session，向该会话发送 |
| device.tcp.client_once | communication.tcp.client | tcp 槽绑定设备，单次连接并发送／交换 |
| device.tcp.receive_once | communication.tcp.receive_once | tcp 槽绑定设备，单次监听接收及可选 ACK |

算子不私建连接参数。设备的 connection 保存地址；defaults 保存可覆盖工作参数；
节点可以按声明继承、常量覆盖或绑定变量／输入。selectors 是静态绑定，不能随运行值改变。

服务通道包含稳定 channelId、显示名称和允许的 IPv4 客户端地址。改名称保留 ID；
删除正在被节点使用的通道会指出流程／节点／槽位并保留输入。一个客户端 IP 只属于一个通道，
一个通道同时保留一个客户端。共享设备不会因为两个节点或两个 Job 引用而复制监听器。

在线 Server 仅修改通道显示名称后，可以测试当前连接草稿并复用原监听端点。
端点测试不应用新的通道规则，也不验证外部客户端；草稿仍需通过 Runtime 入口明确写入。

默认回环地址适合本机模拟。现场地址按 Runtime 所在机器配置；本轮测试不访问真实设备，
也不修改物理网卡。允许列表不替代认证；当前后端不提供 TLS。

## 生命周期和控制

TCP 服务支持 manual、on_project_open、on_project_run 启动策略，由 Runtime 持有监听资源。
on_project_open 在显式配置提交后启动；on_project_run 在正式 Job 准入时启动。
manual 需要先在设备页启动服务。打开／关闭设备窗口和只读刷新均不启动服务。

每台设备独立调度。服务的业务等待与发送可以并行，一个通道等连接不会阻挡另一通道发送。
单次客户端、单次接收沿用每设备串行队列，每次业务打开并释放 socket，不展示持久连接按钮。

- 启动／停止服务复用 connect／disconnect；停止服务暂停后续准入。
- 停止 Job 取消其等待和发送，不误关仍由工程持有的服务或其他客户端连接。
- 维护取消所选设备的排队和活动动作，等待实际退出后断开；无关设备继续运行。
- 恢复准入按原策略开放，恢复会话重建设备资源；两者都不重发业务或恢复旧 Job。
- 切换／卸载工程、Runtime 关闭以及受影响配置替换按实际资源退出处理。
  清理失败保留资源归属，不创建第二个监听器。

设备页按类型 controlCapabilities 和在线 availableControls 展示操作。
单次设备显示事务就绪／忙碌；服务显示监听和实际客户端状态，不用 CONNECTED 代替所有状态。

## 会话、回执与数据

tcpSessionRef 和 tcpSendReceipt 使用 **1.1**，携带 deviceId、Runtime／工程加载代次、
服务／客户端代次和通道身份。tcpMessage 及 PLC 数据载荷继续使用 1.0。
会话属于当前周期与明确设备／通道，不能在发送前换成“最新连接”来绕过失效检查。

可以先取得会话，再让采集／计算依赖该会话，最后发送本轮结果：

```text
通道会话.session ──┬──> 采集/计算子流程.session
                  └──> 会话发送.session
采集/计算子流程.data ───> 会话发送.data
```

子流程声明 session 输入，使本轮业务在取得会话后才开始。
跨设备先后由流程依赖决定；相机取图、处理判定、PLC 写结果继续走各设备队列。

现有 TCP 分帧、ACK、取消与单条消息能力保留。Worker 的 TCP 通路独立有界，
正常 16 MiB 消息能够经过代理传输；普通设备控制通路仍保持原 3 MiB 上限。
测试并非吞吐或现场节拍验收。

成功发送回执表示 SENT_TO_TRANSPORT，不表示对端业务已执行。取消前未发出保持明确未发送；
已经可能发出而回包丢失时保留 OUTCOME_UNKNOWN、请求和会话身份，不自动重放。
显式再次运行是一笔新业务，不能把未知旧结果解释成安全重试。

## 状态、日志与日常修正

Designer 与独立操作端观察同一 Runtime 后端。服务状态提供通道、客户端地址及代次；
诊断按设备和通道查看生命周期、收发、节点及失败记录，支持 UTF-8／HEX 和回执详情。
后台事件、节点日志、未主动记录日志的节点失败都保留发生时的归属。
收发字节预览最多保留 1024 个原始字节，并显示原始字节数；超出时提示“原始数据已截断”。
“部分诊断字段已截断”只表示其他字段的预览被缩短，不表示报文本身丢失；通道筛选和字节显示仍可用。

窗口关闭停止观察，不释放后台服务；重开不会重复挂钩。Runtime／工程／加载代次变化后，
旧观察结果不会混到新设备。读取日志不改变 Job 事件序列。

连接失败或端口占用时，配置提交仍保持 COMMITTED；原写入请求随后显示实际 FAILED 原因。
配置窗口对 COMMITTED＋PENDING 只读观察原请求，对晚到失败去重提示。
修正端口占用或连接条件后，在设备页明确重连／启动并再次运行，不用重复写入掩盖连接结果。

更新通道与节点绑定时，从 Runtime 配置窗口选择所需变更并加入必要依赖；
无关草稿不被带入。替换只影响相关设备和使用者，按现有停止／等待策略释放资源。

## 导出后重新导入

设备包、流程包和完整 Runtime 包使用同一设备定义和静态 selectors：

- 设备／流程复用包显式选择复用或新建。新建生成新 deviceId，绑定一致重映射，并默认禁用。
- 已声明现场字段清空并在导入界面列出，资源、变量和共享设备关系保留。
- 复用现有设备需要目标注册声明满足类型、驱动版本、默认参数、能力与 selector。
  TCP 通道还保持引用通道的地址映射语义；目标设备自身连接与策略不被源包覆盖。
- 完整 Runtime 包保留启用及连接策略；导入到新目录或隔离执行端，核对现场字段与插件依赖后，
  从正式运行入口继续执行。
- 远程空 Runtime 先在执行端导入。已有在线工程再使用比较、资源上传和显式写入；
  不把 Designer 本地路径当作跨机上传。

第三方常驻服务示例见 [device_service](../../examples/device_service/README.md)。
驱动、注册、日志、节点动作与可选设备页动作使用统一机制。
真实相机／PLC、冻结 EXE 和人工现场验收须单独记录，源码模拟通过不代替它们。
