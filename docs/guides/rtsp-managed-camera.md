# RTSP 托管相机

RTSP 可以作为工程设备接入 Runtime 设备管理器。旧的 `vision.io.rtsp_camera`
单次读取算子保持原行为；新增 `vision.io.rtsp_capture`（RTSP 相机采集（设备））
通过 `camera` 槽绑定 `device.camera.rtsp`。两者输出同名的 `image`、`frame`、
`capturedAt`，不需要修改下游 YOLO、翻转、归档或页面的数据连线。

本功能不包含 ONVIF 发现、相机网络改址、云台或发声。海康发声仍为独立动作，
不会因建立 RTSP 连接而触发。

## 新建与迁移

1. 使用包含本功能的 Designer 和 Runtime，刷新算子及设备类型。
2. 打开设备管理器，新建“RTSP 网络相机”，填写不含账号密码的 RTSP 地址。
   用户名、密码使用独立字段；也可指定 `passwordEnv`，由 **Runtime 进程**的环境变量取密码。
3. “测试连接”是显式操作，仅检查建连和码流信息，不启动持续取帧，也不保存图片。
   新建设备、查看列表、读取状态及编辑表单本身均不联网。
4. 新节点选择“RTSP 相机采集（设备）”，明确绑定相机。旧工程则从设备管理器的
   “旧设备节点迁移预览”选择单次 RTSP 节点，再新建或复用设备并确认转换。
5. 迁移只修改本地草稿，可一次撤销。节点 ID、输出端口、连线、页面引用保持不变；
   新建设备时复制旧连接参数，复用已有设备时不覆盖它的连接配置。
   旧 `colorMode` 保留为节点覆写，相关工作参数变量迁移为设备动态来源。
   连接参数的动态变量不允许静默丢弃，需先改成设备连接配置。
6. 保存工程后，通过既有的“写入 Runtime”流程显式发布。保存文件不等于发布，
   修改源码也不会让已运行的 EXE 自动加载新驱动。

旧单次节点无需强制迁移。迁移后的精确算子依赖锁与节点在同一草稿事务中更新；
其他流程仍使用旧算子时，其依赖不会被移除。

密码输入使用遮罩，迁移预览和确认信息隐藏密码及 URL 查询令牌。
这不是加密存储：直接填写的密码会保存在工程设备配置中，分享工程或设备包前需移除。
推荐部署时使用 `passwordEnv`，不要把实际密码写入日志或测试夹具。

## 运行行为

| 内容 | 默认行为 |
| --- | --- |
| 连接 | 首次使用时连接，Runtime 持有一个 OpenCV/FFmpeg 解码器 |
| 取流 | 第一次显式采集后连续解码，只保留一张最新帧，不积累推理期间的帧队列 |
| 节点调用 | 返回未交付过、且未超过 `maxFrameAgeMs` 的最新帧；没有合格帧则有界等待 |
| 帧龄 | 默认 1000 ms，从本机完成解码接收开始计算 |
| 颜色 | 设备默认彩色，可由节点覆写或动态来源选择灰度 |
| 单帧上限 | 默认 32 MiB，解码后尺寸超限报错，不发布超预算图像 |
| 释放 | 默认空闲 5000 ms 后释放；也可选择工程关闭、手动或不再使用时释放 |
| 停止 | 取消当前等待，不中断其他任务的共享相机；共享会话按释放策略退出 |
| 断流 | 清除缓存，返回明确错误；不伪造成功、不自动重放采集 |

循环检测仍由工程的 While 或运行周期控制，托管相机并不自动执行 YOLO、保存人脸
或启动页面。图像是否归档仍由工程中的检测条件和保存算子决定。

`capturedAt` 是本机完成该帧解码接收时的 Unix 时间，不是节点调用时间，
也不是摄像头曝光时间。`maxFrameAgeMs` 约束本地缓存，不能证明摄像头、网络或
FFmpeg 内部不存在延迟；本实现不承诺端到端硬实时。

原图沿现有 FrameStore/worker proxy 传递；`descriptor.acquisition` 保留接收时间、
帧序号、本地帧龄和不含凭据的源标识。慢消费者持有的原图不会被后续取帧覆盖。
单个解码线程拥有 open/read/release，调用方不会在另一个线程强行释放正在读取的句柄。

## 故障处理

| 错误码 | 检查与操作 |
| --- | --- |
| `E_CAMERA_CONNECT` / `E_CAMERA_CONNECT_TIMEOUT` | 检查 RTSP 地址、账号密码、网络与编码格式 |
| `E_CAMERA_READ` | 码流断开或读取超时；检查网络，停止使用该相机的任务后，从设备管理器恢复设备，再运行 |
| `E_CAMERA_FRAME_TIMEOUT` | 未收到符合帧龄要求的新画面；检查码流、帧龄阈值与操作超时 |
| `E_CAMERA_FRAME_SIZE` | 按实际分辨率增加设备的单帧内存上限，或降低相机分辨率 |
| `E_DEVICE_PARAMETERS` | 检查连接字段；使用 `passwordEnv` 时确认变量在 Runtime 中存在 |
| `E_DEVICE_RELEASE_PENDING` | 底层 open/read 尚未退出，不会虚报已释放或再开一个连接；退出后重试恢复 |

OpenCV 的连接/读取超时通过 FFmpeg 后端传入。停止等待可快速返回，但底层解码器的
释放仍需等待其调用实际退出；默认读取超时 1000 ms，不承诺零延迟释放。
显式设置较长超时时，停止或关闭可能先报告释放待完成。若编译使用的 FFmpeg
不支持期限或卡在 native 调用中，应保留资源占用事实，本版本不会强杀解码线程。

## 实现与验证入口

- 驱动：`src/emo_master/apps/runtime/devices/rtsp.py`。
- 类型和算子：`src/emo_master/plugins/builtins/rtsp_capture/`。
- 迁移：`ui/device_migration.py`、`ui/device_wizard.py` 和 `state/rtsp_migration.py`。
- Runtime 测试：`tests/runtime/test_managed_rtsp.py`，含 fake capture、原生本地 AVI
  解码、双进程 Job 经 Runtime 取图、空闲释放和断流恢复。
- Designer 测试：`tests/designer/test_managed_rtsp_ui.py`，含真实工程打开入口、
  新建/复用设备迁移、保存重开、依赖、撤销、变量来源和密码遮罩。

测试使用临时 2.7 工程和模拟码流，不连接现场摄像头。源码、原生 Qt、冻结包与
真实摄像头验收是不同证据，具体执行结果见 [本次测试记录](../testing/2026-10-25-managed-rtsp.md)。
