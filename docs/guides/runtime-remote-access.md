# Runtime 局域网连接与工程资源下载

独立 Runtime 默认只使用本机 loopback 动态端口，首次需要结果端点时才创建监听。
启用局域网接入后，Runtime 在初始化时就监听指定地址和固定端口，不需要先开始任务或打开页面预览。

## 在 Runtime 中保存设置

打开“Runtime 设置”中的“Runtime 远程接入”，选择允许局域网访问，填写监听 IP、固定端口和每任务展示订阅数。
`0.0.0.0` 表示本机全部 IPv4 地址，也可以填写本机某个实际 IP；`::` 表示 IPv6 通配监听。
点击“保存下次监听设置”后，下次启动使用新设置，本次任务及监听继续运行。
关闭局域网接入时恢复本机动态端口，不使用保存的固定端口。

当前链路用于受信任局域网，未启用 TLS。程序不会自动调整 Windows 防火墙、系统服务或网络地址。
固定端口被占用或监听地址不可用时会显示明确启动失败，不会换成另一个端口继续运行。

## 启动参数

源码入口示例：

```powershell
python -m emo_master.apps.operator_runtime.main --allow-lan --listen-host 0.0.0.0 --listen-port 50051
```

参数覆盖本机保存设置，但普通启动不会改写保存值。可选参数如下：

| 参数 | 用途 |
| --- | --- |
| `--allow-lan` | 启用固定监听 |
| `--local-only` | 本次仅本机动态端口 |
| `--listen-host` | 启用接入时监听的本机 IP 或 localhost |
| `--listen-port` | 启用接入时使用的固定端口，1—65535 |
| `--display-subscriptions-per-job` | 每 Job 展示订阅数，1—16，默认 4 |
| `--save-listener-settings` | 保存这些设置后退出，不启动 Runtime 或任务 |

只保存配置的示例：

```powershell
python -m emo_master.apps.operator_runtime.main --allow-lan --listen-port 50051 --save-listener-settings
```

每任务订阅额度用于多个独立客户端，实际结果工作池仍有界。一个客户端内的多个窗口继续共享会话。

## Designer 连接与结果查看

在 Designer 的“连接 Runtime”中填写 `主机:端口`，读取实例和在线工程信息后切换连接。
控制请求、页面结果、Dispatch 结果和预览日志使用同一连接配置；IPv6 地址采用 `[地址]:端口`。
查看已有任务仍需要任务在启动时启用页面采集；只有状态的任务会显示状态及未采集原因。
高级页面连接也接受明确 Runtime 地址和 Job ID，操作只连接已有结果，不创建运行任务。

## 从在线工程下载声明资源

“工程与 Runtime 配置”中的“读回在线配置”只更新本地草稿，不把服务器工程路径作为本机路径。
需要在本机保存完整工程时，点击“下载工程资源…”，明确选择本地工程目录，再按正常流程保存草稿。
下载范围只包括在线工程资源清单中的输入图片、模型、页面静态图片和图标。
生产数据库、业务输出目录、设备文件和任意服务器路径不属于此下载入口。

每个文件按声明的资源 ID、摘要和在线版本分块读取，最终内容校验通过后才原子写入。
相同内容的本地文件会跳过；不同内容不会自动覆盖，界面显示冲突文件，可选择其他目录或先处理该文件。
“取消下载”保留已完成文件并清理未完成临时文件。网络或版本变化失败后可以重新读取在线配置再明确重试。
资源下载在后台进行，不启动工作流，不写入 Runtime 配置，也不自动保存本地工程草稿。

## 首次向另一台 Runtime 写入工程

目标 Runtime 尚无在线工程时，在 Designer 连接它，打开本地工程，再进入“写入 Runtime…”。
有声明资源时先“上传候选资源”，随后校验完整首次候选，最后显式“首次写入 Runtime”。
这些操作复用同一个导入请求；上传或校验本身不提交正式工程，导入成功也不自动启动任务。
请求结果不确定时查询原请求，取消时沿用原候选，不另起一个请求自动补执行。

Runtime 把工程存入自身管理目录；Designer 的工程文件和资源根目录仅用于本机保存、上传。
旧的 `local_project_path` 目录重定位仍只供嵌入式本机 Runtime 使用，不能填入远端电脑路径冒充本机路径。
已有在线工程的更新继续使用读回、比较、上传资源、校验及显式写入，不绕过在线 revision 检查。

## 查看与停止已有运行

Runtime 窗口的“查看已有运行…”可以选择其他客户端启动的根运行或 Dispatch 消费任务，也可选择仍在目录中的历史运行。
查看只改变当前展示，不改变停止目标，不启动任务。页面依赖多个 Dispatch 作用域时，使用同组生产者和消费槽位组合展示。
多个活跃运行并存时，“停止”要求明确选择目标；停止整组选择生产根 Job。终态记录与资源仍在退出的状态分别显示。
客户端断开或关闭查看窗口只释放它自己的连接、订阅和图片资源，不停止 Runtime 中的生产任务。

## 设计并交接 Web 页面

新建工程使用工程 2.9 / Presentation 1.2。页面目标可选桌面、Web 或两者；基础响应式布局继续使用已有上下、并排和换行布局。
Web 使用的 SQLite 历史来源选择“所连接的 Runtime”，固定路径图片也选择 Runtime 并设置允许读取的图片根目录。
选中行图片继承其来源表格的数据位置。数据库和图片文件需实际位于 Runtime 可访问位置，并把来源声明显式写入正式在线工程。

在页面设计区选择“导出 Web 页面包…”，生成 `.emoweb`。包内包含 Web 页面、绑定、动作、布局和声明静态图片；
历史数据只包含组件句柄与版本，不携带数据库、动态图片路径、模型或生产输出。
页面包上传和激活由 Dot Web 应用实现；导出包不会写入 Runtime 配置或启动任务。
仅布局和文案改变时可以单独更新页面包；历史声明改变仍须显式写入 Runtime，新增采集来源需用户明确启动带相应采集的新运行。

“预览 Web 页面（示例数据）”调用 Dot 的 `emo-web-panel preview` 工具，打开浏览器并使用合成数据。
“预览 Web 页面（当前 Runtime，只读）”使用 Runtime 菜单选择的主连接，传递固定地址、实例、工程和历史声明，
在网页中选择已有运行并查询结果/历史；不会启动任务。页面的历史声明须与正式在线配置一致，否则显示原因，
由用户选择明确写入配置或使用示例预览。两个预览入口均不提供生产启停；关闭预览不会停止远端任务。
当前仓库已实现启动和清理接口；尚未安装 Dot 工具时会提示缺少工具，不能据此声称已有真实浏览器预览。
交给 Dot 的完整材料由 `python scripts/build_panel_contract.py` 生成；字段和预览进程合同见 [Panel Contract v1](../development/panel-contract-v1.md)。
