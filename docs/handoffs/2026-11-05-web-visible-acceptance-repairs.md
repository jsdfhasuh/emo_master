## 1. 原因和改动

### Web 切换运行或刷新页面包后的无效消息警告

旧实现先清空共享的允许 Job 列表，再等待下一轮渲染清理旧 WebSocket；
旧连接的消息在检查订阅是否过期之前就进入解析和身份校验。
受控时序下，仍然 OPEN 的旧连接因此会拿空列表校验它本来合法的消息，
产生错误提示；后续新结果展示成功也没有清除这个提示。

现在在创建新 view 的 effect 开头就使旧订阅失效，并取消旧候选结果准备。
每个订阅保存自己的允许 Job、来源问题、Runtime 和工程身份快照。
解析前、异步结果准备入口与完成时，以及连接回调与重连时均检查归属。
创建 view 的 HTTP 响应仍沿用本 effect 的 `valid` 标志，避免旧 socket
清理时递增 generation 把新 HTTP 响应误判过期。

订阅错误单独存储；只在明确切换订阅或当前候选结果成功展示后清除。
心跳和包更新通知不清错；控制操作、目录刷新等错误不受影响。
真正的错 Job、错身份和明确的空允许列表仍会被拒绝。
`reset_required` 先使消息代次失效、再关闭连接的恢复链也保留。
当前连接的解析/准备异常会在控制台记录 view、所选 Job 和异常原因，
不记录整条业务消息。

证据边界：回归使用实际 App/React 与受控 HTTP/WebSocket 排程，
证明上述代码缺陷和修复效果；原可见验收缺少触发警告时的逐帧消息与堆栈，
不能据此宣称原来两次警告的唯一触发原因已经被逐帧还原。

### 图片和自然内容越出卡片

项目布局规范把 `preferredHeight` 定义为期望的最小高度。
Web 原先把它写成 CSS 固定 `height`；图片、标题、边框与留白相加超过
这个固定值时会越出卡片。

普通响应式组件现在使用 `max(minHeight, preferredHeight)` 作为高度下限，
允许自然内容撑高；未指定最小高度时仍保留浏览器自动最小尺寸的语义。
图片不被压扁或裁剪。固定/弹性空白块沿用原有专用分支，网格、宽度和
弹性分配逻辑不变。回归同时覆盖图片、静态图、换行文字、嵌套容器和空白块。

### 从设备管理打开的日志窗口无法输入

设备管理是主窗口的模态子窗口，日志窗口是同一主窗口下的非模态窗口。
旧入口直接显示日志窗口时，设备管理仍会阻止它接收输入。

入口现在先通过设备管理原有的关闭/校验路径保留有效草稿，再打开日志。
有非法输入时留在设备管理并显示校验问题，不打开日志、不丢输入。
有效修改只保留到工程草稿；仍须用户分别执行保存工程和写入 Runtime。

### 设备日志被旧业务日志条件筛空

旧入口只更新工程和设备，遗留的 Job、节点、时间范围以及本地文本等
筛选仍同时生效。现在通过专用 `openDeviceHistory` 入口清理旧历史查询、
分页游标/上界和本地筛选，再仅按当前工程/设备查询一次。

普通手动历史查询保留条件、查询失败后保留上次成功范围、固定上界分页
与完整导出的行为不变；这次没有修改跨客户端历史节点定位能力。

## 3. 给 Dot 的复验要求

固定 ChatGPT Web 最终交付的完整提交 SHA；先核对 PR #11、最新适用的
`AGENTS.md` 和工作区状态。记录操作系统、浏览器、启动命令、软件 Runtime
版本、模拟相机，以及实际工程和页面包版本。不要在复验过程中跟随分支移动。

使用现有明确支持的本机模式 `serve --local-no-auth` 完成 Web 交互；
它只代表本机管理员模式的验收，密码登录和不同账号权限不计为通过。
使用真实软件 Runtime 与模拟相机，在可见桌面中完成以下正常路径。

1. **Web 完整流程和订阅切换。** 创建或编辑测试页面，保存、发布，直接绑定
   Runtime 暴露的数据；普通工作流和 Dispatch 消费者各做一轮。展示实际结果，
   正常停止后在同一 Runtime 再启动；切换查看旧/新 Job，并在运行时更新发布
   页面包、通过界面刷新。确认结果属于所选运行，没有旧图/旧状态覆盖、没有
   “收到无效消息”残留。保存切换前、等待新结果、实际新结果三处证据。
2. **自然高度。** 检查首选高度 260 的检测图和首选高度 100 的静态图，
   以及换行文字和嵌套容器。预览、发布页面都应包住标题和内容，图片自然比例
   保持，下一组件不重叠；复查固定/弹性/零高空白块和固定预览仍正常。
3. **设备日志输入与草稿。** 在设备管理修改一个有效参数，点击运行日志。
   日志窗口应立即可以输入、选择范围、查看详情和导出；重新打开设备管理，
   有效修改仍在草稿里。再输入尚未完成的数值（例如 `-`），点击运行日志，
   应留在原框提示输入问题，不丢失输入、不打开日志。
4. **设备日志范围。** 先在通用日志保留旧 Job、节点、时间和文本筛选，
   再从当前设备打开日志。应仅保留当前工程/设备范围，本地筛选清空，
   不沿用旧分页游标；能看到匹配记录。继续验证普通手动查询仍保留自己设定的条件。
5. **日志查看和输出闭环。** 通过界面比较当前显示、查询历史与完整导出。
   选取一组有已知行数的历史日志，覆盖跨页、首尾条目、字段和数量校验，
   再验证一组含 20 条匹配业务日志的筛选及导出；记录导出时固定的范围/上界，
   不用不断增长的实时总数直接比较较早导出。核对 CSV/JSONL 等实际支持的格式，
   明确每种格式与入口实际跑了哪些组合。
