## 1. 目标与范围

### 1.1 用户最终操作

在 emo_master Designer 中：新建页面 → 拖入组件 → 从“流程数据”树拖入节点输出绑定 → 配置其他页面与导航 → 模拟检查或明确启动草稿调试、查看真实结果 → 保存草稿 → 发布项目包。未发布项目也能明确启动调试，不要求先发布才能验证。

现场人员：导入已发布项目 → 检查设备与依赖 → 明确启动或连接已有运行任务 → 只通过运行页面观看结果、切页和查看指定结果详情。

低代码对象是“页面布局、组件属性、数据绑定和页面导航”，不是自动生成每个项目的 Python 窗口代码。修改这些配置不要求重新打包整个应用；新增组件实现或算法插件仍可能需要更新程序或依赖。

### 1.2 v1 必须包含

1. Designer 内独立的“流程设计 / 页面设计”工作区，保留原流程编辑和算子编辑器。
2. 多页面新建、重命名、排序、复制、删除、默认首页；顶部导航和页面跳转按钮。
3. 网格/分栏/容器布局，拖放、调整占位、属性编辑、复制删除、撤销重做。
4. 数据树自动列出当前项目的节点实例及其正式输出，支持属性选择与变量拖放两种绑定方式。
5. 图像、文本、数值、判定指示、运行状态、结果集合表格、导航按钮和布局容器。
6. 同一个输出绑定多个组件、多张页面，不复制算子、不重复执行或采图。
7. 同一套 Qt 渲染器用于编辑画布、模拟预览、实时预览、浮动预览和现场运行端。
8. 明确的结果作用域、不可变快照、图像资源身份、断线/过期状态、跨页共享订阅。
9. 独立现场入口、草稿与发布隔离、项目包导入校验、失败保留旧版本。
10. 源码、真实 gRPC、Windows 冻结包和不涉及真实设备的验收用例。

### 1.3 不纳入 v1 的内容

- 浏览器远程设计/看板、手机适配、云端部署、任意像素自由画布。
- 用户脚本、`eval` 表达式、任意 Python 导入、任意 QSS 或任意 `.ui` 执行。
- 在自定义页面中任意写 PLC、启动机器人、切换配方或修改算法参数。v1 自定义动作仅导航、冻结显示、恢复实时。
- 通过页面事件重新实现合格判定、PLC 握手或正式生产计数。
- 自动报警抢占翻页、定时轮播、自动下发并运行不受信任的项目包。
- 完整历史生产数据库、报表系统、跨工位产品追溯及其全量历史分页。v1 表格分页仅针对当前结果集合；有限快照回看不等于长期历史系统。
- 强制改造所有算子或重写整个 MainWindow。没有配置页面的项目仍按原流程使用。

## 3. 交互规格

### 3.1 页面设计工作区

左侧设“页面 / 组件 / 流程数据”标签；中央显示当前页面；右侧设“外观 / 数据 / 动作”属性页。顶部保留项目保存和明确的运行控制，页面编辑与开始运行不是同一操作。

页面管理：按稳定 pageId 管理。复制时重新生成 pageId、componentId，重映射副本内部引用；数据来源初始保持原绑定并提示，不按名称猜工位。随后重绑副本仅修改该副本组件的 binding，按 §6.1 写时复制，不能改共享来源导致原页一起改变。删除页面先列出导航引用，允许取消或显式修复；未修复引用阻止发布。

布局：第一版使用有限嵌套的网格容器及行列占位/跨度，不保存绝对屏幕像素为唯一布局。支持拖动换位置、拉伸跨度、分栏比例、对齐、间距和最小尺寸。不同组件不允许无提示重叠；小窗口采用最小尺寸/滚动策略，不无限缩小文字。

编辑动作进入命令栈。一次拖动只记录一个命令；连续属性编辑可合并；页面删除及引用修复为一个事务。普通导航和实时数据刷新不进入撤销栈，不把项目标为已修改。

### 3.2 直接绑定节点输出

“流程数据”显示：工作流 → 节点实例〔显示名称、算子类型〕→ 输出端口 → 已知类型字段。未运行时也可绑定，当前值显示“尚未运行”。只注册但没有添加到项目的算子不出现在这个树中。

支持两种等价交互：

- 选中控件 → 数据属性 → 选择来源 → 选择工作流/节点/端口/字段。
- 将数据树中的端口或字段拖到控件上 → 选择兼容属性 → 确认绑定。

不强制手工注册全局变量，不强制把所有节点结果提升为工作流对外输出。对外输出可作为另一种稳定数据源，但不是直接绑定的前置条件。

不兼容来源禁用并说明原因。绑定成功显示来源路径、类型、状态；提供“定位来源节点”。新增相同类型的算子应自动可用。对可选 overlay 显示配置提示，不自动修改 drawOverlay 或启动采图。

### 3.3 多页面与详情

运行壳提供不可被页面隐藏的连接状态、数据年龄和异常提示。顶部导航来自 pageOrder；组件按钮通过 `navigate(pageId)` 切页，不在工作流增加翻页算子。

普通切页使用目标页面所需作用域的最新已提交快照，同时显示缺失/不完整状态。详情按钮配置 resultScopeId；点击时捕获该作用域在当前页面实际显示的 resultKey，而非后台全局最新结果，再导航锁定。多个作用域而未选来源时拒绝配置，目标页不支持该作用域则明确报错。过期显示过期，可返回实时，不偷偷转到下一次 OK。有限回看不是完整历史。

跨工位总览中，各工位显示各自的检测身份和时间；不声称不同工位天然属于同一产品。需要跨工位关联属于后续显式业务追溯。

### 3.4 预览与现场边界

模拟模式默认启用且固定标识，不访问设备、不写生产计数。实时模式只连接明确选择的已有 Job/会话；无任务显示未连接，不自动 StartJob。第一版在没有会话跟随机制时要求显式选择 Job，不能全局挑“最后一个任务”。

浮动预览与内嵌页面共享一个 DisplaySession。关闭预览或切页只取消对应观察者，不 StopJob。暂停画面只冻结快照，不暂停流程。固定的运行控制操作单独显示，不混入自定义导航动作。

用户明确点击“开始调试”时按 §5.3 冻结当前草稿与采集计划；现场启动读取发布快照。运行任务不热改，新增来源显示“下一次明确启动调试后生效”。布局/文字可本地预览，现场版本不变。明确启动调试可能执行真实设备算子，仍需许可和互斥检查；只有模拟模式保证不访问设备。

## 4. 模块边界与依赖

以下是拟新增位置，实施时可在保持职责的前提下微调文件名，不可伪装成已有接口。

| 模块 | 建议位置 | 边界 |
| --- | --- | --- |
| 页面、组件、绑定、动作、结果 DTO 与校验 | `core/presentation/` | 纯 Python/Pydantic，不 import Qt、apps、protobuf 或算子实例 |
| 项目编辑协调器和页面状态 | `apps/designer/state/presentation_store.py`、`project_edit_session.py` | 工作流/页面共用一份项目草稿和保存事务，不各自覆盖 project.json |
| 页面工作区与绑定选择器 | `apps/designer/page_designer/` | 仅负责编辑，不实现检测逻辑 |
| 共享原生 Qt 组件/渲染器/导航 | `ui/presentation/` | 不 import Designer MainWindow、算子编辑器或 Runtime 执行器 |
| 展示客户端、DTO 适配、只读会话 | `clients/runtime/` | 可被 Designer 和运行端复用；Qt 线程适配留在 UI 层 |
| 结果采集、聚合、快照、资源库 | `apps/runtime/presentation/` | 不创建 QWidget；实现结果状态机、数据所有权和来源证明，不做业务判定 |
| 调试/发布快照与资源引用 | `core/project/` | 纯数据协议，不依赖 cwd、Qt 或具体算子实例 |
| 运行准备与站点解析 | `apps/runtime/` 内独立服务 | 只解析已声明资源与白名单站点参数，不堆入 RPC 或渲染器 |
| 独立现场界面 | `apps/operator_view/` | 读取发布版，只有共享渲染器和必要运行壳 |

组件注册描述包含：组件类型及版本、可编辑属性、可绑定属性及类型、渲染工厂、默认配置、允许动作。它与算法插件注册分离；不要求每个算法配一套 UI。v1 只加载随应用发布的受信任组件，项目包不能通过类路径加载代码。

从现有 RuntimeClient 渐进提取共享部分，旧模块保留兼容导入。多观察者的订阅所有权由 DisplaySession 管理，不能因关闭一张页面就调用全局取消。共享模块不把 RuntimeService、全局计数实现或 Designer 窗口作为导入依赖。

Qt 运行页面采用 QWidget 原生组件、网格/分栏布局和 QStackedWidget 页面宿主；编辑器用同一渲染器叠加选择/拖放层。Graphics View 限用于图像及几何交互等适合的区域，不把全部 QWidget 包装进代理图形项以追求编辑缩放。

## 5. 项目与页面数据契约

### 5.1 单一项目来源

规范项目升级为 2.2，增加 `presentation`，内部版本为 1.0。旧项目迁移为无页面状态，不自动添加设备、运行任务或假业务输出。

`presentation` 建议包含：

- `schemaVersion`、`defaultPageId`、`pageOrder`、`pages`、`navigation`。
- `resultScopes`：一次展示结果的工作流调用边界与调用位置。
- `dataSources`：由绑定操作自动生成/复用的来源定义，不要求用户手工建立变量表。
- 页面含稳定 pageId、名称、组件树、布局；组件含 componentId、type/version、props、bindings、actions。

### 5.2 校验与迁移

结构校验和发布校验分离。草稿允许“尚未绑定”的合法编辑状态，但发布要拒绝悬空 pageId/nodeId/port、类型错误、未决循环调用选择和缺失资源。未知字段、非法枚举、非法数值、重复 ID、循环组件树仍严格拒绝，不能以草稿为由接受任意 JSON。

按原版本严格校验后做 1.x → 2.1 → 2.2 的明确迁移；不能先用新模型填充未知字段再掩盖旧格式错误。原输入不变、迁移幂等、旧工作流/Loop 契约保留。旧程序不支持 2.2 时明确拒绝，不允许静默删页面再保存。保存提供备份，降级使用旧备份。

页面配置保存到项目；Dock位置、窗口位置、编辑缩放、活动页等个人偏好保存到本机设置。真实结果、图像缓存、实时 taskId 不进入项目源文件。

项目整体导出包含页面。现有工作流局部导入导出继续保持原语义，v1 不隐式夹带页面；以后支持带页面片段时必须实现 ID 映射和未解析绑定预览。

### 5.3 草稿调试与发布执行快照

调试与发布共用工作流、绑定和资源编译器；两者均在明确启动前冻结，执行快照不反向覆盖项目草稿。

| 模式 | 来源与创建时机 | 身份及隔离 |
| --- | --- | --- |
| debug | 明确“开始调试”，从当前草稿生成，无需已有发布版 | draftRevision、executionRevision、capturePlanRevision；不启用或修改现场发布版 |
| release | 明确启动已批准发布版 | releaseRevision、executionRevision、capturePlanRevision、siteBindingRevision；不读取未发布编辑状态 |

executionRevision 覆盖算法图、规范化参数、插件版本及输入资源摘要；capturePlanRevision 覆盖作用域、来源、字段和适配规则。纯布局/标题不改变算法指纹；实际展开后的机器路径不进入内容指纹。结果携带运行来源和两种修订，不能只凭 projectId 混接调试与现场任务。

调试默认采集所有完整且校验通过的绑定。合法未绑定控件保持占位，不阻碍其他页面调试；非空但悬空、类型错误或作用域歧义的绑定必须定位并阻止带展示采集的该次调试，不静默排除或猜测。用户可显式清除或禁用错误草稿绑定，禁用项不能作为有效控件发布。流程非法、必要资源缺失仍阻止执行。

预览/切页/重连不生成 Job。新增绑定仅在下一次明确启动调试后采集；停止调试只影响选定调试 Job，不自动停止现场 Job。实际相机/PLC 占用许可单独检查，不因 debug 标签而绕过。无页面项目保留原有运行路径。

### 5.4 资源引用、路径解析与站点覆盖

资源契约在 P1 固化，P2 验证运行准备，完整交付放 P5。project.json 2.2 增加独立于 presentation 的严格资源清单与参数目标引用；旧项目迁移为空，不扫描所有字符串猜路径。

resourceId 对应包内规范相对路径、摘要、大小和用途；参数目标用 workflowId/nodeId/parameterPath 指向资源或站点字段。用途由已声明元数据或受信任适配表确定，不允许包提供 Python 类路径来解析。

| 参数用途 | 规则 |
| --- | --- |
| 输入图片、模型、静态页面图片/图标 | 发布时复制、校验摘要；运行从明确 releaseRoot/debugSnapshotRoot 解析，不保留开发盘符作为读取依据 |
| 输出目录 | 单独的可写站点/运行数据目录，不写发布资源目录，不把已有输出打包 |
| 设备地址、相机序列号 | 站点白名单字段，类型/范围/必填检查；缺失阻止对应设备执行 |
| 密钥/令牌 | 只保存许可的本机秘密引用，不打入包、日志或明文指纹 |

运行准备层将声明引用物化成既有算子可用的合法路径，逐 Job 构造参数，不全局 chdir、不依赖 cwd、不回退开发目录。检查资源缺失、摘要、越界和链接；输入资源快照必须稳定，不能运行中读到被覆盖的模型。

参数顺序固定为：版本锁定默认值 → 草稿/发布参数 → 声明输入资源解析 → 白名单站点字段覆盖 → 最终类型/必填/权限校验。资源与站点目标不得冲突；站点覆盖不得任意改算法阈值或模型内容。记录 siteBindingRevision；密钥只记录非敏感版本引用。换盘符不改变内容指纹，改变模型内容必须新执行修订。自定义文件参数未声明用途时明确不支持自动发布，不谎称所有旧项目可无配置迁移。

## 6. 数据绑定与类型规则

静态来源身份是 resultScope + 工作流调用路径 + workflowId + nodeId + outputPort + 字段路径；运行身份另外携带，不把 operatorId 或显示名当作唯一数据地址。

来源目录以项目节点实例及规范化端口契约为准；与实际加载的插件版本比较。节点存储的简写类型与插件 PortSpec 冲突时报告错误，不能只取较宽松的一方。算法局部变量、日志文本、私有对象不自动暴露。

v1 支持：

| 来源 | 可绑定组件 | 限制 |
| --- | --- | --- |
| integer / number | 数值、文本 | 保留整数/浮点区别，boolean 不自动当数值；单位和小数位仅格式化 |
| string / boolean | 文本、判定指示 | 显式值到标签/颜色映射；无值不当 false/NG |
| image | 图像 | 通过受控 ImageRef 读取，不传 Qt 对象，不猜文件路径 |
| 已知 geometry / collection | 叠加、结果表格、字段选择 | 使用已有契约与坐标空间；不自动取列表第一个对象 |
| runtime_status | 平台状态 | 与业务 OK/NG 分开，只读 |
| 已有命名 global_counter | 计数卡片 | 读取 Runtime 权威值，页面不自行累加或清零 |
| workflow_output | 与其类型一致的组件 | 可选稳定边界，不代替直接节点绑定 |

字段选择第一版覆盖已有、明确的语义类型，如 Blob 的 area/centroid 和 Detection 字段。通用 json/any 默认仅作有大小限制的文本/原始数据查看；没有结构定义不得承诺自动展开任意字段。动态列表的行由集合决定；单值选择需先在流程内筛选/选择，或采用明确且可校验的选择器，不默认第一项。

显示层只做格式化和表现映射，不新增“数量等于 4 即合格”的业务计算。流程执行 COMPLETED 不等于产品 OK。统计用已有正式输出/计数；没有合格率源时不虚构历史统计，新增业务计算应在流程或独立统计模块实现。

### 6.1 单控件重绑与共享来源所有权

dataSource 作为不可变值。单控件重绑执行“创建/复用新来源 → 仅更新该组件 bindings 属性引用”，不原地修改共享来源。全局替换是另一项明确操作，先列出受影响控件，再作为一个可撤销事务执行。

来源去重键含 resultScope/callPath/workflowId/nodeId/port/fieldPath/expectedType/规则版本，不只看端口名。运行采集由编译器去重，编辑对象无需共享可变状态。撤销恢复精确引用；回收来源需同时考虑页面与撤销记录。复制后重绑、删除副本不得影响原页及其详情作用域。

### 6.2 全部展示输出的冻结与预算

节点输出校验后、`_route()` 向下游暴露引用前，采集所需输出的自有版本：图像使用独立缓冲；dict/list/几何/集合使用有界规范化值树或受控序列化。仅冻结 dataclass 外壳、浅拷贝 dict、调用 `_jsonSafe()` 均不够；入 Queue 后才等后台序列化也不构成冻结。

只处理受信任基础值和已知类型，拒绝环引用、非法数值、未知对象，不盲目 deepcopy 插件对象，不从包/网络加载 pickle。字段投影明确只取指定字段，不将投影称为完整原对象。同一来源只冻结一次供多页复用；插件自行在后台并发改返回缓冲的行为须有所有权契约，否则不能保证采集有效，不通过裸对象引用猜测。

P0 必须记录并冻结以下预算值、计费方式和超限行为，P2 不得只留下“有界”口号：单来源/单结果非图像字节、集合元素数、递归深度、值树节点数、每结果来源数、每 Job 未封闭作用域数、单图及每结果原始字节、导出并发/待处理数、每 Job 与 Runtime 全局展示内存、暂存/缓存/租约的磁盘限额。

预算在复制/入队前预留，增量序列化受上限约束；临时副本、编码缓冲及 IPC 缓冲同样计费，不能先无界分配再检查。超限来源标 UNAVAILABLE 并给原因，不默默截断后仍称完整，不改正式算法输出。未封闭作用域超额时按 §8.2 明确缺口，不阻塞检测等 UI。表格只显示 20 行不代表后台大集合受控。

## 7. 一次检测、调用路径与快照一致性

### 7.1 结果作用域

简单无循环流程默认以指定根工作流的一次调用为结果边界。循环检测推荐以“一轮检测所在子工作流的一次调用”为边界。作用域由绑定向导自动建议；重复调用无法唯一确定时必须要求选择，不能悄悄取全局最后一条。

结果键包含 `(runtimeInstanceId, projectId, executionRevision, capturePlanRevision, jobId, resultScopeId, scopeWorkflowRunId)`，附带 executionMode 和调试/发布修订上下文。scopeWorkflowRunId 标识一次实际调用；用户可读序号不作为跨重启/跨 Job 主键。

补充稳定调用位置路径，含父工作流、调用节点、Subflow/Loop body/condition 角色。现有 parentWorkflowRunId 和 iterationPath 用于关联但不能单独代替调用位置。两处调用同一个子工作流必须区分。

绑定输出需能唯一解析到该结果作用域内的一次执行。循环内多次出现的内部节点不能默认“最后一次”；应绑定 Loop 聚合输出或选择更内层作用域。两组不同作用域的结果可同页展示，但必须分别标注，不能伪装成原子的一次产品检测。

### 7.2 结果封闭状态机与终态兜底

ResultSnapshot 是不可变的已提交结果，包含结果键、修订、来源值与状态、ImageRef、游标、时间及诊断。来源至少区分 VALID/MISSING/SKIPPED/FAILED/UNAVAILABLE；0、false、空集合是合法值，连接和陈旧状态另列。

必须明确“执行结束”与“展示数据收齐”两件事：

| 状态 | 含义 | 转换规则 |
| --- | --- | --- |
| OPEN | 作用域已登记，接收冻结输出 | 收到封闭清单或父进程兜底后进入 SEALED |
| SEALED | 执行已结束，预期来源、序号/导出任务和终态固定 | 齐备或截止时间到达后提交 |
| COMMITTED | 来源都已解析成合法值或明确的正常缺失/跳过/执行失败状态 | 最终态，不原地改变；业务仍可能是 NG 或执行失败 |
| INCOMPLETE | 导出失败、传输缺口、超时或异常中止使展示不完整 | 最终态，缺失标 UNAVAILABLE，不沿用上一轮 |

每 resultKey 最多一个最终快照，重复终态与重放幂等。v1 不用迟到图片补写已提交结果；资源过期仅改变可用性，不产生另一件业务结果。

冻结采集计划确定预期来源。封闭清单包含 resultKey、计划摘要、来源状态、来源序号终点、已受理导出任务 ID 与执行终态；来源对应 nodeRunId/port/field，清单大小受预算限制。不能只发一个 completed 布尔值，也不能按不同队列的到达先后判定已收齐。

作用域登记、封闭身份与清单摘要进入可恢复的生命周期记录；大值、图片和无界清单不占心跳/控制消息。完整有界清单与数据可走展示通道；摘要已到而清单未到也受截止时间约束。禁止以 Queue.empty()/qsize() 判断完成。

封闭等待从父进程观察到该作用域执行终态开始，用单调时钟计算。P0 固化有限时限；齐备提前提交，到期逐项标不可用并提交 INCOMPLETE。等待只在展示聚合器，不延迟 PLC 写入、Job 终态和控制受理。正常缺失端口不能复用旧值；执行失败保留本次诊断，不能让上一轮 OK 冒充当前。长期 Job 必须配置逐件子流程作用域，不无限等整个 Job 结束。

Supervisor 登记并收束 Job 的 OPEN/SEALED 作用域。正常 Job 终态允许已受理导出在既定截止时间内完成；强杀、心跳超时、进程异常或展示 IPC 损坏时设置终态栅栏，有界取消/收尾并生成不完整状态。已提交的早期结果不被重写；迟到消息按 generation/resultKey/taskId 拒绝并清理孤儿资源。进程死在作用域登记前时显示明确 Job/展示故障，不编造检测编号。

worker finally 只覆盖正常清理，父进程负责必要接管与兜底。损坏的展示 IPC 隔离到所属 Job，新任务使用新通道，不复用损坏 Queue；关闭读者/句柄/暂存均有时限，不影响其他 Job。必须用真实 spawn 和故障注入验证，不只写单线程伪测试。

### 7.3 逐帧来源、坐标与跨页原子显示

逐帧身份独立于坐标空间。assetId 唯一只证明文件不同；相同 resultKey、尺寸或 sourceId 不证明几何来自那张图。不直接改变现有 coordinateSpace.sourceId 的语义。

可信采集适配在源节点每次图像产出时分配 frameToken，关联 sourceNodeRunId/port 和可用设备信息，同文件重复读取也不同。展示 sidecar 保存来源证明，不往现有严格语义 payload 随意加字段：

| 链路 | 规则 |
| --- | --- |
| 已适配 ImageLoader / 相机 | 每次产出独立 token，路径/设备编号只是辅助 |
| 已声明单图变换、分析 | 可信适配明确输出对应输入，传递 lineage，并采用 frame/仿射/单应变换 |
| 几何/检测集合 | sidecar 同时关联输入帧 token 与输出坐标空间，不只看 sourceId |
| 多图/复合输出、未知自定义算子 | 显式声明来源或复合映射；没有证明标未知，不继承“第一个输入” |

P0 固化最低可信适配集，P3 前通过对应源/变换/Blob 叠加用例；不要求一次修改全部插件。未知链路仍可显示原图或算子已绘制 overlay，但独立图像+几何绑定须明确不支持或阻止发布，不凭尺寸、路径或视觉观感猜配。

图像引用含结果键、端口、不可变资源 ID 与来源证明。独立叠加需 token 对应且坐标变换成立，包含 resize/crop/留白/透视。一个作用域两张同尺寸图、两相机相同默认 sourceId、同文件重读均须分别验收。

后台准备同组快照；图像就绪或明确不可用后，UI 一次模型提交切换图像、框、数值、判定。图片请求带 generation + resultKey + view requestId，切页/重绑/换项目/重连后拒绝旧请求。冻结/详情锁定的是结果键与快照，不是文字；租约过期标过期，不换最新图。不同作用域分别标注，不声称全页面跨工位原子一致。

## 8. 结果与图像发布通道

### 8.1 与现有事件/预览分工

已有 Job/EventStore/SQLite 仍负责执行事件和原有重放，不因 UI 刷新策略丢弃正式事件或计数。旧算子预览 API 保持兼容。

采集计划由 §5.3 的草稿调试快照或正式发布快照编译，在明确启动时固定。未发布项目可调试；每个来源跨页只采集一次，不按组件调用算法，也不热增运行任务来源。

新通道按 §6.2 在路由前取得校验后的自有输出，不从日志、message 或 ndarray 字符串恢复数据。无 presentation 不增加新展示编码；旧预览路径既有同步成本仍计入基线，不声称已消除。

### 8.2 有界导出、丢弃与资源接管

图像先检查尺寸/dtype/通道/预算，预留额度再复制自有缓冲；其他输出先规范化冻结。编码、缩放与展示文件 I/O 放在专用有界任务中，不在 EventStore sink、控制 RPC 或 Qt 主线程执行。复制仍有成本，必须测量。

跨进程只传冻结值/受控序列化数据与资源描述，不传 Qt 对象或插件实例。展示通道独立且同时限制消息数和字节，不能把原 Job/心跳 eventQueue 改为随意丢事件。Queue 后台序列化前的数据所有权必须已经固定。

资源写入 Runtime 分配的会话/Job 暂存区，临时写完原子发布，文件不覆盖上一结果。父进程检查 resultKey/taskId、长度、摘要和路径归属再接管，不读取任意客户端路径。资源转移与原 job workspace 清理显式协调：接管或取消标不可用，不能无限等图片；终态和迟到按 §7.2 处理。

慢消费者可合并中间已提交展示通知，但不能丢封闭语义或隐瞒最新结果缺口。Runtime 保存各作用域的最新快照/状态与游标；推送缺口返回 RESET_REQUIRED 或等价失效通知，由客户端重新取快照。有界健康校验也核对游标/数据年龄：最后一条通知丢失且之后不再产出时，仍可恢复或明确失效，不依赖下一件产品。

采集端超额可跳过整次展示，但要记录该次身份与不可用状态；无法登记作用域时标记展示流缺口。旧 OK 不继续显示为当前有效。分别记录采集、Runtime 分发/会话、UI 层的跳过量，正式事件和生产计数不受 UI 丢弃策略影响。

导出取消、队列读异常、强杀和父进程清理均有期限；不以 Queue.empty/qsize 判断收齐。IPC 故障按 Job 隔离重建，旧代际消息无效，不能只依赖 worker finally。临时文件、缓存和租约纳入磁盘上限，读图也有使用期限；资源过期明确不可用，不换一张图顶替。恢复只清理确认不存活的所属会话，不删其他 Runtime 或正式输出。

### 8.3 存储与资源寿命

Runtime 维护有界的最新快照与有限回看缓存；图片按项目/会话计数与字节双限额管理。锁定回看可申请有期限租约，必须有总量上限，不能靠无限 pin 绕过磁盘上限。

图像过期与事件仍可重放是允许状态，需明确返回资源不可用。第一版不把有限展示缓存宣传成生产历史存储。现有正式输出文件不应因展示缓存清理被删除。

## 9. Runtime API 与客户端生命周期

### 9.1 接口与会话

在现有 proto 体系中增量增加类型化只读接口，具体名字以实施提交为准，能力必须覆盖：

| 拟议接口 | 作用 |
| --- | --- |
| GetRuntimeCapabilities / GetRuntimeIdentity | 协议版本、运行实例、支持的显示能力 |
| ListJobs | 按项目查询任务及 debug/release、执行/采集修订，解决无 Job ID，不自动选最近任务 |
| ListDisplaySources | 返回已加载工程的来源目录与采集计划版本 |
| GetDisplaySnapshot | 返回指定作用域当前快照及一致的 high-water cursor |
| StreamDisplayUpdates | 从游标开始订阅；先补增量再实时跟随，可取消 |
| GetDisplayAsset | 按受控 assetId 有界分块读取及校验，不接受任意绝对路径 |
| Pin/ReleaseDisplaySnapshot | 有期限、有限额的详情查看租约，可选内部合并为句柄 API |

快照获取与订阅必须防止中间漏消息：同一锁/版本屏障生成快照和游标，随后获取严格大于游标的更新；历史已截断返回 RESET_REQUIRED 并重新取快照。新增展示序列按发布范围定义，不混用多个 Job 各自从 1 开始的 event.sequence。

发布实例变化、Runtime 重启或工程执行修订变化时更新 generation 并清理旧会话缓存。禁止全局 lastSequence 导致换 Job 后拒收新数据；收到重复消息幂等处理，不通过重放增加计数。

每个客户端/明确运行会话只有一个 DisplaySession，页面和浮动预览是其观察者。失去一个观察者不取消其他页面；最后观察者退出释放自身通道、读图任务和租约，不关闭不属于自己的 RuntimeService。

### 9.2 正常并发矩阵与执行资源隔离

不再以当前四线程池推导全局两流的最终限制。最低支持组合如下；相机预览使用不与 Job 争用的设备，设备互斥不能代替订阅资源验收。

| 场景 | Job 事件 follow | DisplaySession | 相机预览流 | 要求 |
| --- | --- | --- | --- | --- |
| C1 单 Designer | 1 | 1 | 0 | 状态查询/停止可受理 |
| C2 Designer 加不冲突相机 | 1 | 1 | 1 | 三类订阅同时成功 |
| C3 再加独立观看端 | 1 | 2 | 1 | 同次结果扇出，不重复采图 |
| C4 两个并发 Job | 2 | 2 | 1 | 任务身份独立，控制可响应 |

控制 RPC 与 Job 事件、展示更新、图像读取、相机预览必须分配独立执行/准入预算。P0 优先验证同一 Runtime 内受支持的按 RPC 隔离方案；不能提交后台任务后又在控制 worker 等 Future 来伪装隔离，不依赖未经锁版本验证的 gRPC 私有属性。

若当前同步服务不能可靠隔离，P0 选择同一 Runtime 进程内独立只读 gRPC 服务或异步长流实现，并同时处理旧事件/相机流的控制池占用。只新增展示端口却留下旧长流可耗尽控制池不算完成。保留旧 RPC 路径、取消及内嵌语义；不得创建第二个持有设备/项目的 RuntimeService。具体公共 API、端点、线程/任务配置及兼容路径须在 P0 固化，不要求整仓顺带改成 asyncio。

额度至少满足 C1—C4，分别限制流数、客户端、短请求积压、图片并发/字节与期限。超额快速 RESOURCE_EXHAUSTED，不能在控制 worker 中阻塞等待信号量；饱和时仍留控制和拒绝请求处理资源。取消/异常/结束必须 finally 归还额度。共享锁/I/O 也要有界，独立池不是硬实时保证，不无限加线程。

保留原日志持久化与新展示丢弃语义的区别；多页共享会话，多客户端复用已采集数据。分别测 GetJobStatus、StopJob 受理与实际停止完成。若旧 StopJob 回复本就等收尾，则记录服务端受理时刻，不把回复时间当受理，也不暗改旧语义。C1—C4 真网络通过后才认定容量有效。

### 9.3 连接与兼容性

默认只支持本机 loopback。已有远端使用不能倒退，但新增页面能力未经过认证、授权和网络验收前不作为局域网控制功能交付。没有能力的新服务端应明确报告不支持，不能悄悄退回“预览打开就启动任务”。

## 10. Qt 页面实现与线程规则

QStackedWidget 仅负责页面显示；PageNavigator 负责稳定 pageId、返回栈和 live/pinned 上下文。不要保存 QWidget 指针或 tab index 作为页面业务标识。

页面按需实例化，运行端不 import 页面编辑器和算子编辑器。缓存页面数、集合行数、图像字节数都有上限。隐藏页面停止不必要的解码和绘制，但不关闭 Runtime 采集，也不漏正式统计。

GUI 主线程只创建/修改 QWidget 与 GUI 图形对象。接收、资源读取、解码在后台；使用自有缓冲的 QImage/字节数据，不能让 QImage 引用已被释放或复用的 NumPy 内存；QPixmap 转换/设置留在主线程。按 generation 丢弃迟到任务，有界合并 UI 刷新，不能每个事件无限排一个 signal。

表格使用模型/视图与分页/按需行访问，不为每个单元创建 QWidget。v1 分页绑定同一快照的当前集合，翻页和排序不改变检测结果源；切到新快照重置或明确保留筛选，不混合新旧行。长期历史查询不在本次承诺内。

颜色之外同时显示文字/图标，确保 OK/NG/未检测/运行失败可区分。保留平台级断连、陈旧、模拟和冻结标记。导航页缺失、组件不支持等问题用占位错误呈现，禁止悄悄替换成看似正常的内容。

发布验收覆盖 100% / 125% / 150% 缩放、窗口最小尺寸、多屏移动、长中文名称、长错误文本及键盘导航。共享渲染器不等于不同设备必然像素一致。

## 11. 保存、发布、现场入口与安全

### 11.1 草稿与发布

ProjectEditSession 统一组装 workflow + presentation，原子保存和备份；编辑页/流程时不能相互覆盖。迁移与保存检查必须覆盖 WorkflowStore 的所有导出入口，而非只改 ProjectDocument。

按 §5.3 共用编译器，发布额外做完整页面/导航/绑定校验；调试可不发布而明确启动。项目、依赖、页面和 §5.4 资源清单冻结为发布 revision；执行/采集指纹分开，样式不假装算法变化，草稿不热改运行任务或现场版本。

沿用 `.vxpkg`，升级 manifest 的兼容性字段和完整性校验；如果语义不向后兼容则提升 manifest 版本。构建采用明确 allowlist：项目、必要模型、图像/图标资源与依赖声明；默认排除运行 DB、日志、缓存、测试输出、令牌、临时文件和构建目标。包输出位于项目外或显式排除；拒绝越界链接。

包内依赖版本从实际检查结果产生，不能沿用硬编码 `0.2.0` 表示新能力。哈希只证明完整性，不等于可信签名；v1 只运行可信来源项目，禁止包中脚本/未知 Python 插件自动安装执行。

### 11.2 导入和版本启用

导入先在暂存目录验证路径、大小、重复项、压缩炸弹限额、摘要、schema、组件、绑定、插件及参数资源引用。全部通过才原子启用，失败保留旧版。按 §5.4 检查站点白名单、覆盖顺序和真实路径解析；包里有文件不等于运行能找到它。导入/映射不自动触发。

项目启用与检测启动是两次操作。运行中默认拒绝切换执行版本，要求明确停止或现场认可的安全切换点。回退切回上一完整发布版；数据库/项目格式不兼容时使用备份，不能强行降级后静默丢字段。

### 11.3 启动形态

新增拟议入口：`EmoMaster.exe --runtime` 与 `EmoMaster.exe --operator-view ...`；无参数继续进入 Designer，`--self-test` 保留。参数名在 P5 固化并同步开发/部署文档，实施前不可当现成命令使用。

现场启动器可以启动一个独立 Runtime，再连接 Operator View；多个客户端不得重复争用相同数据目录或设备。服务就绪、项目就绪、页面就绪分别报告，禁止以固定 sleep 代替握手。端口冲突明确报错，不杀死未知进程。

关闭 Operator View 只断开显示；独立 Runtime 的停止由明确控制决定。Designer 内嵌模式的进程退出仍会影响其拥有的 Runtime，不能宣传与独立部署同等隔离。即便界面可独立退出，设备故障/丢失监控时是否停机仍由明确现场策略决定。

默认不自动开始设备流程。后续若配置自动运行，必须是已批准发布版本、明确启动策略和设备验收，不借“自动打开首页”隐式实现。Windows freeze_support、spawn、退出回收和无 GUI 的 Runtime 导入分别测试。

## 14. 性能预算与测试口径

不得写“Qt 天生零延迟”或“已达到生产指标”。P0 固定硬件、驱动/缩放、输入/持久化条件、并发和测量时钟，冻结预算与测试窗口，再比较原基线。

正常参考负载：模拟检测、1920×1080 uint8 BGR、5 次结果/秒、5 页约 50 控件，0/1/2 个观看端；活动页含该作用域的图像与数值。C1—C4 单独记录并发负载，注明预览分辨率/帧率。故障和超载另列，不混进正常结果。

对比分组：原功能（无新通道）→ 新版无 presentation → 启用采集但无观看者 → 一个观看者 → 两个观看者/多页。无观看者不计算可见覆盖率，但采集/封闭/缓存成本仍测，不能以未启用替代启用后的零客户端成本。

### 14.1 时间与完整观测

记录 tScopeEnd（执行线程到达所选结果边界，不含随后异步导出等待）、tSealObserved（父进程看到封闭）、tSnapshotCommit、tUiCommit，以及采图/算法、复制、编码/读图/解码和绘制观测点。显示延迟为 tUiCommit - tScopeEnd；不得改从“图片已准备好”计时来隐藏等待。原定 200 ms 目标按此更明确口径验证。

逐作用域、逐观看端记录生成/封闭/最终提交/完整可见/不完整数，以及采集、分发、UI 分层丢弃；按不同 resultKey 对账，重放不重计。正常活动 live 页的可见覆盖率 = 完整可见的不同结果数 / 统计窗内该作用域应显示的结果总数。超时/缺失作为失败单列，不能删除分母后只测成功帧的 P95。隐藏页、冻结、断线与切页过渡分别统计，不冒充正常 live。

记录当前时间减已显示结果 tScopeEnd 的最大值/P95，并记录最新可用结果与已显示结果的序号差和年龄差。正常持续产出时检验鲜度；无新产品时显示等待触发及最后更新时间，不把空闲误报为算法故障。已有新结果但展示失败时标过期/缺口，旧 OK 不保留“当前有效”。

### 14.2 待测门槛与降级

原型正常负载目标：整组可见提交 P95 ≤ 200 ms；模拟节拍 P95 相对原功能基线回退 ≤ 5%。新增候选目标：活动作用域完整可见覆盖率 ≥ 99%，持续产出时最大数据年龄 ≤ 500 ms。所有数字均为待测目标，不是当前性能结论；必须同时报告失败/缺失，不能靠丢掉绝大多数帧达标。

P0 另外固定有限的结果封闭、导出收尾、读图、控制受理期限；故障截止时间与正常 P95 不是一回事。已知不可恢复的输出提前降级，不必等满时限。超载跳中间展示但报告缺口和计数，末次通知丢失后无新产出也需重取或失效。

记录 GetJobStatus、StartJob/StopJob 受理、实际停止完成、冷启动到服务/项目/首页就绪，以及各进程 CPU/RSS、计账队列/字节、磁盘、句柄。不能用 RTT 代替显示延迟，也不能把 StopJob 最终回复误作受理；P0 用基线为控制请求确定独立门槛。

同机跨进程单调时钟先验证同源，跨机不相减未校时墙钟。UI 模型提交不等于显示器真正呈现，明确观测点。复制、旧同步调参快照、历史写盘和共享资源竞争均计成本；短基线同时报告绝对耗时，避免百分比误导。

目标未达时保留原负载、目标及证据，显式修订能力或架构，不通过删分母、改计时起点或放宽阈值后宣称原目标通过。
