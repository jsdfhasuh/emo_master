## 3. 先选对验收工程，不先再造一套架构

首批从当前仓库、用户已经提供的工程或明确授权目录选取一份**已有实际工程的副本**，只在副本验证。记录原节点 ID、插件/版本、子流程/循环结构、每页需要的输出、图像尺寸/通道、目标屏幕和运行/停止方式。不存在已取得的实际工程时，明确记录缺口，继续可独立完成的代码修复；不能拿固定 ImageLoader→Blob→Count 示例冒充用户工程验收，也不能猜测现场参数。

离线验证允许用录制图像、模拟触发、通信替身替代设备边界，但须列明替换点，尽量保留实际算法与流程结构。不得改写整个流程来迁就白名单；替身结果不证明真实设备、时序或节拍已通过。不得读取无关目录、操作生产设备、覆盖现场项目/数据库或把私有图片/凭据提交仓库。

需求基线中“尚未确认”的项保持待确认，不自行承诺每个算子、任意图像大小或无限窗口。模板/合成样例仍可做单元及回归测试，与实际工程验收分列。

## 4. 下一批只做：同一工程、同一次明确运行、两页观看

**这是当前唯一优先开发批次。** 先完成以下用户路径，再按 §5 的顺序补使用能力，不自动推进冻结打包。

1. 正常打开 Designer，从主界面发现“页面设计”；进入后复用现有 PageCoordinator、ProjectEditSession、PresentationStore、RuntimePages、DisplayHub 和 DisplaySession。旧项目只有明确启用页面并保存才按现有规则升级，不把所有工程启动时无条件改成 2.2。
2. 数据树读取当前工程的实例输出，友好名称在主标签显示，ID 用于定位。直接选择绑定，不另加界面变量、显示算子或强制工作流出口。
3. 复用原运行控制器、RuntimeClient、JobManager/Supervisor 和 PresentationService，在明确的“开始运行/调试”操作中冻结绑定并创建**一个**任务；流程节点状态、日志和自定义页面指向同一个 jobId。没有页面或未启用采集时保留旧路径。区分原运行与隔离调试的计数/输出语义，界面明确标识，不能因统一入口偷偷切换生产数据命名空间。
4. “观看当前任务”默认来自当前工程的明确任务选择；同工程多任务时显示可读状态让用户选择，不能取全局最后一个 Job。高级地址/ID输入可保留，但不是必经操作。外部 Runtime 先协商能力，不能为观看偷偷创建本地设备 Runtime。
5. **已启动且未采集这些输出的任务不能凭空补数据。** 页面说明缺少哪些来源，允许查看已存在结果；新来源仅在下一次明确启动生效。打开页面、切页、重连不 StartJob、不重跑算子，不热改正在执行的采集计划。
6. 两页先绑定当前工程已支持的同一结果作用域；图像、数值、业务判定关联同次结果，切页/第二观察者不增加任务或重复采图。执行状态和产品 OK/NG 分开。
7. 明确停止并确认任务及所属资源结束后，可以再次运行；调用既有停止/释放机制而不是重启整个应用。超时且启动是否成功不确定时先查询/关联同次启动请求，不自动再发一次 Start。关闭只读页面只解除观察，独立 Runtime 生命周期不变。
8. 页面与流程共同保存、另存、撤销重做；重开后绑定正确。编辑中的未保存控件输入也要提交或提示，不能只校验底层已提交事务。不支持的来源必须在绑定/准备前显示原因，不能显示假值或无解释空白。

**本批验收**：一个真实工程副本（或明确标注尚缺该样本）的正常入口路径，两个页面，同一 Job 图数/判定对应；停止后再次运行、页面关闭和重连不误启动/误停；保存重开不丢配置。已有成功演示不替代这份新操作证据。

需要改 Runtime 启动协议时采用增量、可回归接点，保持旧客户端与无页面项目兼容；不一次替换全部 gRPC 服务，不直接复制 prototypes。没有足够工程信息时先完成入口、只读选择、用户输入适配等不依赖设备的部分，报告未完成范围。

## 5. 紧接着补齐的使用能力，按需求而非阶段编号推进

### 5.1 先让现有组件好用

修改现有 tools/models/renderer，不再做一套编辑器。新增属性使用明确默认值及兼容校验，旧页面正常读取，未知属性仍不得静默丢弃：

- OK/NG 映射用“类型 + 值 + 显示文字/颜色”输入，界面负责规范 JSON 编码；用户直接填 `OK`，不要求写 `"OK"`。内部类型严格校验保留，布尔 false 不当缺失。
- 对已知 Blob/Detection 等类型提供字段选择，不要求手写 JSON 路径；未知结构明确不支持自动推断。输出树显示节点名称、所属流程及必要调用位置，不只显示 UUID。
- 补齐导航、冻结、恢复实时、查看当前已显示结果的动作编辑，复用已有 Action。详情锁定 GUI 已显示的 resultKey，不取后台最新结果；不提供设备写入动作。
- 有界字体/字号、文字和卡片样式、目标窗口适配按实际屏幕需求配置；取消把固定 1600×1000 当通用产品约束的假设，但新增 Qt 表面/图片成本仍要测量与计账，不允许无限放大资源。
- `emptyText` 真正用于未检测/合法空值的约定场景；断线、错误、图片过期必须保留独立且不可隐藏的提示，不能用自定义占位掩盖故障。零、false、空集合与缺失分开。
- 离线模拟可切换 OK/NG/等待/错误以检查表现，始终带模拟标识，不读写 Runtime 或计数。

### 5.2 按实际页面需求打通算子、作用域与多图

能力分开判断：输出可列出/可绑定、当前 Runtime 可执行及采集、资源可交付、设备被许可，是不同条件。用现有可信注册信息与端口类型复用支持，不允许包动态安装未知代码；新增可信类型才增加对应适配。测试白名单继续约束测试专用入口，但不复制到每一层作为通用产品能力表。

分别验证同一流程两张图（原图/结果图）、两页两个调用作用域、确有需要时两个明确运行任务。每个作用域独立维护结果身份与最新水位；前后工位可以同页/分页面显示，但不暗示属于同一产品。跨工位产品追溯不在本次范围。

当前全局单作用域/单图限制在后端及客户端验证后再放开，准备校验、采集计划、图像导出槽、预算、UI能力提示和测试同步更新。不能只删 PageCommands.bind 或 checkLocalDraft 的条件。相同来源跨页复用，不按控件重复编码；一个来源失败不把其他作用域的旧值拼成完整新结果。

原始算法图像保持不变。先记录需要的来源数、原图尺寸与通道，再决定预览分辨率、格式、缩放映射及总额度；大图可生成明确标注的预览副本，细节需求另取原图。未知帧来源仍禁止独立几何叠加，不靠相同尺寸猜测。

### 5.3 最后才扩展交付范围

P5-A 的 test_delivery / TestReleaseChannel 保持明确测试含义，不能简单去掉四算子、版本、路径、一次启动等保护后宣布通用交付。普通重复运行先由 §4 的统一任务路径证明；若替换测试宿主的一次启动策略，必须同时具备请求不确定性处理、终态/占用检查和明确的再次启动。

当同一实际工程在源码态完成正常运行和观看，再更新现有交付能力并决定冻结包工作。不先为仍然只支持示例的启动器增加另一套产品入口，不为取得测试包推送 v* 标签或发布 GitHub Release。需要修改外部打包仓时另按权限处理，不顺带改其默认分支。

## 6. 正确性、安全与兼容约束继续有效

以下不是可以为赶进度取消的门槛；原 R01—R11 和 A/B 用例中相应约束继续作为回归依据：

- 只用一个所属 Runtime 的执行与设备管理；准备/查看/导入不隐式启动。相机/PLC/机器人需明确许可与互斥，离线测试不触达生产设备。
- 输出路由前取得展示自有数据；同次图像、数值、判定关联。结果身份、开始序号和消息游标分离，晚到旧结果不能覆盖新结果；执行成功不代表产品 OK。
- 限量、非阻塞采集和显示；超额/超时明确失效，正式事件/计数不能按 UI 跳帧丢弃。任务没真正退出不得提前归还资源额度，不能用 Future.cancel 冒充强制回收。
- 连接断开、代际切换、资源过期和快照/订阅缺口可识别。旧任务没有采集的值不得伪造；冻结详情有期限和总量限制，不是长期历史数据库。
- Qt 控件只在 GUI 线程操作，数据快照一致、通知和解码有界、缓冲所有权正确；关闭观察者不误停外部任务。保护不依赖把窗口限制得不适合实际屏幕。
- 草稿、明确调试与 release 状态分开，既有运行的计数/输出语义不能静默迁移。保存/导入原子化，失败保留旧版；项目包不携带凭据、现场 DB 或可任意执行的插件脚本。

具体 wire、文件和组件格式沿用现有正式契约。必须调整已记录行为时，代码、协议兼容、测试与相应契约同次更新并说明原因；不再用主计划构造与实际实现平行的第二套接口。

## 7. 性能与稳定性：先解释实际成本，不循环追候选指标

原 1080p/5 Hz、200 ms、节拍回退≤5%、数据年龄≤500 ms 继续作为**既有回归基准**保留，旧 FAIL 不改判。它们不是已经由用户确认的全部现场 SLA，也不是入口、组件和绑定修复的统一开工门槛。实际部署承诺需要用户工程的来源数、图像规格、节拍和目标机器；没有这些数据就不自行承诺。

先分段测量采图/文件读取、算法、旧预览、新冻结、编码/磁盘、传输/解码及 GUI 提交/绘制；相同代码做相邻对照，性能测量不与 CI 压力同时跑。当前已确认旧 PreviewSnapshotWriter 与新采集并存，但不能不测就认定它是唯一瓶颈。

在现有运行配置中区分“工程调试需要的中间快照”和“运行页面需要的绑定结果”，定义旧接口何时可获取快照、未采集如何提示。保留兼容的基准组，再单独报告按需策略组；不偷偷删除旧成本后说原基准达标，也不要求每种运行方式永远做全部重复采集。

预热、正式测量、停产等待和收尾分列，记录计划/实际输入率、迟到、完整分母、每消费者应用/绘制数与数据年龄。UI 可合并过时更新，但必须报告；不靠降输入、删失败样本、换计时起点、增加无限队列或放宽超时制造通过。

保持现有预算和故障期限，直至有基于实际规格的显式变更及重新验证；预算不是永不调整的产品硬限制，更不是整个进程 RSS 上界。长期运行必须监测进程/句柄/线程/缓存，测试记录自身也要有界。Qt 组合崩溃需最小复现和针对修复，单次 CI 成功或分文件通过不代表解决。
