## 首版部署和配置

### 先运行完整工程目录

```text
ProductA/
  project.json
  models/
  calibration/
  assets/
  outputs/
```

Runtime 接受工程目录或 project.json。首次选择工程，成功加载后记住位置；以后自动加载它。无需先导入不可变版本仓，也无需先生成 ZIP。工程导出器负责声明资源收集、清单和基本包校验，不让包格式成为运行入口的前置条件。

设备参数和业务输出值沿用节点参数，发布/加载不清空，也不要求外部 --site。声明的资源绑定用工程目录解析，已配置文件参数统一由算子 schema 的 file 元数据解析，禁止以扫描任意字符串猜路径。

- 相对输入和输出都以工程根目录为基准，不依赖 CWD 或 EXE 目录；绝对路径保留显式含义。
- 输入必须存在，输出不能覆盖 Runtime 的数据库、工程配置和输入资源；复用既有 SQLite 目标保护。
- 实际文件写入失败直接报告，不静默改存兜底目录。日志和 Runtime 内部数据沿用现有独立数据目录，不覆盖工程业务输出。
- 准备本次运行时冻结流程和参数。运行中磁盘文件编辑不热改当前会话，停止后重新加载才生效。
- 私有工程不上传公共仓库或 Release；日志不输出敏感凭据。出现凭据管理需求时再确定具体方式，不在首版新建安全框架。

### 最小生产配置

已增量支持 project.json 2.3 的 production 配置，保持 2.1/2.2 可读取。旧工程单次运行不自动升级；新增策略需显式保存。新字段只包括：

| 字段 | 含义和默认值 |
| --- | --- |
| autoStart | 加载成功后自动开始，默认 false |
| mode | single 或 continuous，默认 single |
| cycleIntervalMs | 连续周期的最小间隔，默认 100 毫秒 |
| inputs | 入口工作流输入，默认空对象 |

设备、输出、页面和模型不复制到 production。生产设置的配置入口可以先提供工程配置脚本，Designer 保存必须保留这些字段。2.3 的迁移、严格模型及旧工程序列化一起回归，不丢失未知字段后继续运行。

兼容以工程格式、所需算子和组件为依据。应用构建版本记录到证据，不把全应用版本精确相等作为通用工程运行条件；不实现未经验证的智能版本范围推导。

## 最小运行架构

一个运行端程序拥有 RuntimeService、操作员窗口和本次检测会话，检测仍在既有 spawn worker 中执行。只要不导入 Designer 编辑模块，就实现了 Runtime 独立；不强制额外创建 UI 进程或后台常驻服务。

优先复用现有回环 gRPC 的展示通道，不为了删进程而重写 DisplaySession。连接只监听 127.0.0.1，本批不提供远程控制，也不声称防御本机用户主动篡改。GUI 的开始/停止直接交给所属运行控制器，不新增鉴权与角色体系。

关闭主窗口默认停止并退出。停机有后台操作，GUI 不阻塞；停机失败显示错误并保留窗口。显示重连、切页或冻结不创建任务。保留旧 --runtime/--operator-view 的测试语义，为正式运行端提供新的明确入口。

### 连续执行

1. 一次开始创建一个 Job/worker。编译一次，连续周期在 worker 内执行，不靠 UI 反复 Start。
2. 生命周期算子在会话内复用，结束/故障统一释放；普通单次根调用仍按现有规则释放。无状态算子保持现有调用方式，不新造通用对象池。
3. 每周期使用新 workflowRunId，结果仍由 resultKey/resultOrdinal 关联。不另设重复的产品身份系统。
4. 默认串行。采集/通信节点继续拥有触发与设备连接，宿主只控制是否进入下一周期和周期最小间隔。已有入口长期循环时不默认再包一层连续运行，配置时说明周期边界。
5. 等待下一周期可取消；运行中停止沿用 Supervisor 的取消和强制收尾机制，不把终态等同于实际进程已释放。
6. 任何算子故障终止会话，不自动重跑整条流程，尤其不自动重复 PLC 写入。没有触发与设备故障的区分沿用具体算子契约，不按错误文本吞异常。
7. NG 是业务结果，不是执行故障。页面图像、数值与判定属于同一周期；显示可以合并更新，正式输出和计数不能随 UI 跳帧丢弃。
8. 关闭不需要的旧中间预览，复用已有有界结果和事件保留。长会话产生的新增临时文件必须能够及时清理，不等到 Job 终态才回收，不删除工程声明的正式输出。

### 状态和必要保护

控制器提供工程未加载、就绪、运行、停止中、故障这几个状态；启动/加载过程通过操作 busy 状态处理，不建立多套互相映射的状态机。连续等待仍属于运行会话。

- 不同时启动两次；沿用现有请求身份和 Runtime 所有权机制。启动结果不确定时核实同一请求，不发第二次设备动作。
- 当前任务和所属资源未释放前不能换工程或再次开始。设备连接失败报错，不强制抢占其他程序设备。
- 校验集中在工程加载、开始和外部文件输入边界。内部已验证对象直接传递，不在每层重复检查同一字段，不每周期重新计算模型哈希或编译工程。
- 异常退出不补做上一周期。新启动按工程策略从新的周期开始；包含执行不确定的设备输出时明确提示人工核实，不建设通用灾难恢复框架。
- 输出不能覆盖工程、模型或 Runtime 数据库；缺资源、磁盘写失败和设备故障必须可见，不能伪装为 OK/NG。

新增测试先覆盖改动接点，再运行相关 Runtime、项目、页面与 Designer 回归及 ci_check。基线失败与新增回归分开记录，PASS/FAIL/SKIP/NOT_RUN 不混用。离屏测试、合成工程、实际工程、冻结包和设备验收分别说明。

## 不扩大的首版范围

不把维护角色、RPC 鉴权、通用加密、签名验证、多实例发现、多版本数据库迁移、任意设备安全复位或固定 8/24 小时门禁作为首个可用版本的开发前置条件。必要边界是进程/设备资源正确释放、结果一致、错误可见、输出不破坏输入和运行数据。

不能用缩小测试负载覆盖既有性能失败，也不能以短测通过宣布长期生产可靠。先交付可运行闭环，再按实际工况验证；保留已有失败证据，不为减少防御性编程降低结果正确性或数据保护要求。
