## 1 目标与阶段边界

先让用户在 Designer 中选中一个算子，指定输入、修改参数、执行一次并查看结果；随后在相同 Runtime 执行语义之上，增加整条流程的断点和执行控制。

核心原则：两阶段复用节点执行逻辑、类型化数据、结果检查界面和资源管理规则，但单算子调试不是缩小版工作流调度器。第一阶段不通过反复运行流程前缀来模拟单步，也不提前实现完整断点系统。

| 能力 | A 阶段：单算子调试 | B 阶段：流程调试器 |
| --- | --- | --- |
| 执行范围 | 一次请求只执行选中的一个 operator 节点 | 保留完整流程执行现场并按正常路径推进 |
| 输入来源 | 显式指定数据、可用的历史完整数据或前次调试输出 | 当前调用实际收到的上游数据 |
| 上下游 | 不自动执行，不自动传播结果 | 按现有拓扑、分支和调用规则执行与传播 |
| 状态 | 单算子调试会话状态，可重置 | 当前 Job、调用栈、循环轮次及算子状态 |
| 参数修改 | 当前编辑值用于下一次执行，不自动应用或保存 | 首版固定启动快照，修改后重启调试 |
| 执行控制 | 执行一次、取消、重置、结束调试 | 断点、继续、暂停、进入、跳过、跳出、停止 |
| 系统节点 | workflow_input、workflow_output、subflow、loop 不支持孤立单算子执行 | 按流程语义参与调度 |

A 阶段不包含流程暂停、断点、自动补跑上游、任意节点跳转、失败自动重试或全算子无条件开放。B 阶段不包含反向执行、进程崩溃后续跑、持久化检查点恢复或多流程协调暂停。

## 3 A 阶段用户体验

### 3.1 入口和工作闭环

1. 选中普通算子，通过节点上下文菜单或统一 QAction 打开“算子调试”。参数编辑器中提供同一入口，不另做一套参数表单。
2. 在输入区逐端口选择来源；无输入算子直接显示可执行状态，有必需输入缺失时显示具体端口。
3. 修改当前参数，点击“单步执行”；Runtime 校验并执行当前算子一次。
4. 查看各端口输出、图片、结构化数据、耗时、日志和错误。失败时仍保留可用诊断。
5. 固定输入后反复改参数执行。需要新图片时显式更换输入，不隐式刷新历史来源或采集新帧。
6. “应用”才更新 Designer 草稿，“保存工程”才落盘；单步执行不改变工程 dirty 状态和撤销栈。

不要求先完成整条流程的有效连线，也不要求无关节点配置正确。校验覆盖选中节点、所用端口、绑定、变量定义和资源，不编译无关流程来阻断孤立算子调试。

### 3.2 输入与输出

| 输入类型 | 首版入口 | 校验要求 |
| --- | --- | --- |
| integer、number、boolean、string | 类型对应的输入控件 | 区分 bool 和 integer，拒绝非有限数字和非法隐式转换 |
| 图像 | 本地文件上传、已有完整图像资源、前次调试图像 | 校验编码、解码后尺寸/字节数、dtype、通道和资源所有权 |
| 列表、几何、检测结果等结构化值 | 可用完整结果导入及 schema 驱动的结构化查看/编辑 | 校验端口语义和 schemaVersion；JSON 仅作为高级入口 |
| 可选/可空端口 | 未提供、显式空值、实际值分开表示 | 不把缺失自动转成 null、0、false 或空对象 |
| 图像伴随 frame 等数据 | 同一来源批次成组选择 | 检查尺寸、坐标空间及来源一致性，禁止默默拼接不同帧 |

- 输入冻结到一次执行记录，参数同样冻结；在执行途中编辑面板只影响下一次请求。
- 上游完整数据不存在、已过期或只有摘要时，显示“不可用”和原因，允许用户另选来源，不自动运行上游。
- 来自历史运行的数据标明 Job、workflowRun、nodeRun、轮次、端口及时间；不同修订的数据只能作为用户明确选择的测试数据，不冒充当前输入。
- 选择来源后取得资源引用/租约，或复制到本次调试的有界存储；不能因为历史淘汰导致执行中读到其他数据。
- 固定输入保持不可变；即使算子原地修改数组，下一次执行仍使用原输入，必要时在调用边界复制。
- 输出列表覆盖所有实际输出端口，结构化值可以分页查看；缩略图与摘要不能替代执行所需的完整原值。
- 调试结果不自动路由到画布下游，不覆盖正式 Job 的结果；只有显式选择才能把某次调试输出作为下一次输入。

### 3.3 状态和交互

会话有就绪、运行中、取消中、关闭中、已关闭、故障等状态；每次执行另有成功、失败、已取消、超时、结果不确定等结果。业务结果和资源是否释放分开报告。

- 同一会话最多一个执行请求在途，执行时禁用重复触发；重置、换节点和关闭等待取消及资源清理完成。
- 固定输入下支持查看最近一次与前一次结果；界面必须标出各自参数版本，不把旧成功图像放在本次失败标题下。
- 输入、参数或节点版本变更后，已有结果仍可查看，但显示“结果对应旧配置”。
- 节点删除、工作流切换、工程切换、Runtime 重连后，使用会话身份和 UI 绑定代次拒绝迟到回调。
- 仅在流程设计工作区启用；页设计和操作员 Runtime 不增加调试入口。保留 F5/F6 等现有快捷键，新的键位在 A0 核对后确定。
- 按钮复用现有图标系统和 tooltip，窄窗口可溢出到菜单。普通输入不要求用户手写工程 JSON。

## 4 A 阶段 Runtime 设计

### 4.1 公共执行逻辑与调试会话

保留现有 operator 协议。将正式 Runner 与调试入口真正重复的参数解析、节点调用、输出校验、日志和生命周期辅助逻辑提取为最小公共模块；正式 Runner 仍负责拓扑、分支跳过、子流程、循环和路由。

采用 Runtime 托管的单算子调试会话，在受监督的执行进程内调用公共逻辑。进程启停、取消、心跳、资源退休优先复用既有监管组件，不另建工作流调度器，不在 Qt 或 gRPC 服务线程里直接执行插件。

调试会话具有独立身份、工作目录和结果命名空间；不调用 LoadProject 替换正式 loadedDocument，不伪装成普通生产运行。若内部复用 Job 记录或监管 handle，必须带明确的调试用途并从正式运行列表、页面订阅及业务统计中隔离。

不通过构造虚假的前后置节点、临时完整工程或额外 StartJob 来绕过输入与资源约束。提取公共逻辑前后，必须比较同一算子的正式执行与调试执行结果、错误和生命周期顺序。

### 4.2 协议与执行记录

新增通用单算子调试协议，与旧 pure/live/PLC 预览接口并存。以下是拟定职责，消息和 RPC 的最终命名在 A0 冻结，不表示接口已经存在。

| 接口职责 | 最小内容 |
| --- | --- |
| 查询能力 | 协议版本、可调试算子及端口类型、资源/副作用限制、容量 |
| 打开会话 | 当前草稿、project/workflow/node/operator 身份、参数上下文、资源根引用 |
| 准备输入 | 内联小型类型化值或完整资产引用、端口映射、来源身份 |
| 执行一次 | sessionId、会话代次、requestId、冻结输入和参数 |
| 查询/订阅 | 请求接收状态、执行状态、结果引用、日志及稳定事件序号 |
| 取消/重置/续租/关闭 | 明确目标会话及执行，幂等处理，返回真实清理状态 |

执行记录至少包含 runtimeInstanceId、sessionId、executionId、requestId、节点身份、算子版本、草稿内容摘要、冻结参数及有效绑定来源、输入来源、结果、耗时和错误。已有来源的 Job/调用/轮次字段保留；孤立执行不存在的流程调用字段保持空值。

- 使用独立调试内容摘要识别未保存编辑，不修改工程 revision 或 timestamp。
- 参数来源沿用正式运行的优先级；变量绑定与输出映射的值来自已选择的调试数据。无法解析时列出缺失来源，不静默用参数默认值覆盖绑定。
- 原始参数和最终有效参数都能检查，日志对凭据等敏感字段沿用脱敏规则。
- 不传 Python pickle 或任意可执行对象。大图和大 payload 走有界资产接口，不塞入 unary RPC。
- 兼容现有 1 MiB 入站限制；包含草稿、参数和内联值的应用层预算先按 768 KiB 处理。超限明确拒绝，不在本阶段顺手放大全局 RPC 配额。
- 旧 Runtime 不支持新能力时明确提示更新，不静默退回保存工程、运行整流程或 Designer 本地执行。

### 4.3 幂等、取消与释放

- requestId 在会话内去重。同 ID、同请求内容返回已接收状态或已有结果；同 ID、不同内容返回冲突，不再次执行。
- RPC 超时或断线先查询原请求，不生成新 ID 自动重发。Runtime 重启或确认信息丢失时报告结果不确定，不承诺外部设备 exactly-once。
- 结果内容淘汰后仍在会话有效期内保留有界去重信息；过期请求返回已过期，不以清理结果为理由重新执行。初始每会话最多接收 4096 个执行请求，达到上限后要求结束并新建会话，不在同一会话中删除去重身份后重新接收旧请求。
- 取消优先使用现有协作式 token；取消、期限和强制终止分层处理。Python Future 超时不等于插件停止。
- 未按期限退出时由监督进程终止并 join；确认进程/设备资源退休后才归还额度和允许新会话。失败清理保留诊断，不显示“已释放”。
- 结束、重置、异常、客户端断连后租约到期、工程关闭和 Runtime 关闭都进入同一清理路径，避免遗漏 dispose。
- 外部写操作已返回回执后再取消，仍保留回执；取消不撤销文件、数据库或设备写入。

初始容量与期限作为 A0 的验证起点：每个 Runtime 最多一个通用调试会话，每会话一个在途执行；租约 60 秒、20 秒续租；单次执行默认 30 秒，按算子能力显式配置，实机写入不自动延长并重试；协作取消宽限 3 秒后进入受监督清理。租约维护不能依赖正在等待执行 RPC 的同一客户端线程。

数据缓存按会话限制为 256 MiB 和最近 32 次结果两者先到者；模型、设备 SDK 及执行临时内存另行测量，不宣称缓存预算等于总内存上限。当前输入与在途资产不可淘汰，预算不足拒绝新的准备/执行；输出超额保留明确的结果保留失败状态，不截断执行值后冒充完整成功。阈值调整需更新本计划及测试，不能取消有界限制。

### 4.4 算子支持与副作用策略

首版按已审查能力开放，不依据 operatorId 的名称猜测安全性，也不因 executeNode 存在就允许调试。能力声明缺失的第三方算子默认不开放通用调试；旧插件的普通运行和注册不受影响。能力元数据、manifest 校验与 Python 元数据一致性同时回归。

| 类别 | A 阶段策略 | 必须证明的行为 |
| --- | --- | --- |
| 图像、数值、集合、几何等纯计算 | 优先完整支持 | 相同完整输入与参数下，与正式执行输出一致 |
| 图像加载、批量图像、模型推理等资源/状态算子 | 经审查后支持，会话明确管理生命周期 | 模型复用、批量位置、重置及参数变化后的重新初始化可见 |
| 变量读写、全局计数 | 使用独立调试存储 | 不改变生产持久值、Job 值、定义或计数 |
| 相机、PLC 读取等设备算子 | 经资源和取消验证后接入；保留现有专用入口 | 调用前明确会占用真实设备，读操作也不能绕过资源准入 |
| PLC 写入、TCP 发送、文件/数据库写入 | 默认阻止外部写；仅开放已审查的明确执行路径 | 显式实机确认或用户选择的临时输出目标，记录回执/不确定结果，无自动重放 |
| 未支持端口/插件、系统控制节点 | 禁用并展示原因 | 不通过静默降级或自动跑流程冒充支持 |

设备和文件操作的准入必须发生在可能产生副作用的构造/初始化之前。确认内容绑定节点、参数、目标与本次请求；改变目标或参数使旧确认失效。不能悄悄把用户的正式输出路径改为临时目录后仍显示原路径。

调试变量默认从草稿初始值建立隔离存储；需要使用生产当前值时只能显式读取并复制快照，之后不跟随生产变化、不写回。保持原 projectId 等业务身份，用存储实例/命名空间隔离持久状态。

正式 Job、旧 live/PLC 调试与通用调试使用统一的资源准入检查。A 阶段采取保守互斥：还有普通 Job 或设备预览持有资源时不启动通用调试；还有通用调试持有资源时不启动正式 Job。检查和占用原子完成，不自动停止既有任务，不修改普通 Job 之间已有的并发配置。

资源路径以 Runtime 侧已确认的工程资源根解析，不依赖 Designer 的 CWD；新工程尚无有效资源根时，仅依赖相对文件资源的算子提示补充资源根，其余纯计算仍可调试。远程 Runtime 不假定能访问 Designer 本机路径，图像等按协议上传，模型和设备配置按既有资源规则校验。

这些限制是受信任插件的调试安全策略，不是第三方 Python 代码沙箱。实际设备和外部写入的验收必须单列，模拟设备通过不等于实机安全通过。

## 7 B 阶段流程调试器设计

### 7.1 执行方式和单步语义

在现有 WorkflowRunner 的安全节点边界增加协作式调试控制，使用同一 Worker 保留调用栈、中间值和生命周期算子实例。暂停时只等待执行许可，心跳、取消、状态查询和会话租约继续运行；不使用操作系统级进程挂起来代替调试暂停。

调试开始先冻结当前完整流程草稿并执行正常编译校验，然后停在第一个用户可执行节点之前。系统输入/输出边界自动处理并产生正常事件；仅作连线传播的内部步骤不消耗用户“下一步”。

| 操作 | 行为 |
| --- | --- |
| 继续 | 沿实际路径运行到下一个断点或结束 |
| 暂停 | 请求在下一个安全边界暂停；算子未返回时显示“正在暂停” |
| 单步进入 | 普通算子执行一次；遇子流程/循环进入其当前实际调用中的首个可执行节点 |
| 单步跳过 | 完成当前层节点后暂停；子调用内部断点仍可打断，长循环仍可请求暂停或停止 |
| 单步跳出 | 当前调用返回后停在调用方边界；内部断点仍生效 |
| 运行到此处 | 设置本次调试的临时断点，沿正常路径到达；目标分支未选中则不会命中 |
| 停止 | 取消并释放本次调试，不保留一个可继续的已终止进程 |

While 的条件求值、循环体入口、迭代结束应有可观察位置；支持现有布尔、全局变量和条件工作流模式。无限循环的“跳过”不保证自然返回，界面始终允许暂停请求和停止。失败首版保存故障位置和数据后终止本次执行，不提供可能重复副作用的“直接继续失败节点”。

### 7.2 调试身份和状态

- 断点绑定草稿中的 workflowId/nodeId，实际暂停位置绑定 jobId、workflowRunId、nodeRunId、callPath 和 iterationPath。
- 当前节点尚未执行时显示待执行输入/参数；已完成输出来自明确的调用身份，不拿上一轮节点输出填充本次结果。
- 暂停状态由 Worker 在检查点确认后发布，Designer 点击暂停不是已暂停的证据。Job 生命周期和调试运行状态分层表达，避免把暂停误判成终态。
- 单步命令携带 requestId、调试会话代次和 pauseSequence；重复命令幂等，旧暂停位置的命令拒绝，连续双击不能多走一步。
- 暂停不自动释放生命周期设备，也不自动重新初始化；释放后恢复可能改变现场，第一版不提供透明重连后续跑。
- 调试等待时长从工作流/循环的执行时间预算中扣除，覆盖嵌套调用；设备通信期限、心跳、资源租约和安全看门狗仍按真实时间推进。
- 首版固定启动配置。编辑草稿不热改当前运行；修改后重新启动调试，并清楚区分画布草稿和当前执行快照。

### 7.3 复用 A 阶段与范围限制

复用 A 阶段的节点调用、类型化输入输出、资产租约、结果查看、隔离变量和副作用准入。流程调试会话管理的是执行许可和调用位置，不复制节点算法。

从暂停节点打开单算子试运行作为后续增强：使用输入副本和独立实例，不改动暂停流程的输出、变量或内部状态。有状态/设备算子若无法安全克隆或资源正被占用，应拒绝独立试跑，不能借用活实例“试一下”再假装现场未变。

首版只调试一个根流程及其子调用，不加入多流程协调暂停，不改变正常模式已有的多 Job 运行。不同 Job、真实设备和外部状态不会因本次暂停而冻结。条件断点、命中次数列为 B2 增强；暂停时受控改参留在 B3 独立评估，不混入 B1 基本控制。

| 批次 | 内容 | 出口 | 状态 |

## 8 交付和证据规则

实施期间沿用本计划更新批次状态，不将计划中的能力写成已经存在。源码修改、协议生成、测试和文档按 A0-A5 分批组织；A 阶段验收前不扩展 B 阶段实现。

- 每批记录实际分支、HEAD、相关 dirty 文件哈希、解释器/依赖版本、命令及原始输出。
- 证据分列 PASS、FAIL、SKIP、UNSUPPORTED、NOT_RUN；用户界面、真实 spawn、回环 gRPC、实机和冻结包分别验收。
- 当前有大量并行修改，实施时只改必要接点；同文件既有变更需读懂并保留，不重置、不大范围格式化、不顺带修无关失败。
- 测试使用临时文件、临时数据库、模拟设备和明确的输入夹具；没有额外授权不连接生产设备或向真实目标发送数据。
- 提交推送、修改外部打包仓库、触发构建、发布和部署不包含在“编写计划”中，后续分别按用户授权执行。
