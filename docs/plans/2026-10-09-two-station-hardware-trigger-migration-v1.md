## 1 原工程路径与迁移映射

两个工位具有相同的两拍控制骨架，但几何算法、固定坐标引入位置和后续计算不完全相同。四条业务路径分别保留；只复用经确认语义一致的通用算子或子工作流。

截图用于确认可见节点和执行顺序，不据此认定每条红线就是数据线。新工程同时列出控制依赖和有类型的数据来源。工位 2 左路被裁切，缺失编号和不可见配置不得推测补齐。

### 1.1 共用拍次规则

| 阶段 | 正常处理 | 输出 | 拍照计数 |
| --- | --- | --- | --- |
| 等待第一拍 | 等待外部硬件触发，尚未接收有效帧 | 无 | 0 |
| 第一拍 | 一张有效图像进入一次接收处理链，两路 YOLO 使用这张图及各自预处理结果 | 矫正结果发给 PLC 网关输入通道 | 原子自增输出 1，保持 1 |
| 第二拍 | 接收新图，确定第二拍分支，先归零再执行孔位处理 | 孔位结果发给机器人网关输入通道 | 原子自增输出 2，随后恢复 0 |
| 下一轮 | 下一张有效图重新进入第一拍 | 无 | 从 0 开始 |

计数不绑定 YOLO 调用次数或结果发送成功。第二拍归零不等待 YOLO、网关 ACK 或机器人动作；当前帧仍使用已输出的整数 2。第一拍只计一次，不因两路识别多计一次。

正常单目标基准为两张图、三次 YOLO 调用、一次 PLC 坐标报文、一次机器人坐标报文。单目标是首版离线夹具的明确假设；现场若有多目标或多孔，须先确定选择、配对和发送数量，不能静默选第一项或自行增加设备动作。

## 3 全局变量与每帧执行契约

### 3.1 变量定义

| 变量示例 | 类型 | 初始值 | 生命周期 | 正常写入者 |
| --- | --- | --- | --- | --- |
| 工位 1 拍照计数 | integer | 0 | job | 工位 1 生产 Job |
| 工位 2 拍照计数 | integer | 0 | job | 工位 2 生产 Job |

使用变量稳定 ID，显示名可改。一个连续 Job 的后续调用和子工作流共享值，不每帧初始化。两个 Job 的值按 jobId 隔离；另起调试 Job 不能复位生产 Job。变量窗口按工位绑定正确 Job，不展示另一 Job 中同名定义的初始值冒充当前计数。

正常生产不允许人工同时改写该工位拍次。实现时为生产工位的计数编辑加入停机校验，不全局取消其他变量的正常管理能力。生产累计数如需增加另建变量，不与两拍计数混用。本帧 n 是数据线上的值，不增设“本图拍次”全局变量。

### 3.2 写变量算子的静态接口

扩展现有 vision.state.variable_write，不另建计数服务。

| operation | 正式输入 | 参数 | 正式输出 |
| --- | --- | --- | --- |
| set，默认 | value，变量同类型，必填 | variableId | 写入后的同类型 value |
| increment | after，通用非空依赖，必填 | variableId、整数 delta，默认 1 | 原子提交后的 integer value |
| reset | after，通用非空依赖，必填 | variableId | 恢复初始值后的同类型 value |

after 只建立执行依赖，不写入变量；值为整数 0 仍是有效依赖。increment 仅允许整数变量和整数增量。reset 恢复变量定义的初始值，不把所有变量强制置零。旧 set 不新增必填依赖，不要求旧工程修改接线。

variableId 和 operation 决定接口，必须是编译时固定配置，禁止运行时全局变量等动态来源改变。delta 可按整数类型绑定，但不得改变接口；布尔值、浮点数和溢出必须拒绝。调用现有事务内 increment，不用先读后写模拟原子操作。

同时更新 manifest、Python 元数据、variablePorts、编译器、Designer 端口派生、编辑器和保存重载。新增模式缺 after、端口接错或绑定结构字段时明确报错；切换模式不得悄悄删线后宣称可运行。旧节点打开编辑器不自动变脏，应用配置才保存新模式。

M1 必须解决 int64 Schema 与 Qt 控件不兼容的问题。参数合法范围、控件输入和后端校验一致；复用合适的整数编辑能力，不静默截断大值，也不为迁就控件缩窄既有状态服务的 int64 契约。所有模式保持常量保护和只读预览保护。

### 3.3 正常每帧链路

~~~text
等待外部硬件触发
    → 接收有效 image / frame
    → 本帧 PLC 读取子工作流
    → 原子自增，输出本帧 n
    → Switch
        n=1：本工位第一拍算法 → 正常 PLC 报文 → TCP exchange → ACK 校验
        n=2：复位全局计数 → 本工位第二拍算法 → 正常机器人报文 → TCP exchange → ACK 校验
    → 本帧调用结束，等待下一张新图
~~~

PLC 读取子工作流通过必填 image/frame 输入在图像到达后才被调用，内部使用现有无输入的读取算子。读取结果经显式输出建立计数的 after 依赖，并作为本帧采样数据传给所需消费者；不能只创建一个未被下游使用的孤立读取节点。若最终采用通用 after 扩展，必须证明与该子流程边界等效且不破坏旧读取行为。

该顺序是保留截图顺序的暂定正常采样契约，不宣称已知道 PLC 值的业务用途。若读取失败，有效曝光可能已发生，但当前正常调用必须终止并要求重新同步，不得因计数未推进而继续把下一物理帧猜成第一拍。

Switch 使用 increment 输出的 n，不重新读取全局计数。复位的 after 必须来自第二拍分支；第二拍实际处理还必须依赖复位完成，只有公共 image 输入不能放行非选中分支。复位后全局值为 0、本帧 n 为 2，是明确的正常语义。

第一拍两路可以使用同一原始帧的不同掩码或裁剪结果，但不得各自取图，不能修改共享原图污染另一支。第二拍必须是新帧。重算、回放和重发不重新进入拍照自增路径。n 不在 1、2 时，由工程内明确的技术错误路径停止，不只向演示脚本输出一个标志。

### 3.4 数据来源与类型

下表是数据职责，不新增保存拍次的大对象或旁路状态库。实际使用现有强类型端口与 RunContext 传递。

| 数据 | 来源与消费者 | 一致性要求 |
| --- | --- | --- |
| image、frame | 相机到预处理、YOLO、测量 | 一次调用同源；局部处理保持相应 frame，不混用另一帧 |

### 3.5 技术故障与启动同步

技术故障停止对应工位，不自动重跑已发生的设备输出。第二拍复位之后处理失败，也不回滚计数或复用旧图。业务 NG 的具体处置仍不在本阶段实现。

启动前依次确认旧 Job 和资源已释放、设备处于新周期起点、相机缓存归属明确、模型和固定坐标配置已就绪，之后才允许生产取帧。新 Job 的初始 0 不是物理第一拍的证据。操作员或设备流程承担周期同步，程序执行准入校验；自动启动不能绕过它。清缓存或设备周期复位必须是显式操作，不自动猜测。

## 4 相机等待与采样时序

新增显式“有界等待”和“等待硬件触发”策略，默认保持现有有界行为；预览和单次调试默认有界。硬件等待复用约 100 ms SDK 取帧时间片和取消检查，正常无帧超时继续等待，真实 SDK 错误、断连或无效帧仍报错。

等待期间不自增、不轮询执行本帧 PLC 读取、不反复建连。状态只在变化时展示，Stop 要确认 worker 和设备资源实际释放。首版迁移配置禁用会打乱帧序的自动重连，不改变其他旧工程默认配置。

一个工位内部串行处理，一次调用结束后才进入下一次取帧。M2 必须验证推理或通信未结束时后续硬件帧进入 SDK 的实际缓存路径、FIFO 次序、容量与溢出表现；不得采用 latest-only 丢帧。可识别的重复、缺帧或采样归属不确定时停机同步。

帧号检查只在同一相机会话内有效；验证相机是否确实提供可用帧号，不把重连后的编号当全局单调值。读取 PLC 的结果不能因为排队延迟而默认为曝光时刻值；需要曝光锁存或设备握手时，列入现场采样契约，不能靠软件时间戳伪造同步。

## 5 正常视觉链和坐标契约

### 5.1 YOLO 到测量图像

每路分别确定 YOLO 后测量的是原图、掩码图还是检测区域裁剪图，保留旧节点执行顺序。没有依据时不自动插入裁剪，也不删去旧掩码。

按检测区域测量时，明确接线为：检测集合 → 按类别和规则筛选/排序/选择 → 提取 bbox 或所需几何对象 → 原始测量图像及匹配 frame 的 Crop/ROI → 二值化 → 轮廓 → 几何测量。检测结果不直接当 image，带框和文字的 overlay 仅用于展示。

复用现有集合处理算子，但选中检测集合仍不是 Crop 所需的 bbox。缺失的检测对象到几何对象转换必须补为通用能力，定义输入集合、输出类型和数量。后续取点也保留独立职责。

### 5.2 几何测量和取点

- 增加轮廓到最小外接圆的通用能力，输出符合现有几何契约的圆、圆心和半径；优先复用 circleCollection/circle2d 等现有类型，若需扩展类型则同步版本和消费者。
- 验证边界点、非圆轮廓和多轮廓。Hough 圆、最小外接圆、轮廓质心和最小外接矩形中心不能相互替代。
- 通用取点覆盖圆心、指定矩形特征和经确认的其他测量字段。工位 2 的“外接矩形”先确认具体定义，不按名称猜测为 minAreaRect。
- 工位 1 的 Blob 内心在明确算法定义后复用或补通用实现。未确认前保留算法接口和待办，不能用质心实现并标注为等价。
- 零目标等业务 NG 分支暂缓；不为绕过正常输入契约伪造 (0,0)。算子现有的输入和结果校验继续有效。

### 5.3 坐标相加和业务公式

“图像坐标拼接”按分量相加实现，不作图像拼接或列表拼接。每个拼接节点声明相加项的含义、数量和坐标空间；严格配对和单点广播是明确配置，不通过数组偶然顺序配对。点、位移向量与标量之间不得靠修改类型标签接通。

“图像坐标计算”的具体表达式独立确认。两路结果汇合不默认是求和，文本固定坐标引入不默认是加法或减法；原表达式可能需要的角度、差值和标量转换应落实到算子和端口，缺失能力列入 M3，不留到现场临时改脚本。

ROI 回源与手工补偏移只能对同一偏移执行一次。例如原点 (100,200)、局部圆心 (10,20)，纯平移后的结果为 (110,220)；不能回源后再加原点得到 (210,420)。为每条路线选择一种明确表达，并说明旧“拼接”节点由哪一步实现，禁止伪造 sourceId 绕过检查。

区分像素、参考坐标和设备单位。两次 2D 转换保留顺序和各自参数；只有获得原公式并验证等价后才可合并。最终数值有限性、精度和舍入在报文格式化边界校验。

### 5.4 固定文本坐标

定点标定在本工程中仅指读取文本固定坐标，不建设九点标定或相机标定。沿用资源与工程根目录解析，文件路径不通过普通全局变量绑定绕过保护。

本工程在运行准入时冻结各工位坐标文件的内容、解析参数和哈希，通过工程机制向相应旧节点提供同一版本。可以采用显式会话级读取选项或既有资源快照扩展，但不能只在演示驱动脚本里读取一次。Coordinate Reader 的旧默认行为保持不变。

文件内容在同一路径被修改时，当前会话不混入新值；停止、显式重新加载并校验后才生效。缺文件、错误编码或非法坐标在正常输出前拒绝。frame 端口只声明空间，不会把毫米自动转换为像素；设备单位文本不得贴上图像空间标签冒充转换。

### 6.1 历史协议依据

gateway.log 的记录区间为 2026-08-04 12:15:07.624 至 16:31:09.236，共 14728 行，SHA256 为 5188f2177600505188ca9187e13781c2623cf5b93f7fb0da316d6884cfd94f56。保留必要脱敏协议夹具，不复制整份现场日志或上传现场工程资料。

| 输入通道 | front 端口 | back 端口 | 已确认正常输入 |
| --- | --- | --- | --- |
| robot-input | 10001 | 10002 | "20.38,-5.80"，实际包含双引号 |
| plc-input | 10003 | 10004 | "2399,4509"、"-6,2206"，实际包含双引号 |

双引号字节为 0x22。正常输入样例没有换行，网关 ACK 以换行结束。10000 是机器人连接网关的监听端口，不作为视觉输入端口。工位 1/2 与 front/back 的映射尚未确认，历史端口不代表当前现场已配置。

历史正常机器人报文 1113 次、PLC 报文 1118 次；14 次未加引号的 PLC 8888.0/8888,0 被拒绝，不能作为有效协议。另有 19 次机器人 NG 样例 '0,0EN'，引号为 0x27；该信息仅保留为后续协议依据，本阶段不实现或验收 NG 分支。EX 和 PLC NG 不推测格式。

### 6.2 正常报文和 ACK

工程中显式表达“最终坐标 → 正常报文生成 → TCP exchange → ACK 校验”，不把格式化或成功判断藏在演示驱动中。

- 机器人正常坐标按两位小数、双引号生成，不自行追加网关负责的 EY 后缀。
- PLC 正常坐标按已声明的整数舍入规则生成双引号报文，Y 保留在输入报文中。
- 历史网关将 X 绝对值写 D6、正负标记写 D7（1/2）；没有依据新增 Y 写入。PLC 状态读取占位地址与结果写入地址分开。
- ACK 不只匹配 OK 前缀，还要按当前通道校验可核对的回显或写入值，例如 `OK '20.38,-5.80EY'` 或 `OK D7=2 D6=6`，随后是一个 LF（0x0A），不是反斜杠加字母 n 的文本。ACK 分包和尾部换行由传输分帧处理。
- 网关 OK 仅表示该协议层接受或完成对应操作，不等同于机器人完成动作。FAIL、错通道响应或内容不匹配不能继续按成功处理。

正式发送前确定每路目标数量及稳定顺序。历史正常输入只证明一条坐标对的格式，不证明网关支持坐标数组；多孔时不得自行假设批量报文或逐点动作协议。离线单目标基准不代替这项现场确认。

### 6.3 连接和执行不确定性

TCP 保留单次事务默认行为。确有连接复用需要时增加显式会话模式，按节点生命周期持有，一个连接只有一个在途请求，停止或故障时释放。变更端点或配置需要重新准入，不热切换在途请求。

发送后 ACK 超时归类为执行结果不确定，不自动重发，不回滚设备动作。协议没有事务 ID 和去重凭据，不承诺 exactly-once；重建连接仅用于确认可开始的新事务，不补做上一笔不确定发送。

## 7 双工位生产与展示

最终目标是一个工程保留两个工位入口及四条业务算法路径，每工位一个连续 Job，内部串行、工位间独立。M5 已实现生产端多入口编排，并用实际 spawned worker 验证能力夹具的正常两拍链路；四条旧业务算法仍受 U01～U05 的等价门槛约束，不因编排通过而标完整迁移完成。

### 7.1 入口和工程兼容

工程通过可选的 production.stations 字典声明工位稳定 ID、名称、入口、启用状态、归属页面、入口输入及受保护的 Job 变量，最多两个工位。相机、PLC、模型及网关参数仍保留在原算子配置真源，不新增全局 SiteConfig 或复制一份设备配置。

M5 使用现有工程 2.4 的可选扩展，不增加 2.5。非空工位声明要求明确迁移至 2.4；空 stations 不序列化，旧工程不因打开/取消配置表单自动升级或变脏。已检查加载、校验、序列化、通用导出、正常采集快照和修订身份，未知字段仍明确报错。Designer 的“运行 → 生产工位配置…”在显式保存表单后才应用声明，工程文件仍按原保存机制落盘。

### 7.2 展示契约

原正常展示采集及结果作用域只支持工程主入口，而且采集定义会遍历全部页面。M5 已显式扩展合法工位根入口，不靠增加 jobId 或直接删除主入口校验绕过原契约。

按工位过滤页面、数据源、作用域和采集限制，并将 Job、入口及配置修订身份关联。每个页面必须且只能归属一个工位；拒绝跨工位结果域、保护拍次来源和页面导航。没有工位声明的旧单入口采集指纹和行为保持不变。

现有展示配额最多两个保留 Job，结束但未释放的任务仍占用额度。停止重启一个工位时，需要等待它自己的 worker、展示读取和结果导出实际释放，再启动新任务；另一工位持续运行不受影响。

### 7.3 操作与配置生命周期

生产端按工位管理启动请求 ID、jobId、运行状态、停止过程和展示会话，保留现有启动幂等与结果不确定处理。支持独立及全部启停，部分启动失败显示真实结果，不重启成功工位补偿。

启动前拒绝重复占用同一相机；不得给两个工位默认同一索引 0 并宣称可运行。首版用同一静态选择命名空间的不同 IP 或 cameraKey 证明配置身份不同，拒绝动态身份、index/userId 和混用别名；这不是实际相机发现或独占检测。变量、图像和结果明确属于对应工位与 Job，变量窗口显示工位/Job；运行或资源退役期间后端和 UI 都拒绝人工 set/reset 受保护拍次，不锁无关变量。普通调试 Job 可以修改自己的隔离值，不改变生产 Job。

每次启动声明式硬件工位，UI 与 StartJob 后端都要求显式首拍同步确认，autoStart 不能绕过。production_sync_confirmed 只表示调用者确认，不证明 PLC 周期已对齐、相机缓存已清空或相机已 armed；物理同步与就绪条件仍按 U07 验证。不确定 Start 只查询原 requestId，不发第二次 Start。

声明式生产在工程加载时冻结 manifest 声明的模型/图像/TXT 输入副本与摘要，单工位普通重启复用同一加载版本；输出路径和设备地址保持原真源。每次 Start 检查内部输入副本，篡改拒绝准入。重载/离线更新采用保守边界：所有工位停止并释放后操作，不做单工位热更新。关闭程序由 Runtime 最终确认全部所属 worker 释放，即使某个 Stop RPC 失败或 Start 结果不确定。

当前生产只走 normal station capture；拒绝 prepared/debug Job 在生产 Runtime 绕过工位准入。多根工程的声明式准备快照明确拒绝并提示该边界，而不是任意选一根。M6 再补准备管线的显式根选择和坐标资源声明。

## 11 交付范围与完成标准

当前阶段交付：四条正常路径迁移记录、必要的通用算子补全、用全局变量表达的两拍工程、相机与 PLC 正常采样链、固定坐标版本机制、正常协议集成、双工位示例和分层验收记录。真实资源按既有工程资源机制收集，不把原型模拟数值作为现场配置。
