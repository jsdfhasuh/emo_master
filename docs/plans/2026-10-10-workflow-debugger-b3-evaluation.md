# 流程调试器 B3 后续能力评估

日期：2026-10-10。范围：仅评估与后续出口条件，不把下列功能混入本轮 A/B1/B2 实现，也不表示已经支持恢复或回放。

## 结论

优先考虑有界的只读执行记录导出。多流程协调暂停、反向执行、崩溃恢复和暂停中修改运行配置暂不开放。它们需要新的运行一致性契约，不能由“已经有单步和暂停”推导出安全性。

## 能力与约束

| 能力 | 结论 | 原因及后续出口 |
| --- | --- | --- |
| 多根流程协调暂停 | 延后，独立设计 | 当前正式运行允许多 Job 并发；单个 Worker 的检查点不是全 Runtime 屏障。须定义协调参与者、各自确认序号、超时和取消、已完成/失败参与者、资源仍被占用的表现，并证明既有并发生产语义不变。不能使用 OS 挂起冻结心跳和设备安全看门狗。 |
| 只读执行记录导出 | 下一阶段首选 | 可复用实际调用身份及有界数据资产，但必须有独立的磁盘/数量/保留期限预算、脱敏、摘要与完整值的区别、版本及 SHA 校验。导出不是可重放程序。应先覆盖删除/过期/中断清理和多个只读消费者。 |
| 确定性记录回放 | 延后 | 外部采集、时间、随机数、变量快照及有状态算子会产生不确定性。重放必须显式替换外部 I/O 为记录值，并拒绝再次发送、写库或写文件。不能把普通事件日志当作完整输入。 |
| 反向执行 | 不开放 | 无法逆转已经确认的设备动作、文件写入和数据库事务。纯计算流程可在未来通过已验证检查点重新计算，但应叫“从快照重新计算”，不能暗示撤销了外部世界。 |
| 持久化检查点/崩溃续跑 | 延后，需算子协议扩展 | Python 实例、模型会话和 SDK 句柄不可当作稳定格式。必须声明可恢复算子、状态版本和迁移、完整输入、控制栈、循环轮次、绑定值、变量版本与未决回执；禁止以任意 pickle 作为对外恢复接口。 |
| 暂停中受控改参 | 延后，首轮只考虑无资源纯算子 | 固定启动快照最容易复核。未来修改应绑定 pauseSequence，并校验端口、绑定和资源目标不变；只影响明确尚未执行的位置。状态算子重初始化、图结构更改、已执行节点修改均需重启。试运行结果不得自动回填暂停流程。 |
| 释放设备后透明恢复 | 不开放 | 重新打开相机、PLC 或文件可能改变现场、帧号及协议状态。应显示已失去现场并要求新调试，而不是悄悄重连后继续。 |

## 建议后续计划

1. B3a：版本化只读 trace 包，包含实际调用树、已保留完整数据及过期标记；用户显式导出，默认脱敏，不增加后台永久留存。
2. B3b：纯算子可恢复能力声明与故障注入夹具，先验证不涉及设备/写入的单根流程；旧插件默认不支持恢复。
3. B3c：基于明确状态协议再评估检查点重算与受控改参。独立测试 schema 迁移、旧暂停命令、参数类型/端口变更及变量冲突。
4. 多流程协调另开设计，不复用单根流程的 pauseSequence 作为全局完成凭据；增加真实多 Worker 屏障、部分故障和资源竞争验收。

上述建议不授权新增设备访问、外部写入、打包、发布或部署。本轮的 B3 出口是这份评估，不是实现这些延期功能。
