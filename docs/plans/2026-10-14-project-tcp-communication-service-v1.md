## 1 目标和架构结论

为需要通信的项目提供一个由 Runtime 持有的常驻 TCP 服务端。机器人等客户端连接后，可以跨工作流轮次保持连接；多个普通工作流 Job 通过同一个服务发送数据。无需通信的项目保持关闭，不监听、不等待客户端，也不产生通信故障提示。

**服务生命周期不归某个算子管理。服务是 Runtime 的项目级功能，通信算子只是工作流访问该功能的入口。** 不新增独立安装的软件，不要求 Windows 系统服务，不把平台改成专用双工位调度系统。

项目开关只控制本次新增的托管 TCP 服务，不充当所有网络功能的总开关；现有 TCP Client、TCP Receive Once 和 PLC 算子的显式执行行为保持不变。

必须保留的边界：

1. 项目是否启用、服务是否正在运行、客户端是否连接，是三个不同状态。
2. 项目配置独立保存。新项目及没有通信配置的旧项目默认关闭。
3. 启动方式独立选择“随项目开始运行”或“手动启动”；仅打开项目、打开设置、保存配置都不启动监听。
4. 服务启动后跨轮次常开。停止当前流程和“停止全部流程”不隐式关闭服务。
5. 显式“停止服务”、成功卸载或切换项目、Runtime 退出负责释放服务；不能把客户端界面失联当作服务已停止。
6. 前后工位只是逻辑通道示例，通道数量与名称可配置，不固化为两个工位、两套相机或两条工作流。
7. 现场 PLC 地址按用户确认的 **D800**；本计划不重新争论旧代码中的地址差异，不顺带修改 PLC 逻辑。

## 3 首版范围与暂缓能力

### 3.1 首版必须交付

- 每项目一个 TCP 服务端资源；一个监听端点、多个可配置逻辑通道。底层使用稳定 serviceId/channelId，不以显示名称作身份。
- 项目启用开关、两种启动方式、监听参数、允许客户端 IP 与通道的结构化映射。
- Runtime 常驻监听、客户端接入/断开/重连、共享连接管理、有界发送、明确失败与不确定结果。
- 工作流侧“取得通道会话”和“会话发送”两种通用能力，完整的端口类型、编译校验与执行来源。
- Designer 通信设置、监控 Dock、状态栏摘要；独立操作端具备同源状态与显式启停入口。
- LN5 正常报文的字节兼容夹具，以及 EN/EX 原始样本的无设备传输验证。业务判断与自动发送异常指令不在本轮增加。
- 项目保存重开、包与快照保真、真实 spawn Worker 加本机 TCP 客户端、原生界面分层验收。

### 3.2 暂缓

- 一个项目多个监听服务、共享服务跨项目使用、跨 Runtime 自动迁移、系统开机后台守护。
- TCP 接收触发拍照或流程、任意协议自动识别、完整接收算子、设备 ACK 解析与自动业务重试。
- 广播、负载均衡、未知 IP 自动分配通道、一个通道多客户端、自动踢掉旧连接。
- 手工发送控制台、生产会话的孤立单算子发送调试、从历史记录一键重发。
- TLS、设备级身份认证、互联网暴露、完整审计平台及无限报文归档。
- 改变 LN5 算法、两拍逻辑、D800 读取语义、NG/EX 业务处理策略；不修改旧工程文件。

## 4 项目配置和保存契约

### 4.1 配置结构

新增独立 `communication` 配置及项目 schema 2.5；2026-10-15 已落实显式迁移、模型、保存、包与快照支持，保留旧全局变量、页面和资源契约。

| 字段 | 语义 |
| --- | --- |
| enabled | 默认 false；是否允许此项目使用托管 TCP 服务，不等于当前运行状态 |
| startupPolicy | on_project_run 或 manual；启用后默认展示“随项目开始运行”，关闭时保留所选值 |
| tcpServer.serviceId / name | 稳定身份与可修改显示名称；首版仅一个服务 |
| bindAddress / port | Runtime 所在机器的监听地址与端口，不是 Designer 地址；安全初始地址为回环地址，现场网卡必须显式选择 |
| channels | 稳定 channelId、显示名、允许的 IPv4 地址列表；同一个地址不能归属不同通道 |
| sendTimeoutMs / maxMessageBytes | 明确单位与上下限；超时不表示设备没有收到 |
| 配额 | 连接、排队条数、排队字节数、日志条数及日志字节数均有上限；P0 阶段固定默认值并写进测试 |

默认不监听所有网卡；确需 0.0.0.0 时显示暴露范围说明。地址白名单只是路由和接入限制，不宣称为身份认证。首版 IPv4，不自行扩为主机名解析或 IPv6。

### 4.2 兼容与版本

1. 旧项目缺少通信配置时按未启用处理，打开旧工程不占用端口、不自动升级落盘。
2. 首次明确保存通信配置时进行显式迁移和备份；单纯打开设置不修改工程版本。
3. 禁用后保留配置，不降级 schema、不删除参数；重新启用须重新执行有效性校验。
4. 扫描现有所有 `2.4` 等值判断，尤其全局变量、页面、生产、快照和包校验；加入 2.5 不能使旧能力丢失。
5. 旧 Runtime 不支持新能力时明确报“不支持项目 TCP 服务”，不降级为 TcpClient，不静默忽略配置。
6. 操作端加载运行包仍按已保存配置启动；地址不属于本机网卡或端口冲突时明确失败，不自动换地址或端口。

### 4.3 草稿、已保存与当前生效

- 设置页编辑的是草稿；取消不改变已保存配置与当前连接。
- “保存配置”通过既有项目保存通道落盘，失败时保留草稿并就近提示，不能显示保存成功。尚未落盘的项目先走项目保存。
- Runtime 分开保存期望配置版本和本次服务启动的生效快照。修改监听地址、端口、通道路由、发送参数只标记“下次启动生效”，不热切断已有连接。
- 启动方式只影响后续明确的项目运行入口，保存时不触发启动或重启。
- 关闭 enabled 之前必须确认服务已停止且无未结束的服务启动操作；运行中或状态未知时拒绝关闭，并引导先停止服务/恢复连接。Runtime 再做原子校验，不能只依赖界面按钮禁用。
- 保存配置不通过一次完整 LoadProject 代替轻量同步；若 Runtime 同步失败，显示“已保存到项目，Runtime 配置尚未同步”，启动前必须完成同步校验。
- 活跃 Job 固定其启动快照；新增配置不修改正在执行的节点参数。新 Job 若依赖待生效的不同服务配置，拒绝混用并提示先停流程和重启服务。

## 5 生命周期和启动屏障

| 操作或事件 | 服务行为 | 界面与执行结果 |
| --- | --- | --- |
| 打开未启用项目 | 不创建监听 | TCP 未启用，不显示故障或等待客户端 |
| 打开启用项目 / 打开设置 / 保存配置 | 不启动 | 已启用但未启动；显示启动方式 |
| 开始正式运行，策略为随项目开始运行 | 先完成通用准入检查，再确保服务进入 LISTENING，最后派发 Worker | 监听失败则该次启动批次不进入硬件等待；错误说明地址、端口和原因 |
| 手动策略，流程使用通信但服务未启动 | 不替用户自动启动 | 在启动预检定位依赖节点，提示手动启动服务 |
| 手动策略，流程没有通信依赖 | 不额外启动或等待通信 | 非通信流程可正常运行 |
| 显式启动服务 | 从已保存、已同步配置创建监听 | 只监听，不自动启动流程或发送数据 |
| 一轮结束 / 当前 Job 结束或停止 / 停止全部流程 | 保持服务与其他客户端连接 | 停止流程不等于停止通信；被停止 Job 的发送权限撤销 |
| 显式停止服务 | 确认影响后拒绝新发送，取消排队请求，结束监听并断开客户端 | 依赖该服务的未完成节点收到明确错误；不静默停止无关流程 |
| 同项目的运行前同步 | 同一规范路径、projectId、兼容服务快照保持原连接 | 不因为再次按开始而重建监听；不同通信配置不得悄悄替换 |
| 切换/卸载项目 | 先通过现有 Job、相机配置等关闭保护，再明确释放旧项目服务 | 释放失败则保留旧上下文并报告失败，不假称新项目就绪 |
| Runtime 退出或崩溃 | 正常退出有界清理；进程退出由 OS 释放端口 | 重启生成新 Runtime 身份；不恢复旧请求或自动重发 |
| Designer 与远程 Runtime 失联 | 不推断远端是否仍在监听 | 状态未知；禁止拿缓存状态显示已停止或绿色正常 |

“随项目开始运行”的起点是正式生产启动，不是 LoadProject。操作端已有 `production.autoStart` 会在加载后发起生产启动；若用户已配置该自动运行方式，则通过同一生产启动屏障启动通信，而不是另设加载即监听的旁路。

自动启动成功但 Worker 后续启动失败时，服务保持常开并明确显示“监听中，流程启动失败”；不撤销其他 Job 共用的监听。用户可显式停止服务。批量运行只执行一次幂等服务启动，不为每个工作流争抢相同端口。

客户端尚未连接不伪装为服务启动失败。服务先监听，工作流再通过通道会话节点按其超时策略等待客户端；不得等到末尾发送节点才创建监听，避免机器人等连接、流程等拍照的相互等待。

## 6 Runtime 管理器与多进程通信

### 6.1 所有权和状态

拟在 `D:/jsdfhasuh/documents/my_project/emo_master/src/emo_master/apps/runtime/communication/` 新增服务管理器、TCP 服务、IPC 桥和有界状态记录模块；该目录为拟新增位置。

- Runtime 主进程持有监听 socket、accepted socket 和每通道发送队列；线程或事件循环只做有界网络工作，不阻塞 Qt 主线程或持有项目总锁等待网络。
- 服务身份至少包含 runtimeInstanceId、projectId、projectLoadGeneration、serviceId、serviceGeneration、configRevision。
- 客户端重连产生新的 connectionGeneration。旧连接的延迟事件不能覆盖新连接状态；同名、同 IP 不能证明仍是同一个会话。
- 运行状态区分 STOPPED、STARTING、LISTENING、STOPPING、FAILED；enabled 属于配置维度，UNKNOWN 属于观察/控制结果未知，不伪造服务确认。
- 服务状态提供同代次的快照、递增事件序号和有界订阅/增量查询；发现断档时重新取快照。无 Job 时的服务事件归属服务本身，不捏造 Job 身份写入流程事件流。
- 同一通道已有连接时拒绝新连接；未知 IP 拒绝接入并记录限频事件，不按“其他地址都是后工位”处理。
- 断线后保持监听，客户端可重新连接；不补发旧报文。空闲连接不会因没有业务消息被当作故障，状态仅表示 TCP 连接观测，不等同于机器人健康证明。

### 6.2 Worker 访问边界

1. JobSupervisor 为每个 Worker 建立专用、有界请求响应 IPC，优先使用独立 Pipe/Connection 桥；现有 eventQueue 不承担请求结果回传。
2. Worker 仅获得与 Job 绑定的受限代理。启动和停止服务由 Runtime 管理接口负责，不开放给任意节点随意控制。
3. 请求携带 requestId、Job/节点/调用/循环来源、服务与连接代次、deadline 和数据摘要；由父进程验证归属与当前准入。
4. socket 不经过数据流、pickle 快照或全局变量；用于 spawn 的 IPC 句柄由监管器传递，不把 TCP socket 作为插件参数。
5. Worker 强杀、Job 取消、IPC 断开时由监管器撤销准入并回收等待/队列，不只依赖 disposeOperator。其他 Job 与共享监听不受影响。
6. 同一客户端发送串行化，队列同时限制条数和字节数；满载返回明确背压错误，不无限阻塞或悄悄丢消息。
7. 等待连接、排队和发送都响应取消与 deadline；网络超时不能冻结 Worker 心跳，也不能拖住 Runtime 关闭。

### 6.3 发送结果与未知结果

- 请求尚未入队或尚未进入发送边界时，可返回明确 NOT_SENT。
- 完整写入本机 TCP 栈只能返回 SENT_TO_TRANSPORT，并标记设备确认未启用；不显示“机器人已执行”。
- 部分写入、发送时断线、IPC 回执丢失或取消与发送竞争，无法证明未发送时返回 OUTCOME_UNKNOWN。
- 同一 requestId 与摘要去重；重复查询最多返回已知回执，不能再次发送。去重表有界，过期身份应拒绝重放，不得因淘汰后把旧请求当新操作。
- OUTCOME_UNKNOWN 不自动重试，不切换到新连接补发。停止流程/停止服务也不撤销已经发送给设备的数据。
- 入站数据首版仅为有界原始字节块观察及断线检测。TCP read 次数不是报文数，不假设一次 recv 等于一条完整消息，不自动 ACK 或驱动工作流。

## 7 算子能力与 LN5 协议兼容

### 7.1 新增的工作流接口

| 能力 | 配置和端口 | 要求 |
| --- | --- | --- |
| TCP 通道会话 | 选择已配置服务和逻辑通道，设置等待时限；输出类型化 tcpSessionRef | 只获取/等待已启动服务中的连接，不创建服务；超时和取消明确 |
| TCP 会话发送 | 输入 tcpSessionRef 和待发送内容；输出类型化 tcpSendReceipt | 必须使用输入会话的身份和代次；无连接、会话过期、Job 已停止均拒绝 |
| 坐标报文格式化 | 独立于连接，明确数值格式、引号、分隔符、后缀和编码 | 通用格式能力或独立模式，不改旧网关格式化算子的默认输出 |

端口注册、schema 校验、编译器、节点输入输出检查、结果查看和快照序列化一起补齐；不能仅在算子内部传递一个不受校验的字典。服务、通道使用下拉/结构化选择，显示名称变更不破坏稳定引用。

会话引用包含父进程签发并可验证的租约身份，不能凭手写 ID 获取发送权限。服务重启、项目切换、连接更替和 Job 结束都会使旧引用失效。引用不作为长期配置或历史结果再次执行的凭据。

防止旧视觉结果发给新连接，需要在业务轮次开始、最迟在本次结果计算前捕获会话，而不是在发送末尾重新选择“当前连接”。示例把会话节点放在相机硬件等待之前，通过显式控制依赖和结果连线贯穿本轮；连续执行和 While 每轮重新取得引用。单靠发送节点读最新连接不满足此要求。

编译检查服务/通道引用是否存在；是否启用及是否就绪在选中入口的运行预检中检查，并遍历可达子流程。禁用项目仍能打开和编辑，不因未选中流程引用了通信而阻断无关纯算法流程；实际进入不允许的通信节点则明确失败，不静默跳过。

首版新会话发送不开放生产共享连接的孤立单算子调试；通过现有能力机制明确显示不支持，不能假称纯预览或用当前现场连接偷偷测试。独立调试租约、逐次确认和写保护以后另行设计。

## 11 重点风险与处理顺序

1. **运行前 LoadProject 误断长连接**：先解决同项目同步与真正替换的身份区分；加载候选项目先校验，旧服务释放失败不切换，不为方便直接清空上下文。
2. **跨进程只做出单进程假象**：P3 强制真实 spawn 与真实回环网络验收，禁止模块级 socket 字典方案。
3. **schema 升级丢旧字段**：版本扫描和完整往返夹具先行，尤其不能让 `schemaVersion == 2.4` 分支在 2.5 下漏掉全局变量。
4. **重连把旧结果发给新会话**：会话在本轮前段取得；接入代次和签发租约校验；不提供默认“取当前连接发送”的旁路。
5. **发送超时被解释为未送达**：固定回执语义，保留未知结果，禁止自动重试和断线补发。
6. **配置关闭与运行状态竞争**：后端以版本和状态做原子准入；当前仍运行时不允许保存成“已禁用”掩盖真实状态。
7. **接口新增绕过相机/调试资源保护**：在最新关闭和启动链上接入，并有专门回归；不得自动结束现场调整会话。
