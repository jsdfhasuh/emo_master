## 3. 操作归属

| 操作 | 调整后的归属 | 处理要求 |
|---|---|---|
| 打开、保存、另存工程 | 主界面文件菜单 | 从主工具栏移除打开和保存；从设备管理器移除整工程保存；保留原快捷键及本地保存语义 |
| 写入 Runtime | 顶层 Runtime 菜单 | 使用同一 QAction 和打开方法；不在主工具栏或设备管理器重复放置；流程设计和页面设计下均可进入 |
| 与 Runtime 比较、从 Runtime 读取、上传及写入结果查询 | Runtime 菜单打开的工程配置窗口 | 保留现有能力；窗口直接归主窗口所有，不从设备管理器嵌套打开 |
| 连接 Runtime | 顶层 Runtime 菜单 | 从文件菜单迁入；连接不自动下发或启动 |
| 运行流程、停止运行 | 原“运行”下拉菜单 | 移除主工具栏副本；使用现有命令、当前目标与运行状态；沿用停止所选任务及停止全部的范围区别，不迁入 Runtime 菜单；切换工作区不隐藏停止入口 |

| 撤销、重做 | “编辑”下拉菜单 | 移除主工具栏副本；复用当前工作区的撤销栈、既有 QAction 和快捷键，不因入口迁移新建撤销栈或改变作用对象 |
| 在线监视 | Runtime 菜单 | 独立非模态只读弹窗，不占用流程编辑区，不自动启动任务 |
| 图片加载与流程测试 | 流程图中的图像加载算子及正常运行或已有调试入口 | 移除全局图片测试菜单，不迁移成另一个隐蔽的图片测试器 |
| 整理流程 | “编辑”下拉菜单 | 沿用现有“自动布局”入口并统一名称；移除主工具栏副本，不改画布工具区 |
| 整工程资源与现场绑定 | 主界面文件菜单 | 移出设备管理器；打开时独立取得所需类型元数据，不要求先打开设备管理器 |
| 新建、导入、导出设备 | 设备列表工具区 | 导出依赖有效选择；导入仍按既有禁用副本语义处理 |
| 删除所选设备、旧节点迁移 | 设备列表的“更多”菜单 | 删除保留引用检查；迁移保留预览与草稿边界 |
| 应用到草稿、放弃当前属性修改 | 所选设备属性区域 | 靠近属性表单；保留切换设备、关闭时自动保留有效修改的现有行为 |
| 刷新列表、读取在线状态 | 合并为一个显式“刷新”入口 | 复用现有读取逻辑；自动状态刷新仍可保留，不增加轮询器 |
| 测试连接、连接或断开、诊断 | 所选设备详情区 | 明确只作用于当前设备，按真实状态与能力决定可用性 |

## 4. 布局方案

### 4.1 主界面

顶层菜单承载操作命令，原主工具栏精简为工作区切换区，不再保留四个命令按钮：

```text
菜单栏：文件 | 运行 | 编辑 | 视图 | Runtime | 设备管理
工作区切换：[流程设计 / 页面设计]
```

页面设计保留原有页面预览等模式能力，不再借主工具栏放置上述通用命令；页面预览沿用页面工作区入口。运行、编辑和 Runtime 菜单在两个工作区均存在，动作按当前目标、编辑上下文及实际状态使能。

运行与编辑下拉菜单的核心命令如下，其余既有功能保留：

```text
运行                         编辑
  运行流程       F5            撤销       Ctrl+Z
  停止运行       F6            重做       Ctrl+Shift+Z / Ctrl+Y
  停止全部                     --------------------
  --------------------         整理流程   Ctrl+L
  运行目标与并发…              其他既有编辑命令
  其他既有运行管理命令
```

Runtime 下拉菜单的主要分组：

```text
连接 Runtime…
写入 Runtime…
在线监视…
--------------------
发布工作页面…
```

- 原“运行”菜单保留，运行、停止、停止全部、运行目标与并发及既有辅助能力不迁入 Runtime。只有用户已明确取消的全局图片测试项从该菜单移除。
- “编辑”菜单统一承载撤销、重做和现有布局命令，布局命令名称统一为“整理流程”；不向画布工具区增加布局页或整理按钮。
- “写入 Runtime…”点击后进入统一工程配置窗口，包含比较、读回、上传、校验、提交及查询；不是点击菜单就直接提交。
- 文件菜单保留新建、打开、保存、另存、最近工程及工程资源与绑定；不再承载 Runtime 连接、写入或页面发布。
- 新增 Runtime 菜单中的工程级 QAction 不归入仅流程模式可见的 `flowActions` 或仅页面模式可见的 `pageActions`。调整原 `update()` 隐藏整个运行菜单的逻辑，不能把“工作区是否可见”当作任务是否可停止的条件；保留实际目标、任务状态及能力校验，不一律启用所有命令。
- 运行菜单是运行和停止的主要入口，流程设计、页面设计及支持的窄窗口尺寸下均须可访问。流程运行中切换到页面设计后，仍可通过运行菜单停止对应任务；停止所选与停止全部保持原语义，不根据当前画布猜测任务对象。
- 实施已核对现有 `DesignerActions`：运行使用 `F5`，停止使用 `F6`，不是新增 `Shift+F5`；撤销、重做保留 `Ctrl+Z`、`Ctrl+Shift+Z` / `Ctrl+Y`，整理流程保留 `Ctrl+L`。菜单与键盘复用同一 QAction 和既有快捷键分发，不另造执行路径；快捷键不替代可访问的菜单入口。Qt 菜单显示其主快捷键，兼容的重做快捷键继续有效。
- 顶部只保留工作区切换，不保留打开、保存、写入、图片测试、整理流程、运行、停止、撤销、重做的重复按钮，也不换成隐藏工具栏或悬浮按钮作为变相副本。
- 复用已有状态栏或运行摘要展示目标，例如“Runtime：本机内嵌”或实际 `host:port`，同时标明未下发或在线版本。不得仅凭本地草稿打开成功显示 Runtime 就绪，也不新增持续轮询体系。

### 4.2 设备管理器

保留左侧类型树、中间实例表、右侧详情的主体结构，撤掉当前跨窗口四列铺开的命令网格。

沿用设备管理器现有窗口模态。编辑完成后保留草稿并关闭，再从主界面保存或写入；不因迁移按钮而引入新的多窗口并发编辑方式，也不增加关闭确认步骤。

```text
设备管理
[新建] [导入] [导出] [更多 v]                         [刷新]
[搜索设备名称____________________________________________]
[设备类型树] | [设备实例表] | [所选设备名称与在线状态]
             |              | [测试连接] [连接/断开] [诊断 v] [更多 v]
             |              | [基本信息] [连接] [工作参数] [策略]
             |              | 属性表单
             |              | [应用到草稿] [放弃当前修改]
             |              | [节点引用] [在线状态] [诊断日志]
----------------------------------------------------------
当前草稿状态                              [保留草稿并关闭]
```

- 顶部命令按内容宽度紧凑排列，不将少量按钮均匀拉伸至四个大列。
- 常用设备操作就近放置，低频操作收进菜单；连接与断开按当前状态呈现，不同时给出容易混淆的主要动作。
- “读取实际参数”归入所选设备的诊断操作；设备发现按设备类型能力提供，不因未加载在线工程而额外禁用已有合法草稿操作。
- 未选择设备时保留简洁空状态，不显示一组可编辑的空属性。实例表为空与在线工程未加载分别表达，不能相互冒充。
- 底栏固定，正文可滚动；选中设备名称和属性上下文清楚，不让用户必须滚到底部才能操作当前设备。
- 采用现有字号、间距、图标、工具提示和可访问名称，不引入新视觉框架。底部只显示简短状态，移除目前重复解释保存、草稿、Runtime 的长段文字；必要说明放工具提示或操作影响区域。

### 4.3 图片通过流程算子加载

普通图片流程的操作为：放置图像加载算子，选择图像路径或绑定工程资源，连接处理节点，然后运行该流程或使用已有流程调试。读取路径由执行端 Runtime 解析；远程执行需要图片作为其可访问的资源，不能把 Designer 文件选择成功当作远端文件已就绪。

- 移除主工具栏、原运行菜单中的全局“图片测试”及其选择测试图片、开始测试、停止测试子项，不另建全局图片输入状态。
- 复用已有 `vision.io.image_loader` 参数编辑和资源绑定，保持图像来源在流程图中可见，不在执行前偷偷替换节点输入。
- 不再要求一般图像流程进入 `checkLocalDraft()` 的四算子白名单；普通流程仍执行自身合法性、依赖和资源校验，缺少算子或模型时显示真实问题。
- 取消全局入口不等于删除算子预览、流程调试、页面预览或共享的展示服务。先核对引用，只清理已取消入口的动作、状态栏与回调，避免残留对 `testActions`、`testStatus` 的无条件访问。
- 图像加载节点不会自动把整个流程变成无副作用测试。流程中存在相机、PLC、文件写出或通信节点时，按该流程原本语义运行，不承诺“测试图片”会自动禁用这些节点，也不为此增加全局弹窗限制。

### 4.4 整理流程归入编辑菜单

复用“编辑”下拉菜单已有的“自动布局”命令，显示名称统一为“整理流程”，移除主工具栏上的对应按钮。画布工具区保持现状，不新增布局页或重复入口。

复用 `autoLayoutNodes()` 与既有布局、视图聚焦和撤销行为，不重写布局算法。整理仅改变当前可编辑流程的布局，不增删节点或边，不改变参数，不保存磁盘、不写 Runtime、不启动任务；只读监视窗口不提供该编辑命令。

### 4.5 在线监视独立弹窗

通过“Runtime > 在线监视…”打开主窗口所属的非模态 `OnlineGraphDialog`，复用现有在线与历史快照、任务及节点结果展示，不再设置为 `Qt.Widget` 嵌入编辑区。

- 撤掉 `编辑工程 / 在线监视` 模式切换条和只为它服务的嵌套页面切换；保留流程工作区、工作流标签、运行摘要和本次或上次节点结果。
- 打开默认监视不切换当前流程或页面，不改变草稿、撤销记录、选择、缩放及滚动位置；纯观察不要求先通过尚未完成的草稿参数校验。
- 同一 Runtime 的普通监视窗口重复打开时激活已有窗口；关闭后可重新打开，正确释放定时器、只读请求和窗口资源，不积累重复轮询。
- 普通监视仅观察在线或历史版本，打开、刷新和关闭均不写配置、不启动、不停止任务。Runtime 无在线工程时显示正常空状态，不转而加载本地工程。
- 切换 Runtime 时沿用现有窗口失效和请求隔离机制，明确关闭或解绑旧目标，不让旧返回数据显示成新 Runtime 的结果。
- 配置窗口中的“在线 / 历史只读图”复用此弹窗入口。由明确“运行在线版本”产生的带启动结果窗口继续保留原请求查询与停止出口，不被普通监视窗口句柄覆盖；不另造第二套图展示逻辑。

## 5. 正常状态与首次下发

### 5.1 状态展示

| 实际状态 | 主界面工程写入入口 | 设备管理器 |
|---|---|---|
| Runtime 不可达 | 显示连接失败原因，并保留连接或重试出口 | 本地设备可编辑；在线动作按连接状态不可用，不能写成“尚未下发” |
| Runtime 已连接、无在线工程 | 显示“尚未加载工程”，提供首次写入当前工程 | 显示“当前工程未下发”；保留草稿编辑，不重复显示设备读取失败 |
| 已加载当前工程 | 进入已有比较、校验、写入流程 | 显示当前在线状态与本地差异 |
| 加载的是其他工程 | 明确显示两侧工程，沿用完整替换与影响确认 | 本地设备照常编辑，在线操作不得错误指向另一工程 |
| 写入或上传结果仍未知 | 沿用原请求查询与取消出口 | 不通过再次打开窗口、刷新或切换入口自动重放 |

使用现有错误码和服务端身份信息区分未加载、不可达与其他工程，不依赖中文或英文报错字符串判断。仅为实际缺失的状态信息补最小接口，不新增通用状态机。

### 5.2 首次写入的要求

1. 从主界面触发后，先通过现有协调器保留有效的待编辑属性，取得当前工程草稿，而不是默认读取磁盘上的旧工程。
2. 当 Runtime 明确无在线配置时，显示完整首次候选及目标 Runtime；首次写入不伪装成基于现有版本的部分更新。
3. 显式确认写入后，复用现有工程准备、资源校验和首次加载能力。校验本身不提前执行设备操作。
4. 初次下发与保存工程分开。不得直接串联现有“保存工程到磁盘，再 LoadProject”来覆盖用户文件；不得丢弃未保存草稿。
5. 当前 `LoadProjectRequest` 只携带 `project_path`。实现时必须正确保留候选文档、资源根目录与运行副本的关系；不能只把 JSON 放入临时目录就假定相对资源路径仍有效，也不能提前回收 Runtime 仍使用的文件。必要时局部补充首次加载接口，复用既有工程准备和资源机制。
6. 首次写入成功后展示在线版本，设备状态可正常读取；不创建 Job、不触发采集、不执行 PLC 节点。设备是否建立连接遵循已有连接策略，确认区域应准确表达这一影响，不能笼统承诺绝不连接设备。
7. 如提交时目标已存在在线工程，转回比较或替换路径，不用旧加载接口绕过在线版本检查。失败或取消保留草稿并给出实际结果，不自动重复下发。
8. 首次写入复用已有协调器请求表、活动写入者与取消 Event；资源准备不长期持有工程锁，返回准备中后可用原请求查询或取消。提交前取消不安装配置、激活设备或创建任务；提交后取消返回已提交事实。失败或取消的原请求不重放，准备中的旧 `LoadProject` 与第二个首次写入不能抢占同一在线权威。

实施接点：新增局部 `InitializeProjectConfiguration` RPC，接收当前草稿、资源根目录和可选的真实来源文件身份；来源文件只标识工程副本，不作为写回目标，也不读它代替当前草稿。校验不激活设备；提交将首次成功回执与在线配置写入同一现有 SQLite 事务，沿用原查询表。保留真实来源身份，避免随后运行或只读检查因临时虚拟文件名而被误判为“工程副本未加载”。

本轮必须打通当前本机 Designer/Runtime 的首次下发场景。远程已有在线工程的比较、上传与写入不能退化。远程空 Runtime 的跨机器工程安装不能凭“把本地路径发过去”冒充支持：优先复用已有远程导入能力；若当前没有可用能力，明确标注该能力边界并单列后续范围，不为此次布局整改扩建远程部署系统，也不将本机通过记为远程首次下发通过。

### 5.3 与运行入口的关系

当前“运行流程”经过 `MainWindow.startJob()`、工作流运行控制器和 `RuntimeClient` 将任务交给 Runtime；已有在线版本的启动也通过同一客户端的 `startJob()`，只是附带已比较的实例和版本信息。

以上是执行架构说明，不作为迁移菜单的理由。运行命令继续位于原“运行”下拉菜单，撤除工具栏副本；Runtime 菜单负责连接、配置和观察。入口精简不改变执行端、任务对象或停止范围。

| 执行目标 | 实际含义 |
|---|---|
| 本机内嵌 Runtime | Designer 启动时创建本机 Runtime 服务，客户端调用该服务执行；不要求用户另开一个 Runtime 窗口，也不是 Designer 自己绕过 Runtime 计算 |
| 独立 Runtime 地址 | 客户端通过 gRPC 请求当前连接的 Runtime，可以是本机独立进程或远端主机 |
| 当前全局图片测试 | 借用内嵌 Runtime 的隔离准备与启动，只支持已验证的四类内置算子；本计划取消其全局 UI 入口，不将其当作正常流程执行 |

“运行流程”按当前选定的运行目标执行，不一定只运行当前看到的画布，也不保证采用尚未下发的本地修改。计划要求在原有运行目标及状态区域清楚展示执行端、目标流程和在线版本，保留草稿与在线版本的既有选择规则，不静默选用另一份配置。

首次下发不再由“运行前同步”独占。运行入口需要处理首次下发或在线差异时，复用主界面的统一流程，并明确是否继续运行；单独点击写入永不自动启动 Job。

本轮不重构任务调度、在线版本选择或周期配置归属，不新增“必须停掉所有任务才能打开设备管理器”等限制。已加载工程继续使用现有选中变更、影响范围和停止或排空策略。
