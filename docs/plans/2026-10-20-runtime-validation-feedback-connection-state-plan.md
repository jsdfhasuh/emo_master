## 3. 校验过程与结果反馈

### 3.1 点击后立即反馈

- 用户点击校验后立即显示“正在校验完整工程…”或“正在校验选中变更…”，校验按钮显示忙碌文案并暂时禁用重复提交。
- 继续在线程池执行现有请求，不在 Qt 主线程做网络请求、工程编译或资源检查。
- 请求返回后恢复正常按钮状态。失败允许修正后重新校验，不能永久禁用按钮或要求重启。
- 没有选中变更、格式不适用、候选已失效等本地可判断问题，直接给出具体提示，不能无说明地提前返回。
- 工程或 Runtime 已切换的迟到结果，不更新新上下文，也不在已关闭窗口上弹错误框。

### 3.2 成功与失败分别表达

| 结果 | 用户可见行为 |
|---|---|
| 主动校验通过 | 明显显示“校验通过，尚未写入 Runtime”；使用图标、文字及适当样式，不只依赖颜色，不强制增加成功弹窗 |
| 写入前自动校验通过 | 直接进入既有写入影响确认，不先弹一次“成功”再让用户确认一次 |
| 校验失败 | 弹出有明确原因和处理方式的错误框；原窗口保留简短失败摘要，便于关闭弹窗后继续修改 |
| 校验中 | 显示进行中，不显示为失败或已写入 |
| 取消 | 显示实际取消结果，不当作错误；校验、升级和写入的取消分别遵循各自操作边界 |

校验本身不保存、不下发、不连接设备、不创建 Job。校验成功不能写成“工程已部署”或“Runtime 已就绪运行”。

## 4. 两个窗口的错误弹窗规则

改动范围限工程配置窗口和 Runtime 连接窗口。复用 QMessageBox，必要时仅增加窗口内的小型呈现方法，不建设跨应用通知系统。

### 4.1 信息结构

弹窗包含操作名称、易懂的失败原因、已发生或未发生的影响、可执行的下一步。错误码、原始消息及可获得的流程 / 节点 / 字段位置放在可展开的详细信息中，允许复制；不把完整工程或凭据作为诊断文本。

截图场景的建议文案：

```text
工程校验未通过

当前工程格式为 2.1，在线配置写入需要 2.6。
本次没有写入 Runtime，也没有保存本地工程。

可以升级当前草稿后重新校验；升级可撤销，原工程文件保持不变。

[升级草稿并重新校验] [关闭]
```

不为可能只是界面提示问题的情况使用“文件损坏”“必须重启”等无依据结论。

### 4.2 按真实结果呈现

| 情况 | 处理要求 |
|---|---|
| 用户主动操作的本地校验错误、RPC 明确拒绝或异常 | 弹出一次对应错误，恢复可操作状态 |
| 请求正常返回但 `state=FAILED` | 同样弹窗，不能只处理 Python 异常分支 |
| 首次打开配置窗口，Runtime 返回未加载在线工程 | 正常首次写入状态，不弹错误 |
| 写入响应丢失，结果尚未确认 | 提示“结果尚未确认，请查询原请求”；保留请求身份，不声称确定失败，不自动重发 |
| `COMMITTED` 附带发布、资源释放、副本导出或连接恢复错误 | 保留已提交事实，弹窗显示后续异常；包括 `connections` 明细中的设备重连 / 通信监听恢复 `FAILED:`，不提示通过重复写入恢复，也不伪装整体回滚 |
| 后台查询重复返回同一失败或警告 | 同一请求、同一结果只通知一次，不连续阻塞用户；使用现有请求 / 当前操作状态做局部去重 |
| 用户修改后明确发起新操作，又发生失败 | 作为新操作正常通知，不能因为消息相同而永久屏蔽 |
| 正常等待、已取消、未加载工程 | 使用窗口状态反馈，不当作错误弹窗 |

弹窗的显示不能令原查询流程失效、重复发起提交或重入同一命令。处理前先消费当前 future、更新对应状态，再通知用户；沿用既有取消、查询及终态逻辑。

连接明细仅明确的 `FAILED:` 计入失败通知；等待、连接成功、监听成功、连接意图已被替代或重启后未知不当作明确失败。查询原请求发现新的失败应通知；相同失败不因其他设备连接成功而重复弹窗。不为此改动新增自动重连、重复提交或后台轮询机制。

## 5. 旧格式工程的正常操作出口

### 5.1 何时升级

打开配置窗口即可显示“当前格式 2.1，在线配置需要 2.6”及升级入口，但仅打开窗口、比较或读取连接信息不修改草稿。

用户可以主动选择“升级草稿并重新校验”，也可在主动校验失败的弹窗中选择该动作。按钮附近清楚说明这是一次草稿修改；该次明确选择本身即授权升级，不再叠加重复确认。点关闭或取消则草稿、撤销栈和磁盘都保持不变。

该入口复用 `migrateProjectPayload(..., enableDevices=True)` 对其已支持旧格式的迁移。未知版本、非法字段或不支持的节点仍返回准确诊断；不把任意文档都强行提升为 2.6。

### 5.2 草稿、校验与写入分别处理

1. 通过现有协调器保留有效待编辑属性，取得当前草稿，不能读取磁盘旧文件代替未保存修改。
2. 先在独立候选上迁移并通过文档结构校验。结构迁移失败时不留下半升级草稿。
3. 用户明确选择的成功升级，在现有 `ProjectEditSession.transaction()` 中形成一次可撤销修改；保留工程身份、来源目录、流程顺序、节点参数、边、布局及原有资源语义，不清空此前撤销历史。
4. 复用现有读回或历史恢复后的界面刷新方式，同步流程画布、标签、已打开编辑器及草稿状态，避免旧画布下一次同步又覆盖升级后的内容。
5. 更新配置窗口的本地候选，清除旧校验结论、实例和选中项缓存，重新读取当前在线状态并校验。Runtime 若已加载在线工程，走既有比较 / 替换路径，不继续假定首次写入。
6. 结构升级成功但后续流程编译、节点或资源校验失败时，保留明确升级后的草稿并展示具体失败；用户可修改或撤销升级，不伪称整体校验通过。
7. 无论从“校验”还是“写入前校验”进入，选择升级并重新校验只完成升级与校验，不自动提交。校验通过后仍由用户明确发起写入并确认影响。

仅补齐在线配置所需的格式结构，不自动改造旧相机 / PLC 节点、不自动生成现场设备标识或连接参数。遇到这类节点的现有编译诊断，保留其位置和错误码，引导到已有迁移入口，不另建硬件迁移系统。

已经是 2.6 的工程不经过升级确认。升级后再次打开、比较或校验不产生重复升级记录；撤销升级后重新识别格式，不复用旧的“已校验”结论。磁盘只有在用户另行保存时才更新。

## 6. 当前连接与待切换目标分区

### 6.1 当前连接区

打开窗口立即展示当前客户端的连接类型，后台一次性读取现有连接的身份与状态。连接类型来自真实传输对象及其所有权，不能用 `_runtimeTarget` 是否为空或 `runtimeService` 是否非空单独判断；gRPC stub 也存放在 `runtimeService` 字段中。

本机内嵌、只读探测成功且无在线工程时：

```text
当前连接
类型：本机内嵌 Runtime（随程序启动）
状态：已连接
在线工程：尚未加载工程
```

读取期间显示“状态：正在读取”；实际失败显示“当前连接信息读取失败”及原因，不凭对象存在就显示已连接。没有在线工程不等于连接失败。已有工程时显示工程标识及可获得的文档 / 执行版本；只有相关版本读取失败或不支持时单独说明版本不可用，不抹掉已经读到的实例事实。

独立 Runtime 展示实际主机与端口，包括本机独立 gRPC 服务；不能把所有回环地址都称为本机内嵌。内嵌 Runtime 即使已有页面预览端点，类型仍为本机内嵌，不为展示地址启动页面服务或监听器。

### 6.2 切换目标区

```text
切换到独立 Runtime
地址：[主机:端口]

[读取目标信息] [取消]
```

- 内嵌场景下，待连接地址可为空，但它明确属于“切换目标”，不再承担当前连接状态的展示。
- 当前使用独立服务时可预填真实地址，不伪造默认 `127.0.0.1:50051`。
- 沿用现有先只读探测、再明确切换的流程。成功后显示候选实例、在线工程和能力，按钮改为“切换到此 Runtime”。
- 当前连接区和候选信息区互不覆盖；候选失败时弹窗并提示“原连接未改变”。取消时释放本次候选客户端，不关闭原内嵌 Runtime，也不停止其任务。
- `Cancel` 改为“取消”；空地址、格式不正确和当前确有未结束请求等正常拒绝，给出对应处理方式。
- 当前连接查询和候选探测复用现有异步机制、超时与连接切换规则，不增加持续探测循环，不为打开窗口要求停止所有任务。
- 查询晚到时仅更新匹配的窗口与连接上下文；关闭窗口不触发新弹窗或自动切换。

主界面 Runtime 摘要与窗口复用同一连接类型表达，避免一处显示内嵌、另一处仅因页面端口存在而显示成独立连接。不新增“切换回内嵌并创建新服务”等超出本次反馈的操作。

## 9. 实施顺序与完成标准

1. 重新记录实际 HEAD、工作区差异及相关文件哈希；已有后续修复先核对，不覆盖用户或其他任务的修改。
2. 用临时 2.1 / 2.6 工程和本机内嵌客户端建立截图对应的反馈反例，明确校验与连接信息的正常路径。
3. 修正校验忙碌、成功和失败反馈，接通两个窗口的错误弹窗，覆盖异常及明确失败结果，保留原查询 / 取消语义。
4. 复用迁移与草稿事务接通明确升级、刷新、重新校验及撤销，不把升级动作串成自动写入。
5. 完成当前连接与候选目标分区，统一连接类型表达，验证查看、探测、失败、取消和切换。
6. 执行定向及受影响回归、静态检查，更新指南和独立验证记录；新增失败证据保留，实际修正后另记复测。

完成标准：用户能看懂校验是否进行、是否通过、为什么失败以及如何继续；旧格式工程不只得到重复版本错误；打开连接窗口能明确识别当前本机内嵌 Runtime，不以空地址表示未连接；错误可见且不重复骚扰。全过程不自动保存、下发或运行，不删除必要的设备和资源保护。

计划完成不等于软件实施完成，实施状态以固定源码及独立验证记录为准。源码修复通过适用范围的软件验证即可推进无设备人工走查，不以无关暂缓风险作为门槛。未经另行要求，不构建、发布、提交、推送或操作现场设备；已有 Python 进程或冻结 EXE 不会因计划及源码编辑而热更新。
