## 1. 目标与范围

按用户选择的“起始页直设”方案，在现有独立操作员 Runtime 中实现可用的工程起始页、本机目录设置和真实日志查看。保留 Python 3.10、PySide2 / Qt QWidget，不把讨论用的网页预览嵌入产品。

用户应能直接回答三个问题：当前 Runtime 把内部数据存在哪里、这个路径为什么生效、运行失败后到哪里查看明确原因。

| 本轮实现 | 本轮不实现 |
|---|---|
| 起始页直接显示工程入口、目录及来源、最近日志 | 重写 Designer、流程编辑器或工程业务页面 |
| 保存本机下次启动默认目录，展示配置覆盖关系 | 修改系统或用户环境变量、热切换正在使用的数据根 |
| 全局日志入口、级别筛选、记录详情、真实日志文件夹入口 | 日志删除、任务重试、设备控制、日志上传或云端收集 |
| 读取现有 JSONL 日志，展示必要的启动诊断 | 新日志数据库、通用监控框架、改写 Job 持久化和轮转策略 |
| 正常打开、运行中查看、返回、关闭及初始化失败处理 | 自动搬迁数据库、托管工程、历史日志或业务留档 |
| 源码回归、隔离的原生 Qt 窗口验收和使用文档 | 修改真实摄像头工程、连接相机/PLC、打包发布或现场验收 |

不新增 `project.json` 字段。Runtime 内部目录属于本机应用设置；设备、模型、业务输出路径及生产策略继续属于工程。不得用更改 Runtime 数据目录替代配置工程留档位置。

## 3. 目录配置契约

### 3.1 优先级与存储

独立操作员启动统一按以下优先级解析一次：

```text
显式 --data-root / OperatorWindow(dataRoot=...)
    > EMO_RUNTIME_DATA_DIR
    > 本机保存的默认目录
    > 当前平台的系统默认目录
```

- 沿用 `QSettings("EmoMaster", "Runtime")`，新增独立键 `storage/defaultDataRoot`；不把设置文件放进待配置的数据根，避免改变根目录后找不到设置。
- 新增小型、无 Qt 依赖的目录解析函数，输入显式值、环境、保存值和平台默认值，返回规范化路径、来源及覆盖提示。界面不自行重新推断来源。
- GUI 入口读取 QSettings 后将有效绝对路径明确传给 `ProductionRuntime`；控制器保持无 Qt 依赖。直接构造控制器的既有调用仍可显式传入隔离目录。
- `--check` 使用同一解析规则计算受保护路径，但不创建 Runtime、数据库、日志目录或 Job，不改写本机设置。工程包导出/安装的既有边界保持不变。
- 本机保存值必须是明确的绝对目录；支持 Windows 盘符路径、UNC 和中文路径。CLI 原来允许的相对路径继续按启动 CWD 解析，不借此新增限制。
- “使用系统默认”只修改待保存选项；点击保存后移除本机覆盖键，而不是把某个用户的绝对路径硬编码成系统默认。

独立入口当前显式传入 DB 和 logs 路径，因此 `EMO_RUNTIME_DB_PATH`、`EMO_MASTER_RUNTIME_DB_PATH`、`EMO_RUNTIME_LOG_DIR` 不会分别覆盖它们。本轮保留该行为；存在这些变量时，在展开的目录诊断中说明“不用于当前独立入口”，不虚称它们已生效，也不扩展成任意环境变量编辑器。

### 3.2 当前值与下次值分开

界面同时呈现两组不同信息：

| 信息 | 语义 |
|---|---|
| 当前有效目录、来源 | 本次初始化采用的路径；Runtime 成功创建后以真实实例路径核对。 |
| 下次启动默认目录 | 可编辑的本机设置；存在 CLI/环境覆盖时，保存后仍可能不生效。 |
| 未保存 / 已保存、仍被覆盖 / 下次生效 | 根据草稿、持久化结果和实际优先级给出，不只显示笼统“保存成功”。 |

展开显示数据库、日志、任务目录、托管工程根及显示缓存；从当前实例或统一解析结果获取，不使用文本输入框拼接“实际路径”。托管根不等于当前工程目录，更不等于业务图片留档目录。

保存只更新本机偏好，不关闭任务、不重建 Runtime、不切换日志目录、不复制原目录内容，不要求用户为了编辑下一次默认值先停止检测。`QSettings.sync()` 后检查状态，保存失败显示明确原因，不能给出成功提示。

格式错误、路径指向文件等正常输入错误在保存前反馈。目标目录可以尚不存在，由下一次初始化创建；不为设置验证提前创建业务数据库或扫描工程。实际创建/写入失败保留路径、失败阶段和底层原因，不静默回退到其他目录。

换根后不会自动带走旧根的在线配置和历史日志；原目录保持原样。工程记忆、显式工程加载及在线版本恢复仍按现有控制器规则处理，不因打开设置页或保存设置而重新加载工程。

## 4. 起始页与运行页面

### 4.1 起始页直设

- 顶部保留产品名、真实状态以及常驻“查看日志”；加载工程后仍提供“Runtime 设置”入口。
- 未加载工程时，主体左侧为工程选择、最近成功工程和最近日志；右侧直接显示目录设置。较窄窗口上下排列，不堆叠大量工具按钮。
- 最近工程首版复用已存在的 `projectPath`，显示最近一次成功记录；没有历史就显示为空，不新增一套工程历史管理器。
- 最近日志只显示真实记录的时间、级别和简短消息；“查看全部日志”恢复全部级别筛选，不沿用隐藏错误的旧筛选。
- 不为业务留档编造统一路径：未加载显示未加载；已加载如缺乏权威的单一目录数据，不拿 Runtime 根或 `jobs` 冒充归档目录。

### 4.2 加载后与往返

保留现有 `RuntimePages`、多流程页、运行目标、启停和设备入口。设置/日志是应用工具页面，不替换工程定义的业务页面。

- 使用窗口内的独立工具区域或堆叠页切换；进入设置/日志不能调用 `_removePages()`、关闭 DisplaySession、释放图像 pin 或改变 Job。
- 返回恢复原业务页或设置页，保留未保存目录、日志筛选、选中记录和滚动位置。
- 日志/设置入口不依赖 `canLoad`，运行中也可使用；停止入口及真实运行状态保持可见。
- 自动加载上次工程、恢复在线版本和 `production.autoStart` 继续遵守原规则。起始页不是新增启动门槛，不额外要求一次确认才能生产。

### 4.3 初始化失败

起始页在 Runtime 初始化之前即可建立。初始化失败时，页面保留有效配置来源、失败路径和简短原因，设置及日志入口仍可使用；不得只显示空白内容区。

没有成功实例时显示“本次启动目标目录”，不标成“正在使用”。允许关闭、保存下次默认值；目录权限等问题在外部修正后，可显式重试本次初始化。重试前释放失败初始化已创建的资源，只执行一次，不后台无限重试，不重复已启动的工程。

如果数据库/日志尚未建立，错误保留为本次窗口的启动诊断，明确标记“未写入日志文件”。不能声称用户到一个不存在的日志文件中就能看到全部原因。

## 5. 真实日志查看

### 5.1 数据来源

复用 `RuntimeJsonlLogWriter` 和现有 `RuntimeEvent` / JSONL 字段，不建立另一套持久日志存储，不改变现有轮转大小、保留天数和总量策略。

- 默认读取当前实例 `operationalLogWriter.activePath`；尚无活动文件时明确显示暂无本次文件，可查看该日志目录中的历史文件。
- 提供简单文件选择，显示实际文件名和时间；依据当前 writer 的活动路径标记文件，手动固定是独立的选择模式。历史文件可能包括本次轮转前的记录，不仅凭选择方式断言“不是本次故障”，也不把上一次运行的错误当作本次故障。目录没有文件与读取失败是不同状态。
- 打开目录使用当前 writer 的实际 `directory`，初始化失败时使用本次目标日志目录。不会跟随已保存但未生效的下次设置。
- 补充有限的独立端启动事件，如目录解析、Runtime 就绪和工程加载失败，复用现有 writer 直接记录。仅为这些明确事件增加允许列表，使用真实时间和错误信息；不伪造 Job，不写入 Job 生命周期表。
- writer 不可用时保留有限的本次启动诊断，并展示 `enabled` / `failureMessage` 的实际结果，不另建永久备用日志系统。

网页预览中的 `runtime.log`、示例错误码及“模型文件不存在”不能作为正式文件名或真实故障依据。

### 5.2 视图与错误详情

列表以“时间、级别、来源、消息”为主，默认不会铺开长 ID、完整 JSON 或堆栈。支持全部、错误、警告、信息、调试筛选，提供无匹配结果和恢复全部的明确出口。

选中记录后显示：完整时间、真实错误码、原始消息、可用的工程/流程/节点/Job 身份、payload 和按需展开的原始记录。已知名称可用时显示名称；缺少名称保留 ID，不根据当前工程给其他运行记录错误配名。

处理建议只来自可靠的结构化诊断或经过验证的错误码映射；未知错误展示原始原因，不通过字符串猜测一律归为“缺少模型”。查看记录不触发下载、执行或重试。

首版采用独立端紧凑 QWidget 视图，复用真实记录契约与现有筛选语义。Designer 的 `StructuredLogView` 含设计端依赖及额外导航，本轮不整体搬迁它、不导入 Designer，不为一个日志入口扩大为全平台 UI 重构。

### 5.3 读取与界面更新

采用小型只读增量 JSONL reader 和一个有界后台读取任务，不在 Qt 主线程读取整份日志，不复用 25 ms 状态轮询频率读文件。

- 初次读取采用文件尾部窗口，建议最多 2 MiB / 2000 条；明确显示“最近记录”，不冒充完整历史。
- 视图最多保留 10000 条，单轮读取有字节/条数上限；不把大文件全部装入内存。超过显示范围可打开原日志文件夹查看，不删除文件内容。
- 当前文件按偏移增量读取，显示区可见时约 1000 ms 刷新；同一时刻最多一个读取任务在途，慢读取不排队积累。
- 起始页最近日志和日志页共用读取状态，不启动两套重复读盘轮询；业务页无日志展示时停止相应轮询。
- 正常文件轮转后跟随新的活动文件；用户主动选中的历史文件不被自动切回。半行暂存到完整换行后再解析，解析失败有计数/原因，不能让整个页面退出。
- 按文件与偏移区分记录，不按消息去重吞掉重复真实错误；任务返回带文件/窗口选择身份，旧响应不能覆盖新选择。
- 自动刷新保留当前选择与横向滚动位置；只有跟随最新时才纵向滚动到底部，否则按可见记录保留阅读位置。启动诊断内容不变或正常追加时保留文本选区、光标与滚动位置。关闭/隐藏停止新读取，已发出读取有界收尾，退出不遗留后台线程。
- 列表、详情和错误提示使用纯文本，路径及消息中可能出现的 RTSP/HTTP 用户信息和敏感字段须按现有脱敏规则或局部白名单处理，不把完整设备配置加入新启动日志。

“打开日志文件夹”使用 `QDesktopServices.openUrl(QUrl.fromLocalFile(...))`。目录不存在或系统无法打开时给出当前路径和失败提示，不创建假日志、不执行 shell 拼接命令、不错误报告已经打开。
