## 1. 用户需求与范围

已明确的需求：

1. 页面设计中移动已有控件不顺手，希望改善拖动跟随、摆放和整体交互。
2. 尽量复用流程设计的基础交互代码，两个工作区使用一致的操作习惯。
3. 页面需要随窗口尺寸**自动重新排版**，不能只等比缩放固定画布。
4. 当前没有实际投入使用的页面工程，不以还原旧页面布局、开发旧布局迁移工具或维护双编辑器作为本轮前置任务。
5. 流程设计保留自由摆放、端口连线和现有操作习惯，同时加入动态参考线、轻微吸附、多选对齐和等距分布。
6. 上述功能的开关与操作放在主窗口顶部的 **“编辑”菜单**。
7. 后续授权范围为连续完成 P1—P4；完成后交由用户人工验收，不自动发布。

建议分阶段交付：先完成编辑菜单与流程画布对齐辅助，再落实公共交互与页面响应式布局。第一阶段可独立使用，不等待页面改造结束。

本计划不改变工作流执行、设备访问、参数绑定、任务调度、Runtime 写入权限和发布步骤，不引入 Qt6、QML 或 Web 编辑器。沿用 Python 3.10、PySide2 / Qt QWidget；QGraphicsView / QGraphicsScene 属于同一 Qt Widgets 技术栈。

## 3. 编辑菜单与公共操作约定

在现有撤销／重做之后、整理流程等操作之前加入以下分组；保留原有菜单操作：

```text
编辑
  撤销
  重做
  ────────────────
  ✓ 动态参考线
  ✓ 轻微吸附
  对齐                  > 左对齐
                           水平居中
                           右对齐
                           ──────────
                           顶对齐
                           垂直居中
                           底对齐
  等距分布              > 水平等距分布
                           垂直等距分布
  ────────────────
  整理流程
  ……现有操作
```

行为约定：

- 动态参考线与轻微吸附默认开启，独立开关；关闭参考线仍可保留吸附，关闭吸附仍可显示参考线。
- 两个开关作为本机编辑偏好保存，不写入工程，不改变 dirty、撤销记录或已发布页面。页面接入后共用同一偏好。
- 对齐和等距分布是立即执行的命令，不是永久开关。对齐至少选择两个对象，等距分布至少三个；不足时显示真实原因。
- 菜单在打开、选择变化、工作区变化时更新状态，执行时重新检查当前工作区和编辑状态，避免修改隐藏画布。
- 不增加与现有快捷键冲突的新组合；拟用按住 Alt 临时绕过吸附，实施时验证不影响已有 Alt+方向键浏览。
- 流程画布继续支持 Ctrl 点击多选和空白处左键平移。共同选择体验的后续阶段可补充 Shift+空白拖动框选；不直接占用原来的平移手势。
- 第一阶段页面尚未接入时，菜单明确提示仅流程设计可用，不能让页面菜单操作修改隐藏的流程；页面阶段完成后同一 QAction 分派到当前编辑器。

## 4. 流程画布：参考线、吸附与排列

### 4.1 动态参考线与轻微吸附

- 对齐依据为节点主体矩形的左／中／右、上／中／下，不包含端口名称、连线、提示和选择装饰。
- 拖动时优先参考邻近节点；每个方向只显示当前最有用的参考线，避免整屏线条和吸附目标争抢。
- 初始吸附距离建议约 6 个屏幕逻辑像素，按当前缩放换算到场景坐标。数值是待原生走查调整的交互参数，不是已验证的性能指标。
- 接近目标时轻微吸附，继续拖动即可脱离；相近候选保持稳定，避免反复切换造成抖动。
- 多选拖动采用整个选择组的统一位移，保持节点之间的相对位置，不逐个吸附而拉散选择组。
- 参考线只负责绘制，不成为可选择、删除或阻挡鼠标的图元；线段范围有限，不改变自动适应画布的内容边界。
- 只有正常鼠标节点移动进入辅助对齐。加载、保存重开、恢复历史、自动布局和程序设置坐标不触发隐式吸附。
- 完成或取消拖动、切换工作流、删除对象及关闭工作区时清理提示。Esc 恢复本次拖动起点，不产生新的工程修改记录。

### 4.2 多选对齐与等距分布

| 操作 | 定义 |
| --- | --- |
| 左／右／顶／底对齐 | 以选择集合对应的最外侧主体边缘为基准 |
| 水平／垂直居中 | 以选择集合整体包围范围的中心为基准 |
| 水平／垂直等距分布 | 按相应方向排序，保持两端对象位置，使相邻主体之间的边缘间距一致 |

不同尺寸的节点按边缘间距计算，不把“中心间距相等”冒充“空隙相等”。当外侧跨度不足以容纳所有节点时，不生成负间距的新重叠；在现有消息区说明空间不足，用户可拉开两端后重试。这是该排列动作的局部反馈，不限制自由移动或其他编辑。

允许选择工作流输入／输出节点参与排列，它们本来就可移动；不可删除的边界节点规则不扩展成不可对齐。

一次排列只产生一次撤销；位置原本已满足要求时不增加无效记录。只有被选择的节点移动，未选择节点与连接拓扑不变，相关连线继续按既有路由逻辑更新。

### 4.3 对现有流程体验的影响

新增的是辅助线、可关闭的轻微吸附和主动排列命令。节点仍自由摆放，窗口变化不触发流程自动重排。缩放、平移、端口连线、节点参数、调试、运行与停止保持原有语义。

复用 `flowEditAllowed()` 等现有编辑条件；不因新增对齐功能要求停止所有任务，也不削弱现有运行中编辑限制。

## 5. 页面设计：直接拖放与响应式布局

### 5.1 页面保存排列关系

目标是同一页面在不同窗口宽度下重新排版。采用有顺序的布局容器，第一版覆盖“上下排列、并排排列、自动换行”；控件记录填满／适合内容、最小宽度、必要的宽度比例、间距与对齐等布局意图。

页面不以任意绝对坐标作为唯一位置依据，也不要求用户逐个输入行、列、跨度。下方仅定义布局语义，字段名与 schema 在实施阶段统一确定。

| 内容 | 初始交互与布局规则 |
| --- | --- |
| 图片与结果区域 | 宽窗口并排；可用宽度不足时按稳定顺序上下排列 |
| 指标卡片组 | 根据卡片最小宽度自动换行，可选择等宽 |
| 标题、数值、单位 | 可以编为同一组，随组移动，保持内部关系 |
| 图片 | 内容维持宽高比，避免窗口变窄后变形 |
| 按钮与文字 | 保留可读字号和正常点击区域，文字按规则换行 |
| 数据表格 | 使用可用宽度；无法压缩的列在表格内部滚动，不把整个页面撑出横向溢出 |

窗口宽度变化只计算显示布局，不修改组件 ID、绑定、查询来源、导航动作和工程 dirty。重排不应重建数据会话、重新启动查询或丢失选择状态。

### 5.2 直观的编辑动作

- 控件影像连续跟随鼠标，保持按下时的抓取点；原布局暂留占位，落点出现明确预览。
- 拖到同组两个对象之间显示插入线；拖到对象旁边或下方显示并排／上下排列的候选效果。
- 常见拖放自动形成必要的局部布局关系，不要求用户先手动建立多个空容器。
- 跨容器移动显示目标容器和插入位置；整体移动一组对象时保留组内关系；不静默修改数据绑定。
- 调整控件尺寸时映射为宽度比例、最小尺寸或填充规则，显示结果可预期，不用一个自由像素宽度掩盖后续自动重排行为。
- 提供选择、Ctrl 多选和分组操作；框选采用不冲突的共同手势，不改变流程空白左键平移。
- 拖动时只更新视觉和候选布局；候选改变才重新计算，松手进行一次权威校验与工程提交。取消或无效落点保留原布局，正常操作可以继续。
- 保留属性面板尚未应用输入的原有处理：合法输入在明确的提交边界保存，非法输入留在原位置供修正，不能因拖动刷新而丢失。

### 5.3 页面中的“对齐”和“等距”

菜单名称与流程一致，但页面命令写入布局关系，使窗口变化后仍然成立：

- 同一布局组内的边缘／中心对齐转换为组内对齐规则，不写入互相覆盖的绝对坐标。
- 作用范围始终是所选对象。只有整组都被选择时才直接修改组级规则；选择部分兄弟控件时采用控件级规则，或明确预览新建子组，不能静默改变未选兄弟控件的布局规则。响应式让位造成的位置变化必须在落点预览中可见。
- 水平／垂直等距分布转换为对应布局轴上的间隔分配；自动换行后分别应用于每行／列，保持元素顺序。
- 跨容器选择先明确排列范围，提供编组或移动到同一布局层的正常操作入口；不能悄悄把其他容器的内容一起移动。
- 页面吸附针对当前合法容器、插入位置和对齐候选。关闭吸附后仍提供合法落点预览，不绕过响应式布局规则制造重叠。

P2 需给出每类布局在各轴上支持的命令及实际效果。某个方向不适用时说明布局原因，并提供明确的分组／排列方式调整入口，不能把六种自由坐标命令机械套入所有容器。页面这些规则需用原型验证；第一阶段的流程对齐不依赖其完成。

### 5.4 宽度预览

编辑区提供可调整的预览宽度与少量常用宽度按钮，先依靠容器规则自动排版，不要求用户维护多份独立页面。

例如在宽／中／窄三种窗口下，示例页面分别显示：图片与结果并排、指标四列；指标两列；图片与结果上下排列、指标继续换行。验收同时连续改变宽度，防止只在几个固定点“看起来正确”。

桌面 Qt 页面也必须自动重排；不能把响应式限定为未来 Web 终端的特性。

## 6. 代码复用与改造边界

统一基础交互，不让页面继承整个流程场景：

| 层次 | 处理方式 |
| --- | --- |
| 边缘／中心计算、参考候选、吸附、分布数学 | 小型公共几何模块，不依赖流程执行、页面数据源或工程会话 |
| 缩放、平移、选择反馈、拖动取消与提示绘制 | 在两个真实使用入口出现时提取必要的 Qt 交互接口，保持流程原行为 |
| QAction、设置与撤销 | 复用 DesignerActions、现有 settingsStore、ProjectEditSession；不另建历史账本 |
| 流程场景 | 保留节点、端口、连接命中与路由，只接入所需辅助功能 |
| 页面编辑层 | 目标为 QGraphicsView / QGraphicsScene 编辑表面，承载组件选择、拖动影像和响应式布局预览 |
| 页面运行显示 | 继续使用原生 QWidget 控件；编辑预览与实际显示消费相同布局规则与测量结果 |

页面实际控件外观继续复用现有 renderer 与组件工厂，不另画一套容易与运行显示偏离的“假控件”。先以图片、文字、表格和嵌套容器验证 Qt 代理承载与控件内滚动／输入的交互；拖动期间可用缓存影像避免反复重建原生控件。实现选择依据这组有限验证，不先建设通用画布框架。

流程拖动必须保留“局部连线更新＋释放后细化”，不能逐帧调用完整自动布局或全图路由。检查实际原生鼠标抓取者，避免把端口连线、标题编辑、展开端口按钮误识别为节点拖动。

## 7. 工程格式与已有计划协调

实施前版本为工程 **2.7**、Presentation **1.0**；本轮当前源码已支持工程 **2.8**、Presentation **1.1**。流程对齐辅助和本机开关本身不需要工程格式升级；版本推进由可保存的响应式页面合同引入。

页面响应式规则涉及保存合同，需要同步模型、校验、新建默认值、保存重读、Qt renderer、页面导出及文档；不能只修改 schemaVersion 标识。实施时沿用 `WorkflowStore().toPayload()`、`ProjectDocument`、`saveProject()` 的完整路径，并核对 reset 默认结构。

工作区已有以下待实施计划：

- [Runtime／Designer Web 接入计划](./2026-10-30-runtime-web-integration-plan.md)。
- [Web 操作员面板独立开发计划](./2026-10-30-web-panel-dot-development-plan.md)。

它们原提出工程 2.8／Presentation 1.1 及 responsive 覆盖。本轮已统一版本归属并同步这两份计划：2.8／1.1 用于基础响应式页面，具体字段见 [共享布局合同](../development/responsive-layout-contract.md) 和 [工程格式规范](../project-json-spec.md)。未来 Web 字段仍需依据届时支持状态决定版本，不能重复占用此版本号；本轮不实现 Web 或新增 RPC，也未生成尚无消费者的 TypeScript 交付物。

设置一个明确的合同定版点：**任一方向首次对外提供响应式 schema、TypeScript 类型或页面包 fixtures 之前**，先统一基础布局语义与字段；谁先进入该步骤，谁同步另一计划及合同源，再共同更新导出 schema、类型和样例包。P2 在此基础上收敛原型，P3 实现已定版合同，不等到 P3 才发现 Web 已按另一套规则开发。该协调不阻塞 P1 的流程对齐功能。

需要协调的具体差异：现有 Web 计划写的是 Qt 桌面布局加 Web responsive 覆盖；本次用户要求同一桌面页面也随窗口重排，因此应共享基础响应式语义。若未来需要终端覆盖，覆盖项仍引用同一 componentId，不复制组件、绑定或执行逻辑。
