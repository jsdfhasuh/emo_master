三、架构与改动边界

Web/MCP 必须在 Designer 关闭时独立工作，不启动、不连接、不控制 Windows Designer。

共享的是工程模型和编辑规则，不是桌面进程、当前草稿内存或撤销栈。不同草稿各持独立会话；HTTP 与 MCP 调用同一业务服务。

优先直接复用 ProjectEditSession、WorkflowStore、正式工程读写及已有无界面函数。只有 Web 当前确实需要、但仍耦合界面的业务规则才局部提取。

任何阶段提取了桌面规则，都在同一变更中调整对应 Designer 调用并验证直接受影响行为，不能拖到阶段 D 才接回。未提取的操作不需要迁移。

一项操作只有一个事务负责人。不要重复嵌套事务，不要为统一形式重写整个 MainWindow、控制器、画布同步或撤销系统，也不要复制另一套 Web 专用工程模型与规则。

本轮按新建 Web 服务实施。不要增加旧 Web/API/数据迁移、多租户、全客户端兼容矩阵、分布式锁、复杂审计或幂等账本。

完整浏览器流程画布、Qt ROI 绘图移植、MCP 自动发布和生产启停，不在本轮范围。

四、按 A–D 四阶段执行

A：能力发现与最小可用服务
完成真实算子／设备目录、完整详情、实际编辑能力查询、独立草稿、流程／普通节点／参数／连线、撤销重做、保存、本地校验，以及同一服务的 HTTP／MCP 入口。

B：资源与正式工程交付
完成真实字节上传和替换、资源绑定、基础页面配置、当前草稿输出绑定、正式工程导入导出和鉴权下载，验证 Designer 能打开交付物继续编辑保存。

C：目标候选预检
完成单工程 ZIP 流、独立候选检查、真实目标编译、结构化诊断、修复后的再次检查，以及实际异步边界的取消和清理。

D：完整工程编辑能力
补齐流程复制／删除／入口／接口、Subflow、Loop、Dispatch／Join、设备、变量、页面布局导航、现场参数及正式运行／生产配置，并从新增公开入口验证。

Runtime 候选预检可在核心契约明确后并行准备，不等待全桌面改造。A/B 可作为中间交付，但不能宣称完整计划完成。

五、落实算子能力发现与编辑契约

提供算子摘要搜索、完整详情、设备类型声明和实际编辑命令的输入结构，不能只返回名称列表或工具名。

递归保留真实参数 schema、完整端口、版本、用途、设备要求和条件扩展，包括 required、nullable、enum、default、description、xEnabledWhen、xVisibleWhen、xValidateWhen、xOdd 等。保留扩展字段不等于自行发明其执行规则，业务校验复用现有实现。

通用配置必须支持 ROI points/regions 等嵌套对象和数组，不展平、不字符串化、不浅合并。node.configure.params 按计划完整替换；变量绑定未传保留，显式 [] 清空。

明确区分：
- 算子功能声明；
- 当前服务实际已实现的编辑操作；
- 指定草稿版本在指定目标上的检查结果。

不编造支持百分比，不把目录存在或配置成功当成实际可运行。查询失败不能伪装成空目录；能力查询不得执行算子、加载模型试跑或连接现场设备。

以正在连接的 Runtime 返回值为准，不能用本地新 manifest 冒充未升级目标的能力。源码注册测试保留 manifest 与返回版本一致的断言；远端集成请求使用目标返回版本。

工具 inputSchema 应说明具体命令和必填字段，不能只接受无约束 object。能力信息来自实际已实现命令，未完成操作明确标记，不提前声明支持。

1. 工程与状态

3. 文件传输
严格按 file-transfer.md 完成上传元数据、期望修订、长度／摘要、资源登记和鉴权下载。

4. 校验与诊断
本地 validate 不强制依赖在线 Runtime；目标 precheck 才使用明确目标的真实声明和编译器。
保留 code、message、workflowId、nodeId、fieldPath 和已知 resourceId 等定位信息，不把全部异常压成一段字符串。
正常 FAILED/INCOMPLETE 检查报告与工具调用失败分别处理。
候选预检不替换在线工程、不提交配置、不创建候选 Job、不连接设备；预检通过不等于实际执行成功。

5. MCP 协议与认证
保持项目 Python 3.10 基线。阶段 A 实测并记录一个官方 SDK、协商协议和实际客户端组合，不擅自升级整个平台。
请求取消遵循该组合的实际语义；不能删除整个草稿或擅自撤销已提交编辑。重连先读取状态，不自动重放写请求。
HTTP、MCP、上传下载统一使用工作区凭据；凭据不进入工程、日志或 URL。MCP 关闭时基础 HTTP 草稿服务仍可使用。
