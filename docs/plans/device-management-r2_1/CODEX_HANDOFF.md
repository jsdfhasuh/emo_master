## 2. 不可缩减的完整功能

正式第三工作页面“设备管理”；拖入设备相关算子先选设备或新建设备，之后设置本次动作与参数来源；其他节点复用设备 ID。设备默认参数与节点覆写分离，MAC 优先发现／回读。连接、释放、故障策略由插件声明允许值和默认值，插件可固定。

设备竞争只由每设备串行执行入口／FIFO 处理，占用时等待、采集安全完成即释放。不得回到“采集主流程独占”、Switch／父子互斥证明或同设备两个节点不得同时启动。明确业务先后仍由流程表达。

同一帧可通过显式分发交给多个受管理独立流程，必须有正式 Join 汇合及明确的投递／执行结果，不用抢同一队列或各取最新图代替。

整个工程在线比较、读回、选择写入或保持差异监视。保存文件不改 Runtime；在线结果采用 Runtime 快照／实际周期版本，不拿本地新配置解释旧结果。

## 3. 必须遵守的三份契约

### 配置写入与周期（主计划 §7—8）

- 同一 Runtime 一次只受理一份配置写入，不阻塞监视、查询和停止。
- 候选来自“在线基线＋选中变更＋已确认依赖”，不夹带本地未选或未完成修改。
- 预检查不代替提交点检查。所有在线 mutation 路径收口，提交点检查 Runtime 身份与预期版本。
- SQLite 是在线配置的权威存储；完整候选、版本与配置回执一笔事务提交。导出文件是副本，不建文件／数据库双权威事务。
- 软件配置整体提交，硬件重连及实际结果单独报告。配置写入不执行 PLC 写入节点或触发拍照。
- 普通参数提交不等待整个运行组结束。新周期领取新计划，旧周期、排队图像和晚到消费者继续持有旧计划；不兼容连接／资源变化才排空或停止相关使用。
- 客户端断线查询原 requestId／读回版本，不自动换新 ID 再写一次。重启不读取 Designer 尚未下发的工程文件。

### 设备操作（主计划 §5—6、§10）

- 一个设备一个权威 DeviceExecutor，不把锁要求变成每设备进程要求。本次 SLMP 优先设备 IO 线程，华睿采用固定的受管 Host 适配；不另建可配置通用 Host 调度器。
- 参数应用、触发／等待、取得对应原图及必要 SDK 帧释放是一个操作；下游算法／投递／容量等待不持锁。
- 必须处理软件触发迟到帧、自由运行参数生效帧、硬触发缓存与重连代次；不能只将旧 capture 包一把锁。不能每次取锁都无条件清硬触发缓冲。
- 请求无效／排队取消只影响本请求，不一律隔离设备。底层未退出或帧对应不确定时才阻止后续操作。
- 未确认副作用不自动重放。等待、操作、恢复预算分别有界，无限硬触发须可取消。
- 生产观看默认订阅已有图；主动试拍才取图。旧诊断关闭不能恢复已被新运行配置取代的 original。

### 分发与图像（主计划 §9）

- 目标归本运行组的 targetSlot，不向同名 workflow 的所有任务广播。消费者复用，不每帧创建进程；启动前确认并发容量。
- Dispatch 返回投递回执；Join 按 dispatchId／目标槽／周期收集完成结果。部分投递不重发整批，消费者崩溃不自动重跑未知副作用。
- 本次仅实现同 Runtime 的结构化分发，不增通用消息主题、跨机消费者、持久重放、分布式恰好一次。
- FrameStore 采用 Runtime 所有的共享内存原图与明确 FrameRef；条数、字节有界，排队和执行持引用，真实退出后释放。不同消费者不能改坏同一原图。
