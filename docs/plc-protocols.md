# PLC 通信格式选择与验证

PLC SLMP Read / Write 的参数页第一项为“通信格式”，可选 MC 3E Binary（二进制）或 MC 3E ASCII。该设置决定实际报文编码，不是数值显示格式，也不是 PLC 自动识别结果。

1. 按 PLC 对应以太网端口的配置选择通信格式，填写 IP、端口和已知可读取的地址。
2. 点击“应用”保存到工程；旧工程未保存 `frameEncoding` 时默认 `binary`，原有行为不变。
3. 在“PLC 通信测试”页从当前参数重新加载，再连接。此页的设置是调试副本，不会自动写回工程参数。
4. TCP 连接成功后显示“通信格式待验证”。读取一次成功并通过响应校验后，显示“通信已验证”。这只确认当前目标、路由和操作能通信，不代表所有地址都可访问。
5. 改变通信测试页的通信格式需要先断开连接。验证通信只需要读取，不需要解锁或写入。

“PLC 通信测试”默认展示读取操作。需要手动写入时，展开“手动写入 PLC”，连接后勾选“解锁本页手动写入”，填写值并点击写入按钮。展开不会自动解锁；收起写入区或离开此页会停止连续读取、取消尚未发出的排队写入并重新锁定。已经发出的读写继续等待结果，写入回执在收起后仍然显示。

“调试当前算子”按参数页配置执行当前节点，读取算子显示“执行读取”，写入算子显示“执行写入”。该入口不运行整个工作流，也不受通信测试页的手动写入锁控制。写入算子调试会实际写入，不会自动运行下游的恢复节点。

持久化参数为 `frameEncoding: "binary"` 或 `frameEncoding: "ascii"`。界面结果使用该次执行保存的参数，因此查看历史结果时不会把新选格式套到旧结果上。

当前范围为已有的 D/M 设备、普通 3E 字访问及调试页 M 位访问。ASCII 的 D/M 地址使用六位十进制，范围 0..999999；16/32 位有符号、无符号和浮点数的解释方式与 Binary 一致。iQ-R 扩展设备字段、其他帧类型不在本次支持范围。

软件不会自动尝试另一种协议，也不会在写入失败后切换协议重新发送。格式不匹配、非法报文、PLC 错误码均保留为错误，不标记验证成功。

自动测试只连接本机模拟端，覆盖固定报文样例、分片响应、数据类型、字/位读写、路由、错误码、取消、连接生命周期及界面参数保存。ASCII 尚未在现场 PLC 上验收。

报文布局交叉核对参考：[pymcprotocol Type3E 实现](https://github.com/senrust/pymcprotocol/blob/main/src/pymcprotocol/type3e.py)。测试使用独立模拟端和固定字节样例，不依赖该库运行。
