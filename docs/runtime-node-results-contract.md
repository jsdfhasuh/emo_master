# 流程设计节点结果查看契约

本功能沿用 Python 3.10、PySide2、原 WorkflowRunner 与事件订阅。
节点结果是原任务的真实执行观察，不调用算子编辑器重新计算。

## 第一批：统一面板与会话状态

- 原生流程设计右侧使用「节点结果」，包含图像输出、数值输出、执行信息、输入数据。
- 图像节点默认打开图像标签；无图像端口的节点默认显示输出摘要，控制节点显示执行信息。
- 输入是已有真实摘要，图像只提供尺寸；集合只提供数量。`0`、`false`、空值保留原义。
- 当前草稿配置入口独立于结果，只读历史不禁止继续编辑。
- 历史只保留当前会话的两次明确接受的任务。启动尝试未接受不轮换记录；第三次接受淘汰最早任务。
- 节点名称、端口类型与工程修订在启动前冻结。节点摘要按任务、工作流、调用身份接收，旧调用不会覆盖新调用。
- 每任务至多64个定义/观察，定义和观察共同受512 KiB紧凑JSON额度约束；两任务合计1 MiB。
- 运行中、失败、跳过清除旧有效完成输出；任务终态后迟到节点事件不能恢复输出。
- 画布继续使用当前作业状态，历史选择仅作用于右侧查看，不启动或停止任务。

第一批的原始证据仅覆盖面板和摘要，不追认该批已有真实图片。

## 第二批：真实图片与两次任务保留

新增可选 `OpenRunInspectionSession / RenewRunInspectionSession / CloseRunInspectionSession`。
请求包含当前工程副本身份，回复提供 Runtime 实例和检查会话标识。每 Runtime 最多两个会话，租约30秒，客户端每10秒续约。
`StartJob.inspection_session_id` 在明确启动前协商；接受回复提供实际工程修订。
旧 Runtime 返回 UNIMPLEMENTED 时明确说明两次图片能力缺失，原任务执行仍可使用旧接口。
没有会话的旧 StartJob、节点预览、上传、读图保留原路径；不新增默认页面采集或改变设备执行。

`ListNodePreviewSources` 和 `StreamPreviewAsset` 可携带检查会话。检查来源包含
Job、工程副本、修订、workflowRunId、nodeRunId、captureId、正式输出端口。
会话查询使用被冻结的任务定义，不以修改后的草稿代替。旧快照没有新身份字段时仍可走旧接口，但不会成为新检查会话的有效图片。

Runtime 在原终态回调、旧快照晋升及失败工作区清理之前，原子复制已提交索引中与节点最后完成调用匹配的图片。
失败/取消只接管此前有效完成节点；最后一次运行中、失败、跳过，身份不匹配，或只有临时未提交索引，都没有可展示图片。
任务终态、资产接管就绪和进程退出是三个不同条件。RPC 用 PREPARING 表达尚未封闭的图片接管；客户端在同一个5秒请求期限内检查就绪，不固定 sleep 假定完成。
不会因查看器接管失败改写检测任务成功/失败。

保存结果图仅保留已完成保存节点的工作区副本，校验注册回执的 SHA256 后接管；不读取可变开发输出路径。
当前支持该选项的 PNG/JPEG/BMP 文件头，其它格式明确报告不支持。节点图像快照仍使用原 PNG 编码。

资源保持用户指定上限：每任务64条、512 KiB摘要，两任务1 MiB；编码文件每任务64 MiB、会话128 MiB，纳入原工程512 MiB/全局2 GiB额度。
Runtime最多两个实际检查读者，流结束的 finally 才释放文件引用；淘汰、关闭或租约到期不提前删除仍被实际读者持有的文件。
删除失败继续计账并拒绝新增图片复制，保留轻量文件所有权回执，不保留被淘汰的节点摘要。
会话历史不跨 Runtime 重启或 Designer 项目切换；关闭会话不发送 StopJob。

Designer只新增一个惰性启动的读图/解码工作者、一个待处理选择和一个图片交付槽。
GUI通知只传代际编号，不能在Qt事件队列积压图片。所有I/O离开GUI线程；实际工作退出前不归还该工作者。
切换先清空旧图，项目代际与选择代际分离，拒绝迟到回调；选择节点不取消正在明确发起的Start请求。
只解码当前选择，单图8 MiB；编码读图暂存最多4 MiB，与Qt读取缓冲合计8 MiB，超出时保留原编码资产但明确拒绝本地显示。
解码QImage拥有像素，释放编码缓冲后才做格式转换，转换临时空间至多8 MiB。
主面板用原生绘制按适配比例画共享QPixmap，不生成放大的整图副本。

实际验证：真实spawn Runner＋本机typed loopback gRPC，A/B图片与计数不同，A在B晋升后仍可读取；失败、协作取消、强杀、循环最后失败、配额、租约、淘汰及实际读者清理。
原始失败与修复后结果均保存在 `docs/testing/node-results-2026-10-04/raw`。第二批相关回归121项通过。

本功能不改变项目格式、算子语义、入口工作流或默认设备执行行为；不增加生产历史数据库。
第二批尚未交付独立大图窗口，不能代替第三批的真实Qt路径验收，也不能替代原1080p/5Hz性能目标。
