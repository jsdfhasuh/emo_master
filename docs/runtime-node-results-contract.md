# 流程设计节点结果查看契约

更新：2026-10-23。本节描述当前实现；早期批次的测试结论保留在文末引用中。

本功能沿用 Python 3.10、PySide2 / QWidget、WorkflowRunner 和原事件订阅。节点结果是明确启动任务后的真实执行观察，不重新计算算子，不增加生产历史数据库，不改变检测判定、原图、设备执行或工程格式。

## 节点最近两次执行

- 右侧「节点结果」包含图像输出、数值输出、执行信息、输入数据，按钮为「本次执行 / 上一次执行」。
- 历史单位是同一节点的实际调用，不是整个 Job，也不是最近一次成功调用。一次循环内依次输出 `5、2、3`，本次显示 `3`，上次显示 `2`。
- 按工程副本、所选运行目标、Runtime / 检查会话、`workflowId + nodeId` 隔离；调用使用 `jobId + workflowRunId + nodeRunId` 标识。
- 下一次开始时轮换一次；同一次完成或失败仅更新记录。没有开始的分支跳过不挤掉两次实际执行。
- Job 接受本身不清空或轮换节点记录。新任务尚未执行该节点时，可看旧记录，但显示原任务、原时间和「本任务尚未执行」。
- 本次失败或取消不复用上一执行的输出。任务终态关闭仍在运行的记录，显示取消或中断，不永久停在「运行中」。
- 跳过时显示「本轮已跳过」，保留的结果仍标明实际来源。上一次是失败调用时如实显示失败，不能跳过它选择更早成功。
- 节点名称、端口和工程修订使用该记录所属任务启动时冻结的定义，不被后续草稿覆盖。配置入口仍编辑当前草稿。
- Job 仍负责启动、停止和日志来源，只保留被两条节点记录引用的旧 Job 与最新 Job；第三次启动不能释放仍被节点引用的旧结果。
- 画布继续显示当前实时观察，历史选择只影响右侧和大图，不反向修改画布或控制任务。
- 切换工程、Runtime 实例变化或检查会话失效清理旧上下文；不恢复跨重启历史。

输入来自真实摘要，图像/数组显示尺寸，集合显示数量，`0`、`false`、空值保留原义。长定义或超过额度时显示 `E_INSPECTION_METADATA_BUDGET`，不把被淘汰记录伪装成未执行。

## 运行中图片通道

沿用可选 `OpenRunInspectionSession / RenewRunInspectionSession / CloseRunInspectionSession`。会话冻结工程副本引用，回复包含 Runtime 实例和会话标识；30 秒租约，客户端每 10 秒续约。Runtime 默认最多两个会话，随工程的并发任务配置扩展；无限并发配置不设置会话数量上限。实际读者上限仍为两个。

`StartJob.inspection_session_id` 在明确启动时协商，接受回复提供实际工程修订。没有检查会话的旧启动、节点预览、上传、调试输入和读图继续使用原路径；显式关闭旧快照采集的 `NONE` 选项保持原语义，不偷偷恢复采集。不新增默认页面采集或设备操作。

1. Runner 在原有输出校验及采集位置冻结本次图片。Worker 同步编码为不可变文件，后续算子修改同一 ndarray 不能改写已发布图片。
2. Worker 沿现有通道发送内部 `inspection.snapshot` 元数据；它是事件批处理屏障，先提交节点开始/保存回执，再交付文件，最后提交完成。图片不进入公共事件日志。
3. Supervisor 在事件顺序锁与自身锁之外调用现有检查存储接管文件；事件 sink 只更新调用元数据，不做磁盘 I/O。
4. 只有匹配的 `node.completed` 才开放查询。图片已提前采到但节点失败/取消时仍不可作为有效输出。
5. 节点完成即可查询，即使整个 Job 仍为 RUNNING。Job 终态仅负责关闭未完成记录及清理，不再从最后索引导入历史。
6. 已发布文件归检查存储所有。第三次调用淘汰最早记录；正在读取的文件等实际 stream 的 finally 退出后才释放。

采集或接管失败仅影响该次图片可用性，记录原因，不改写业务执行状态。只保留节点最近两次，不积累整段视频图片。

保存结果图沿用已经注册的工作区 `artifacts` 副本和 SHA-256 回执，验证后生成 `__saved_result__` 显示预览。不从可能被下一轮覆盖的开发输出路径读取历史，不把显示预览替代保存原图。

## 旧调试快照的异步持久化

普通 Runtime Job 在 `legacySnapshotPolicy=ALL` 时，使用每任务一个后台写入者持久化
`preview_staging`。这与上面的实时检查会话图片通道不同：旧快照只保留每个
`workflowId + nodeId + port` 的最后结果，**不是逐帧保存、业务历史或正式图片输出**。

- 生产者先冻结图像和 JSON 输出；后台继续使用原有原子文件写入、索引提交和旧资产释放。
  下游原地修改数组或集合不会改写已提交的快照。
- 队列中同工作流、同节点、同一组有效输出端口的旧调用可以被较新调用替换，并移动到
  队尾；正在写入的调用不替换。一次调用的图片和配套几何信息共用 `captureId`，不同
  部分输出的先后顺序保留，不把不同时刻的端口拼成一次调用。
- 默认最多 **64 个待写调用**，另有至多一个正在写入的调用；待写与正在写入的数据合计
  按图像 `nbytes` 和 JSON UTF-8 大小计账，预算 **64 MiB**。达到预算时可取消地等待容量，
  不无限堆积。单次合法大图超过预算时，只在缓冲为空时允许一份；不人为禁止大图。
  这不是进程 RSS 上限，Python 对象、替换时短暂复制、PNG 编码和实时预览另有开销。
- 成功终态前排空最后的待写快照、回收后台线程，再发送 `job.completed`，之后 Runtime
  才提升索引。正常失败/停止丢弃未开始的诊断写入，只等待已经开始的文件写入结束；
  成功收尾期间收到停止仍报告 `job.aborted`，不为排空快照重放任何业务算子。
- 可选快照 I/O 失败仍报告 `preview.snapshot.failed`，不掩盖业务失败，不改变正式保存
  回执。任务终态的 `payload.previewSnapshots` 记录提交、合并、写入、失败、丢弃和峰值。
- `NONE` 不创建此后台写入者；实时检查会话、页面采集、Image Saver 正式输出、工作流
  顺序、循环和推理参数保持原语义。直接使用 `PreviewSnapshotWriter` 的调用者仍同步。

本轮实施与源码验证见 [2026-10-23 异步快照验证记录](testing/2026-10-23-async-preview-snapshots.md)。

## 精确查询与界面

`ListNodePreviewSources` 携带工程引用、检查会话、Job、workflowId、nodeId，以及新增的 `workflow_run_id / node_run_id`。两字段为空时沿用所选 Job 中该节点最新保留调用的查询语义，Designer 历史查看必须传精确身份。

来源包含工程修订、Job、workflowRunId、nodeRunId、captureId、正式输出端口。资产 ID 绑定这些身份；原始尺寸使用 `original_width / original_height`，`width / height` 是实际传输预览尺寸。

| 查询状态 | 语义 |
| --- | --- |
| PREPARING | 所选调用尚在执行，完成输出未发布 |
| CURRENT_AVAILABLE | 所选已完成调用有可读取图片，不要求 Job 终态 |
| NO_CURRENT_SNAPSHOT | 该调用失败、取消、无此端口、未采集或已淘汰；不回退到其它调用 |
| EXPIRED | 检查上下文或所选 Job 已超出保留范围 |

Designer 延用单后台读图/解码工作者、单待处理选择与单交付槽，GUI 通知只传代际编号。查询、复制、读图、解码不放在 GUI 线程。相同选择不重复读取；切换节点、端口、运行目标或本次/上次先清空旧图并取消旧选择，迟到结果不能覆盖新选择。

连续循环的普通事件刷新不反复取消正在读取的同位置结果，让一组完整的输入、数值、执行信息和图片先到屏幕，再跟随新执行。显式选择仍立即切换。只读取当前选中节点，不轮询全工程。

读取 PREPARING 在同一 5 秒期限内有界等待。查询图片或读取资产流时的一次暂时断连、超时，都进入原有每 10 秒续约恢复路径；即使续约本身没有失败，也会在成功续约后重读当前选择。相同选择的 UI 刷新不触发紧密重试，成功读取后不再因正常续约重复读图；切换选择取消旧图的恢复意图。

任务终态轮询不清除读图错误提示，也不自行触发重读。取消、解码失败不自动重试；会话失效或 Runtime 身份变化则清理历史。图片恢复不补执行、不重放业务任务。旧 Runtime 缺少检查接口时明确说明图片能力不可用，不编造来源。本轮交付要求 Designer / Runtime 配套更新，不承诺任意历史版本混用。

YOLO 的 `drawOverlay` 默认开启，成功执行时输出 `overlay`；零目标也输出无框图像，绘制使用副本，不改动输入或检测结果。已有工程显式保存的 `false` 仍表示关闭，不自动改写工程或写入 Runtime。

主动关闭的可选图像输出，由算子在本次完成事件的 `diagnostics.imageOutputMessages` 中按端口说明原因。Designer 将说明随该次节点调用保留，所选端口有明确未输出原因时直接显示，不再发起无效读图。YOLO 分别说明关闭的 `overlay` 和 `croppedImage`；本次/上次切换不读取后来编辑的草稿参数，已实际输出的端口不受子流程汇总诊断影响。没有这项诊断的旧记录继续按原通道查询，不能推断历史开关状态。

## 大图与原图

- 普通 2K / 4K 图像在 Runtime 保持比例适配到不超过 `1920×1080`，不放大小图。
- PNG 编码仍超过 4 MiB 时按有限次数继续缩小，同时满足 8 MiB RGBA 解码预算。
- 预览不改变传入下游的数组、业务原图、保存原图或原有调试快照；不提供新增的全分辨率分块浏览功能。
- 主面板和大图标明原始/预览尺寸，二者共享 QPixmap 与所选执行身份；预览 100% 指显示预览的像素比例，不是恢复原图。
- `NodeImageViewer` 是非模态原生窗口。打开、重复打开、关闭后再打开不增加第二次读图；关闭查看器或租约不发送 StopJob。
- 缩放沿用 QGraphicsView transform，支持 10% 到 800%、滚轮、平移、100%、适配、全屏、Esc；不创建放大的整图或额外 alpha mask 缓存。

界面保留原生纵向滚动、窄标签箭头和长名称提示，保证元数据、图片、底部操作互不覆盖。有图像端口或保存结果图时默认图像页，否则默认数值或执行信息；缺图原因在右侧和大图同步显示。

## 额度与释放

| 资源池 | 上限与计账 |
| --- | --- |
| Designer 定义/摘要 | 每任务至多 64 个定义/观察、512 KiB；节点历史至多 64 组，每组两次，连同引用的任务元数据合计 1 MiB |
| Runtime 元数据 | 至多 64 组节点、每组两次，256 个图片来源；每任务 512 KiB、会话 1 MiB；超过后不复制新图片并显示原因 |
| 编码资产 | 每任务 64 MiB、每会话 128 MiB；与原工程 512 MiB / 全局 2 GiB 共同计账；淘汰后仍被读者持有或删除失败的文件继续计账 |
| 读图/编码暂存 | 单次编码 4 MiB；精确大小拼接，旧/新拼接或 Qt 编码复制合计至多 8 MiB |
| 解码/转换临时 | 当前选择 8 MiB；读前核对尺寸及 Qt 原生格式，包括 16 位 PNG；释放编码缓冲后转换，转换临时至多 8 MiB |
| Qt 显示图片 | 24 MiB；QImage 实际 bytes + QPixmap 宽×高×4，主面板与大图共享 cacheKey 不重复计账 |
| 实际资产读者 | Runtime 最多两个；流结束、实际工作退出后才释放，而不是请求取消时提前归还 |

淘汰后删除失败只保留文件所有权和读者回执，已淘汰的来源/回执元数据释放。受管文件不人工删除或篡改是当前正常使用假设，不为未证实的极端组合新增通用补偿或容错系统。

Runtime 加载同 projectId 的另一目录后，旧副本合法会话仍能续约、读取、关闭，另一副本不能冒用。Designer 切换工程先拒绝迟到结果，后台关闭旧会话；断网关闭失败由原租约清理，不能声称网络不可达时已经即时删除文件。

主窗口退出仍先结束原订阅与 Start/Stop 工作者，再关闭检查会话和客户端。不改变主窗口对自己启动任务的原有退出收尾策略。
