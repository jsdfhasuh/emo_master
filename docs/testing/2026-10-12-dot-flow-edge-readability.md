## 1 验收前置

1. 在新的独立检出中取得用户指定的正式交付 SHA 与完整夹具，记录 `git rev-parse HEAD`、`git status --short`、工程 SHA256。不能仅检出分支最新版本、旧 HEAD 或旧安装包；版本不同须先说明。
2. 建立独立检出和测试数据目录，保留已有本地修改与工程。不要 `reset --hard`、覆盖用户工程、重启生产 Runtime 或连接生产相机/PLC/机器人。
3. 记录 OS、Python、PySide2/Qt、屏幕分辨率、系统 DPI、画布 zoom、启动命令及源码/安装包身份。源码变更不会自动更新旧进程或 EXE。
4. 使用真实可见且可操控的 Qt 桌面。Linux 可用可控 VNC/noVNC；真实桌面进程不能使用 `QT_QPA_PLATFORM=offscreen`。无桌面时标记桌面用例 `NOT_RUN`，不要用 offscreen 截图替代。
5. 获取上述正式基线和改后两套同工程、同坐标、同窗口、同缩放截图。基线尚无新示例，可将交付版本的示例复制到独立测试数据目录供两版读取，并记录相同哈希；不要将新源码覆盖到基线。两版使用隔离副本，不能让前一版保存操作改变后一版输入，也不要主动自动布局来制造差异。
6. 夹具须有：稀疏链、至少 1 个输出分到 4 个目标、同一源节点的不同输出、不同信号交叉、多个端口连向同一目标、长中文/重名节点、受阻路由，以及 100 节点/300 边压力图。
7. 真实工程以交付包提供且获准分享的副本为准。当前开发工作区的未跟踪 `projects/` 不能假定在远端存在；替代夹具须标注，不能宣称已测真实业务工程。

## 2 必测用例

每项初始状态为 `NOT_RUN`。一条截图不能代替整行全部交互，失败后保存现场和最小复现工程。

| ID | 操作 | 预期与证据 |
| --- | --- | --- |
| E01 总览 | 打开稀疏图、密集图，不点击任何对象，分别截取同视口前后图 | 全部连接仍存在且可辨；普通线不压过节点文字；位置/缩放没有被自动改变，工程不因显示变化变脏 |
| E02 节点聚焦 | 选中高连接节点，再 Ctrl 多选第二个节点，再取消其中一个 | 分别突出直接关联边及并集；不扩展到整条链；记录实际边名单与端点；高亮边不自动进入删除集合 |
| E03 端口悬停 | 悬停一个有 4 条支路的输出，再悬停同节点另一个输出和输入；移开 | 只突出对应端口连接；不同输出不混；离开恢复原选择；端口标题不被遮挡 |
| E04 拖线兼容 | 从输出端口按下拖线，经过兼容/不兼容端口，取消一次，再成功连接一次 | 仍能正常启动、吸附、拒绝错误并取消；预览不被聚焦抢走；一次实际连接按既有规则形成一次编辑 |
| E05 单边 | 悬停、点击独立支路，再点击空白清除 | 指定边全路径与两端可辨；兄弟支路不误亮为选中；没有巨大的选中外框；空白点击与平移不被隐形区域拦截 |
| E06 公共段 | 检查同源 4 分支干线，悬停并点击公共段 | 公共段不重复加深/变粗，分叉点明确；点击出现候选支路，不任意选中一条或整组；候选显示完整源/目标，重名可区分 |
| E07 消歧菜单 | 在菜单中逐项悬停、取消、重开并选定第三条支路 | 悬停仅预览，取消恢复原选择；选定后只有精确目标边被选中；打开菜单不制造工程修改，菜单中 Delete 不触发批量删除 |
| E08 删除撤销 | 清除其他选择，通过公共段选定一条边，删除、撤销、重做、再撤销 | 每次只影响目标真实边；其他 3 条仍在；撤销恢复正确端口和公共段；没有残留线/端点环；保留操作前后工程副本 |
| E09 不同信号 | 检查同节点不同输出、不同节点的交叉线与相近并行线 | 不合成同一信号干线，不给普通交叉画连接点；在交叉附近选择时身份清楚，不能误删兄弟信号 |
| E10 错误状态 | 使用受阻夹具，选择无关节点，再悬停/选中受阻边 | 错误仍有虚线及原因，不被淡化到看不见；选中不洗掉错误形态；不自动移节点掩盖受阻 |
| E11 拖动重布线 | 连续拖动高连接节点，松开后立即再次拖动、删除一条边或切换工作流 | 画布响应正常；旧路由不回写、不崩溃；公共段/端点最终正确；点击不形成额外历史记录，拖动仅产生应有编辑 |
| E12 生命周期 | 在聚焦或菜单打开时切换工作流、工程，删除源节点、撤销，再关闭重开 | 聚焦不串到同名节点/端口；没有幽灵干线、旧菜单或已删除边回调；无崩溃 |
| E13 空白构建 | 从空白工程用工具箱搭出至少 8 个节点、12 条有效连接，包含同源 4 分支、不同信号交叉和汇合 | 不编辑 JSON 完成；能自然发现聚焦与支路选择；记录卡住的入口、额外点击和误操作，不只测试预制示例 |
| E14 保存重开 | 保存 E13 到新目录，关闭重开；另对既有工程副本仅做查看再比较 | 节点、边、端口和位置保留；聚焦/菜单不写入工程；只查看不改 dirty/撤销记录；旧文件不被覆盖 |
| E15 缩放与长文本 | 系统缩放 100/125/150/200%，画布 50/100/150%，在小窗口和常用大窗口重复 E03/E05/E07 | 线、端点、中文长标题、菜单可读可点，无越界遮挡；记录实际分辨率/DPI，不以改图片尺寸代替系统缩放 |
| E16 响应性 | 在真实图与固定压力图上各做至少 30 次聚焦/选择，并拖动、缩放和平移 | 保存操作录屏及开发交付的同机耗时数据；对照计划 P95 门槛；远程传输卡顿和本地 UI 卡顿分开记录，不凭感觉给出毫秒值 |

E15 最少完整执行参考桌面的系统 100% 与 150% 组合，其他组合分别记录；Windows 四种系统缩放属于 Windows 原生验收矩阵。平台不支持的组合写 `UNSUPPORTED` 并标明桌面结论范围，不能写 Windows 全矩阵通过。

对 E13 可使用无设备的数值、布尔、比较等算子；实施交付时附可用节点与类型说明。如果为了凑线数必须制造无效连接或手写 JSON，应记录为夹具/入口问题，不绕过校验。有可运行的纯算子夹具时，另记录改动前后输出一致；这只证明该夹具运行未回归，不是设备验收。

字段映射依赖提示单独检查：它仍是临时提示，不被归入公共段、不出现在可删除的真实边候选中。涉及此提示的流程需要交付方提供无需外部写入的查看夹具，不能为了测试提示实际写生产数据库。

## 3 可读性对照任务

在同一工程和视口中，按固定任务各执行 3 次：找到指定节点一个输入的来源；找到指定输出通往某个目标的支路；通过共享干线准确选择并删除指定支路，再撤销。

记录正确性、步骤、耗时、误选次数、是否需要移动节点/反复放大。首次使用和熟悉后的数据分列，不能把熟练度差异包装为优化收益。以下问题必须用实际画面回答：

- 无选择时，能否看清节点和阶段，普通线是否仍然太抢眼？
- 聚焦后，能否读出源节点、源端口、目标节点、目标端口，而不是只看到一条亮线？
- 公共干线是否真的减少重复视觉信息，还是引入了新的菜单负担？
- 某条支路被选中时，会不会误以为全部兄弟支路都被选中？
- 淡化后能否发现无关区域的错误，弱化线是否仍可点击？

## 5 停止与结论

- 发生误删多条边、保存后图变化、端口身份串线、旧工作流状态污染、持续冻结或崩溃时，停止相关操作，保留工程副本/日志并列为阻断；不要靠重排全图、删缓存或重启全部服务消除证据。
- 必测功能存在 FAIL，或本平台可执行的必测项仍为 NOT_RUN，不能给出整轮桌面 PASS。平台缺口必须显式写入结论，缺少参考 DPI 也只能给出部分验收。
- 软件自动化、Windows 原生桌面、Debian 原生桌面、安装包、现场设备分别下结论，不相互替代。本轮后两项默认 `NOT_RUN`。
- dot 完成后回传报告和原始证据，不自行修代码、提交、推送、部署或扩大测试到生产设备。修复由开发侧处理，再按新 SHA 复验失败项和相邻回归。
