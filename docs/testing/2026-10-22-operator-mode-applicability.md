### 发现与修复

1. **几何取点切换兼容特征会清空对象。** 从 `bboxCenter` 切换到 `bboxTopLeft` 时，
   原有 `bbox` 或 `measurements` 仍然适用，却被重置为空，导致再次要求选择。
   修复为保留仍适用的对象；原对象确实不适用时才重新推断。新建且有多个可选对象时仍须选择。
2. **动态特征按未生效的固定值推断对象。** 特征绑定到全局变量、资源或现场参数后，
   无输入连线的旧节点仍按固定 `circleCenter` 自动填入 `circles`，应用后可能错误限制输入。
   修复为先收集全部绑定来源，再推断对象；动态特征不使用固定特征的兜底值推断，已有明确
   对象和有效连线仍保留。处理对象自身已绑定时，打开和切换特征也不改写其固定值草稿。
3. **已绑定参数仍被固定值草稿阻止应用及图校验。** 例如保留 `sigmaColor="unfinished"`，
   切换到双边滤波并绑定合法数值变量，表单依然报“请输入有效数值”。修复为绑定生效时保留
   原草稿，不校验未使用的固定值；全局绑定及其控制的条件字段交由应用和 Runtime 校验实际
   解析值，静态图检查不再误报固定值。取消绑定后重新校验，非法的有效绑定值仍被拒绝。

源码修改限于 `_operator_modes.py`、`operator_mode_presentation.py`、`param_form.py`、
`main_window.py` 和 `flow_graph_model.py`；补充 Designer 和 Runtime 两个现有模式测试文件。

### 复现证据

- 修复前新增的六个针对性用例全部失败：兼容特征的两个对象值、动态特征的三类绑定来源、
  绑定数值替代未完成固定值。另有两个 teardown 错误，原因是测试构造的简化资源绑定未清理；
  已补充夹具 `finally` 清理，不将其算为产品缺陷。
- 表单修复后继续复现静态图校验错误：`params.sigmaColor must be number`；随后修复校验层。
- 测试迭代中的 `bbox` 端口类型误写已按实际 `bbox2d` 契约纠正；重绘后断言改为读取当前
  FlowNode，而非已替换的旧对象。原有“兼容切换也清空”的断言改为保留对象，同时保留新建
  歧义对象必须选择的反例检查。没有删除失败用例或降低非法有效值的拒绝要求。
- Mypy 初次发现四处新分支类型标注缺口，补充类型标注后通过。
