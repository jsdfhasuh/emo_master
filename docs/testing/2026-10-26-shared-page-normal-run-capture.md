# 共享页面在正常运行入口启用采集

## 问题与范围

- 基线 SHA：`633de0e197f5553168a7786440199f68f3410bed`，在已有未提交修改上局部修复。
- 用户已打开“摄像头与人脸”新布局，运行面板显示任务运行中，但页面预览提示“尚未运行”。
- 本轮未停止用户正在运行的任务、未修改在线工程、未连接真实相机、未提交或打包。

## 根因与修复

- `MainWindow._capturePresentationForRun()` 使用默认的单入口页面筛选。跨生产、消费两个入口的共享页不完整属于其中任一个入口，因此两个入口都被判断为没有需要采集的页面。
- 对交付的 `RTSP Live Face Closeup.emoproj` 调用该判断，修复前返回 `False`，修复后返回 `True`。此检查只加载工程模型，不执行设备或算子。
- 改用已有的 `presentationForWorkflow(..., capture=True)`，与 Runtime 正常采集计划及消费任务登记保持一致。每个任务只采集自己拥有的页面来源。
- 页面服务未启用不等于业务未运行。修正缺少服务、未找到页面运行记录和 `OFFLINE` 的提示，不通过查看操作启动服务、创建任务或补执行。
- 原双任务测试手动设置了 `capturePresentation=True`，未覆盖 Designer 普通运行入口。本轮新增普通 `MainWindow.startJob()` 到 `watchCurrent()` 的回归，覆盖 `ALL` 和 `NONE` 节点快照策略。

## 生效边界

- 当前已启动的 Designer 不会热加载源码修改；旧任务在启动时未登记页面采集计划，重新打开预览不能补回这次采集。
- 需要正常结束旧任务，重新启动修改后的 Designer，再从当前新版工程启动任务。未替用户执行此现场切换。
- 未做本轮真实摄像头验收、全仓库测试或冻结 EXE 验证。不把模拟设备测试描述为现场预览已恢复。
