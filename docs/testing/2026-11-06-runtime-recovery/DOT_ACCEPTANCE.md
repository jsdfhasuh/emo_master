# 给 Dot 的可见 Web 复验说明

请对 PR #11 中 **ChatGPT Web 修复评论明确给出的完整 SHA** 做可见桌面复验。先记录实际 HEAD、分支、工作区状态、操作系统、浏览器版本、Runtime 实例和测试数据目录；若远端后来又有新提交，先说明差异，不把移动分支当作固定版本。

本轮目标是确认 Web 从创建、保存、发布，到真实软件 Runtime 结果订阅、停止和重启，再到日志查看、导出的完整交互，以及本次修复的双标签恢复。开发侧已经有组件回归和真实子进程反例；你的报告仍需区分可见 UI 操作、辅助接口核验和未执行项目。

## 环境

读取当前 `AGENTS.md` 和 `web_panel/README.md`。使用临时测试工程、临时 Web/Runtime 数据目录、真实软件 Runtime 与模拟相机。新建工程按当前模型生成并完成保存重读与编译，当前格式为 ProjectDocument 2.9 / Presentation 1.2；不直接把旧证据工程的版本字符串改成新值。

使用仓库已有的本机免密入口，不需要输入密码。例如在已正确安装 Web 面板的环境中，将地址和数据目录替换为本轮测试值：

```text
emo-web-panel --data-dir <本轮临时Web目录> serve --mode grpc --runtime-address 127.0.0.1:50051 --host 127.0.0.1 --port 8780 --local-no-auth
```

该模式是默认关闭、显式启用的本机管理员模式。只连接本轮测试 Runtime，监听 literal loopback；按已有部署文档使用，不更改认证代码，不使用 mock Runtime 替代真实软件 Runtime。测试时保持其他重型测试或构建任务停止，记录有无同时运行的工作负载。

## 1. 页面编辑与发布闭环

1. 可见浏览器打开 `/editor`，核对本机管理员提示、Runtime 目标、工程及实例身份。
2. 从初始空白页面开始，创建检测页和详情页，添加图像、数值/判定和导航组件。用界面实际目录选择工作流、节点、输出，保留能够辨认新结果的值或序号。调整布局、撤销/重做并切页，确认交互连贯。
3. 上传一张 BMP 和一张 PNG，检查编辑显示、保存后重开及发布后的显示；不要只验证 HTTP 上传成功。
4. 保存草稿后重开页面，核对布局、文字、绑定和资源。再留下一个未保存改动，执行下面第 3 节的双标签恢复。
5. 通过界面明确点击发布，核对发布状态、正式页面版本和 Runtime 输出配置确认。记录发布前后任务状态；发布本身不应隐式开始检测或自动停止现有任务。
6. 返回运行页，明确选择工作流、开始任务、选中该任务和页面。新任务初始“数据未就绪”画面要单独截图，再截图首个新结果；两张图不能用同一个时刻代替。

## 2. 真实软件 Runtime 结果、停止和重启

普通工作流和 Dispatch 分别执行。至少各保留一段不少于 200 个有效结果周期的连续运行，覆盖之前在 iteration 142 左右出现问题的范围。记录实际有效周期数和时长，运行不足不能写成通过。

检查页面图像、数值、结果身份连续更新，编辑器实时预览和运行页读取当前所选任务；切换任务、页面及订阅后不混入旧任务结果。Dispatch 主任务和消费者分别记录身份；消费者初始无数据及首次新结果各保留截图。

每种流程至少取得 5 个明确发生在采集中的停止样本。记录停止请求、驱动取消回执、最终任务状态、设备及执行资源退场；在同一 Runtime 中再次启动并确认新图。队列等待停止另列，不能替代采集中停止样本。连续运行中如出现一次非预期 FAILED、UNKNOWN、IMAGE_BUSY/IMAGE_QUARANTINED 持续不恢复，应立即保留现场和对应日志，不用后续成功样本覆盖它。

额外执行普通任务与 Dispatch 的多次正常启动，保留是否出现双任务在开始前一同 heartbeat timeout 的结果。无需修改 watchdog 超时或对 worker/编码器做额外故障注入来完成本节。

## 3. 双标签页恢复与草稿隔离

1. 同一浏览器打开 A、B 两个标签。A 在编辑器中留下可辨认的未保存文字、布局和绑定改动，先不要刷新。
2. B 通过界面退出，再明确点击“进入本机模式”，取得新会话；也可使用自然会话过期后重新进入的等价场景。这样共享 cookie 已更新，但 A 页面中仍可能持有旧 CSRF。
3. A 点击保存。预期出现重新进入提示和入口，未保存草稿保留；不能卡在反复 403 后没有恢复出口。
4. A 明确重新进入。预期恢复本标签原未保存内容并显示恢复提示；只有再次点击保存才写入服务器，发布也需重新明确点击。核对 B 的当前会话没有被 A 注销。
5. 重新制造 B 退出并进入、A 留有未保存改动的场景，再以“发布”作为触发动作复验，确认恢复不会自动继续发布。
6. 切换 Runtime 目标或工程，核对不会把 A 工程草稿带到另一工程。账号隔离若没有可用的第二个合法账号，应写“未执行”，不要更改身份数据模拟人工登录。

这次缺陷的样本需要核对实际收到 **403 / `CSRF_MISMATCH`**。如果 A 在 B 退出与重新进入的间隙被轮询提前触发了 401，应单列为 401 恢复，不能用它替代旧 CSRF 的恢复验证；记录真实响应，不修改 cookie 或绕过鉴权来制造通过。

sessionStorage 不可用时的内存草稿恢复已有组件测试。人工环境若能通过正常浏览器设置合法复现，再单列验证；不能做到就列为组件已覆盖、桌面未覆盖。不以强制刷新作为本次修复成功的唯一出口，因为刷新会丢掉仅存在内存的草稿。

## 4. 日志查看与导出

通过可见界面操作当前提供的日志入口，记录入口名称、范围、筛选条件和文件格式。至少核验 Runtime 完整历史、当前任务/消费者日志以及发生异常时的设备相关记录。每个实际导出的文件都记录文件名、字节数、SHA-256、记录数量和首末时间/序号；检查筛选范围与界面选择一致。

可以用只读数据库/脚本校验界面导出文件的记录数与范围，这属于辅助证据，不能替代点击导出的人工步骤。未跑到的入口、格式、覆盖确认或多文件范围组合须逐项写明。

若出现长停顿、启动失败或图像不可用，额外保留：

- 任务/消费者/请求/cycle/resultOrdinal/Runtime 实例身份；用户点击 Stop 的准确时刻。
- heartbeat timeout 的 `heartbeat` 原始字段和 PID。
- 原始失败的 `outcome`、`diagnostics.deviceWait`、`diagnostics.deviceAction`、`cycleCleanup`。
- Runtime 全局日志中的 `device.ipc.failed / E_DEVICE_IPC_CLOSED` 及其 `deviceIpc` 字段。
- `presentation.export.retirement_failed`、导出结果诊断、相关原始 Runtime JSONL，以及恢复前后状态。
- 测试进程是否仍存活、同机其他工作负载、可取得的 OS 调度/资源观测。仅有时间间隔不足以断言 CPU 饥饿或驱动卡死。

monotonic 字段用于同一主机时钟域内的先后和间隔，不能直接当作北京时间；以事件 epoch 时间对齐界面和操作记录。

`heartbeat.seen` 只表示父侧消费过诊断心跳事件，不代表共享 cell 是否曾更新。若长停顿或双任务启动失败复现，按 [剩余因果复核第 5 节](remaining-causality-review.md#5-dot-最少需要额外保留什么) 保留同窗口、真实 PID 的阶段、线程等待和调度信息，尽量覆盖 watchdog 终止前；仅重跑一遍可见流程或再次导出 ERROR 摘要不足以确定这两项的底层原因。

## 交付

给出逐项通过/失败/受阻/未执行表、中文报告、关键截图、测试工程、页面包、原始日志、界面导出文件与校验记录。首次未就绪画面缺失、仅实时观察而未截图、未获得取消回执等证据缺口必须明确列出。

证据包上传后重新下载核对大小和 SHA-256 再宣布交付成功。上传超时且没有回执时，先查询或核验已存在文件，不把不确定结果算成功。

结论只覆盖实际执行的平台与设备。Linux 软件 Runtime 和模拟相机通过，不代表 Windows、真实相机或 PLC 通过。本轮不合并 PR、不发布 Release、不部署或改动现场工程。
