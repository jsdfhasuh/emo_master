# 算子输入文件与工程资源绑定核查

以下是修复前的核查记录。核查范围为仓库中 82 个内置算子。工程师在普通节点编辑器中选择新文件后，5 个算子可能仍然读取原先绑定的文件。受核查生产工程的现场第 5 版有 2 处节点文件绑定，只有 YOLO 检测的路径发生冲突。修复后的文件选择和写入行为见[工程格式规范](../project-json-spec.md)。

## 影响清单

| 算子 | 节点参数 | 有工程文件绑定时的运行行为 | 受核查生产工程的现场第 5 版 |
|---|---|---|---|
| YOLO 检测（`vision.inference.yolo`） | `modelPath`，检测模型 | 使用绑定的 ONNX 模型。图像和帧输入不改变模型选择。 | 已发生冲突。节点填写新模型的相对路径，绑定资源指向旧模型。现场任务的 11 次检测均使用旧模型。 |
| 单张图片加载（`vision.io.image_loader`） | `imagePath`，输入图片 | 使用绑定的图片。普通节点编辑器单独换图后，原绑定仍生效。 | 已绑定。节点与绑定指向同一张图片，当前一致。 |
| YOLO 分类（`vision.inference.yolo_classification`） | `modelPath`，分类模型 | 使用绑定的分类 ONNX 模型。 | 无此项绑定。 |
| 坐标读取（`vision.io.coordinate_reader`） | `filePath`，坐标文件 | 从绑定文件读取坐标。帧输入不选择坐标文件。 | 无此项绑定。 |
| 本地视频取帧（`vision.io.video_loader`） | `videoPath`，视频文件 | 用节点固定路径取帧时，绑定文件优先。若接入 `videoPath` 输入端口，算子使用上游传来的 Runtime 绝对路径；编辑器会提示文件由端口提供。 | 无此项绑定。 |

## 编辑入口与判断依据

普通节点编辑器读写节点的参数值。工程文件绑定独立记录“工作流、节点、参数 → 资源 ID”。Runtime 准备工程时，逐条检查绑定目标是否为打开单个文件的参数，并将该资源解析出的路径填入执行参数。因此，触发条件是同一字段已经有资源绑定，且后来只改了节点填写值。[Runtime 绑定解析](../../src/emo_master/core/project/runtime_directory.py) · [普通节点编辑器](../../src/emo_master/apps/designer/ui/main_window.py)

在这五项中，当前 Designer 的“工程资源 / 现场绑定”窗口只列出单张图片加载的输入文件作为绑定目标。工程编排接口也可以向其他打开单个文件的参数写入绑定，Runtime 会处理工程内已经登记的关系。视频和坐标没有专门的资源类别，下文对这两项使用工程中显式登记的绑定验证。[Designer 绑定目标枚举](../../src/emo_master/apps/designer/ui/resource_bindings.py) · [内置参数用途表](../../src/emo_master/core/project/snapshots.py) · [工程编排绑定命令](../../src/emo_master/authoring/drafts.py)

PatchCore 的模型部署目录、图片批量加载和文件列表的输入目录属于目录参数。图片保存和检测归档使用输出文件参数。这些字段不满足上述单文件输入绑定条件。数值型阈值可单独引用全局变量；现场第 5 版所有节点的全局变量参数绑定数为 0。

## 验证

- **现场证据**。沿用已远程只读核实的第 5 版配置、上述现场任务的节点完成事件，以及现场工程文件和运行副本的 SHA-256。其余四项的复现使用本地临时工程。
- **本地复现**。在无设备临时工程中，让五类节点都填写文件 A，另绑定内容不同的文件 B。通过 `RuntimeService.LoadProject` 准备和编译，再执行准备后的工作流。图片像素、视频来源、坐标内容和两种 YOLO 的实际模型指纹均对应 B。给另一个视频节点的路径端口传入文件 C，实际解码的是 C。
- **已有检查**。工程目录解析、视频算子、视频参数界面和全局变量文件绑定限制四组测试共 70 项通过。未执行现场生产任务或修改现场配置。
- **源码基线**。HEAD 为 `b75df0adb7a90a4e0b540ff1c8c09e9339cfcdbd`。核查使用带未提交改动的工作区，相关改动涉及 Designer 参数与日志显示、Runtime 资源处理、工程快照与编译。本轮仅新增此核查记录。
