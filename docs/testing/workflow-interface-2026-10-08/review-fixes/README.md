# 工作流接口审查后改进（2026-10-08）

## 使用方式与范围

- 双击 `Workflow Input` 或 `Workflow Output` 的标题、卡片主体，分别打开输入或输出页；标签菜单的“设置工作流接口”使用同一表单。
- 普通配置只需填写接口名称、选择数据类型；可新增、删除，支持自定义类型和列表类型，不需要填写 JSON。
- 每行“属性…”可编辑必填/可选要求、是否允许空值，以及语义数据的结构版本。`required`、`nullable` 都有“未指定”选项，保留字段缺省与显式 `false` 的区别。
- 取消属性窗口不应用属性；属性窗口确认也仅改变当前表单，仍需在主窗口“确认配置”。取消主窗口会丢弃整个接口表单的修改。
- 确认配置更新项目草稿，保存项目后才写入文件。原有引用节点同步、不兼容连线清理、运行中禁止编辑及模态结束后的运行状态检查继续生效。

只修改 Designer 接口入口、表单、鼠标事件生命周期及项目编辑会话的接口顺序比较；没有修改 Runtime 协议、项目文件格式、算子实现、示例工程或构建依赖。其他任务的相机、PLC、参数标题、工作流关系等未提交改动不纳入提交。

## 三项修复

### P1：取消模态窗口后，下次点击意外移动原节点

双击回调仍延后到当前原生事件返回后执行；打开接口模态窗口前结束该节点自身的场景鼠标抓取，避免第二次鼠标释放落在弹窗后，原节点一直被抓取。节点已销毁、切换工作流或关闭窗口时，丢弃过期回调。

真实 Qt 回归覆盖输入/输出、标题/主体、取消/有修改确认/无修改确认，并刻意将第二次鼠标释放发送到弹窗，再移动鼠标、点击另一个节点。验证节点位置、鼠标抓取、取消后的草稿签名和算子编辑器状态。

### P2：完整描述符不能编辑

增加属性表单，支持全部既有字段 `required`、`nullable`、`schemaVersion`。保持字符串与描述符、别名及字段缺省的原样往返，不静默降级或丢弃版本限制。改变语义类型后若版本不兼容，保留限制并提示；用户可明确取消“限制版本”来修正。版本值继续使用核心契约验证，不放宽校验。

测试覆盖两种方向的可选/空值配置、语义列表、有效/无效版本、明确移除属性、取消和无修改确认，以及 Runtime 的缺失键和空值判定。

### P2：仅调整接口顺序被当成未修改

主窗口使用有序条目比较。编辑会话在比较签名中额外记录输入/输出的端口名称顺序，让顺序变化进入脏状态、检查点和事务撤销/重做。此信息仅存在于内存比较中，不增加持久化字段；描述符字段等普通字典的键顺序仍不算修改，原有项目版本/时间元数据处理保持不变。

测试覆盖当前/非当前工作流、输入/输出、删除后重新添加形成的顺序变更、边界/子工作流节点刷新、撤销、重做、保存和重载，以及真正无修改时不追加历史。
