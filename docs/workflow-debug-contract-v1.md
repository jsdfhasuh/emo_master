# 流程调试控制契约 v1

状态：B0/B1/B2 实现与受限软件范围审查完成。本文约束已实现行为；通过情况及完整回归与末次窄修复的版本分界见 [实施与审查记录](testing/operator-step-2026-10-09/B0-B3-review.md)。设备、发布包和部署未验收，mypy 仍有既有基线失败。

## 所有权与配置

- 与单算子调试共用 Runtime 资源准入、租约、受监督 spawn 进程和资产格式。一个 Runtime 最多一个调试资源所有者。
- 使用独立调试身份，不创建生产 Job，不调用 LoadProject，不保存或应用草稿。
- 启动时冻结完整草稿。只允许已审查的算子；构造、编译和调用均在 Worker 内。设备、外部写入、资源根适配和第三方插件未开放。
- 本轮只运行一个根流程及其子调用，不协调其他流程，不实现恢复、回放、反向执行或配置热更新。
- 整份草稿按现有编译器验证；编译器可能创建参数校验实例，因此整份草稿中的算子均须通过准入，包括未到达的分支与未选择的工作流。不能用不可达节点绕过副作用审查。

## 控制状态

- STARTING -> READY -> RUNNING / PAUSE_REQUESTED -> PAUSED -> RUNNING -> SUCCEEDED / FAILED / CANCELLED。
- 只有 Worker 到达安全点才确认 PAUSED。命令接收不等于状态转换已经发生。
- 每条修改命令携带 requestId、会话 generation；推进或试运行还携带 pauseSequence。相同命令幂等，旧暂停序号拒绝，响应丢失查询原命令。
- READY 状态仅允许配置断点，不允许推进、暂停或试运行。Designer 启动前先下发断点并等待 Worker 确认，再启动流程；条件与命中次数从第一个可执行节点起生效。断点配置被拒绝时保持 READY，可修正后重试；确认结果不明时禁止启动，不自动重发。
- Runtime 通过 `preStartBreakpoints=true` 声明此能力。旧 Runtime 未声明时，无预设断点可沿用原启动路径；有预设断点则在启动前明确拒绝并提示升级，不静默忽略断点。能力缺失判断发生在发送修改请求之前，不能在确认丢失后降级重试。
- pauseSequence 必须是严格整数；即使数值相等也拒绝 boolean 或 float。Designer 只有在当前快照匹配已确认暂停序号时才启用推进、定位和试运行，不能使用上一暂停点的数据操作新暂停。
- 停止后不可恢复原现场；关闭确认进程、IPC 和工作目录退休后才释放资源。
- 心跳及 60 秒租约按真实时间运行，客户端每 20 秒独立续租。暂停累计时长仅从 Runner 的循环预算扣除。
- 单个活动算子和独立试运行各有 30 秒真实时间监督期限；暂停不触发该期限。长循环仍受配置的循环预算约束，也可随时请求暂停或停止。

## 安全点与身份

- 工作流输入/输出边界不消耗单步。普通算子、子流程、循环进入前可暂停。
- 进入：沿实际执行路径到下一个可执行位置。
- 跳过：完成当前节点，在本层下一位置或当前控制节点返回处暂停；内部断点仍可打断。
- 跳出：在当前调用的调用方返回边界暂停；根调用跳出等同运行至结束。
- 循环条件求值、循环体入口、迭代结束为可观察安全点；空循环也能响应暂停和停止。
- 单步进入不会消耗在循环内部传播上，进入实际执行的算子或条件工作流。内部循环安全点响应暂停请求，并记录有界位置事件。
- 静态断点使用 workflowId/nodeId；动态位置使用 jobId、workflowRunId、nodeRunId、callPath、iterationPath 和阶段，不复用上一轮的输出身份。
- 运行到此处只增加临时断点，不跳转、不执行未选中的分支。

## B2 边界

- 条件表达式仅允许标量、布尔运算、比较和受限字典/列表下标。禁止调用、属性访问、推导式和任意 eval；表达式长度、AST 节点数及求值深度有上限。
- 数值字面量可带正负号，列表下标支持负整数字面量；符号不可作用于变量或 bool，不允许非有限浮点常量、算术表达式或布尔隐式转换。
- 命中次数按静态断点累计，暂停时保留动态调用身份。条件错误以诊断暂停，不静默忽略。
- “命中起点”为累计经过该静态断点的次数下限，到达下限后的每次经过仍须满足条件。更新同一断点保留命中次数，删除后重建重新计数。
- 变量监视读取调试隔离存储，不读取或修改生产变量。
- 暂停节点试运行只开放审查过的可克隆纯计算算子，使用输入副本、独立实例和隔离变量快照。结果单独展示，不注入主流程。
- 试运行期间禁止恢复主流程。若试运行不能协作退出，需要终止整个受监督会话，不能宣称原现场仍可继续。

## RPC 与数据

共用有界 `OperatorDebugRequest` / `OperatorDebugReply` 消息，新增 `control_json`；RPC 使用独立 WorkflowDebug 命名空间，禁止拿单算子接口操作流程会话或反向混用。

| RPC | 职责 |
| --- | --- |
| GetWorkflowDebugCapabilities | 版本、已审查能力、控制命令及容量 |
| OpenWorkflowDebugSession / GetWorkflowDebugSession | 固定草稿、进程准入、会话和 Worker 状态 |
| PrepareWorkflowDebugInputs / StartWorkflowDebug | 类型化根输入冻结、一次启动 |
| ControlWorkflowDebug / GetWorkflowDebugCommand | 命令接收、Worker 确认或拒绝、响应丢失后的原 ID 查询 |
| GetWorkflowDebugSnapshot / ReadWorkflowDebugEvents | 实际调用数据与稳定事件序列 |
| WriteWorkflowDebugAsset / ReadWorkflowDebugAsset | 复用 PNG / JSON 有界分片资产 |
| RenewWorkflowDebugSession / CloseWorkflowDebugSession | 独立租约、停止、资源退休 |

每会话保留最多 32 个完整调用快照，当前暂停、最近试运行和最近输出受保护；过期快照明确报错，不复用 ID。缓存仍受 256 MiB 和单值 64 MiB 等 A 阶段上限约束。Worker 发送完整快照后等待父进程采用确认，父进程统一淘汰，避免读取已删除或被替换的资产。

失败保存第一处实际失败调用的身份和可保留数据，然后终止本次执行。不存在“继续失败节点”或自动重放。试运行结果单独标记，参数通过原 schema 和算子校验器检查。

## Designer 入口

在流程设计工作区的“编辑 > 流程调试”打开，F5/F6 保持原功能。填写根输入后启动，在第一个可执行节点之前暂停。断点表支持启用、条件和命中起点；表格选择节点后可运行到该位置。调用数据按实际身份保留输入/输出，图像通过资产读取，调用栈及隔离变量有独立页签。

启动时自动应用当前勾选的断点；下发与确认期间冻结表格和启动/推进按钮。启动后修改断点仍需点击“更新断点”。浏览历史快照不改变当前暂停位置，单步与“暂停节点独立试运行”始终针对当前暂停节点，试运行资格不由所选历史快照决定。

暂停节点独立试运行复用 SchemaParamForm，不另外引入原始工程 JSON 参数表单。定位按钮沿现有工作流导航选择节点，不覆盖生产节点结果。切换到子流程查看不会结束流程调试；工程或 Runtime 身份失效则关闭。

调试期间画布可继续编辑，但窗口显示启动快照及配置已更改提示；更改不热注入。正式运行入口在已有调试窗口活动时拒绝启动，不自动保存或关闭调试；Runtime 原子准入仍是跨客户端的最终约束。

## 验收

必须覆盖嵌套调用、重复调用身份、循环、分支、旧命令、暂停预算、断连与停止退休；正常 Runner 的调试控制器为 None，必须保持原有行为。软件测试不等于设备、冻结包、部署或现场验收。
