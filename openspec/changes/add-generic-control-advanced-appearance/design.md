# 通用页面控件高级外观设计 v0.7

## Context

本设计采用 2026-11-20 核实的 `main` 提交 `6cbff0dcbea671663cf9ab773c6ce5c81690da35`。前版图稿的代码基线是其父提交 `6c19ef8a`；附图使用仓库历史截图，新增界面和效果均为待实施原型。

当前 Qt 与 Web 已经使用共享页面定义，但分别实现编辑和显示。Qt 的卡片、标题、主值等直接设置局部 QSS，状态更新可能重新写样式；Web 多处通过 React 行内 `style` 设置外观。另有图像背景、SQLite 列表等自绘部分。添加代码输入框不足以完成能力，必须打通相应应用入口。

现有模型有 14 种组件类型。本 change 完成 13 种可见类型和 2 个页头宿主按钮，`spacer` 保持布局用途。实施可以先贯通三种代表组件，但交付判定以完整覆盖表为准。

## Goals / Non-Goals

### Goals

- 在原 Designer／Web 布局中提供可发现、可编辑、可预览的高级外观入口。
- 通用表单负责跨端基础效果；原生 QSS／CSS 提供当前端的进一步定制。
- 当前对象的配置在确认、撤销、复制、保存重开、数据刷新及对应运行显示后保持正确。
- 为每种控件公开实际存在的样式部位，保证示例选择器能命中真实对象。
- 使用现有模型、会话、资源、草稿、发布及渲染模块完成局部扩展。

### Non-Goals

- 不建立独立样式服务、主题市场、双端实时同步或任意代码互转。
- 首版不增加页面级原生样式与组件级代码的全局级联。
- 不改变设备、算子、结果绑定、页面动作或 Runtime 启停归属。
- 不将检测框、测量标注等图像内容绘制统一转换成 CSS／QSS。
- 不为样式需求额外新增表格选行、分页或历史业务能力；只适配现有模式。
- 不增加全部属性组合、极端故障、跨版本混用或性能专项作为完成门槛。

## Decisions

### D1. 以完整覆盖表约束实现

[component-coverage.md](component-coverage.md) 是对象与部位范围。每类至少有一个常用字段和一个本端代码规则实际生效，并能从相应作者端进入。不能只为所有类型显示同一个代码框，却只让按钮产生效果。

类型之间共享入口、保存结构、作用域与预览流程；可用字段和选择器按真实渲染对象生成。按钮四态只用于按钮；状态行使用已有业务状态；图片和表格按实际部位显示选项。

逐类型“一字段＋一规则”是覆盖抽样，不是全部高级能力的验收。自定义颜色、边框宽度／线型、图标位置／尺寸／间距和按钮四态，须各在一个适用对象上验证两端效果。文字、数值、时钟和数据库数值的原生样例必须命中实际文字部位，表格样例命中表头或已有 item；不得用所有对象外框变色替代内部部位支持。

具体回放使用 [examples/target-effects.md](examples/target-effects.md) 的参数，从原入口完成编辑、局部预览、确认、保存及运行。复用同一示例工程和证据，已有字段与新增代码组合后的文字、圆角和内距也应正确，无需逐字段全排列。

### D2. 就地扩展共享外观定义

优先扩展 `Surface`、`TextRole`、`IndicatorStyle`、`ControlAppearance` 等现有定义，不建立第二套主题配置。已有属性继续复用，不重新作为新增功能实现。

| 内容 | 本次增量与默认关系 |
| --- | --- |
| 颜色 | 保留原语义色，增加可校验的 `#RRGGBB` 自定义颜色；Qt／Web 使用相同颜色语义。背景透明继续使用既有透明含义。 |
| 边框 | 增加可选颜色、宽度、线型；未提供的字段继续使用原默认值。 |
| 图标 | 对有图标的按钮增加尺寸、位置和图文间距；资源与动作图标沿用当前机制。 |
| 按钮状态 | 为默认、悬停、按下、禁用提供按需覆盖；未填写的状态字段继承该对象基础配置。 |
| 原生代码 | 在 `VisualProps` 和 `ControlAppearance` 追加同型可选 `customStyle`。 |

拟定保存结构如下，字段名在实施时应作为同一契约同步到所有生成物：

```json
{
  "customStyle": {
    "qtQss": { "enabled": true, "code": "..." },
    "webCss": { "enabled": false, "code": "..." }
  }
}
```

- 普通组件：`component.props.customStyle`。
- 页头按钮：`presentation.shell.startControl.appearance.customStyle` 与 `stopControl.appearance.customStyle`。
- 缺省字段或空代码：使用基础外观。关闭开关：停止应用并保留代码。
- 修改一端的代码、开关或通用表单：原样保留另一端代码。
- 可选字段进入发布模型与契约生成，不能绕开严格模型校验临时塞未知键。

“清空自定义代码”只把当前对象、当前语言的 `code` 置空，保留当前开关值、通用配置、状态配置和另一端代码；空代码显示当前通用配置与适用状态。清空也属于弹窗草稿，取消后不提交。普通外观分组恢复默认只处理该组字段；现有“整个页头恢复默认”仍是清除整个页头配置的显式操作，不与停用某端代码混为一谈。

生成示例工程时读取实施 HEAD 的正式格式。核查基线记录工程 2.10、页面 1.3；不把历史截图或旧工程作为生成模板，不只修改版本号伪装升级。

### D3. Designer 保留原入口与弹窗语义

普通组件：选中对象 → 浮动属性面板的“外观” → 新增“高级外观…”。它与“组件外观与表现…”打开同一个设置流程，直接定位高级区域。`spacer` 不显示该入口。

弹窗由常用字段、自定义 QSS、选择器提示、局部预览和确定／取消组成。内容可滚动，代码区可调整大小。开关、代码、预览均属于本次弹窗草稿；代码编辑不逐键修改工程主模型。

- 预览使用实际 Qt 控件及相同样式应用函数。短暂编辑停顿后更新预览，避免每次按键重建完整页面。
- 按钮预览展示真实样式状态，但不连接任务或导航动作；判定控件使用既有状态映射的示例值。
- 确定经现有 `session.editPresentation()` 一次提交，更新主画布，并进入现有撤销记录。
- 取消、关闭、Esc 丢弃本次弹窗草稿。打开前 `commitPending()` 已提交的其他属性不属于该取消范围。

页头开始／停止按钮继续从“页面设置 · 全局外观… → 页头 → 对应按钮外观”进入，沿用页头自定义开关。它们仍是宿主控件，不改为可拖放普通组件。

### D4. Web 使用自己的 CSS 编辑与预览

在现有右属性区“外观”组增加高级入口。原属性区较窄，代码编辑使用可调整大小的弹窗；保持现有顶部工具栏、工具区、画布和属性区关系。

Web 弹窗遵循相同草稿／确定／取消含义，使用实际浏览器组件预览 CSS。确认后沿用现有撤销和草稿修改流程，保存／重开／发布使用现有接口。宿主按钮从运行页头的对应分组进入。

本次局部预览、现有编辑画布、已有预览入口和正式运行页共用样式处理；需检查 `Editor.tsx` 的画布实现，不能只改正式 `PanelRenderer`。不增加独立预览引擎、另一套渲染模型或没有现成需求的预览模式。

### D5. 稳定部位与当前对象范围

拟定 Qt 部位属性 `emoPart`，Web 使用 `data-emo-part`。常用部位包括 `root`、`title`、`value`、`helper`、`marker`、`action`；图片／表格／导航按实际对象补充 `viewport`、`table`、`header`、`tab` 等。

仅列出该对象实际拥有的部位；不存在的部位不生成示例。文本可能是 `QLabel` 或 `QTextEdit`，不能统一硬编码 `QLabel`。表格单元格由原生 item／delegate 绘制，不能伪造每格的 QLabel 选择器。

部位归属优先复用现有组件身份，并区分实际并存的预览／运行实例；仅在渲染处补充必要标识，不建立独立所有者注册服务。当前对象规则只直接命中其拥有的部位，复制组件时重新绑定。嵌套容器的子组件独立；仅给选择器加容器祖先前缀不足以保证这一边界。

- Web：需要解析或改写选择器时复用成熟解析能力，仅处理本版支持的规则形式；给直接命中元素附加当前对象约束，保持根、内部部位和子组件边界一致。
- Qt：为真实对象设置必要标识，协调当前对象控件／子控件与已有叶子局部样式；声明的语义和绘制交给 Qt，不自研完整 QSS 解析／求值器，不把代码挂在整个 QApplication。
- 图第 08 页已提供 `marker`，本轮必须把判定控件当前拼入主值的圆点接入真实独立部位，并保留原位置、显隐、颜色联动与业务值；Web 对应标记使用相同语义。不为没有圆点的组件新增该部位。

对公开的文字颜色、字体等常用继承属性，嵌套子组件应继续使用自己的基础配置，即使它没有自定义代码也不能被父容器意外染色。沿现有组件基础样式显式保留这些值即可。容器尺寸和内距产生的正常布局变化不算样式外溢；本期不建设任意 CSS／QSS 的全属性隔离沙箱。规则直接命中和一个字体／颜色继承场景合并验证。

选择器列表和通常的伪状态纳入首版。QSS 的 `qproperty-*` 不作为自由属性入口，图标尺寸等由常用字段控制。CSS 首版支持组件内普通规则、选择器列表与适用伪类；其他 at-rule 未支持时应明确提示，不能默默存为“已生效”。不嵌入 JavaScript。

`#RRGGBB` 是通用表单的跨端字段格式，不因此把原生代码中 Qt／浏览器已经支持的颜色或其他普通声明全部缩减为一套自定义白名单。这里需要的是部位、作用域和少量明确限制，不是新样式语言。

### D6. 定义可解释的覆盖关系

应用顺序为：当前默认外观 → 该对象通用配置 → 当前适用状态配置 → 已启用的本端代码。代码内部仍遵循本端选择器规则，并非把字符串放到最后就能覆盖所有声明。

Qt 要在 `appearance.py`、`shell.py` 及相关渲染入口生成最终样式，处理卡片、标题、主值和按钮的现有局部 `setStyleSheet()`。数据刷新后使用相同合并入口，不能用基础样式把用户规则冲掉。沿用已有样式比较，不额外建设缓存、依赖追踪或性能专项；必要的状态更新仍按原路径完成。

Web 将可自定义覆盖的外观行内声明整理为可协调的基础规则，使普通用户规则能按约定覆盖；布局、尺寸与业务状态来源仍由原模型负责。避免要求用户给所有属性补 `!important`。

停用或清空代码可回到当前通用设置与适用状态。按钮真实禁用条件、选中页、检测判定仍由原业务状态驱动；预览选择状态不写入真实业务状态。结构化状态外观按当前状态选取，原生规则按上述覆盖关系应用；系统不新增颜色“是否合规”的业务判定器，也不偷偷覆盖用户选择的颜色。

### D7. 图片、表格与导航有明确适配工作

| 现有实现 | 必须完成的接入 |
| --- | --- |
| `ImageView.paintEvent()` 直接填背景 | 将背景交给可样式化视口／Qt 样式绘制，或让绘制使用同一外观解析结果；换帧后不得恢复固定主题色。检测图像与标注继续使用原内容绘制。 |
| 集合表格、SQLite 表格／列表 | 使用真实 QTableView／QHeaderView／QListView 的部位及子控件规则；保留原分页、筛选、选择和数据行为。 |
| `_RecordListRow.paint()` 自绘 | 将常用外观和公开支持的原生 item 样式接到选中背景、标题／副标题等实际画笔／样式选项；先验证样式未被固定主题颜色覆盖。状态徽标继续按业务状态映射。 |
| `PageNavigation` 的 tabs／buttons 模式 | 分别暴露 QTabBar 的 `::tab:selected` 与可选中 QPushButton 的 `:checked`；Web 提供真实选中属性对应的提示。 |

原生规则只承诺本轮公开的实际样式部位。可以采用局部适配函数或必要的小型部位映射；不为此创建通用主题引擎或重写所有表格结构。

自绘适配优先让 Qt 样式绘制／样式选项承担可样式化背景、字体和颜色，再保留既有内容绘制；必要时只适配少量已公开属性。不把任意 QSS 手工翻译为绘图指令，不重建通用绘制引擎。

### D8. 保存、发布与资源沿用原路径

Designer 工程保存和页面发布保留两端样式。Web 继续使用独立 SQLite 草稿及 `build_package()` 生成发布数据，不自动回写 `.emoproj`。`PublishedProps`、`PageShell` 和投影函数需检查字段是否保留。

样式资源沿用现有工程资源标识与导出路径；图片资源选择继续通过已有表单完成。首批代码示例只使用颜色、边框、字体和状态规则，不建立任意外部资源下载机制。

按现有契约生成脚本同步本次字段涉及的 Schema、TypeScript 和 SDK 生成物，不扩成独立 SDK 兼容项目；无新增字段的正常页面沿用默认值即可，不建设额外迁移框架或历史版本矩阵。

### D9. 诊断与示例保持可验证

编辑器复用能取得的解析／应用反馈，提示明显结构错误及本版明确不支持的规则；不要求完整属性语义校验、选择器命中统计或自动修复。检查通过不等于规则已经命中，对公开支持的部位仍以实际效果为准。

已明确识别的错误仍存在且当前分支启用时，保留代码草稿并阻止确认；用户可修正，或停用该分支后保存文本。错误预览直接回到当前通用外观并标明“当前代码未应用”，不额外维护最后有效预览版本缓存。未被基础检查识别的声明仍按 Qt／浏览器实际能力处理，不承诺任意原生代码都有效。

包内 `examples/` 是计划阶段写法；实施时应由实际选择器提示导出／核对并替换。每类 Qt／Web 至少一条规则产生可观察变化。实施配置、代码和真实运行截图使用 v0.7 `target-effects.md` 的同一组参数；v0.6 图稿保留为布局、风格和交互参考，不从其像素反推配置。业务状态示例不通过给所有主值固定绿色掩盖真实 NG／空值等状态。

完整验收分为全类型的基本效果、代表对象的共享流程、不同渲染路径的必要检查；同一次操作可满足多个规范场景。选择能够证明结果的现有自动化或实际界面操作即可，不要求每条场景同时提供单测、集成、UI 自动化和人工录像。

## Risks / Trade-offs

| 实际风险 | 最小处理 |
| --- | --- |
| Qt 子控件自有 QSS 或刷新覆盖原生代码 | 在公共应用入口合并，覆盖状态、时钟、图片和表格的正常刷新。 |
| Web 行内样式优先于代码 | 整理可覆盖外观声明，提供明确的基础层与当前对象用户规则。 |
| 嵌套容器规则命中子组件 | 明确对象所有者，验证相邻／嵌套／复制三个正常场景。 |
| 自绘部位显示入口却无法生效 | 接入实际绘制；用真实样例数据验证，不以占位提示代替。 |
| 两端原生语法不同 | 分别编辑和预览；通用配置比较语义，不要求逐像素一致。 |

## Migration Plan

1. 读取实施 HEAD、仓库 AGENTS 与正式格式，核对后续提交是否已完成部分工作。
2. 先接通共享字段与保存发布，再以代表组件贯通两端，随后按覆盖表完成其余类型。
3. 现有无自定义代码的页面按缺省值继续运行；启用开关可以停止代码应用并保留内容。
4. 用正常新建／保存路径生成验收工程，包含数据库样例与所有可见类型，记录实际环境和提交。
5. 所有必要任务完成并形成证据后才归档；计划格式验证不能代替功能验收。

## Open Questions

没有需要用户再次确认的范围问题。字段的具体代码组织、样式诊断组件选型和局部适配实现由执行者按现有模块作常规工程决策，并在影响可观察行为时更新本设计。不得因此减少 13＋2 的覆盖范围。
