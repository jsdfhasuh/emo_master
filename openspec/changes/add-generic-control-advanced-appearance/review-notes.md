# 高级外观计划审查与修订说明

审查日期：2026-11-20。原计划 v0.6 → 修订计划 v0.7。完整范围仍为 13 类可见组件＋2 个宿主按钮，36 项实施任务仍全部未完成。

## 结论

原方案的实现方向成立，没有必要推倒重写，也没有要求 30 套测试脚本、全属性组合、硬件矩阵或完整 CSS／QSS 编译器。不能把任务、规范场景和验收表的重复描述简单相加，称为三套测试。

需要修正的是两类问题：一类措辞可能诱导执行者建立额外框架或重复验收；另一类验收过弱，可能出现入口和字段完成了，但图标排列、内部文字、独立圆点等实际效果仍欠缺。v0.7 已收窄前者并补齐后者。

修订后，从需求、接入位置和验收判定上能够覆盖本轮确认的功能预期。当前仍是计划，不能据此声称新功能已实现，或保证未经实际运行的最终视觉质量。

## 1. 过度防御和实现边界

| 审查项 | 原文实际问题 | 修订结果 |
| --- | --- | --- |
| CSS／QSS 解析与诊断 | 原文并未要求完整自研解析器，但只写“解析”“检查”可能被扩大成语义分析或自动修复项目 | D5／D9 明确复用成熟能力；只做作用范围、公开规则形式和有限反馈，声明语义交给 Qt／浏览器。不增加命中统计、自动修复或普通属性的第二套白名单 |
| 所有者隔离 | 必须保留，但“子组件不受影响”不宜扩展成任意属性、布局和继承的完全沙箱 | 复用组件身份，限定直接命中；对子组件自身字体／颜色保留基础值。正常容器布局影响不算外溢，不建注册服务或全属性隔离框架 |
| 自绘适配 | 将所有 QSS 手工翻译为 QPainter 指令会超出本轮需要 | 优先使用 Qt 样式绘制／选项及少量已公开属性适配，保留原内容绘制；没有删除图片与 SQLite 的真实适配要求 |
| 样式重复应用 | 固定基线已存在样式比较，不能将它误判成没有依据的新优化 | 沿用 `appearance.py`、`shell.py` 的既有比较；不新增缓存、依赖追踪或性能专项门槛 |
| 多个预览名称 | 应接入现有显示入口，不能据措辞再建几套预览产品 | 一个实际局部预览，复用原画布、已有预览和正式运行处理；无新渲染引擎 |
| 状态颜色约束 | “状态配色正确”可能被解读成强制某颜色代表某业务含义 | 保留业务值、映射和动作条件；通用状态字段与原生规则按声明优先级应用，不建立颜色合规判断。交付样例仍应能看出不同结果 |
| 默认工程可用 | 无新增字段仍正常显示是必要的默认行为，不是额外迁移工程 | 保留缺省值；不引入历史版本、跨版本混用或迁移矩阵 |

CSS 的颜色等属性确实可能经父元素继承；只给选择器添加所有者约束不能自动阻止这种继承。因此嵌套验证保留一个没有自定义代码的子组件，直接观察其基础字体／颜色即可，无需恶意输入矩阵。依据：[MDN CSS 继承](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Cascade/Inheritance)。

既有样式比较和局部应用依据：[appearance.py](https://github.com/jsdfhasuh/emo_master/blob/6cbff0dcbea671663cf9ab773c6ce5c81690da35/src/emo_master/ui/presentation/appearance.py)、[shell.py](https://github.com/jsdfhasuh/emo_master/blob/6cbff0dcbea671663cf9ab773c6ce5c81690da35/src/emo_master/ui/presentation/shell.py)。本轮没有改产品源码。

## 2. 测试如何减到必要程度

| 验证层 | 保留的最小工作 | 不要求的重复工作 |
| --- | --- | --- |
| 全类型基本效果 | 13 类＋2 按钮，两端各看一个适用常用字段和一条原生规则；复杂控件命中实际内部部位 | 不为 15 个对象分别建立工程、独立截图或全流程脚本 |
| 共享编辑流程 | 每端用代表组件从真实入口完成编辑、预览、确认／取消、撤销；宿主独立入口补基本确认 | 不逐控件重复全部弹窗与生命周期操作，不同时强制人工与自动化两套证据 |
| 保存发布 | 一份含各类配置的工程／草稿，走各端原有保存重开和发布路径，核对另一端代码未丢失 | 不逐控件单独发布，不建立双向同步或 SDK 兼容矩阵 |
| 不同渲染路径 | 状态、时钟、图片、表格各一次正常更新；图片自绘、SQLite 列表、导航已有模式分别接通 | 不做颜色／字号／模式／平台全排列，不加压力或故障注入专项 |
| 对象范围 | 同一页合并相邻、嵌套、复制和一个字体／颜色继承检查 | 不做选择器攻击库或全属性沙箱测试 |
| 宿主动作 | 每端各一轮软件 Runtime 正常开始／停止，复用同一个受控工程 | 不要求相机、PLC、机器人、生产工程或所有运行模式 |
| 示例与交付 | 正式格式的工程与 Web 包、实际截图、必要部位说明；新建／修改示例工作流才做已有编译校验 | 不扩为工作流调度、设备、通信专项，不重新绘制全部 14 页方案册 |

项目原来必须通过的门禁照常执行。这里约束的是本 change 新增的验证量，不表示可以绕过既有门禁。同一操作和证据可同时满足 requirement、task 和 acceptance 条目。

## 3. 真正影响预期效果的缺口

### 3.1 类型接通不等于新增能力齐全

原“一字段＋一规则”允许拿已有字号和外框变色完成多项记录，无法证明新配色、图标位置／尺寸／间距、四态及内部主值已实现。

已在 D1、任务 4.2／5.1／6.2 和验收第 4.1 节明确：常用高级字段必须能从界面编辑；文字／数值类代码必须命中实际文字，表格命中表头或已有 item。新增能力在代表对象上组合回放，不增加全类型全字段测试。

### 3.2 图里公开的 marker 不能“选择不做”

第 08 页已经列出 `marker`，原文却保留“如果公开”的条件句。现已明确在判定控件落实真实独立部位，保持位置、显隐和状态联动；不会给全部组件强加圆点。

### 3.3 错误预览与确认必须一致

原文允许错误时显示最后有效或基础预览，却没规定错误启用代码是否可以确认。现明确：已识别错误时，当前分支启用则不能确认；可修正或停用后保存文本。预览显示当前通用外观并标明代码未应用，省去最后有效版本缓存。

这是一个已知错误的正常编辑行为，不是承诺检测任意 CSS／QSS 错误，也不引入复杂恢复系统。

### 3.4 清空范围不能误删别的配置

现明确清空仅将当前对象、当前语言 `code` 置空，保留开关、通用字段、状态与另一端代码；清空后取消不提交。恢复的是当前通用配置，不是出厂主题。整页头恢复默认仍沿用其独立的显式操作含义。

### 3.5 用一份参数回放目标效果

新增 [examples/target-effects.md](examples/target-effects.md)，补齐启停、方向／复核结果和角度数值的表单参数及代码对应。保留原 14 页图作为布局／交互参考；实际配置、代码与截图以这份参数记录对应，避免执行者按图稿缩放猜字号或临时手调未记录参数。

## 4. 完成后应能实际做到

| 用户预期 | 修订后的完成依据 |
| --- | --- |
| 在我原来的 Designer 里操作 | 原浮动属性面板入口与原弹窗；实际启动作者端，从入口完成一次操作，不只调用渲染函数截图 |
| 多数控件可用 | 13 类＋2 宿主逐项覆盖，复杂控件实际内部部位有结果 |
| 普通选项和 QSS／CSS 都能改 | 新增常用表单实际可用；原生规则可覆盖支持部位，并保留未显式覆盖的基础字段 |
| 改后效果与预期对应 | 右侧图标 12 px／间距 6 px、按钮四态、方向左边框 4 px、真实主值字重及数值卡配色可回放 |
| 保存、发布、运行后仍正确 | 各端原路径往返保留配置，正常状态／数据更新后仍生效 |
| 不影响原检测与启停 | 预览不执行命令，真实值、绑定、目标和可用条件保留；软件 Runtime 正常启停通过 |

没有要求跨端逐像素相同、任意原生语法全支持、整页主题级联、CSS／QSS 自动互转或新业务动作；这些不是本次已确认的实现目标。
