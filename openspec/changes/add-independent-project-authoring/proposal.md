# 独立工程草稿与 MCP 编排服务

**交付版本：V7.1 · 实现审查修复版；日期：2026-11-13。**
**同一变更：`add-independent-project-authoring`；固定审查提交：`3f717510751f4bd0d8277c3c2bf676236f51f49e`。**

本版在 V7 上收敛修复，不创建第二个功能变更，也不要求从头实施 A–D。V7.1 是文档修订号，不是 SDK、协议或产品版本。原始 V6/V7 归档和历史验收证据不改写。

## Why

原目标不变：AI 不打开或控制 Designer，通过真实能力发现、独立草稿、资源、校验/预检及正式交付生成可继续编辑的工程。固定提交已有这条主干和 Sol 的首轮验收记录；实现审查发现 CI 接入、节点复制资源引用、保存/导入后的声明恢复、预检准备响应性及导出检查状态仍需修复。不能把定向首轮通过记录当作当前“无遗留问题”的证明。

本轮任务是复核并关闭这些具体缺陷，而非增加新产品范围。CI 失败为上轮已读取的历史日志事实；复制/恢复/响应性问题主要来自静态调用链，实施者须在当前工作区用直接场景确认。若后续提交已正确修复，复用并记录证据，不重复修改。

## What Changes

- **F1**：修正已观察的五个类型错误，并在干净 CI 同款环境核对 `httpx`/可选 MCP 测试依赖；不关闭类型检查，不把 MCP 变成基础 HTTP 必装项。
- **F2**：区分历史 SDK 1.5.0 交接快照与当前协议生成物，修正校验绑定；保留历史原字节/摘要、当前生成检查及有意义的兼容性验证。
- **F3**：`node.copy` 在同一事务中保留指向原节点的资源/现场参数绑定，重定向新节点，复用资源字节。
- **F4**：让已保存、重启或导入的草稿有正常的声明恢复/重新采用路径，依据明确目标与工程依赖版本；离线无声明仍可如实 INCOMPLETE。
- **F5**：将候选冻结、资源检查、复制、压缩及摘要等阻塞准备移到已有工作线程边界，同时保留实际工作拥有资源和取消后清理的语义。
- **F6**：导出区分“未附带报告/导出本身没做检查”与“此版本未预检”；只有完整匹配草稿、修订和目标身份的报告才能附为已通过。

原有五项能力、A–D 功能目标和 G1–G7 验收仍保留。六项修复复用现有验收组，不增加七套新测试框架。具体新增待办为 tasks.md 的 6.0–6.7；原 0–5 的完成记录按固定提交保留为历史，不代表修复版已经验收。

## Capabilities

### New Capabilities

沿用尚未归档的 V7 变更中的五项新增能力，不重复创建近义能力：

- `project-draft-authoring`：完整独立草稿、事务、复制、保存与恢复。
- `operator-capability-discovery`：真实目录、未知信息与已有草稿的声明采用。
- `project-resource-delivery`：资源引用、正式导入导出、报告关联和字节交付。
- `candidate-project-precheck`：固定快照的无执行预检及非阻塞准备/工作所有权。
- `mcp-authoring-access`：HTTP/MCP 同一业务入口、实际工具契约及可选 SDK。

### Modified Capabilities

在参考提交中，这五项仍属于同一活动 change 的新增能力，因此沿用其 `ADDED Requirements` 组织，不因修订号变为 V7.1 就自动写成主规范 `MODIFIED Requirements`。执行时若用户已在后续提交归档该变更，先比较现有主规范并记录实际落点，不覆盖、撤销或重复归档。
