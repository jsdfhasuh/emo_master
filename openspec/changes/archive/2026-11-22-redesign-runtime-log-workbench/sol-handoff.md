## 实现时不能遗漏的接线

- 仍只有一个 `RuntimeGlobalLogs` 常驻读取源。最近页与有限补齐沿用现有查询链路，不能给每个 Job 再开长期订阅。
- 已加载范围的树筛选和现有服务端历史范围查询都保留。不能以已加载 200 条可搜索替换原本可检索历史的高级条件。
- 新 Job 页面必须连接完整范围导出。缓存导出不等于此 Job 全部可查询记录，仍复用固定上界和前向分页导出。
- 执行身份按真实字段关联。无证据时显示缺失或未确认，不按名称、最近时间或缓存位置猜当前节点、父调用、设备轮次。
- proto / 合同生成物通过仓库脚本生成，不手改镜像，不借此次改造迁移桌面栈或重写 Web 日志系统。
- 通用详情直接解释选中 node.started / completed / failed / skipped 的 ioSummary / metrics / diagnostics 和实际原因字段；这是必需项，不依赖 node.log。YOLO 现有检测数量和耗时在完成事件的 metrics 中，整数加法可只有标量输出摘要。不要为满足界面覆盖给 82 个算子补重复日志。
- 算子日志从 node.log.payload.data 取得主动记录字段；message / level / code 与执行身份按事件读取。默认易读页区分 0 / false / null / 空字符串 / 空数组，原始页复用 LogJsonTree。结构一致的简单对象数组可表格化；未知 key 不猜单位，lifecycle 不猜初始化 / 销毁。
- 展开与复制只基于当前收到的数据；保留截断 / 脱敏说明，不宣称原始页能恢复发布端已裁剪的数据。不要重写 logger 协议，不为每个算子新建专属渲染器，不将所有算子参数和输出额外写入日志。
- 当前事件直接读取，不为每次点击跨事件查询。已加载关联摘要单列其来源和执行身份，不合成后冒充原始事件。历史结果和图片必须匹配所选执行且实际可用；不拿最新结果替旧轮次，不新增全轮图片历史库。
- 单算子调试继续在既有 OperatorDebugWindow，复用同一个 Qt 详情组件或格式化适配点。ReadOperatorDebugEvents 读取 wrapper 的内层 event；GetOperatorDebugExecution 读取同 session / generation / executionId 的结果。它没有自动 node.completed / ioSummary，不造 Job、不新增 RPC、持久副本或轮询器。inputSources 只是来源说明，finishedAtMs 不能当日历时间。保留原有 PLC 日志与结果查看能力。
- 预览只解释当前已收到的失败消息和附带日志，成功预览持久日志流不在本期。旧事件 mode / totalIterations 缺失时显示未记录，不新增工程定义回查与补推断。

## 原生界面验收

用软件 Runtime 和可控测试设备执行两条路径，记录是人工操作还是原生 UI 自动化：

1. **While / 连续运行任务与单算子调试**：产生告警 → 查看调用 / 轮次上下文 → 定位当前 → 节点执行摘要 / 主动数据 / 原始树切换及复制 → 开关详情抽屉 → 下钻设备诊断 → 返回原事件；同时验证历史阅读、加载更早、运行时间和信息区收起。在同一走查追加一次软件单算子调试，查看独立日志与同次结果，不新增第三套走查。
2. **Runtime 重启后的历史任务**：查最近 / 更早历史 → 使用原有高级范围查询 → 打开具体 Job → 导出完整 Job → 检查导出内容和固定上界范围。

原型可点击、OpenSpec 校验通过、单元测试数量增加，不能替代原生界面接线验收。真实设备、打包产物或远程 CI 没执行就写明未执行，不能把软件模拟或源代码测试记为这些环境通过。
