## 沿用 R2 的实施范围

1. **收紧实施与回归范围。** 统一使用“本期必做 / 按实际影响触发 / 保留约束”。日常主链、视觉和日志接入必须完成；未触及的 Runtime 内部模块不自动变成本次重新实现、逐项重验的任务。
2. **限定日志共享抽取。** 只抽取工作台实际需要的模型、Qt 组件和读取能力；完整 RuntimeClient 仍位于 Designer，不整包迁移，不新建通用 SDK。
3. **明确读取和启动语义。** 单一读取驱动限定在每个宿主内部；不同客户端可独立观察。保留 EventStore→JSONL 投影。轻量启动准入与完整 StartJob 预检保持原职责。
4. **删除机械测试配额。** 不要求每个修复固定新增一正一反；只补现有测试未覆盖的实际行为风险。
5. **用有限事件验证日志阅读。** 历史位置、固定上界、去重和增量更新使用确定性夹具，不默认要求长时间运行或压力专项。
6. **收紧视觉与多端验收。** 默认尺寸保留代表视图；窄窗口至少检查 StartupPage，其他按实际布局影响追加。Web 定向验证仅在相关实现或共享契约受影响时追加，既有必需 CI 保留。
7. **复用验证证据。** 同一相关源码版本的一次执行可覆盖多个验收项；P9 汇总结果，相关修改使证据失效时才重跑。
8. **纠正规格与证据表述。** 增量规格使用操作段头；原日志来源规则明确 Designer 宿主作用域。R1 原型的模拟局限如实列出。

## 使用方式

将本目录放入目标仓库的 `openspec/changes/`。若已有同名 Change，先比较并合并本轮差异，保留实现者的实际进度与证据；不要覆盖 `openspec/config.yaml`、正式 specs、其他 Change 或无关工作区改动。

阅读顺序：`proposal.md` → `design.md` → `tasks.md` → `acceptance.md`。实施清单以 tasks 为准，触发规则与完成条件由本版设计和验收共同约束。

在仓库根目录验证：

```bash
openspec validate runtime-platform-overall-v1 --strict --no-interactive
```

包生成阶段的实际校验版本、范围、结果见 [validation.md](validation.md)。CLI 通过只说明 Change 规格校验通过，不证明 Runtime、Qt 或设备功能通过。

## 完成范围

本期同时交付 Operator 原生视觉、共享 Job 工作台、原有本机日志和日常运行主链。Runtime 继续负责执行、工程、Job、设备和结果；总体目标不缩成单独日志页面。

未改动且无传递影响的内部能力保留既有约束和基线证据，注明“本轮未重跑”。不把历史证据写成本轮 PASS，也不为了把整张表变成 PASS 扩大实现范围。产品源码、现场设备和冻结包的状态与计划文档校验分开记录。
