# Operator 视觉基准与截图说明（R2）

## 原始参考

- `screenshots/operator-startup-before.png`：用户原起始/设置页截图。
- `screenshots/operator-production-before.png`：用户原生产页截图，作为同一产品的浅色视觉基准。

这两张改版前参考图随计划包原样保存在本地，包含工作站和工程信息。公开仓库的实施截图见 [Windows 原生 Qt 验收](../verification/native-qt/native-runtime-r3.json)。

## 保留的改版目标

- Operator 自有起始/设置、日志、设备与生产页采用一致的浅色视觉语言。
- 浅灰蓝背景、白色表面、细边框、适度圆角；蓝色用于主操作/选中，状态色有明确语义。
- 标题、路径、辅助说明、状态、诊断层级清楚；统一控件、焦点和禁用态。
- 起始页保留工程/最近日志、本机目录和远程接入内容。
- 生产页仍由工程 Presentation 决定，工程自定义 QSS 不被覆盖。
- Designer 外观不因共享抽取改变。

## 原生验收范围

1. 正常使用尺寸采集起始/设置、生产、日志、设备的代表视图，主窗口默认基准为 1060×800 逻辑尺寸。独立设备窗口或实际目标机器不同则记录实际值。
2. StartupPage 必须检查 900×700 窄窗口，保留响应式切换和可到达的选择/保存/返回操作。
3. 日志或其他视图只有布局、响应式或溢出行为受本次改动影响，或发现具体问题时，才追加该视图窄窗口验证。
4. 如现场实际使用不同 DPI，仅补该实际缩放，不建立全部页面×尺寸×DPI 组合。
5. 两种 technicalHost 挂载位置、带自定义生产页 QSS 的工程仍须检查，因它们直接受到外壳样式作用域影响。
6. 按钮、返回、焦点和目标保持并入原生日常主链，不逐控件造自动化测试；一次有效走查证据可覆盖多项要求。

原生 Qt 截图和点击不可由 HTML、图片稿或 offscreen 单元测试替代。原型的模拟程度与局限见 [prototype-notes.md](prototype-notes.md)。
