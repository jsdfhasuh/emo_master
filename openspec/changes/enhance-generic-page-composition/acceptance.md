## 2. 本轮受影响步骤

### A — 可以设计、复制、保存和发布

**A1：Qt动态文字。** 在已有renderer/layout夹具中保留一个直接反例：短占位→完整时间→长文本/多行→短文本，实际可用宽度和字体参与尺寸，文本不被内部高度截断，横向对齐更新后保持。最终交付工程核对历史时间与展开日志。可用正常页面滚动访问高内容，不要求塞进首屏。

**A2：Web整数绑定。** 用正式Web编辑器把一个现有integer输出绑定到indicator，配置状态映射、保存重开、发布预览。目录/拖放/下拉共用的绑定判断须接通；复用现有精确类型夹具检查1、true、"1"仍不同，不逐个算子重复。把此操作放在同一保存发布旅程，不为每个属性重复打开工程。

**A3：Web复制历史页。** 从当前Runtime目录添加表及主图/局部图，用本页表格关联recordValue/历史按钮；复制整页，保存重开并正式发布。原页和复制页可以独立选择不同记录，各页图像/字段/翻条跟随各自表格，RPC仍访问原声明来源。随后再次进入编辑器并发布，验证目录重建没有混淆UI与Runtime身份。复制内部引用的直接用例可复用同一夹具，不增加跨工程/全部控件组合矩阵。

当前源码模型、生成Schema/TS、已安装SDK和发布包必须一致。属性编辑继续普通undo/redo和恢复默认；未改这些机制时引用V1.2证据，当前绑定/复制至少实际保存重开一次。

### B — 正常运行页达到目标结构

同一工程在Qt/Web核对生产与历史两页；1366×768与1920×1080逻辑视口各做一次目视检查，最终截图来自真实运行页面，不用独立HTML替代。

- Web主栏包含标题、连接/任务状态、当前观察与控制对象摘要、原开始/停止及选择入口；Runtime/页面包设置、工作流输入归入可展开运行设置，技术诊断另可展开。
- 原已选目标、权限、确认和实际命令保持。用软件Runtime完成一次正常启停并切换生产/历史，确认控制按钮仍作用于明确对象；不是新建权限或多任务矩阵。
- 同一状态映射展示一个有色状态和一个未映射/空状态。Qt/Web的row浅底覆盖整行，切换后不残留旧色；badge/text仍按各自语义。无需每种颜色单独录制旅程。
- 保持左图右结果、历史主图/列表/局部图/详情的结构；图片contain，日志展开后可读；超高页面可滚动。
- 冻结和恢复原resultScope身份机制继续使用；如果本轮仅移动宿主按钮、不改变冻结/结果代码，复用原同次结果证据并检查入口仍可用。

不得以像素级相同、全部DPI、全部浏览器或现场工位精度作为完成条件。

### C — 历史仍能查看正确记录

本轮重点是新Web实例引用的实际消费：复制后的表格查询、选择、字段/图片联动及一次相邻记录导航必须使用正确来源，原页与复制页会话不互相抢选择。使用原有真实历史记录即可。

持续新增后的按键定位、生产写图/写库、同次主图像素一致和历史引用到期恢复默认引用已有证据。只有本轮实际修改到这些路径，才补跑相应原检查；不因为文档版本变化重做完整归档专项。

## 4. CI收尾

审核基线的失败记录见 [review-report.md](review-report.md)。本轮按以下步骤验收：

1. 执行现有mypy命令，修正主题类型关系；不靠全局忽略或关闭模块检查通过。
2. 对asset_retirement_browser核对当前诊断/结果身份入口和等待条件；若只是布局变化，调整实际操作，再执行原停止、终态及图片归属断言。若正常行为确实失效，则修应用。
