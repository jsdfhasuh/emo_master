# 最小必要验收与完成标准

**V1.2；待实现后的验证计划，不是已通过记录。** 用户没有存量工程，本轮只验收当前2.10/1.3及同步更新后的Qt/Runtime/Web，不要求旧工程、旧页面包或旧SDK可用。以三条用户旅程覆盖“能设计、能运行、能回看”。同一检查已在开发阶段完成，且之后没有影响该路径的修改时，最终记录直接引用，不再重复执行。

## 1. 只使用一个交付工程

工程采用正式 2.10/1.3，保留资源、变量、生产及 devices 声明，包含两个独立 Page。通过现有软件模拟及 ImageSaver/SQLiteWriter 实际生成五条记录，pageSize=3；之后运行第六条。字段至少含稳定键、保存时间、结果、主图/局部图引用、一个可空详情和多行日志。

生产/历史读取同一流程的记录；若示例通过 SQLite VIEW 输出日期、时间等显示列，VIEW 是示例数据库配置，不是新查询语言。主图与局部图使用明确固定展示比例并 contain。当前字体在执行环境包，不重复塞进工程/Web 页面包。

交付同一工程、所需图像/小库、发布 .emoweb、当前 SDK、简短操作步骤和真实 Qt/Web 截图。所有模拟图框、判定和回执以短标记注明。无需第二个测量项目或 palette 预设发布物。

## 2. 三条用户旅程

### A — 可以设计、保存并得到目标结构

从正式 Designer 打开交付工程，在原属性面板修改一处 surface、主值字号、按钮外观和一个页级配置；包含一次撤销/重做及恢复默认。用既有拖放移动一组，保存重开。Web 编辑器确认对应属性可编辑，当前 SDK 消费同一配置，正式发布的包可打开。

Qt/Web 展示同一份配置的两页。检查目标层级：

- 页头 → 页签 → 简短状态 → 主要内容；Job ID/资源释放等诊断不常驻主体。
- 一个外层卡片内可以组合无装饰标题/按钮/字段，普通文字不被通用最小高度撑大。
- 生产页主图与紧凑结果侧栏为主；历史页主图/记录列表/局部图与详情清楚分区。
- 数值可大于标题，辅助文字次要；页签选中态、状态色和正文层级可辨。
- 图像 contain，折叠后回收空白，Designer 辅助信息不改变业务几何。
- 1366×768 与 1920×1080 逻辑视口做一次并列目视检查，重要操作可访问，超高内容可滚动；不是逐像素、全 DPI 或多浏览器矩阵。

具体布局配置见 reference-layouts。将同一字段组合临时改为测量值/单位/另一枚举映射，再撤销或恢复，证明无需新组件类型。该步骤在同一工程完成，不要求单独演示产品。

**完成判据：**最终文件在正式入口可编辑、可保存、可发布，真实 Qt/Web 页面达到目标结构与密度。配置只写进 JSON 或独立 HTML 漂亮均不算通过。

### B — 生产监控看的是同一次结果

用已有软件 Runtime/模拟宿主运行示例。生产页同次显示图像、结果、对应请求标识及实际存在的回执字段；没有回执时中性显示，不从任务 COMPLETED 推断确认。图像可使用明确模拟检测结果，不能冒称真实模型输出。

冻结当前显示后产生下一条，页面保持冻结的那次结果；恢复后回到最新。原连接/作业状态仍实时，原宿主开始/停止入口可用。若示例配有 displayed_result 详情按钮，使用原身份打开；无需为了验收额外增加第三个正式 Page。

在同一数据夹具中展示几个枚举结果，确认判定组和数值层级清晰。无改动的权限、目标仲裁、跨任务控制机制复用现有回归，不专门增加组合测试。

**完成判据：**新外观没有破坏同次结果和原宿主操作，常用操作可见，技术诊断可展开。

### C — 生产保存后，历史能查到并持续浏览

1. 以同一流程生成五条记录。历史列表初选首条；主图、局部图、结果、时间和日志对应同一稳定键。
2. 点选另一条，上一条/下一条跨一次页边界。图像与字段同步，首尾按钮状态正确；可选 i/N 的编号按时间倒序查询序，最新为 1/N。
3. 保留当前选择，再由同一模拟生产流程保存第六条。下一条按原选中键取真实相邻记录，不因页码偏移重复当前条。生产结果推送不能抢走所选历史。
4. 点“回到最新记录”，确认读到第六条，图像与关键字段和刚才生产页对应的同一个 key 一致。当前已在首条时也能再次刷新取得后续新记录。
5. 设置一个声明列的关键词，再清空；列表和已配置 count 采用相同条件。切生产页再回来，仍恢复原选择/查询/折叠，图片重新取到有效引用。
6. 展开原始详情可读多行日志。两种不同原始尺寸的图像在声明展示比例中正常 contain，页面不被图片加载撑乱。

本旅程同时覆盖真实归档、历史选中联动、正常持续新增和切页返回，不再分别建立“静态历史通过”与“生产通过”的两套证据。

**完成判据：**用户既能看实时生产，又能逐条查到刚保存或更早的同一记录，回看动作只使用历史读取和页面状态，不干预生产。

## 3. 少量直接检查

下列检查针对这次实际改动；已有测试能表达时扩展原夹具，不为每个 Scenario 单独新建测试。

| 检查 | 最小范围 | 目的 |
| --- | --- | --- |
| 精确类型与缺值 | 一个参数化夹具区分 1 / true / "1"；中性 emptyText 的原诊断不丢 | 防止新增整数支持把业务状态混为一类 |
| 当前工程/包/SDK | 直接复用旅程A的最终2.10/1.3工程：编辑、保存重开、当前.emoweb与实际SDK一致 | 检查当前链路完整性，不另做旧格式/迁移/旧摘要回归 |
| 历史图片生命周期 | 同一夹具一次 A 晚到而 B 已选中、一次 B 缺图、一次受控 imageRef 到期后按键重取 | 验证图文不会错配和普通离页恢复；到期用受控时间，不等待五分钟 |
| Annotate | 一张含中文、类别色、灰度转 BGR、虚线端点的综合图；按实际配置检查输入未改及执行包字体/许可证 | 验证实际显示和离线部署依赖；不做字形逐像素锁定或算法精度专项 |

历史插入漂移已经在 C 中覆盖；可用同一小库对原查询函数加直接测试，不再补并发删除/修改/全部排序组合矩阵。必要 SQL 上下文、受管路径、超时、原权限检查继续原实现；没有新行为不新增同义“安全测试”。

环境支持时执行 `openspec validate enhance-generic-page-composition --strict`。当前功能的有效检查继续执行；仅用于旧格式读取/迁移、旧包摘要、旧SDK固定快照的测试按本次已授权范围删除或改为当前格式用例，并说明变更。不得为掩盖当前功能失败删断言或把跳过记成通过；无关历史失败不扩大为无关重构。

## 5. 完成与证据

只需一份简短交付记录，含：最终 HEAD/工作区、依赖版本、三条旅程实际结果、必要检查结果、同一工程/页面包、Qt/Web 两页截图和未验证项。截图标明实际环境/逻辑视口；原生 Qt 自动化、Web 渲染和人工操作据实描述。无需每阶段打证据 ZIP、重复全量测试或另建测试平台。

**必须同时满足：可编辑组合成立、运行数据同次、生产可归档、历史同条回看、Qt/Web 正式保存发布成立。** 只满足其中一部分，不能称“页面设计能力已经完善到本轮目标”。

允许原生字体和边框细节差异；不要求逐像素复制设计图。不把本轮扩大成现场 YOLO 精度、PLC 回执/夹持动作或外部 Windows EXE 发布验收；这些未做时如实说明即可。
