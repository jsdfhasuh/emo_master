# 设计

**V1.2：先把正常功能做完整，再用最少的直接验证证明它。** 配置细节以 [contracts.md](contracts.md) 为准，审核变化见 [review-report.md](review-report.md)。

## Context

目标是让用户在 emo_master 内编辑并使用生产监控、历史回看两个独立 Page。固定基线为 31afa5ecab8b7ddb53f0d6bdedc620f0a243e340；Python 3.10 / PySide2 / Qt Widgets 和现有 Web 技术栈继续使用。基础能力与源码依据见 [source-map.md](source-map.md)。

此次复查发现：V1.0 的正常使用要求仍有缺口，而部分纯视觉选择被写成配置阻断，保存/发布/截图验收在不同阶段重复出现。V1.1补齐可编辑布局和生产到历史闭环；V1.2依据用户“没有现成工程”的明确说明，再删除旧工程、旧包、旧SDK和旧渲染兼容工作，直接统一当前正式实现。

## Goals / Non-Goals

### Goals

1. 同一可编辑配置在 Designer、Qt、Web 表达目标结构和信息层级。
2. 主图、结果及对应请求/回执使用现有同次结果机制；宿主状态实时。
3. 历史列表、大图、局部图、详情和日志属于同一条记录，生产持续新增和切页返回时仍能正常浏览。
4. 一个软件模拟工程完成生产显示、实际图像/SQLite 保存、历史回看与正式发布。
5. 相同组合换绑定/单位/映射即可服务其他视觉、设备或测量项目。

### Non-Goals

不重写检测/PLC 逻辑，不建立专用业务组件、第二布局引擎或历史服务；不扩展为任意脚本/CSS/SQL/格式语言、模板商城、交互式标注编辑器、长期数据库快照或新权限体系。现场模型精度与机械动作另由真实项目联调确认。

## Decisions

### D1. 增强现有七组组件

| 组 | 增强 | 用途 |
| --- | --- | --- |
| container | none/card、表面/内边距、collapse | 图像卡、结果组、状态带、日志折叠 |
| text / number | title/value/helper、横纵排、纯文本换行 | 标题、数值、单位、记录详情 |
| indicator | 整数映射、text/badge/row、浅底圆点 | 判定与状态表达 |
| page_navigation | 兑现 tabs/buttons | 双页导航和选中态 |
| image | aspect/fixed、contain、背景对齐 | 主图与局部图 |
| navigation_button | primary/secondary/link、有限历史动作 | 冻结/恢复、详情、逐条浏览 |
| sqlite_table | table/list、字段角色 | 可选中的历史记录列表 |

不增加专用“检测卡片”。标题/操作/图例由普通容器组合。复用现有复制、编组和解组；本轮不新增 palette 组件树拖入协议。一个正式示例承担配置参考。

### D2. 外观与真实尺寸一起做

surface.none/padding=0 只是外观起点。现有默认 minHeight=64、minWidth=160、部分测量硬加成和 Designer 布局内的 bindingHint 均会撑大内容。新样例叶子按内容测量并明确 min0；真实 sizeHint/minimumSize/heightForWidth 使用同一份有效字体、内边距和内容信息。编辑辅助移到已有覆盖层/提示，不占业务布局。

保留原 ResponsiveLayout 求解、拖放、吸附和 canvasOffset。只提取必要的共用测量辅助，不引入通用样式/布局解释器。Web 从同一 token 定义取值，允许平台正常字体差异。

图像始终 contain。明确比例的示例避免翻图时面板跳高；使用原图比例的配置在新图尺寸变化时触发 updateGeometry/布局刷新。具体示例比例、间距和字号见 [reference-layouts.md](reference-layouts.md)，全部可在工程配置中修改。

### D3. 运行外壳保持轻量

shell 只负责工程身份、状态和操作呈现；diagnosticsInitiallyExpanded=false 是一个初始显示偏好，不增加 operation/debug 两种产品模式。

开始/停止继续调用现有宿主路径。已有目标选择入口和权限可用性保留；没有触及这些语义就不新增权限/多任务组合测试。显式 page_navigation 自动隐藏宿主重复导航，允许页顶/页底各一处；视觉重复不阻止保存或生产。

Qt 按原 navigation.mode=tabs/buttons 渲染。这是既有协议的实现修复，不按旧/新外观分成永久两条路线。

### D4. 保持三类数据原有归属

| 数据 | 归属 |
| --- | --- |
| live 连接、作业与控制 | 宿主 |
| 本次检测及对应图片、判定、请求、回执 | 已有 resultScope |
| 历史查询、选中键、详情、折叠 | 页面/组件查看会话 |

生产继续直接绑定 node_output/workflow_output，不增加变量暴露层。历史 recordValue 只引用同页组件，不进入 Runtime 结果采集。缺值与业务结果分开：统一 neutral emptyText 即可，不新设三套回退配置；内部原因留给诊断。任务完成不推导产品合格或 PLC 确认。

### D5. 历史按真实记录定位

table/list 共用 SQLite 来源。recordValue 提供选中行标量，imagePath/imageRefs 继续负责图片。普通表沿用 PK/rowid，VIEW 可以声明 recordKey。

OFFSET 适合普通分页，但持续新增会移动旧页边界。previous/next 因此按选中 keyValues 调用既有 QueryHistoryPage 的可选 anchor 参数；同条恢复使用 step=0，前后条使用 -1/+1。服务端依声明键和原排序取目标所在有界页，返回 selectedRowId 与新图片引用。一次短只读事务保证本次响应自洽，保留原超时预算；不加载整库、不保持长期快照、不新增 RPC。

页面切走后返回，也用同条查询恢复选择和新 imageRefs。过期图片引用最多做一次同条重取；不是全局延长 TTL 或无限重试。当前记录确实不在查询集合中时明确提示，不把“原 OFFSET 页里找不到”当作记录消失。

### D6. 历史 UI 功能限定到真实可用

过滤只提供服务端已有的单列关键词，默认有效声明列；修复 Web “所有声明列”与 Runtime 不一致的问题。时间和日期用声明显示列或既有 VIEW；日志纯文本保留换行和折行。

position/count 是可选显示。count 复用现有 aggregate 且传同筛选；未引用不发请求。查询序号会随显式重查变化，记录身份不会因此变化。不为 i/N 建实时排名机制。

切 B 先清 A 图，字段与加载占位先更新；原 generation 过滤 A 晚到回调。缺图不清 B 标量，也不变成业务 NG。必要直接反例只验证这一处真实异步错配风险。

### D7. 同一工作流形成历史闭环

模拟工程用现有算子生成可识别 record key、时间和结果，Annotate 输出展示图，ImageSaver 保存图像后 SQLiteWriter 保存该条字段/路径。只有成功保存的同一 key 才作为历史可回看的记录。生产页直接绑定这一流程输出；历史页从声明来源读取。

小库的初始五条由同一流程生成，后续再运行一条。这样同时验证生产归档、历史最新记录和继续浏览时的正常新增，而不是用两个互不相关的演示数据源拼效果。

历史主图可保存原图和标注图；示例选用标注图，与生产显示对应。局部图来自工作流明确保存的结果。任何模拟框、判定与回执在示例中简短标识，不能伪称现场识别或写入。

### D8. 标注输出保持单一来源

增强已有 Annotate：类别显示名/色、中文标签底、置信度、线条色/虚线/端点。使用已有 Pillow，随执行环境包附字体与许可证。Web 接收位图，无需每个工程/页面包带同一字体。只改绘图副本，不变更算法输入/frame 坐标，不新增浏览器几何推断。

### D9. 只有当前格式和当前消费者

新建、编辑、保存、发布和交付统一为2.10/1.3。用户没有存量工程，不设计旧格式加载/迁移、条件升级、版本撤销、旧包摘要兼容或双版本渲染。

appearance/shell对所有页面使用同一当前默认；容器默认card、叶子none，布局组可选none。typography继承当前主题，不维护cardStyle/fontSize旧优先级。继承/自定义/恢复默认与普通undo/redo仍是编辑功能，但不承担格式切换。

当前工程仍完整支持设备、资源、变量、生产和Dispatch。相关版本判断与正式入口同步到目标格式；受影响fixture与生成样例可以直接更新。无需为删除所有历史代码扩大成全仓清理。

当前SDK、Schema/TS/wheel、Qt/Runtime/Web一起更新，契约产物写入现有web_panel/contracts/panel-contract-v1/。不新增并行消费目录，不保留旧SDK字节或旧响应结构测试；历史交接档案不作为当前构建门槛。当前包完整性和生成一致性仍要检查。

历史锚点依现有接口增加两个查询参数并通过正式脚本生成；普通分页和按键查询是当前功能的两种操作，不是兼容分支。Annotate采用一条当前绘图实现及明确默认，无旧像素路径承诺。

### D10. 验证围绕三个用户旅程

A：设计并保存同一个工程，在 Qt/Web 实际运行/发布。

B：产生结果，呈现同次图文，冻结/恢复不影响宿主状态。

C：保存这一条，历史查到同一条，选择/翻条/切页恢复可用。

每阶段只验证刚改动的路径，最终组合时复用仍有效的记录；没有影响的路径不重复整套跑。少量直接检查覆盖类型区别、当前工程/包往返、持续新增/引用到期和图文晚到。详情见 [acceptance.md](acceptance.md)。不把每个规范 Scenario 变成一项新测试或单独截图报告。

## 实施顺序

1. 正式模型/版本与编辑入口；共享显示解析和真实测量。
2. Qt/Web 控件表达、导航与轻量外壳。
3. 历史标量/稳定键、最小 anchor 契约、列表与会话联动。
4. Annotate、同一模拟归档工程、当前 SDK 与正式发布。
5. 集中完成三条旅程，修复实际缺口，更新使用文档和真实完成状态。

任务只维护 [tasks.md](tasks.md)。A/B/C 为最终用户旅程，不要求三个独立发行包。暂未完成的工作不因某张截图可用就标为完成。

## 范围控制

不要求旧工程、旧页面包或旧SDK客户端继续可用，也不为它们建设迁移或回退。保留当前功能所需的字段校验、资源约束、查询预算、结果身份及现有宿主权限，不新建平行防御框架。验证聚焦当前正式工程和当前Qt/Web消费者。

执行时实际HEAD有后续实现则比较复用，不回退到参考提交。与本次改动冲突的旧适配可直接删除；不把用户这次说明扩展为无关历史文件清理或技术栈重写。公开语义如需调整，写清影响；局部代码组织和资源选择按现有代码处理。
