## 1. 结论

**V1.0 有几处过重的配置与重复验收；即使按旧条目全部完成，仍不能保证达到两张目标图及正常历史回看的完整体验。**

主要原因是：控件显示字段列得较全，但真实紧凑尺寸、生产到历史的归档链路、持续新增后的逐条定位和过期图片恢复没有被完整锁定。V1.1 因此同时做两件事：删掉与目标无关的机制；把正常功能链路补齐。不是单纯减少测试数量。

本轮只修订计划文件。平台源码没有修改，目标功能仍待 Sol 实施和实际验收。

## 3. 必须补齐的功能缺口

### 3.1 去掉边框仍可能不紧凑

基线 ResponsiveItem 默认 minHeight=64/minWidth=160，布局测量还有固定加成，Designer 的绑定提示也占内容位置。只增加 surface.none 和 padding=0 无法保证目标图的紧凑字段、图例与小按钮。

修订：样例普通叶子 min0；测量使用真实字号/内边距/内容；编辑辅助不挤业务布局。给出可修改的列宽权重、图像比例、字号和留白，直接约束最终效果。[基线与落点](source-map.md)

### 3.2 生产页与历史页可能各自能演示，却查不到刚做的这一件

旧验收允许生产用模拟输出、历史用另一份预置小库，没有证明新结果实际进入历史。

修订：同一模拟流程经 ImageSaver 保存图像，再用 SQLiteWriter 写稳定键和同次字段。历史 first 必须找到这条新记录，主图/局部图/结果与生产对应；使用已有算子，不增加归档平台。[完整例子](reference-layouts.md#5-同一模拟生产写入同一历史)

### 3.3 持续生产时，按旧页码翻条会重复

这不是假设性防御。直接调用基线 readPage 已复现：

| 步骤 | 实际结果 |
| --- | --- |
| 原记录 1–5，时间倒序，pageSize=2 | 首页 [5,4] |
| 选中4，生产新增6 | 原记录仍在，但页边界改变 |
| 再读旧的下一页 page=1 | 返回 [4,3] |
| 用“下页首条”当下一条 | 重复4；应该是3 |

修订：既有 QueryHistoryPage 只加 anchor_key_json/anchor_step；按真实键定位同条或前后条，返回实际目标页和 selectedRowId。保留普通分页，不新增 RPC/查询服务/跨请求快照。[契约](contracts.md#52-稳定键与按键查询)

### 3.4 切走后再回历史，保存选择还不够

Runtime 图片引用现有有效期为300秒，旧引用不保证返回时仍可读；原 rowId 是摘要，也无法直接定位数据库键。

修订：保存真实 keyValues，返回时按 step=0 重取同条和新 imageRefs；实际到期错误允许同一选择恢复一次。两个图片共用这次重取，不做后台续期或循环重试。[来源](source-map.md)

### 3.5 筛选界面与真实 Runtime 语义不一致

Web 的空“所有声明列”选项会配非空关键词发请求，但基线 readPage 要求有效声明列；直接调用确实返回“请选择要筛选的显示字段”。只在前端演示夹具检查会漏掉。

修订：使用已有单列关键词，默认有效列；若配置 count，Qt 适配传同一筛选。无需新增全文搜索引擎。

### 3.6 可编辑性及图像/文字的细节

明确 appearance/shell 的设置入口、继承与恢复默认；修改普通属性不意外把主题继承改成自定义值。比例改变要更新布局几何；日志用纯文本保留换行；历史时间来自记录列。它们属于日常使用能力，不为其建立新配置框架或格式语言。

## 4. 实施后能达到什么

下表是**完成 V1.2 并通过三条用户旅程后的结果要求**，不是当前已实现状态。

| 用户目标 | V1.2 对应能力 | 达标方式 |
| --- | --- | --- |
| 第一张图的页头/页签/状态带/主图/侧栏 | 轻量 shell、真实 tabs、通用容器、紧凑测量 | A：实际 Qt/Web 同配置结构与密度 |
| 结果有清楚主次，不堆调试信息 | typography、valueLayout、状态row、诊断折叠 | A/B：正常运行页面主信息清楚 |
| 图像有类别色、中文名、虚线/端点 | 现有 Annotate 参数扩展 | 综合真实输出图进入生产/归档 |
| 生产结果与图片属于同一次 | 原 resultScope、冻结/恢复 | B：同次图文与宿主实时状态 |
| 生产监控与历史回看分页 | 两个正式 Page、共享宿主导航 | A/C：正常切页不重启生产 |
| 列表选中后大图/局部图/详情一起变化 | recordValue + 原 imageRefs + 选中会话 | C：同 key 核对 |
| 上一条/下一条/回到最新可用 | 按键邻条查询 + first | C：跨页并有正常新记录插入 |
| 切页回来仍是所选旧记录且图片可读 | keyValues + step0 新refs | C + 到期直接检查 |
| 刚产生的结果能进入历史 | ImageSaver → SQLiteWriter 实际归档 | C：生产第六条与历史同 key |
| 用户自己还能调整，而非只能看截图 | 正式属性入口、undo、保存/发布 | A：同一最终文件继续编辑 |
| 其他视觉/测量项目能复用 | 没有专用类型，字段/单位/映射可换 | A：同一组合换配置 |

因此，V1.2 的能力范围已经覆盖用户给出的两页**结构、信息表达、交互和生产到历史流程**。实际达标必须看最终工程和 Qt/Web，而不能只看任务勾选。

不将像素级相同、模型训练精度、真实 PLC/机械动作、任意报表/主题系统算进本轮页面目标。它们没有因本次计划修订被证明完成，也不成为额外阻塞。

## 5. 验证怎样缩减

V1.0有54条Requirement、86个Scenario、43项任务；V1.1收敛到37条、45个、22项。V1.2进一步删除仅为历史兼容设置的规范与场景；当前数量见validation-report。Scenario是功能语义示例，**不是要求新增的测试数量**，最终以完整使用流程达标。

最终只围绕三个用户旅程：A设计/保存/发布；B生产同次结果；C归档/历史回看。补少量直接检查：类型映射、当前工程/包/SDK、图像晚到/缺图/引用到期、综合Annotate。每组复用现有夹具；没有新增权限矩阵、全版本矩阵、并发删改矩阵、性能专项或第二测试平台。
