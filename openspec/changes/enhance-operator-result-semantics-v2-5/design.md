# 设计

## 1. 目标与边界

将算子运行信息变成可理解、可追溯、可统一展示的数据，而不是机械翻译 JSON 字段。本次只针对当前正式工程格式和当前运行链路。用户不需要历史项目迁移，因此不设计旧工程迁移、旧 Manifest 兼容、旧 SDK 双版本或历史日志回填。

## 2. 当前实现基础

审查基线：b75df0adb7a90a4e0b540ff1c8c09e9339cfcdbd

- PluginManifest 已有 operatorId、displayName、version、inputPorts、outputPorts、paramSchema、summary。
- 端口描述符当前校验 type、required、nullable、schemaVersion。
- Runtime OperatorInfo 已传递端口 specs、paramSchema、summary、版本等元数据。
- 正式 Job 完成事件已有 metrics、diagnostics、ioSummary；日志投影不保留完整 outputs。
- 单算子调试已有 sourceIdentity、operatorVersion、outputs、metrics、diagnostics、elapsedMs。
- Designer 已有 LogRecordDetail、LogJsonTree 和通用值展示能力。

必须优先复用现有能力，不另建注册中心、日志数据库、结果查询服务或逐算子 UI。

## 3. P0 审查先于方案定型

审查 82 个 operatorId，逐一读取当前 Manifest、OperatorMeta、执行实现、共享 helper、继承类和设备托管路径。每个算子检查：

1. 实际注册身份与版本。
2. 全部输入端口的类型、必需性、用途、来源及现有摘要。
3. 全部输出端口的真实内容、结构、单位、坐标语义、用途和日志可见性。
4. 全部 paramSchema 属性的名称、用途、默认值、约束、枚举、条件参数和敏感性。
5. 默认值、节点配置、输入覆盖、变量绑定、设备继承的优先关系及实际执行参数。
6. metrics 每个字段的实际赋值、单位、统计口径及重复来源。
7. diagnostics 每个字段的真实含义、来源、严重程度、敏感性和回执语义。
8. 成功、失败、跳过、取消及设备托管路径的实际返回结构。
9. 当前未返回但源码可可靠计算且有价值的缺失信息。
10. 无需补充或暂不可可靠获取的字段及理由。

P0 完成后，根据实际字段全集确定 resultSchema、端口说明、生效参数快照结构；不能先定假想 schema 再让算子迁就它。

## 4. 统一语义元数据

复用现有 PluginManifest，并在 P0 后确定可选运行结果说明字段。需覆盖输入端口、输出端口、配置参数说明、metrics、diagnostics；适用时补充单位、格式、重要程度和敏感标记。

端口说明表达中文名称、当前算子中的用途和数据摘要提示。真实类型、required、nullable、schemaVersion 仍由现有端口契约负责；语义说明不得改变连接兼容性。

字段说明归属于 operatorId + operatorVersion，不能只根据字段名全局翻译。未知字段保留原名、原值和类型。

### 4.1 配置参数与生效参数

paramSchema 描述用户可配置参数，不等于实际执行参数快照。生效参数从算子执行前真实解析结果获得，区分节点配置、默认值、输入/绑定覆盖、设备继承和无法确认来源。只有源码链路能明确追踪时才标注来源；否则标记 unknown。不得从当前工程节点反推历史运行值。

### 4.2 敏感信息

参数快照进入持久化事件前完成脱敏。密码、Token、API Key 和设备认证信息不得进入日志 payload、原始 JSON、诊断文本或导出文件。优先复用现有敏感字段规则；不足时补充最小明确标记。不能只在 UI 隐藏明文。

### 4.3 运行数据补齐

新增 metrics / diagnostics 必须来自真实执行路径。补充前确认它没有被 outputs、ioSummary 或框架生命周期准确表达。允许纯计算算子没有专用 metrics；不得制造重复计数、估算耗时或推断业务状态。

## 5. Runtime 身份传递

正式 Job 事件从实际注册算子描述符获取 operatorId 和 operatorVersion，并与节点生命周期记录关联。不能从显示名称或当前工程配置猜版本。

优先扩展现有事件 payload / OperatorInfo 通道。只有现有字段确实无法表达时才修改 proto，并运行正式生成脚本。框架节点或无真实算子身份的记录不伪造身份。

单算子调试沿用已有 sourceIdentity 和 operatorVersion，不重复建立身份机制。

## 6. 日志详情展示

复用 LogRecordDetail 和通用值组件。左侧执行树、查询、分页、导出不在本 Change 重做。

建议顺序：
1. 运行概览：算子名称、状态、节点总耗时、算子内部耗时、核心业务结果。
2. 输入数据：中文端口名称、用途、真实摘要。
3. 本次生效参数：参数名称、说明、值、来源；敏感值隐藏。
4. 输出结果：中文端口名称、用途、真实标量/集合摘要及可用结果资产。
5. 运行指标：按性能、业务统计、实际处理参数等语义分组。
6. 诊断信息：处理摘要、设备/模型/通信信息、警告和回执。
7. 技术详情：原始字段、类型、原始 JSON、记录身份。

无数据的区域可以隐藏。不能填充推测内容。相同值在概览可以合并显示一次，但原始来源必须保留。0、false、null、空字符串、空数组、空对象和字段缺失必须分别处理。

正式 Job 目前只保留有限 ioSummary，不保留完整 outputs。语义元数据只能解释已有摘要，不能恢复未保存图像、集合或完整检测框。调试结果只有真实 outputAssets 存在时才预览。

## 7. 82 算子覆盖

完整列表与逐项状态见 reference/operator-field-audit.md。覆盖按 operatorId 校验，不能只数 Manifest 文件。共享模块和继承算子必须逐个 operatorId 审查真实参数、端口和执行分支。

## 8. 验证策略

- 全部 82 个算子：静态字段完整性和元数据覆盖检查。
- 代表算子：真实软件执行与 UI 展示，覆盖图像、推理、集合、几何、数值、控制流、通讯、设备和存储。
- Runtime：身份版本、参数来源、脱敏、事件投影。
- Designer：输入、参数、输出、指标、诊断、原始 JSON、复制和展开。
- 单算子调试：同一说明机制正确关联调试结果。
- 不连接生产相机或 PLC；使用现有模拟设备、隔离服务和测试夹具。
- 不要求全部 82 个算子运行真实模型或设备。

测试只覆盖本次新增行为及直接反例，不为每个字段、每个算子建立重复测试。

## 9. 非目标

历史项目/日志迁移、旧版本兼容层、日志回填、第二套日志存储、全量 outputs 持久化、逐算子自定义 UI、所有算子强制增加 metrics 或主动 logger、Web 日志 UI、工作流调度和设备管理重构、无业务价值的防御性框架及重复测试。
