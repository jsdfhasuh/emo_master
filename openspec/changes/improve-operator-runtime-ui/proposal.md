# 改进独立操作员端（Operator Runtime R4）界面与排障体验

## Why

本变更承接独立 Operator Runtime R3，修订 Any 于 2026-11-28 提出的 `improve-operator-runtime-ui`。原设计参考提交为 `78a547270324553b8e88dea5a05258e562fcfb08`；本版保留原变更 ID、三阶段范围和两个能力规范，不另起重复计划。ChatGPT Web 已再次读取 `main` 上的关键源码（见包内 README 的审查记录），实施前仍须固定实际目标 HEAD 并核对差异。

独立运行端已有显式启停、单在途异步操作、资源释放、设备访问、JSONL 有界读取及脱敏、无 Designer 导入等基础能力。实际短板是：

1. **P0：有页面工程进入工具页后失去全局停止入口。** `OperatorWindow._attachHostTools()` 将 `technicalHost` 和启停按钮放入 `RuntimePages`；切换 `contentStack` 后业务页及其子控件被隐藏。日常运维入口也被埋在技术诊断折叠区。与 `docs/operator-runtime.md` 中工具页切换保留停止入口的约定不符。
2. **P1：本机日志排障体验不足。** `RuntimeLogView` 缺少关键字和模块筛选、可见的设备筛选状态及便捷复制；本机时间与启动诊断显示口径不一致；变化时 `QTableWidget` 重建最多 10,000×6 个表格项，存在明显渲染开销。不能把这一独立端 JSONL 查看器与 Designer 的 `runtime-log-workbench` 混为一谈。
3. **P1：设备状态难读。** `DeviceManagementDialog` 以单个下拉框及原始 JSON 展示设备，难以查看全量设备及正常状态；但已有设备声明、动作能力、串行访问、TCP 通道与诊断功能，无需另建后端。
4. **P1/P2：外壳与日常操作不一致。** 顶部空间利用、字体/图标、DPI、起始/设置页、最近工程、窗口记忆和忙碌反馈需要改善。

## What Changes

### Phase 1 — 常驻外壳与最小共享主题（P0 优先）

- 固定顶栏、按需上下文横幅和独立内容区；工具入口移出技术诊断区，保留正常返回及业务页面状态。
- 保留现有一对**全局**启停按钮及已有 `workflowControls` 流程级启停按钮。全局按钮在单流程业务页/顶栏之间按页面模式停靠；工具页有活动运行时保留可见的软件停止入口，启用条件仍遵守既有状态与 `busy`/`closing` 约束。多流程保持原有全局批量操作与流程级操作的目标语义。单活动 Job 直接停止；复用已有 `_stopChoice()`、`viewRun()` 和控制器的完整 Job ID/归属校验，不新增选择或确认步骤。
- 工具页使用宿主标准按钮外观，返回业务页恢复工程自定义配置。顶栏在长工程名、窄窗口和 150% DPI 下优先保留停止与返回入口。
- 仅复用必要的字体、浅色色板、离线图标、屏幕边界能力；作用域限制在宿主及工具页，不覆盖业务控件，不整体重写 Designer 主题。

### Phase 2 — 本机日志与设备管理（P1）

- 本机已加载 JSONL 记录支持级别、模块、关键字、设备组合筛选，设备筛选可见可清除；恢复全部和工具页往返规则明确。表格展示本机时间、级别语义色、脱敏详情复制；保留原记录与文件。
- 采用 `QTableView + QAbstractTableModel`，稳定增量刷新，保留双滚动模式、身份锚点和三种导出范围。三个导出范围统一遵循发起时的组合筛选快照；完整文件导出沿用现有文件范围、后台任务和取消语义。
- 共享设备弹窗改为左列表、右详情、可折叠原始状态；根据真实设备状态契约区分正常、未连接/未初始化、维护、异常和未知，不将 TCP Server 无客户端连接等同于故障。保留两端既有动作及日志下钻。

### Phase 3 — 起始/设置页、窗口偏好及整体验收（P1/P2）

- 优化起始页排版、长路径与复制；远程监听设置展示本次有效值、已保存下次值和未保存草稿，准确说明启动参数优先关系。
- 最近 5 个成功工程、窗口尺寸/最大化恢复；不改变既有 `projectPath` 和在线恢复规则。
- 加载/更新/停止反馈沿用已有操作状态。
- 阶段定向验证，最终统一执行受影响源码检查、正式 Source CI 与 Windows 原生 Qt 100%/150% 走查；按 `AGENTS.md` 记录证据层次与未验项。

## Impact

- 范围：`src/emo_master/apps/operator_runtime/`、必要的 `src/emo_master/ui/` 共用模块与 `device_management.py`、必要时 Designer 原导入路径薄转发、`docs/operator-runtime.md`、受影响测试与验收记录。其他文件只有为解决明确的直接依赖问题时才修改。
- 基线工程格式 `schemaVersion: "2.10"`、`presentation.schemaVersion: "1.3"`、`devices.schemaVersion: "1.0"` 保持不变；生成临时工程时使用实施目标正式支持的最新格式，不人为降低版本。
- 不改 Runtime 服务/协议、RPC、工作流调度、工程格式、页面设计能力、设备注册、日志落盘/轮转/保留、权限及发布链路。不引入后台常驻服务、第二套状态机/账本、通用 UI 框架、Qt6/QML 或在线依赖。
- 用户已确认取消新建多运行选择窗口：不替换已有选择弹窗、不新增任务管理中心、不限制现有并发能力；原运行控制仅作为外壳迁移后的回归保障。
- 不改变 `PageShell` 业务页作者配置、DisplayHub/DisplaySession、显式启停、取消不补执行、未知 Start 结果不自动重放、资源释放、设备串行访问、日志脱敏和读取上限。保留 Designer 日志工作台现有行为。
- 软件停止不是硬件急停；本轮不承诺硬实时或设备安全等级。测试仅使用临时工程、模拟设备及可控任务；真实设备、冻结 EXE、正式发布不属于本轮默认完成条件。
