# 验收场景与交付证据 · V2.3 通用算子详情与调试接线

验收对象是实际 PySide2 / Qt Designer + 软件 Runtime。随包 HTML 仅是交互参考；原型可点击、OpenSpec strict 校验通过、静态检查或单元测试通过，均不等于桌面交互与 Runtime 集成已经验收。实施进度只记录在 `tasks.md`，本文件列出判定标准，不预先标记通过。

## 1. 六组行为验收

以下分组用于复用已有测试和集中验收，不要求每条标准都新建一个测试文件或一个独立测试。

### G1. 来源与运行目录

对应规范：两个一级来源、任务首页、Designer 独立日志；设计 D1–D4、D12。

- 日志窗口只有 Runtime 运行日志与 Designer 本机日志两个一级来源。先按可信生产者来源分类，再决定 Runtime 记录属于 Job 还是系统事件。
- Designer 本机事件即使携带 Job / workflow / node 标识，也留在 Designer；客户端连接或查询失败不冒充 Runtime Job 失败。
- 首页先显示当前活动任务，再显示最近已结束任务。同一 Job 的 While / ForEach / 连续根调用不新增首页任务行；实时与历史摘要按 Job ID 去重。
- 当前任务操作使用已有 `allowed_actions`。历史查询从现有 `jobs` 表读取终态任务并稳定分页，历史摘要不出现当前运行的停止操作。
- Runtime 重启后能查询保留的历史任务和旧实例产生的事件。查询目标实例校验与事件自身的历史实例标识不混用。

复用现有 `test_operational_log_integration.py`、`test_log_history_instance.py`；仅为新增 Job 历史 keyset 查询补充必要用例。

### G2. 近期事件、实时补齐与有界窗口

对应规范：事件窗口合并、有界阅读；设计 D5.1、D5.2、D5.3。

- 打开长时间 Job 时取得近期原始事件页及固定历史上界，补齐随后增量；与现有 Runtime 全局读取来源合并，按当前查询存储上下文的全局 eventId 去重。
- “加载更早”沿用固定上界与服务端原始页游标。排序、边界记录和过滤后空页正确，不使用 UI 可见行决定翻页是否结束。
- 最近页、向前分页与实时合并不误删、不重复；字节上限和无结果页遵循设计中的游标契约，旧正向查询与完整分页导出语义保持。
- 原始事件窗口不超过 10000 条。历史阅读时不继续缓存每条新事件载荷，仅显示已观察到的新增数量/新事件提示，不抢滚动位置；返回最新后重建最近窗口并补齐增量。
- 主动翻更早页时可从另一端退窗，界面说明范围变化并保留选择与阅读锚点。若无法同时保留锚点并维持容量上限，停止扩窗并提示切换窗口；展开分支不永久锁住全部历史载荷。

复用现有分页、实例切换和 `test_runtime_log_refresh.py`、`test_log_scroll_viewport.py`；针对新增最近页 / 更早页 / 合并与窗口边界补聚焦用例，不新增长期压力或故障排列矩阵。

### G3. 执行结构、循环与筛选范围

对应规范：真实调用树、可展开循环、筛选与既有历史检索、上下文导航；设计 D6、D7、D9。

- 普通工作流、连续根调用、子工作流、并行分支和嵌套循环按真实执行标识组织，同名节点不跨调用合并；缺少关联证据时如实标注。
- While 的两种现有执行路径采用相同的 `bodyExecuted` 三态语义：true 表示循环体执行并正常完成、false 表示条件为 false 未进入循环体、缺省表示未记录。最终 false 检查不算业务轮次；失败或取消造成无完成事件也不能当 false。
- ForEach / Repeat 仅在总量可准确确认时显示进度；无限 While 不显示百分比；空 iterationPath 对普通非循环调用合法。
- 高级筛选默认收起并保留条件摘要。Job 执行树先由已加载原始事件建立，再投影本地筛选；只看 WARN / ERROR 仍保留命中事件的祖先。
- 执行结构与同范围时间列表共享窗口和筛选。独立服务端历史检索保留现有 project / job / device / component / level / workflow / node / time 条件，能检索当前窗口之外的保留记录；命中列表不被宣称为完整执行树。
- “查看本轮上下文”明确是已加载范围，可继续加载更早记录；尚未完整时不称为完整上下文，返回时恢复原筛选、选择与阅读位置。

复用 `test_operator_logging.py`、现有循环和连续运行用例；新增覆盖树投影与三态解释的少量数据驱动用例，不按每种循环深度、筛选组合或控件分别造测试。

### G4. 时间与当前执行位置

对应规范：实际生命周期时间、证据驱动定位；设计 D8、D9。

- Job 使用实际 startedAt，受理时间与执行开始时间分开；RUNNING / STOPPING 且有有效开始、无实际结束时持续显示墙钟估时，不称为纯计算耗时。
- 正常终态 Job 的耗时固定，下游仍持有资源不会延长 Job 自身计时；连续调用之间等待不计入单次 workflowRun 耗时。
- 子工作流 / 轮次 / 节点仅用匹配的有效生命周期时间配对；Job 终态不会被复制成每个子对象的结束时间，skipped 没有 started 时不伪造耗时。
- `E_RUNTIME_RESTARTED` 的结束记录标为中断确认时间，开始至确认的差值不冒充实际执行耗时。
- 原始时间缺失、配对未加载、原因不明分别按现有证据显示；没有明确保留清理证据时不得断言“记录已清理”。
- 定位当前仅使用同 Job 连续观察到的生命周期证据；既有节点摘要只有身份匹配且事件接续未中断时才可辅助；证据不足回最新活动区并提示位置未确认，不自动把最后日志当活动节点。被筛选隐藏时临时显示定位上下文并能返回原筛选。

在树与状态用例中合并验证，不新增当前节点 RPC、单独状态账本或大型时钟故障测试。

### G5. 设备身份与诊断往返

对应规范：设备诊断下钻、上下文归一化及摘要含义；设计 D11。

- executeDevice 与 captureDevice 提供相同的可用执行上下文；原生诊断 append 形成 row 前单点补充 source 中缺失的执行字段，保留原始 source。
- 可信顶层范围 / Job / device 身份优先，合法空 iterationPath 不被覆盖；不只修 `projectEvent()` 而遗漏原生设备事件，也不在客户端和 UI 重复写不同的兜底。
- 有明确设备身份才能查询相应缓存；Runtime / project / load generation 不匹配时说明近期缓存不可用于该历史范围，持久化 Job 事件仍可查看。
- 设备摘要聚合次数可能跨 Job / 轮次，不显示为本轮失败数；后续设备恢复不会抹去已经发生的节点失败。
- 下钻复用通道、HEX / UTF-8、详情及导出。设备缓存不重新追加到 Job 树，不将缓存 cursor 当 Runtime eventId；返回恢复原 Job、事件、筛选和位置。

复用 `test_device_operational_logs.py`、`test_device_feedback_closure.py`、`test_device_workspace_usability.py`；仅对 source 归一化及本次入口集成补充必要断言，不增加设备型号矩阵。

### G6. 通用节点详情、调试接线与导出边界

对应规范：右侧详情抽屉、通用节点数据与原始检查、单算子调试接线、明确导出边界；设计 D10、第 9 节。详情与调试验收合并在本组，不新增另一套测试框架。

- 事件选择打开右侧抽屉，显示业务字段及可折叠原始 JSON / payload。关闭后恢复主区域空间并保持选择、筛选、展开与阅读位置。
- 无主动 node.log 的普通算子仍可从已返回的节点生命周期事件查看状态、ioSummary、metrics 与 diagnostics。node.started / completed / failed / skipped 按实际类型和字段展示；完成摘要不要求等待一条算子自写日志，失败或 skipped 不伪装成成功结果。
- node.log 展示 message、日志代码与 payload.data；框架节点事件与主动日志使用同一值查看组件。用一组代表数据检查 0 / false / null / 空字符串 / 空数组 / 空对象及字段缺失没有混淆。未知字段保留 key，不猜单位；lifecycle 不变成没有证据的“初始化”。
- 对象、混合数组和长文本可展开；结构一致且值为简单类型的对象数组可用紧凑表格分段浏览。展开 / 分页只看当前收到的数据。复制值、日志数据或当前记录时内容和所选事件一致，按钮文案不暗示后台取回了完整历史。
- 易读 / 原始页切换保留同一事件，原始页保留 LogJsonTree 的层级 / 类型 / 惰性展开 / 长文本 / 复制能力。截断或脱敏标志可见，不把缺少顶层 truncated 当作全量证据。
- ioSummary 明确是输入 / 输出摘要，metrics 与 diagnostics 只展示实际返回内容；旧循环日志不跳到最新一次节点结果。不把 data 当作完整参数或输出，不从仅有 shape / count 的摘要造图或造列表。结果不可用时如实说明，不为这次验收新增全轮图片保留或恢复功能。
- 单算子调试的易读详情接入已有 DebugConnection.snapshot：ReadOperatorDebugEvents 返回的外层 sequence / type / generation / executionId 负责会话关联，具体事件按内层 event.eventType / message / code / payload 展示，不把所有外层 type=node.log 都解释为算子主动日志。generation 切换及 executionId 不同的记录不串入当前结果。
- 单算子调试经 OperatorExecutor 执行，不依赖 WorkflowRunner 自动产生 node.completed 或 ioSummary。成功结果从同 executionId 的 GetOperatorDebugExecution 读取已返回的 outputs / outputAssets / metrics / diagnostics / elapsedMs；不存在的字段不强造，失败结果不要求具有 metrics。inputSources 是输入来源，不等于完整输入；finishedAtMs 是内部单调时刻，不显示成日历时间。事件与结果的原始检查各对应其当前来源；不为共享组件伪造任务事件或复制一份 Job 历史。
- 调试的已有结果查看、PLC 可读日志与原始事件能力保持可用；同一展示组件接入两个入口，不增加另一套轮询。纯预览的缓冲日志、实时预览失败系统事件沿用既有边界，本轮不要求所有预览记录进入 Job，也不重复验证其未修改的限流和缓冲机制。
- “导出整个 Job”从固定上界开始读取完整可查询分页，包含未加载到 UI 的记录；不受当前 WARN / ERROR、本页或 10000 条窗口上限影响。
- 导出期间新增事件不改变本次范围，取消 / 失败不报告成功。导出范围说明是仍可查询的 Job 历史，不宣称恢复已被清理的数据。
- 设备诊断导出只称“已返回近期缓存”，沿用可获得的截断说明。

复用 `test_operational_log_integration.py::testHistoryExportReadsCompleteFixedRangeAndCancellationKeepsTarget` 等既有导出测试；针对新 Job 入口补充 Job / 筛选 / 上界接线断言，无需重写导出算法测试。详情扩展现有 `test_log_dialog.py`、`test_log_json_tree.py` 与 `test_operator_debug_window.py`，共用取值和展示断言。`test_operator_logging.py` 及 `test_operator_debug_sessions.py` / `test_operator_debug_data.py` / `test_operator_debug_rpc.py` 用于查明或复用既有数据契约；Runtime 相关路径未改时，不因新增展示组件另跑或重建其全部测试套。

新增详情验证按下列数据路径取少量代表输入，可合并为参数化用例或复用现有夹具。这里是五种来源的取样规则，不是五套新增测试，也不要求每种来源重复验证所有值类型、复制和控件行为。

| 代表来源 | 必须能判断的结果 | 采用的证据 |
|---|---|---|
| 整数加法，无主动日志 | 正常完成仍可阅读节点状态与 ioSummary；没有 node.log 不显示成“没有结果” | 现有整数算子 / 软件 Runtime 事件或其真实投影夹具；Qt 接线在 Q1 合并核对 |
| YOLO 完成事件 | 已返回的 metrics、diagnostics 可读，图像 / 集合摘要不会冒充图像和完整检测列表 | 现有同结构事件夹具足够，不要求下载模型、推理硬件或重新运行全部模型 |
| SQLite 主动记录 | 真实 node.log 包裹中的 payload.data 被读出，原始记录与复制范围一致 | 复用 SQLite 主动日志夹具或已有小型软件数据库用例，不重测数据库功能 |
| 托管设备节点 | 设备绑定、已有诊断字段与本次执行关联正确，未被当作另一个算子展示协议 | 复用现有软件设备 / diagnostics 夹具，与 G5 共用身份断言，无厂商矩阵 |
| 单算子调试 wrapper 与结果 | 外层 type 与内层 eventType 区分；同 session / generation / executionId 的日志和结果使用正确来源；无 node.completed 仍能显示成功结果 | 复用现有调试会话 / UI 夹具；一条缺少 metrics 的结果足以确认缺省处理，无需新建调试执行器 |

值类型、嵌套展开、数组分段、当前值复制和截断提示在共享组件集中验证一次；只在两个入口分别检查适配与身份接线。禁止把以上取样扩大为全部内置算子逐一测试、逐字段截图比对、所有循环深度或真实设备组合门禁。

## 2. 两条 Qt 桌面人工走查

两条走查均在实际 Qt 窗口和软件 Runtime 中执行。可用可重复软件流程产生多轮记录与分页数据，无需为证明“长时间”真实等待数小时；预置历史数据、软件设备与真实 Runtime 产生的数据应在记录中标清。下列动作覆盖前述分组，不另扩展为逐控件矩阵。走查中同时对照 reference/visual-guide.md 的区域和操作关系；静态图片不能代替实际 Qt 操作证据。

### Q1. 持续任务告警 → 循环上下文 → 设备诊断 → 单算子调试

1. 打开运行首页进入软件 Runtime 的持续运行任务，确认首页仍是一个 Job，详情出现多个根调用或循环轮次，实时新增可见。
2. 展开高级筛选、只选 WARN / ERROR；进入一条循环内设备告警，确认祖先路径和已加载范围提示正确。切换时间顺序后条件和选择仍在。
3. 在同一软件任务中查看一个无主动日志算子的完成事件（例如整数加法）和一条主动日志，分别确认完成摘要与 payload.data 可读；在其中一条记录上完成对象 / 列表或长文本展开、复制与原始树切换，不把所有动作在每种算子重复一遍。截断样例注明来自软件 Runtime 还是测试夹具。关闭后阅读位置保持。查看本轮已加载上下文、加载更早记录，再返回原筛选。不要用原型模拟样例替代 Qt 接线证据。
4. 打开设备近期诊断，切换通道与 HEX / UTF-8 后返回原 Job 事件；记录缓存是否匹配，遇到不匹配时确认提示而非展示其他代次缓存。
5. 停在历史位置观察新增提示和滚动锚点，返回最新并定位当前；分别记录有证据定位与证据不足提示的实际结果。STOPPING 到终态期间观察时间显示和停止后的固定状态。
6. 沿本次走查打开一个软件算子的单算子调试窗口，执行并查看易读结果，确认即使没有 node.completed 也能显示该次成功状态与实际返回值；查看已返回日志时按内层事件解释。切换已有另一条执行记录，确认结果及原始记录不串次，再返回原工作台。用一个软件算子即可；更丰富 payload 和缺省字段由 G6 共享夹具验证，不另加第三条走查或真实硬件操作。

覆盖：G1、G2、G3、G4、G5、G6 的抽屉、通用节点详情及单算子调试接线。循环三态、设备聚合、10000 上限和标量空值等不易在一次走查中穷尽的判断由对应聚焦测试提供证据，不要求人工重复所有组合。

### Q2. Runtime 重启 → 历史任务检索 → 完整 Job 导出

1. 使用已保存的软件 Runtime 历史，重启 Runtime 后打开更早历史并分页，确认终态 Job 只读且能够读取旧实例事件。若包含重启确认失败任务，核对中断确认时间的文案。
2. 进入有多页记录的历史 Job，只加载近期窗口并设置 WARN 筛选；使用现有服务端高级历史检索找到窗口外记录，确认命中列表与本地过滤范围区分明确。
3. 返回该 Job，执行“导出整个 Job”。将导出中的 Job ID、范围上界及记录数与软件 Runtime 对同一保留范围的查询结果对照，确认包括未加载记录且不受本地 WARN 条件影响。
4. 切换 Designer 当前会话与本机历史，检查一条携带 Job 标识的客户端错误仍位于 Designer 来源；返回 Runtime 后其查询条件与阅读状态不串扰。

覆盖：G1、G2、G3 历史检索、G4 重启时间、G6 完整导出。取消保留目标、固定上界期间新增事件等既有规则优先使用已有测试证据，无需在人工走查另造复杂故障。
