## 1. 六组统一行为标准

### G1. 来源、任务目录与关联关系

- 一级来源只有 Runtime 运行日志和 Designer 本机日志。先按可信生产者来源分类，再判断 Runtime 记录的真实 Job 归属；系统事件只包含无真实 Job 归属的 Runtime 记录。
- Designer 本机事件即使携带 Job / workflow / node 标识，也保留在 Designer。客户端连接或查询失败不冒充 Runtime Job 失败。
- 首页保留“运行中”和“最近已结束”。按任务自身 status 归组：已受理、启动中、运行中、停止中在上组；已完成、失败、已停止在下组。active 不单独决定执行结果，不把已完成改成运行中。
- “最近已结束”合并常规 recent 页与当前快照内终态且 active 的任务。当前 Runtime / 工程 / Job 身份去重，实时 RunState 优先；同一主目录任务只出现一次。
- 即使终态 active 任务早于常规 recent 页，它仍显示，不能在合并后按常规页额度裁掉。后续成功快照中不再 active 时恢复普通 recent / 更早历史规则，不永久缓存所有曾活动的任务。
- **普通同步子工作流调用仍在同一 Job 内执行，父调用沿现有调用语义等待子工作流返回后继续。** 该结构、While / ForEach / Repeat 轮次和连续根调用不产生新的首页 Job，也不计作“关联任务”。不能为了呈现已完成主任务而改变普通调用的等待语义。
- **托管派发的下游具有独立 Job，才可作为来源任务的额外关联任务。** 当前 Runtime、工程、非空运行组和 source_job_id 精确对应时，才统计实际未终态关联成员。相同名字、时间邻近、同一节点或循环路径不足以建立关系；其他独立启动的 Job 仍按自身身份显示，但不因此算作这个来源的下游。
- 已确认的成员显示各自真实状态和“还有 N 个关联任务未结束”；快捷引用不增加主目录数量。来源 Job 已终态但仍 active、无法确认具体成员时，采用“结束处理未完成”及准确说明，不编造设备关闭、保存结果、进度或即将恢复。
- 从来源任务查看关联 Job 后，返回恢复原来源、有效筛选、结构 / 时间模式及可查询的选择 / 锚点。采用轻量书签和单个有界事件窗口，不永久保留多套历史载荷。原位置确已不可查询时保留筛选并如实提示，不伪造恢复成功。
- 当前操作以 `allowed_actions` 和现有执行前身份重查为准。终态 active 移入下组后，Runtime 允许的停止操作仍可使用；具体停止对象与运行组语义沿用已有请求。纯历史摘要不获得当前运行控制权，也不依据副提示自行产生 stop 权限。
- 历史目录继续从现有 `jobs` 表读取终态摘要，保留工程、状态、结束时间和稳定分页。Runtime 重启后可读取保留历史及旧实例事件；请求使用当前目标实例校验，事件保留原生产实例。

**本轮最小证据组合：** 用已有目录夹具放入一个终态 active 来源、两个真实未终态下游、一个同名但身份不匹配的任务，以及超出 recent 页的来源记录。在同一组数据中判断分组、数量、实时优先、页额度、下一快照退出保留和权限。普通同 Job 子调用沿用已有工作流契约与 Q1 树身份，不另建所有派发 / 循环组合矩阵。来源返回在原 Q1 的相关步骤核对。

### G2. 近期事件、实时补齐与有界窗口

- 打开长时间 Job 时取得近期原始事件页与固定历史上界，补齐随后增量；与唯一的 Runtime 全局读取来源合并，按当前查询存储上下文的全局 eventId 去重。
- “加载更早”沿用固定上界及服务端原始页游标。排序、边界和过滤后空页遵循既有合同，不以 UI 可见行决定是否还有下一页。
- 最近页、向前分页与实时合并不误删、不重复；旧前向查询及完整导出的方向、字节边界和末页语义保留。
- 原始事件窗口不超过 10000 条。历史阅读时按原规则仅显示已观察到的新事件提示，不持续缓存所有新载荷，不抢滚动位置；返回最新重建近期窗口并补齐增量。
- 加载更早页导致退窗时，说明范围变化并保留当前选择 / 锚点。无法同时满足保留和容量时提示切换窗口；展开分支不永久锁住其全部历史。
- 新增关联导航沿用上述单窗口和有限查询方式。只保存必要身份、过滤与锚点，不引入每 Job reader、全量历史复制或多窗口无限保留。

**证据使用：** 基线已有分页、实时交界、实例切换和容量检查继续有效。本轮只核对关联往返或实际改动触及的接线；不因为这份标准是完整文本就重跑所有窗口边界、压力或故障组合。

### G3. 执行结构、循环与筛选

- 普通工作流、连续根调用、子工作流、并行分支和嵌套循环使用真实 workflowRunId、parentWorkflowRunId、nodeRunId、iterationPath 和循环节点身份组织。同名对象不跨调用合并，缺少关联证据时如实标明。
- While 两条已有执行路径保留 bodyExecuted 三态：true 为循环体执行并正常完成，false 为条件为 false 未进入循环体，缺省为未记录。最终 false 条件检查不计入循环体轮次；失败或取消没有完成事件也不等于 false。
- ForEach / Repeat 仅使用可确认总量；无限 While 不显示虚构百分比。普通非循环调用的合法空路径与缺失字段保持区别。
- 主行突出已知名称、轮次、状态、时间与消息，不重复铺满 UUID。完整 ID 和原始路径仍可在详情 / 提示中查看，分组与选择继续使用真实键。
- 第 1 / 第 2 轮由真实零基索引转换，嵌套路径逐段保留；如 `[0,1]` 对应外层第 1 轮、内层第 2 轮。技术条件仍能精确输入 `0/1`。不能用当前可见行号制造整个 Job 的累计次数。
- 高级筛选默认收起，常用条件与技术条件分层。折叠不清除生效值，条件摘要保持可见；名称候选来自已知且身份匹配的元数据或已加载记录，精确 ID 输入保留，同名对象可区分。
- Job 执行树由未被本地条件裁剪的原始窗口建立，再投影筛选。只看 WARN / ERROR 时保留命中祖先，结构 / 时间视图共用窗口、有效条件与选择。
- 服务端高级历史保留已有 project / job / device / component / level / workflow / node / time 能力，可查当前窗口之外的保留记录。调用 ID、原始轮次路径、关键字等仅本地支持的条件不伪装成服务端全库查询；历史命中列表不冒充完整执行树。
- “查看本轮上下文”说明已加载范围，可继续加载更早。历史命中回到结构、查看上下文再返回，均使用真实身份和现有范围语义，恢复原有效筛选、选择与阅读位置。

#### 日期时间输入的统一标准

| 入口 | 筛选对象 | 沿用字段 |
| --- | --- | --- |
| Job 已加载事件 | 事件发生时间 | startTimestampMs / endTimestampMs |
| 服务端高级事件历史 | 事件发生时间 | startTimestampMs / endTimestampMs |
| 更早历史任务目录 | 任务实际结束时间 | startEndedAtMs / endEndedAtMs |

- 两端默认“不限”；可只启用一侧。清空实际移除该边界参数，不把控件初始日期、1970 年、当天或最近一小时当默认范围。
- Qt 日期时间输入使用真实本机时区，显示秒并保留毫秒。回填、折叠、往返和请求转换不丢精度；不把原型 UTC+08:00 固定偏移复制进产品。
- 区间统一为 `[开始, 结束)`，包含起点、排除终点。相等边界是合法空区间，不放大成全天或擅自补一毫秒。
- 起点晚于终点只显示行内提示，不发无效请求，不用倒置条件将旧结果清空；此前有效条件继续对应当前显示结果。输入纠正后可正常应用，不新增确认框或重试。
- 翻页继续使用已提交范围，不混入尚未提交的控件编辑值。从 Job 进入服务端历史时固定该 Job / 工程并传入支持的有效条件，返回恢复原范围。
- 共享 StructuredLogView 的 Designer 本机历史沿用同一日期输入适配，不保留另一套需要手填毫秒的正常查询入口。

**本轮最小证据组合：** 复用一组确定的事件时间：起点之前、恰在起点和恰在终点。验证一次毫秒与半开边界，再检查三个入口字段接线。将“不限 / 相等 / 倒置后保留”合并进同一日期控件或页面检查；本机非整秒时间往返一次即可，不建立所有时区 / 夏令时矩阵。结构展示用一条真实身份与嵌套路径记录检查选择、精确路径和切换保持，不为每种循环深度重建工程。

### G4. 时间状态与当前执行位置

- Job 使用实际 startedAt，受理与开始分开。RUNNING / STOPPING 且有有效开始、无实际结束时显示墙钟估时，不称为纯计算耗时。
- 终态 Job 的运行时间保持固定，关联 Job 活动或 Runtime 保留的所有权不延长来源 Job 自身耗时。独立下游按自己的状态计时；连续调用之间等待不计入单次 workflowRun。
- 子工作流、轮次和节点只用匹配的有效生命周期时间配对。Job 终态不能充当每个子对象的结束事件；无 started 的 skipped 节点不伪造 0 ms。
- E_RUNTIME_RESTARTED 的记录为中断确认时间，开始至确认的差值不冒充实际执行耗时。
- 原始时间缺失、配对未加载、原因不明依据已有证据区分。列内可使用“时间信息不完整”等短标签，详情 / tooltip 保留真实原因；没有清理证据时不声称记录已清理。
- 当前定位使用同 Job、当前连接和连续生命周期证据；缓存 RUNNING 或最新一条日志不能单独证明当前位置。证据不足时提示位置尚未确认；被筛选隐藏时临时显示正确目标及祖先并可返回原条件。

**证据使用：** 沿用已有计时 / 定位模型检查。本轮目录状态数据同时确认终态 active 的耗时不增长，并在实际 Qt 核对短标签和详细原因即可；不新增状态账本、当前节点 RPC 或大型时钟故障测试。

### G5. 设备身份与诊断往返

- executeDevice 与 captureDevice 保留相同的可用执行上下文；诊断 append 形成 row 前的集中 source 归一化及原始 source 保留继续有效。
- 可信顶层范围 / Job / device 身份优先，合法空 iterationPath 不被覆盖；不在客户端或多个层次重复发明兜底逻辑。
- 只有明确设备身份才打开相应近期缓存。Runtime / 工程加载代次不匹配时如实说明该缓存不可用于历史记录，持久化 Job 事件仍可阅读。
- 设备同类问题累计次数和经过时间可能跨任务 / 轮次，不写成本轮失败次数；恢复摘要不抹去已失败节点的历史结果。
- 下钻复用既有通道、HEX / UTF-8、详情和已返回缓存导出。缓存记录不重复追加到 Job 树，缓存 cursor 不当作持久事件 eventId；返回恢复原 Job、选择、筛选和位置。

**证据使用：** 原身份归一化和缓存合同未改时沿用基线相关测试，不重测驱动和设备型号。Q1 只确认本轮改动后的页面、抽屉与设备返回仍连通；若本次确实改到设备接线，增加对应的必要断言。

### G6. 共享易读详情、调试和导出

- 选中事件打开右侧详情，关闭恢复事件区域空间并保留列表上下文。默认易读层与原始 JSON 对应同一条收到的记录。
- 无主动 node.log 的普通算子仍能阅读实际节点生命周期事件中的状态、ioSummary、metrics、diagnostics 和原因。started、completed、failed、skipped 按真实类型展示，不要求算子再打一条业务日志，也不把失败或跳过伪装成成功。
- node.log 使用真实 message、code 和 payload.data。通用值保留 0、false、null、空字符串、空数组、空对象及缺失区别；未知字段不猜单位，不把 lifecycle 自动解释为初始化。
- 对象、混合数组和长文本可展开；同结构简单对象数组可表格分段浏览。只展示当前收到的数据，不因展开操作声称取得完整历史。
- 易读 / 原始页共用当前对象；LogJsonTree 的类型、层级、惰性展开、长文本和复制能力保留。截断 / 脱敏信息准确，缺少截断标记不等于完整输出已被保存。
- ioSummary 是摘要；metrics 和 diagnostics 只展示真实返回值。旧轮次日志不自动跳到最新节点结果，不从 shape / count 生成图片或完整列表，不新增全轮结果保留。
- 本轮只在现有适配点中文显示**已知框架默认消息**和明确状态字段。算子主动消息、用户业务文本、未知事件 / 状态保留原文；不根据英文字符串全局替换，也不递归改写任意业务数据中叫 status 的字段。
- 完整 ID、原始 message / status / eventType、JSON、复制原值和复制当前记录仍对应输入记录。简化显示不能改变结构身份或导出内容。
- 既有单算子调试继续复用同一详情组件。事件以 ReadOperatorDebugEvents 的真实 wrapper 与内层 event 区分；外层 type=node.log 不必然是算子主动日志。同 session / generation / executionId 才能关联结果。
- 调试成功结果读取同次 GetOperatorDebugExecution 的实际 outputs / outputAssets / metrics / diagnostics / elapsedMs，不依赖或伪造 node.completed / ioSummary。inputSources 不冒充完整输入，finishedAtMs 不当作日历时间；失败或缺省字段保持实际情况。
- 原调试结果和 PLC 可读日志 / 原始事件保持，不新增调试 Job、RPC、存储或轮询。纯预览及实时预览失败信息继续使用既有边界，不建立成功预览持久日志流。
- “导出任务完整记录”使用当前 Job 的完整可查询范围与固定上界，包含未加载记录，不受本地日期、WARN、节点、关键字或 10000 条窗口限制。不能传入反向分页参数或继承另一视图的筛选。
- 高级历史的“导出完整选定范围”遵循该页面已提交的服务端条件。导出时新增事件不改变既定范围，取消 / 失败不报告成功；设备诊断导出只代表已返回近期缓存。

## 2. 两条既有 Qt 路径的当前核对

Q1、Q2 继续作为统一操作路径，可以由已有 Qt 自动化脚本驱动或人工完成。记录实际方法。未改变的步骤可以引用原报告；本轮改变的步骤需要当前窗口与实际数据证据，不只复用旧图。

软件设备、临时工程、分页夹具和真实 Runtime 产生的记录分别标明。无需真实等待数小时来证明长时间运行，也不为本次界面调整新建独立验收工程体系。

### Q1. 任务状态 → 循环阅读 → 关联往返 → 易读详情

1. 从 Runtime 首页进入原持续工作流，确认一个 Job 下的普通同步子调用、循环和连续根调用保持真实结构；不要把每轮显示为新首页任务。来源切换与普通任务入口保留。
2. 使用已有目录状态夹具或已有软件派发场景，查看一个已完成且仍 active 的来源任务和真实独立下游。确认来源在最近已结束、下游按自身状态显示，来源耗时固定，副提示与权限正确。没有真实成员证据的场景只显示准确的未知原因说明。
3. 在来源详情设置有效筛选并选中一条事件，查看关联任务后返回，确认原来源、模式、筛选及选择 / 锚点恢复。不得以重新打开默认页面代替来源返回验证。
4. 在原 While 场景筛选告警，观察祖先、轮次和已加载范围；展开 / 收起常用与技术条件，输入真实 ID 或路径，切换结构 / 时间并查看右侧详情。主行简洁，完整身份和时间原因仍可查；收起条件不清值。
5. 复用原整数加法完成摘要和 SQLite 主动日志，核对中文框架 / 状态展示、实际返回值、同一事件原始 JSON 和复制。选一条记录完成必要展开 / 复制即可，不把每种控件操作在全部算子重做。
6. 原设备诊断、历史阅读、返回最新、定位当前与 STOPPING 到终态的路径继续可用。本轮改动若触及对应接线，在同次操作中核对返回位置和固定时间；未改底层的缓存、窗口上限与生命周期边界引用既有证据。
7. 既有单算子调试入口继续使用共享详情，已知状态易读而原始结果不变。同次会话 / 执行关联沿用现有检查；若本轮只改共享显示，不再重复建立新的调试执行器或完整会话测试。

关联状态可以使用明确标识的现有夹具，不能把夹具声称为真实相机 / PLC 的运行结果。普通调用等待和独立 Job 关系要由已有合同与真实身份支持，不靠一张示意图判断。

### Q2. 历史目录 → 日期范围 → 返回任务 → 完整导出

1. 沿原 Q2 使用保留历史与重启后的软件 Runtime，打开更早历史。目录用任务结束时间输入，未启用边界不限，分页沿已提交范围；旧实例事件与当前查询实例的区分保持。
2. 在一个有多页事件的 Job 中设置本地 WARN 及含毫秒的日期条件。从高级历史入口查窗口外记录，确认事件时间字段、半开边界和固定任务身份；返回保留原有效条件和阅读位置。
3. 在已有日期输入路径中检查不限、相等空区间、倒置时行内提示并保留旧结果。纠正后正常应用。三个入口复用同一转换，只检查各自接线，勿重建三套边界矩阵。
4. 从 Job 入口导出完整记录，与同一保留范围和上界的实际查询对照：包含未加载记录及本地日期 / WARN 范围外记录。高级历史选定范围导出仍遵循其已提交条件，不混用两个按钮的含义。
5. Designer 当前会话 / 本机历史以及带 Job ID 的客户端错误仍属于 Designer。共享日期控件回填和来源切换如受本次修改影响，在这里核对；其余来源归属复用原检查。

固定上界期间新增、取消保留原目标文件等未改变的导出算法继续使用现有测试证据，不为这次日期输入增加复杂故障场景。
