## 4. 不可误实现的关键合同

- `status` 决定本 Job 是否结束；`active` 表示 Runtime 仍需要保留相关运行处理，不能直接等价成正在执行。终态 active 与常规最近页并集合并，不被最近页额度挤掉；实时结果优先，不建立永久置顶缓存。
- 普通 `SubflowRunner.run()` 同步等待且共享 jobId；托管 Dispatch 组创建独立 Job。实际匹配 Runtime / 工程 / 非空运行组 / source_job_id 后才能写“还有 N 个关联任务未结束”。未知具体原因写“结束处理未完成”，不猜关闭设备或保存结果。
- 任务完成后耗时固定；关联任务各自计时。停止仍服从 allowed_actions 和现有身份复查，不能因为终态就一律取消源任务对关联组的既有停止操作。
- 关联往返保存一个轻量来源书签，复用一个有界事件窗口；禁止每任务长期缓存或第二条全局订阅。
- 日期输入默认不限，保留毫秒和本机时区，区间为 `[开始,结束)`。相等是合法空区间；倒置输入仅行内提示，旧结果及已生效条件保留，下一页不混入未提交值。
- 高级筛选保留全部原字段、精确 ID 和原始嵌套路径；折叠只改变显示。历史搜索的稀疏命中不能用来构造完整执行树。
- 已知框架默认文字和明确状态字段才映射中文；算子主动业务文本、未知值、原始 JSON、复制原记录和导出保持。调试仍使用真实会话 / 代次 / executionId，不产生假生产 Job。
- 不增加 RPC、表、状态枚举、设备采集、逐算子渲染器或全量扫描。本次只调整 UI 输入、目录呈现、必要局部状态和既有接线，保留 PySide2 / Qt Widgets。
