## 1. 本次审查的对象与结论边界

本次将原运行日志工作台计划与后续易用性修正整合到同一个 `redesign-runtime-log-workbench` change。核对实现基线为 `fa4b72d751189c2689882a0a0d127fd280a35fde`，不是仍未实现工作台的早期设计基线。

原 38 个已完成任务及原实施报告作为历史实现事实保留；任务 7.x 的 11 个新增项保持待完成。完整 spec 以 21 个 ADDED Requirement 描述最终目标，当前正式 capability 尚未建立时可由这个 change 一次形成完整规范。不存在另一个补充 change 的实施或归档依赖。

这里审查的是**完整计划能否准确指导已有代码的后续修改，以及改动与验证是否必要**。源码阅读、旧 Qt 证据、原型点击和 OpenSpec 校验不等于本轮产品已经修改或通过测试。实际实施者需记录新工作树的结果；不得把原实施报告的通过数量沿抄为 7.x 的证据。

## 2. 需要修正的是实际使用问题

已核对的现状与对应修改：

- 目录把所有 active 任务放入“正在运行”，其中包含已完成、失败或已停止的任务。按 status 归组，并保留当前仍需管理的终态任务，能直接消除状态与位置的矛盾。
- “下游资源仍在收尾”无法准确解释所有 terminal-active 情形。用实际独立下游 Job 说明；没有明确原因时使用“结束处理未完成”。这是更准确地表达已有数据，不是新增运行状态机。
- 时间筛选要求手填整数毫秒。复用 Qt 日期时间输入并转换成原参数，保留时间精度和边界。
- 高级条件展开占用较多空间、树主行出现长 UUID 和不完整时间的长说明、共享详情中部分框架状态仍为内部枚举。分层显示和有限的框架文案适配即可改善，不需要改存储、执行图或重做主题。

以上均来自已存在的正常交互路径，没有为了假想极端场景扩展功能。

## 3. 必须保留的正确性，不属于过度防御

| 保留项 | 为什么与正常使用直接相关 |
| --- | --- |
| 来源先判 Runtime/Designer，再判有效 Job | Designer 连接/查询错误可以带 Job ID，但不能变成 Runtime 执行事件；系统事件不能重复显示任务记录 |
| 当前 RunState 优先、目录唯一、terminal-active 不受 recent 页裁剪 | 长时间下游处理可能比最近页更早；不能因展示调整让仍有合法操作的任务消失 |
| Runtime/工程/运行组/来源 Job 精确关系 | 同名流程、多轮调用和普通子工作流都会出现，按名称或时间猜测会直接展示错误任务 |
| allowed_actions 与操作前身份检查 | 移到最近已结束的源 Job 仍可能允许停止关联任务；界面不能自行新增或移除权限 |
| 实际开始、终态冻结、缺配对和重启确认的区别 | 工程师需要判断实际耗时；关联下游更久不等于源任务还在运行 |
| 全局交付进度、固定历史上界、原始页游标与单个有界窗口 | 正常持续运行、历史翻页和本地筛选会同时发生，已有这些约束避免重复、漏读或无限堆积 |
| 日期可空、毫秒精度、起含终不含、倒置不提交 | 直接影响边界事件能否找到以及用户是否误以为无结果；在输入边界统一处理即可 |
| 原始值/身份保持、完整任务导出与当前筛选分开 | 可读化不能把 false/0/空值改义，不能把当前窗口或筛选结果误当整个任务 |
| 设备缓存范围和独立调试身份 | 当前设备缓存不是任意历史证据；单算子调试不是生产 Job，不能从别次结果补一张看似正确的输出 |

保留既有这些检查，不意味着在每层重新实现同样的判断。本轮修正应在已有归属、展示和输入适配点完成，不再加重复兜底。

## 4. “子流程”术语已校准

当前普通 `SubflowRunner.run()` 同步等待子调用；`RunContext.childWorkflow()` 保留同一 Job，并用新的 workflowRunId 与 parentWorkflowRunId 表达父子关系。普通子工作流、While 轮次和连续根调用都应留在同一任务执行结构里。

派发运行组由 `JobSupervisor._startRunGroup()` 创建独立下游 Job。Dispatch 获得接收结果即可返回，Join 才等待目标结果；这种独立下游任务可能在源任务完成后继续执行。不能据此宣称所有子工作流都会在父 Job 完成后继续运行。

另有 terminal-active 仅来自本 Job 进程、事件桥或结束处理记录的情况。`owns_resources` 不是“正在释放相机”的直接证据。完整计划据此采用以下口径：

- 找到真实未终态下游 Job：显示实际数量、名称、状态与查看入口。
- 无法确认具体原因：显示“结束处理未完成”，说明接口没有提供具体未完成项。
- 普通任务正常结束且不再 active：保留结果，不增加提示。

源码依据与关键函数集中列在 [source-map.md](source-map.md)，避免在不同文档里出现相反解释。

## 5. 已明确排除的过度实现

| 容易扩大的方向 | 本计划采用的最小做法 |
| --- | --- |
| 新增资源清理服务、结束状态机、清理超时或后台重试 | 复用现有 status/active/ownership，只修正界面分组和说明 |
| 为显示关联任务数量新增 RPC 或固定队列轮询 | 使用已经返回的 ListRuns 及真实关系字段；队列详情不是本轮必做 |
| 新任务表、第三份设备日志库、跨会话置顶账本 | 复用现有 jobs/jobEvents 与设备近期缓存；terminal-active 仅从当前实时快照合并 |
| 给关联返回保存多个完整任务窗口 | 仅一个轻量来源书签，返回通过现有查询恢复；不能查到锚点时如实提示 |
| 为旧日志重建父子关系、名称、循环总数或历史图片 | 只用记录和身份匹配的已知元数据；缺失保持可见，不回查任意工程猜测 |
| 为 82 个算子补写同样的日志或注册专用详情渲染器 | 正式执行框架摘要与主动日志共用通用显示；调试入口复用同一组件 |
| 新时区平台、通用表单框架或多层时间校验 | Qt 可选日期时间控件及轻量适配，在 UI 提交边界处理一次，复用服务端原语义 |
| 全局中文化或把未知英文业务内容自动翻译 | 只映射已知框架默认文案和状态，用户消息、未知值及原始记录不改 |
| 按 HTML 原型全面重写 Qt 主题或迁移技术栈 | 保持 Python 3.10、PySide2/Qt Widgets 和既有组件，只整理相关布局与阅读层次 |
| 为预览新增成功日志持久化或把调试包装成 Job | 保留现有预览失败缓冲信息及独立调试会话，不增加平行日志系统 |

既有 V2.3 曾经实现的 RPC/查询扩展已属于当前基线。表中的“不新增 RPC”指本轮 7.x 无需再次扩展协议，不要求删除已有历史目录和反向查询能力。

## 6. 测试是否过度

### 原必要门禁保留

原 G1–G6 对来源/目录、实时窗口、执行结构、生命周期时间、设备归属、通用详情及导出有明确职责；Q1/Q2 对原生 Qt 接线和软件 Runtime 的实际操作有证据。它们继续作为完整工作台的验收结构，不因精简测试而删除有效断言或绕开仓库必须门禁。

保留既有已完成证据，不意味着为了新增文案再从零执行所有旧检查。实施者先识别本轮真正受影响的范围，运行必要相关检查；如修改影响原边界，再扩大到能证明该问题的最小范围。

### 新验证聚焦行为

7.x 的验证按现有测试与走查组织，不要求每一条设计说明新增一个测试函数：

1. **目录与关联：** 在一个小型真实形状夹具中同时验证 status 分组、实时覆盖历史、早于 recent 页的 terminal-active 保留、后续退出特殊保留、正确关系数量、同名不同身份反例，以及允许的停止操作。关联跳转/返回复用同一 Qt 路径。
2. **日期输入接线：** 共享转换只验证一次毫秒与 `[开始, 结束)` 边界、未启用和倒置处理；各入口检查字段接线和回填，不分别复制完整时间矩阵。
3. **易读不改事实：** 用已有代表记录验证真实身份、原始消息和值仍一致；共享组件验证一次，独立调试只确认接线和正确执行身份。完整 Job 导出沿用原 Q2，增加有效日期条件后仍保持原完整范围。
4. **原生界面：** 在既有 Q1/Q2 中观察当前首页、折叠筛选、树与详情、日期查询与返回；使用实际 Qt 截图及操作记录，不另起第三、第四条完整端到端流程。

明确不新增字符串 helper 镜像测试、逐条标签断言、全算子/全模型/真实设备矩阵、全时区或所有故障排列、全分辨率像素快照、长时间压力专项。纯文字和间距调整以实际界面核对为主。旧 Patch 01 为简单字符串新增的镜像测试不作为整合后必留门禁；有价值的目录行为断言继续保留。

“软件 Runtime 通过”不等于真实相机/PLC通过；未运行的环境只按实际限制报告，不为了文档完整而伪造结果，也不把无关硬件验证变成这次 UI 改进的新前置条件。
