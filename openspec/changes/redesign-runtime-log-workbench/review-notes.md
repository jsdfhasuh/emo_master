## V1 → V2：第一次审查的补齐背景

此表保留修订历史，其中“仅补 false”“Diagnostics 投影”等原描述已在下一节收口，不能替代 V2.1 的具体定义。

| 审查发现 | V2 修订 |
|---|---|
| 当前 QueryRuntimeLogs 只支持 afterEventId 升序页，实时 reader 首次连接只从尾部开始；历史页替换当前页，历史模式不接收实时追加 | 扩展同一 QueryRuntimeLogs 支持最新页与 beforeEventId；固定 upperEventId；首次快照后从上界补实时增量；更早页追加而非替换 |
| WARN / ERROR 服务端筛选会丢失建立树和计时所需的 INFO 生命周期事件 | Job 执行树先使用未裁剪的已加载原始事件建立，再应用 UI 筛选；明确筛选范围 |
| While false 条件检查也产生 iteration started/completed，但没有执行循环体 | 复用 mode；只补 bodyExecuted=false；UI 不把最终 false 检查计为业务处理轮次 |
| 计划提出新增 loopType，但现有 loop.started 已有 mode | 删除重复 loopType；仅在准确已知时补 totalIterations |
| jobs.startAt 是受理时间，startedAt 才是实际开始时间；durationMs 按 startAt 计算 | Job 运行时长使用 startedAt / endedAt；受理时间单独显示；不直接把 durationMs 当实际执行耗时 |
| RunState.active 可能因 Dispatch 下游资源所有权而保持 true | Job 自身计时按 JobRecord 终态判断，不由 active 单独决定 |
| Device Manager 将执行标识放在嵌套 source，Diagnostics 投影主要读取顶层字段 | 在 Diagnostics 投影处单点归一化 source；executeDevice / captureDevice 统一传递可用字段 |
| 系统事件先过滤 Job 关联记录，可能出现空可见页但仍有下一页 | 按服务端游标继续翻页，不因当前可见页为空而结束 |
| 测试清单把既有行为再次列为新增测试 | 改为复用现有分页、导出、缓存范围、实例切换和滚动测试；只为新增行为补聚焦测试 |
| 设备缓存与历史 Job 的加载代次不同，不能映射成历史完整诊断 | 保留近期缓存边界；无法匹配时显示不可用，Job 持久化事件仍可查看 |

## V2 → V2.1：交给实施者前消除的具体歧义

| V2 中仍可能导致偏差的内容 | V2.1 修正与实施范围 |
|---|---|
| 反向分页提到“可见事件”游标，没有完整约定末页、空页或字节预算截断 | 按原始页事件定义反向边界和继续条件；补齐末页、零记录页、字节预算导致部分返回或单条不可返回的行为；保留旧正向语义 |
| 只增加 proto 字段，旧 Runtime 可能忽略新字段而返回旧方向结果 | 通过现有 `RunReadRpcMixin.GetRuntimeInfo.capabilities` 声明新增能力，客户端识别后启用；未支持时如实显示能力范围，不伪装成最近页 |
| “保留实时订阅再补 gap”容易被实现成第二个持续 Job reader；查询 cursor 与界面已收到事件并不等价 | 保留唯一 RuntimeGlobalLogs reader，定义交付水位和有限缺口补取；快照上界、查询进度、界面已应用范围分别处理 |
| “高级筛选默认仅已加载”与“全 Job 搜索以后再做”会误删既有服务端查询能力 | 保留原有服务端高级查询；明确结构树筛选作用于已加载原始页，服务端命中列表不声称结构完整；不新增全量索引或后台全表扫描 |
| “查看本轮完整上下文”可能仅清空筛选，实际缺页却标完整 | 按实际已加载范围提示上下文完整性；加载更早页、返回原筛选及阅读位置均有明确语义；不承诺无法证明的全量上下文 |
| “定位当前”可能用最新事件或最近节点观测直接猜当前执行点 | 明确身份匹配与连续事件证据要求；NodeRunInspection 仅是最近观测，缺证据时显示当前位置未确认，不引入全 Job 当前节点快照服务 |
| “保留已加载页 / 展开项”与有界内存存在冲突 | 明确 10000 条原始事件窗口及轻量定位状态；展开历史不构成无限持有原始事件的豁免，窗口变化需如实提示范围 |
| 仅 RUNNING 动态计时会遗漏 STOPPING；重启后的 endAt 被当作实际执行终点 | STOPPING 有实际开始时间时继续计时；终态固定，资源 active 不覆盖自身终态；E_RUNTIME_RESTARTED 的 endAt 标为重启确认时间，实际结束未知 |
| 缺少起止配对就分别宣称“已清理 / 旧历史” | 只在有证据时显示具体原因；其他情况为时间信息不完整，不新增清理审计表，也不伪造节点结束时间 |
| While 只规定 bodyExecuted=false，未定义 true、缺省、异常及旧版 While | 定义 true / false / 缺省语义，覆盖旧版 While 和 V2 While；异常不补造 completed，旧事件缺字段不等于 false；复用 mode，不新增 loopType |
| “Diagnostics 投影”可能被理解为只改 projectEvent，从而漏掉原生设备路径 | 在 `DeviceDiagnostics.append()` 形成 row 前单点归一化 source；可信顶层字段优先，合法空 iterationPath 保留；execute / capture 对齐可用身份，历史缺失不宣称回填 |
| 设备摘要 occurrences 容易被展示为当前 Job 或本轮失败次数 | 明确既有聚合跨 Job / 轮次，累计次数和聚合时长采用设备范围标签；恢复只代表后续成功，不改变先前失败节点结果 |
| 有 Job ID 的 Designer 本机错误可能被误归 Runtime | 先按 originApp / 已知采集来源分类，再在 Runtime 内判断 Job 归属；复用现有 Designer 带 Job 错误用例 |
| 正式 capability spec 在 V2 重写时缺少右侧抽屉、完整 Job 导出等已确认能力 | 恢复正式要求与验收项；抽屉关闭保留上下文；完整 Job 导出固定范围并遍历服务端页面，不能受旧 `_historyFilters` 或当前缓存上限误裁剪 |
| source-map 保留新增 loopType 等过时条目，多个补充段落口径不一 | 合并为单一实施合同并修正源码映射，源码事实、计划新增能力和未验证结果分开标明 |

## 这次修订的验收边界

- 本次处理的是计划可实施性，未运行修改后的产品代码；文件结构或 OpenSpec 格式检查不能代替行为验证。
- 不为每个控件、字段和嵌套深度新建独立测试。优先扩充既有查询、导出、循环、设备和 Qt 行为用例，仅补新增合同的必要断言。
- 最终结果仍需按阶段用软件 Runtime 与真实 Qt 窗口核对；原型交互通过不能替代正式实现验收。
- 不引入第二套日志采集系统、永久执行树存储、通用防御框架、跨 Runtime 设备缓存映射或额外硬件测试矩阵。
- 实施者需如实报告已完成任务、实际验证命令与结果、尚未验证的场景；不能仅凭完成清单宣称效果已有保证。

## V2.2 → V2.3：补齐全算子数据覆盖，再审核实现与测试负担

### 补齐后的再审结论

当前方案可作为实现依据；没有发现需要再加一层通用日志协议、持久账本、恢复 / 重试框架或逐算子渲染注册机制的依据。核心改动是复用已有数据、共享展示能力并接通独立调试入口。计划完成不等于产品完成，最终效果仍需实际实现和现有两条原生走查证明。

本轮将实现 / 合同核对与验证负担检查分开审查，再由主审对照原型和交付包收口。复核了无主动日志、完成结果、托管设备、独立调试会话四种容易混淆的数据来源。检查发现的当前问题及处理如下：

| 发现 | 处理 | 对实现范围的影响 |
|---|---|---|
| V2.2 的 4.8 只强制 node.log.payload.data，完成摘要仍可选，无法覆盖大部分算法算子的有效信息 | D10 / spec / 4.8 改为直接展示当前框架事件的真实 ioSummary / metrics / diagnostics；主动日志为附加 | 扩展通用展示，不批量改 82 个算子 |
| 单算子调试普通日志仍 str(event)，改任务抽屉不会自动覆盖 | 独立 4.9 适配已有事件 wrapper 与同次执行结果，实际复用同一展示能力 | 一个真实入口接线任务；无新 RPC、存储或轮询器 |
| 单算子不经 WorkflowRunner，不能等 node.completed 来展示结果 | 使用已有 GetOperatorDebugExecution；日志和结果明确来源与身份 | 删除伪造 Job / 完成事件的实现方向 |
| 相机 / PLC 的显式日志部分在兼容直连路径，不能按代码中出现 logger 就称每次托管执行都有 | 盘点记录执行条件；托管路径优先展示现有指标和设备诊断 | 不重复写同一份设备内容到 node.log |
| D7 允许为旧事件回查匹配版本工程定义补 mode / total | 删除此可选回查与推断分支；缺失直接显示未记录 | 减少兼容代码、定义查询与相应测试 |
| 多入口可能各复制一份 JSON 展开、复制和空值测试 | 共享组件验证一次；入口只验证取值、身份与返回状态 | 合并到 G6 / 6.2，不增加另一套测试 |
| 单算子调试可能变成第三条独立验收流程 | 并入 Q1 的一小段软件调试，Q2 保留历史与导出 | 仍为两条原生走查 |
| 原型历史 node.started 显示“运行中”、通用样例宣称源码字段、SQLite 手填身份存在串接风险 | 改为“开始记录”；通用数据明确模拟；receipt 从当前事件上下文取身份 | 修复当前可见语义，不新增后台防御 |
| 调试正文暴露 RPC 名称、非字符串 diagnostics.text 可能被忽略 | 正文使用来源名称，技术标识折叠；未作为文本展示的 text 保留在通用字段 | 减少理解负担、保留原有数据 |

### 本轮明确不增加的工作

- 不给 82 个算子逐个增加重复 logger 调用；不把缺少主动业务日志当作基础记录缺失。
- 不逐算子、逐模型或逐硬件验收，不新增厂商设备矩阵；原型与组件夹具可使用真实契约形状，注明模拟。
- 不为共享展示在运行日志和调试窗口各写相同的类型、数组、长文本与复制用例。
- 不重测未改变的 logger 限流 / 脱敏、全部调试 RPC、资产传输和完整状态机；实际修改到相关路径时才补对应检查。
- 不增加成功预览持久日志、全轮次图像历史、旧记录数据回填、全历史扫描或多故障组合门槛。

### 保留的必要正确性约束

| 保留项 | 正常使用中对应的问题 |
|---|---|
| 固定上界、原始页游标、唯一 RuntimeGlobalLogs 与有限补齐 | 打开长任务、加载更早、切回实时会遇到；处理不正确会漏页或重复 |
| 有界窗口和历史阅读锚点 | While / 连续任务长期运行会持续产生记录；不能无限缓存，也不能抢走阅读位置 |
| workflowRunId / nodeRunId / iterationPath 与调试 session / generation / executionId | 同名节点执行多次、切换结果是日常行为；必须避免把另一轮结果填进当前详情 |
| 设备 source 单点归一化及缓存范围 | 防止历史任务读取另一工程代次或另一设备的近期缓存；不在各层重复兜底 |
| 0 / false / null / 空值、摘要与截断语义 | 视觉检测的“0 个目标”和布尔 false 都是有效结果；不能被缺省符号替代 |
| 两条原生 Qt + 软件 Runtime 走查 | 原型和组件验证不能证明真实窗口、查询、复制、导出与返回状态已经接通 |

这些约束通过现有机制和少量直接反例验证，不扩成任意版本兼容、线程交错穷举、时钟故障或长时间压力专项。

### 本次验证数量与停止条件

V2.3 有 38 项待实施任务、16 项 Requirement、39 个 Scenario；比 V2.2 只新增一个独立调试入口任务。验收维持 G1–G6 六组行为、Q1 / Q2 两条走查；分组数量不是要求新建测试文件的数量。整数加法、YOLO、SQLite、托管设备及调试 wrapper 作为不同数据路径的代表，不做“算子 × 字段 × 入口 × 失败方式”的排列组合。

实现完成并通过受影响验证后进入交付；没有新证据时，不为清空假想风险反复扩测。当前真实验证记录见 `readiness-check.md`，全部产品任务保持未勾选。

### 最终独立交叉复核

补齐后再次只读核对 D10、4.8 / 4.9、spec、G6 / Q1、交接说明和 82 项清单，未发现功能合同阻断或新增过度测试要求。发现的三处 node.log 数据路径简写已统一为 `node.log.payload.data`。清单的 ID 与入口、任务状态、规范数量及两条走查一致；未据此声称产品已实现。
