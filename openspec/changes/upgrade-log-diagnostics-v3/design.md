# 日志诊断 V3 设计

基线为 2026-11-28 的远端 `main`，提交 `ea5aefa9cf62f0d7ee3ac0fb6fa4a14661dc663b`，含 R4 与 Designer 主题和视口尺寸修复。Designer 与 Operator 共用 `ui/runtime_logs/` 任务工作台。Operator 本机 JSONL 和 Web 各有自己的数据源、筛选与导出入口。M1 修正会丢记录或误导排障的行为，M2 的增强可逐项交付。

## M1 · 保住业务记录，准确呈现执行情况

### 心跳只负责判活（D1）

周期心跳默认每 500 毫秒一次。Supervisor 更新判活后还会追加业务事件，心跳同时占用 SQLite 和内存的保留配额，历史查询又过滤心跳。默认 10000 条配额下，长时间低活动的任务会逐步丢失早期业务记录。

在 `JobSupervisor.consumeWorkerEvent()` 既有身份、终态检查和锁内处理 `process.heartbeat`，更新判活状态后返回。Worker、共享心跳时间戳、超时和终态事件沿用原路径。`batchableWorkerEvent()` 已把心跳排除在普通批次之外。

新任务的 `StreamJobEvents` 不再收到周期心跳，也不会为心跳分配业务序号。业务事件按序交付，可从原游标继续，终态和取消按原条件结束。同步更新 `docs/runtime-event-flow.md` 的心跳持久化说明。旧 Job 仍能重放原有记录，全局历史继续过滤已存心跳。

正常启动新 Job 会分配新 ID。Runtime 重启时，遗留活动 Job 由恢复入口直接补写失败终态，随后归入历史。本轮保留现有 SQLite 单条和批量裁剪，以及已有旧库读取路径。若以后引入跨版本续跑同一 Job，再评估混合窗口的裁剪规则。

### SQLite 回执与子工作流日志（D2）

`sqlite.write.started` 发布明确的开始消息，保留原回执中的初始状态。只给历史 started 记录中已知的默认 `UNKNOWN` 显示开始文案，结束记录显示实际结果。同步写入和后台写入沿用各自的最终回执与未确认语义。

`componentForEvent()` 将 `subflow.*` 归入 execution。`RuntimeJsonlLogWriter` 在既有筛选中纳入子工作流事件和普通 SQLite 起止事件。调整 `sqlite.write.finished` 当前只接纳后台回执的分支，使同一原始事件只入队一次，继续使用既有投影、脱敏和大小限制。

### 执行树与失败定位（D4、D5、D7）

- 共享执行树将本来就没有工作流调用身份的 Job 事件（如 `job.*`、`process.terminated`、已确认的派发任务级事件）放入默认折叠的“任务生命周期”。需要关联却缺少证据的记录仍放入“未完整关联事件”。有调用身份的记录沿用实际归属。
- While 只有收到明确的 `bodyExecuted=false` 才标“退出条件检查”。只有旧结束记录缺该字段时才提示“执行情况未记录”。ForEach、Repeat 沿用已有语义。
- 实时连续跟随时，有有效开始时间且能确认仍活跃的工作流、轮次和普通节点可显示墙钟估算耗时。暂停阅读后，这些内部对象若尚无结束记录，显示“结束状态待刷新”并停止增长估算值。历史窗口或终态 Job 只看到一端时说明当前范围内缺哪一端。Job 自身按任务状态计时。RUNNING / STOPPING 且有有效开始时间时继续估算。终态停止，重启收尾标出中断确认时间。
- 点节点直接打开同一节点运行实例的已加载记录，优先结束记录，其次开始记录或确属该实例的附带记录。纯结构占位提示当前范围尚无记录。抽屉标题显示可确认的节点名称与实际记录类型。切换主动日志或设备记录时，详情与原始 JSON 始终指向当前这条事件。
- 当前窗口有失败时，在“查看失败”入口直接显示已加载的失败条数和一条代表记录，优先节点失败。用户点开前即可看到已记录的轮次、工作流、节点、日志代码与简短原因。跳转选中这条原始记录，各条失败保留原身份、级别和消息。时间顺序或相同错误码不足以判定失败因果。仅在宿主支持且身份足够时提供画布或设备入口。

## M2 · 按使用场景分别交付

### 历史名称（D2）

将创建该 Job 时的工程名和目标工作流名写入 Job 记录，随历史查询返回。普通启动、生产页启动和派发槽位分别取各自使用的工程与工作流。尤其是 `JobSupervisor._startRunGroup()` 中的消费者直接创建 `JobRecord`，必须在这个入口填入对应槽位的目标工作流名。

优先复用编译结果中的真实名称。关键 workflow、node、loop、subflow 生命周期按事件归属写入对应名称，子调用的目标名与调用节点名分开。在实际发布 `job.accepted` 的路径，只要有真实工程名、工作流名，就把对应值写入原有受理事件。派发子 Job 只补实际存在的记录。完成事件的 JSONL 投影同步保留名称。共享记录适配器从真实字段或 payload 读取，冻结值优先。仅在当前工程和修订有可信匹配时回退到当前名称，其余使用原 ID。

在既有迁移路径为 jobs 添加默认空值的两个名称列，旧历史无须回填。`RunState` 复用已有 workflow_name，补 project_name。`JobHistorySummary` 追加这两个名称，沿用现有 proto 和 Panel 契约生成流程。任务目录的工程列优先展示冻结名，提示保留完整工程 ID。已有真实槽位时显示槽位。“最近活动”使用共享的默认事件中文文案，自定义消息保留原文。

### Markdown 完整 Job 导出（D9）

两个宿主已有各自的完整 Job 导出入口。Designer 的 `exportHistory(jobScope=...)` 自行分页，现有格式传入的范围是 `runtime_history`。新增 Markdown 时明确传递本次选择的 Job 身份和“此 Job 完整可查询记录”范围。Operator 的 `_exportWhole()` 已调用 `exportWholeJob()`，沿用其 `whole_job` 范围。Operator 当前筛选导出继续表明“当前已加载范围”。

两端沿用各自固定上界分页，交给已有 `core/log_export.py` 单遍写出任务身份、实际导出范围、逐条时间线和总数。消息和摘要中的换行及 Markdown 特殊字符按文本处理。时间线使用真实毫秒时间、上下文、日志代码和可用的简短结果，缺失项如实省略。复用已有写入、取消和原子替换流程。摘要只取返回记录中可展示的字段，沿用来源已有的脱敏与截断。

### 本机日志与 Web（D3、D11）

Operator R4 已用 `QTableView + LogTableModel` 增量更新，已有级别着色、阅读位置恢复、复制、四条件筛选和本机快照导出。在现有模型的显示角色、详情和筛选标签中补常见框架中文文案、模块名及有效摘要，未知或自定义消息保留原文。关键字也应能命中列表可见的中文文案和原文，并由同一筛选条件决定筛选导出的内容。本机两类 JSONL 继续按既有尾读与脱敏路径处理。

Web 的开始和结束条件改为可编辑的本地日期时间，精确到毫秒。请求仍传整数毫秒，支持空边界、左闭右开区间。范围倒置时解释原因、保留上次生效结果。列表和易读详情均显示已知框架默认文案，列表保留文字级别及样式。详情优先使用记录中的冻结名称并可切换回该条 JSON，自定义及未知消息保留原文。沿用现有字符串游标、实例校验和导出接口。

### 共享桌面体验（D3、D6、D7、D10）

- 任务详情、历史列表、系统事件和单算子调试复用 `core/runtime_log_messages.py` 的无 Qt 格式化函数，按事件类型和已知默认消息匹配。补齐子调用、派发、停止/中止、重启失败、进程终止、SQLite 起止、产物、日志丢弃（`W_OPERATOR_LOG_DROPPED`）和已知跳过原因。未知值和自定义文字照原文显示。对实际返回的预启动容量或资源失败、SQLite/TCP 回执、IO 结果和模型信息，沿用已有结构化摘要。
- 复用 `StructuredLogEntry` 与共享 `LogRecordDetail`。节点行内展示一两项已有结果或失败原因，折叠分支统计当前窗口内不重复的 WARN/ERROR 事件。文字与既有主题色表达级别，耗时沿用对应对象的时间规则。
- Job 抽屉直接读取所选设备事件，前置已有设备、动作、通道、槽位、累计次数、回执与报文 HEX/UTF-8 预览。有截断标识时一并显示。注明累计次数的统计范围，可能跨 Job 或轮次。设备缓存不可用时仍能查看原事件已有的这些字段。打开设备诊断另行核对缓存身份，返回原位置。
- 把 `cycleId / planRevision / runGroupId / dispatchId / deliveryId / invocationId / targetSlotId / documentRevision` 等技术键收进可展开的“记录身份”。易读区省去技术默认空值，归并与外层重复的设备包络。业务值 `0`、`false` 按实显示，原始 JSON、复制和机器导出继续保留实际收到的记录。
- 提供样板起止事件折叠。只收起已有结构行能够表达的普通子项，保留告警、失败、跳过、主动日志、设备、产物和 SQLite 回执等诊断记录。关闭折叠可恢复原始行，定向定位始终选中原事件。
- 时间顺序补工作流、节点、从 1 开始的轮次和已有日志代码。任务搜索可命中中文显示文案、原始消息、日志代码、工作流名、节点名及当前权限可见的已加载 payload。复用现有输入防抖，实测卡顿时才评估随窗口释放的缓存。
- 高级历史页收起重复筛选条件，保留生效条件提示。历史列表显示日期和毫秒、日志代码、中文模块名及从 1 开始的轮次，原始路径仍可查。设备下钻补足仍只有秒的时间显示，沿用已有报文切换、原始记录及返回入口。保留详情已有的后台 SQLite 回执、算子版本、参数及结果结构。

## 后续选项 · 两轮对比（D8）

先收集现场人员实际要比较的两轮日志与要回答的问题，再决定是否立项。如启用，“仅看差异”按状态或结果筛选，实际耗时及其差值另列。仅在同一循环实例内按相对于轮次的真实调用身份唯一配对。身份缺失或不唯一时显示“未匹配”，不按出现顺序配对。该选项不计入本期开发或验收。

## 验证范围

M1 用一个小配额 Job 经真实 Supervisor 入口送入错误、超过配额的心跳和后续业务/终态记录，验证可查、按序订阅与正常结束。复用已有判活、批次屏障和超时用例。共享页的节点选择、失败定位和样板折叠可沿用同一条原生 Qt 流程。Markdown 的跨页内容与取消路径验证一次。Designer 和 Operator 各从自己的完整 Job 菜单导出同一示例，核对文件范围和选中 Job。各项对应的现有用例和最终候选 CI 见[实施与验收清单](tasks.md)。
