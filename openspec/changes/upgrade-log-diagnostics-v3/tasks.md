- [x] 1.2 更新 `tests/runtime/test_runtime_persistence_contract.py`、`tests/runtime/test_heartbeat_liveness.py` 中依赖业务心跳记录的断言。用软件 Supervisor 和缩小的配额依次接收一条错误、超过配额的心跳、普通单条和批量事件、终态。核对判活时间更新、心跳期间业务序号不变、原错误仍可查，从已确认游标续订的业务事件及终态按序、不漏不重。沿用现有失活与超时用例。旧库复用已有读取夹具，核对全局历史过滤旧心跳、逐 Job 重放按原序号返回真实已存记录，无须跨版本续写同一 Job。
- [x] 1.3 修正 SQLite 的正常开始文案。仅为旧开始记录中的默认 UNKNOWN 展示“开始写入”，真实结束状态、用户消息及后台最终回执按原义显示。将 `subflow.*` 归入执行日志，将它和普通 SQLite 起止事件纳入 JSONL。沿用 `tests/runtime/test_jsonl_logging.py` 写入夹具，核对前后台回执及子工作流事件各自只写入一次。
- [x] 1.4 将确属 Job 级的生命周期事件归入任务分组，其他事件按实际调用身份归属。While 收到明确的退出条件检查后再标注未进入循环体。暂停阅读时，尚未见结束记录的内部工作流、轮次和普通节点停止更新估算耗时，显示“结束状态待刷新”，Job 实际处于 RUNNING / STOPPING、有开始时间且尚无结束时间时继续计时。已终态的 Job 即使仍占用资源，耗时也固定。终态 Job 的早期窗口只有开始时显示“当前范围未见结束记录”，循环头未加载时说明范围。复用 `tests/designer/test_job_log.py` 的时间与执行树样例，同时观察暂停前后的分支和 Job。
- [x] 1.5 点节点直达同一次执行的代表记录，详情抬头显示节点与当前记录类型，切换附带日志时原始 JSON 随之切换。当前窗口有失败时，点击前显示真实失败数，以及代表性失败已有的轮次、工作流、节点、日志代码和短因。点击后选中真实失败，保留并行分支各自的证据。沿用 `test_runtime_job_workbench.py` 的原生 Qt 流程核对提示、选择与抽屉中的事件身份，Operator 复用共享入口检查。

## 2. M2 · 可独立交付的改进

- [ ] 2.1 在普通 Job 和派发子 Job 创建时冻结工程、实际目标工作流名。已有 `job.accepted` 在可取得真实名称时一并保存。关键工作流、节点、循环、子调用事件及 JSONL 精简投影保留当次执行的名称和 ID。按需扩展仓储、读模型及尾随协议字段。用同一组持久化和 JSONL 样例，核对工程改名、Runtime 重启后另一个客户端仍显示原名。离线打开原有 `job.accepted` 行和有名称的完成事件，核对事件中的名称。旧记录只在同工程同修订且来源可信时借用名称，其他情况显示 ID。核对受影响的生成契约。
- [ ] 2.2 为完整 Job 导出增加 Markdown 时间线。Designer 与 Operator 各确认一次入口可选 `.md`，导出范围均为该 Job 在固定上界内仍可查询的全部事件。Operator 另有当前已加载范围快照。沿用单遍写入、原子替换及原格式。完整分页和取消复用 `tests/designer/test_operational_log_integration.py` 的现有流程，用一份 Markdown 核对未加载页、跨页顺序和末尾条数。取消及写入失败保留原目标。
- [ ] 2.3 Operator 本机日志在 R4 的 `QTableView` 和 `LogTableModel` 上补已知事件的易读消息与详情，关键词可命中显示文案和脱敏原文。保留两个 JSONL 文件家族、组合筛选、阅读位置及相同筛选下的快照导出。复用 `tests/ui/operator_view/test_runtime_log_view.py` 的筛选、复制流程，用同一条记录核对两种词均可搜到，原始复制仍脱敏。
- [ ] 2.4 Web 历史查询支持本地日期时间、毫秒、可空边界和左闭右开区间，倒置时保留已显示结果。列表和详情均展示可识别的框架默认文案，列表等级有文字与样式，详情可切回原始记录。自定义消息和未知值保留原文。沿用时间转换用例和一次浏览器走查，在列表及详情核对同一条框架默认消息的中文和同一条自定义消息的原文。游标、实例和导出复用原有回归。
- [ ] 2.5 共享中文文案用于任务详情、历史列表、系统事件、既有单算子调试详情，覆盖子工作流、派发、任务停止/中止/失败（含重启）、进程终止、SQLite 起止、产物、算子日志丢弃、已知跳过原因及已记录的预启动容量/资源失败。沿用后台 SQLite 回执、算子身份和版本、参数及结果摘要。
  - 在共享格式化用例中复用一条框架默认消息、一条自定义消息和一条预启动失败样例，核对中文、原文及已有的容量或资源摘要。各桌面入口沿用同一适配。
  - 节点行展示已有结果或原因，等级及状态保留文字与语义色。折叠分支按实际出现的 WARN/ERROR 事件计数，时间线显示工作流、节点和从 1 开始的轮次。在同一条 Qt 流程中确认折叠后异常仍可见，按事件 ID 定位被折叠的普通起止行时选中的是原始事件。
  - 任务内关键词支持日志代码、工作流名、节点名、原始消息、显示文案和已加载的可见 payload。选同一已加载事件，分别用它的代码、工作流名和节点名检索，确认结果包含该条事件。
- [ ] 2.6 补齐历史列表、任务目录和设备详情的查阅条件，沿用历史筛选和设备下钻的代表性流程。
  - 历史列表收起重复筛选并保留生效条件，显示日期、毫秒、日志代码、中文模块名和从 1 开始的轮次。查同一任务时核对目录的冻结名称、已有槽位、“最近活动”的共享中文文案及名称提示中的完整工程 ID。
  - 直接打开持久化的 Job `device.*` 事件。抽屉应显示该条已有的设备、动作、通道、槽位、累计次数与统计范围、回执和 `dataHex` 的 HEX / UTF-8 预览。无匹配设备缓存时仍可查看这些字段。有匹配缓存时再下钻，检查诊断列表的毫秒时间、等级区分和返回原 Job 的位置。
  - 用同一条记录检查技术身份和重复包络已归组折叠，业务 `0`、`false` 仍可见，原始 JSON 与复制结果对应实际收到的记录。
