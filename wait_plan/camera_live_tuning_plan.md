# 相机常用属性实时试调、触发预览与节点命名

- 整理日期：2026-09-10
- 状态：待实施，本文件仅保存方案，不代表功能已实现。
- 本阶段范围：常用参数实时试调、触发预览、关闭确认与恢复、画布节点命名。
- 高级属性页暂不实施，已拆分到 [camera_advanced_properties_plan.md](camera_advanced_properties_plan.md)。本阶段不开发设备属性树、XML 属性解析或任意高级属性编辑。

## 1. 首次连接与配置来源

- 首次连接只读取相机实际配置，不自动用项目中的曝光、ROI 等值覆盖现场配置。
- 界面分别管理相机实际值、当前编辑输入、会话原始值、节点已保存值，不能相互冒充。
- 提供“试用节点配置”：用户主动点击后，才把节点保存的常用配置应用到相机，并纳入本次可恢复试调。
- 将连接、配置、采集分开。未连接时的本地编辑不访问硬件；连接、载入表单、回读刷新不得通过控件信号意外写入设备。
- 连接方式、IP、设备标识、用户名称和索引用于选择目标相机，不作为修改相机 IP 或设备名称的入口。
- 连接后解析稳定设备身份；同一台相机通过不同选择方式打开时，仍使用同一设备占用锁。

## 2. 预览与触发

- 预览默认选择自由采集，用户选择不同触发模式后随之切换，不再在 Runtime 中强制覆盖成自由采集。
- 已有项目显式保存的触发配置不得被静默改写；项目值单独保留，用户试用节点配置或主动选择模式时才进入对应试调。
- 启动预览需要设置触发模式时，先记录实际原值；默认自由采集造成的设备改动也纳入关闭确认与恢复。
- 自由采集连续显示画面，沿用最高每秒 10 帧的预览刷新节奏；该限制不等于相机采集帧率。
- 软件触发显示“软件触发一次”按钮。每次点击发送一次触发命令并获取一张图像，不自动连续触发；请求未完成时禁用按钮。
- 软件触发超时不自动补发。发送结果或取图结果不确定时明确报告，由用户停止并重新准备采集后再试，不能因通信重试多拍一张。
- 硬件触发开启后显示“等待图片”，外部信号触发出图后更新画面、帧号、设备时间戳和实际曝光，保留上一帧并继续等待。
- 硬件无图超时只表示尚未收到图像，不结束会话、不反复重连；通过短时分段取帧保证停止和配置操作及时响应。
- 等待期间必须检查 SDK 在线状态，区分无触发、掉线和真实 SDK 错误，不能在设备已断开时一直显示等待。
- 自由采集保留“单帧”；软件模式由“软件触发一次”替代；硬件模式由外部信号触发，不提供会误发软件命令的单帧按钮。
- 预览中切换触发模式、输入线或边沿时，串行结束在途取图、停采、清理旧缓冲、配置并回读、恢复采集；采集代次标识防止旧图像或旧状态更新新模式界面。
- 软件触发超时、配置失败及其他真实故障明确报告并停止采集；不能将其当作硬件模式正常等待。

## 3. 常用属性实时试调

- 保留当前中文分组和模式联动：连接、触发与重试、图像输出、曝光增益帧率、采集区域。
- 曝光、增益、帧率、ROI、像素格式、触发设置等可写相机参数，在编辑完成后实时应用，不等待关闭时首次写入。
- 数字输入在回车或失焦时提交；下拉选项、开关在选择完成后提交。避免发送未输入完成的中间值，处理在途编辑请求时保持有序。
- 写前重新核对设备身份、可写权限、范围和步长。设备不支持或不能可靠读取原值的属性明确提示并禁止试调。
- 每项属性首次修改前保存原值及选择器上下文；手动曝光、自动增益、ROI、像素格式等需要同时保存受影响的关联属性。
- 先记录修改意图，再调用 SDK，再记录返回码与回读结果；失败请求也可能已经改变设备，不能只记录成功项。
- 目标值与实际值相同时跳过写入。整数、枚举、布尔精确比较，浮点沿用现有明确容差；失败不得显示“已生效”。
- 取帧与参数修改共用同一个连接并串行执行。采集中不可写时暂停采集、重新检查权限，修改并回读成功后按当前模式恢复。
- 曝光自动模式等动态配置不能把瞬时测量值当作静态恢复目标；恢复原自动模式及其关联配置，而不是要求自动模式下曝光读数恒定。
- 输出颜色和去马赛克属于图像处理参数，实时更新处理结果但不声称写入相机；超时和重试同样属于执行设置，与相机属性写入分开记录。
- 任一写入或回读失败，停止后续操作与采集，列出已生效、失败、未执行及状态未知项，不静默自动回滚。
- 不开放网络设置、重启、恢复出厂、断电保存、任意命令或原始寄存器写入；软件触发为单独受控的采集操作。

## 4. 停止、关闭与恢复

- “停止”仅停止采集，保留配置连接和原始快照；停止、重新开始预览不重新定义恢复基线。
- 断开相机、关闭窗口、切换设备或项目、删除节点或工作流、正常退出应用，都必须处理未决调整。
- 存在调整时统一展示“原始配置 -> 当前实际配置”，包含必要的联动项；提供“保留调整”“放弃并恢复”“继续调整”。
- 保留调整：保留已生效的设备运行配置并释放连接，不重复写入，也不执行断电保存。状态未知项必须先核查，不能报告全部成功。
- 放弃并恢复：按依赖顺序恢复本次会话修改过的相机配置及关联模式，逐项回读验证；同步恢复本次试调的软件处理设置。
- 恢复前若发现非预期外部改动，停止并报告，不盲目覆盖。恢复中禁用新修改和重复关闭。
- 继续调整：取消当前关闭、删除、项目切换或应用退出操作，保持窗口和会话可用。
- 恢复失败或掉线时，列出未恢复项，提供重试、返回及明确警告后的放弃恢复并关闭，不显示虚假成功。
- 所有正常关闭入口需要支持取消，不能沿用强制关闭绕过确认。不得先删除节点或释放 Runtime，再让用户选择继续调整。
- 异常退出不能保证恢复；持久保留设备身份和未完成修改记录，下次启动提示人工核查，不自动恢复或重放写入。

## 5. 架构与项目保存

- 不改变算子的初始化、参数校验、执行、释放资源及输出契约，常用配置能力作为可选编辑器扩展，不要求其他算子实现。
- 扩展现有 Runtime 会话管理，连接与采集分离；不能继续依靠反复调用执行算子、参数变化即重连来实现实时配置。
- 相机 SDK 句柄由 Runtime 工作线程持有，串行处理连接、常用配置读写、预览、单次触发与释放；界面异步请求，不在 UI 线程等待设备。
- 会话接口覆盖常用配置实际值、实时试调与回读、采集状态、软件单次触发、调整记录、保留与恢复；本阶段不增加高级属性目录接口。
- 嵌入式与 gRPC 共用实现。请求绑定会话、设备身份及请求标识，支持重复识别和结果查询；失效会话不自动重放设备操作。
- 配置会话与工作流按真实设备身份互斥，外部软件占用时明确报错，不强行接管设备。
- 保留设备调整和保存节点配置分开。用户明确选择将哪些已验证常用设置保存到节点，项目磁盘保存仍走现有流程。
- 当前“应用”按钮不得隐式确认设备调整或重置原始快照。保存节点值不能误用过期、未生效或状态未知的界面值。
- 旧项目无需因本阶段增加高级配置字段。自动工作流仍使用已保存参数，不弹试调确认框，维持原有超时、失败和释放语义。
- Runtime 日志记录设备、属性、原值、请求值、回读值、结果及恢复过程；日志不包含图像二进制内容。

## 6. 画布节点命名

- 所有算子节点支持双击画布标题原位编辑；双击节点其他区域仍打开算子配置。
- 回车确认，Esc 取消，失焦确认有效输入。名称为单行，去除首尾空白，支持中文，长度为 1-64 个字符；空值恢复原名。
- 允许同名节点，内部始终通过节点 ID 区分。编辑文字时隔离画布删除、拖拽等快捷操作。
- 复用现有 displayName，同步画布、侧栏、已打开编辑器标题，标记项目未保存并随项目保存。
- 不改变节点 ID、算子类型、端口、位置和连线。长名称省略显示并提供完整名称提示。

## 7. 实施顺序与验收

1. 拆分连接与采集，建立稳定设备互斥、常用属性基线和修改记录。
2. 实现自由采集、手动软件触发、硬件等待及模式切换。
3. 接入常用参数实时试调、回读、联动恢复和可取消关闭流程。
4. 接入节点配置选择保存，并实现画布节点标题编辑。
5. 完成自动化、界面验证和可执行的真机验收。

- 自动化覆盖首次连接不写配置、表单刷新零写入、同设备不同选择方式互斥、重复请求及在途状态处理。
- 验证软件模式没有自动触发、每次点击只触发一次、超时不补发；验证旧缓冲隔离、硬件等待中断连识别和停止响应。
- 验证实时参数回读、部分写入失败、状态未知、关联恢复、恢复失败及异常退出记录。
- 验证关闭窗口、切换项目、删除节点或工作流、退出应用各入口均可取消，不绕过确认。
- 验证相机保留与节点保存分离、旧项目兼容、嵌入式与 gRPC 一致性、节点名称保存重开及连线不变。
- 检查中文状态、控件随触发模式变化、等待时保留上一帧、长名称和窄窗口布局。
- 真机先读取并记录原配置，再验证自由采集、手动软件触发、曝光试调、保留和放弃恢复；最终恢复测试前配置。
- 硬件触发须先确认设备能力和实际接线；没有外部触发条件时明确标记未验收，不用模拟通过代替现场出图验收。
- 本阶段验收不包含高级属性页，不执行高风险操作或相机断电保存。
